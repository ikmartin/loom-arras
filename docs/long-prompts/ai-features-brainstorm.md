# brainstorming and ideas for chat overhaul

One of the primary aims of loom is to maximize the usefulness of ai agents in aiding the mathematical learning, writing and discovery process. Loom should
1. provide a powerful CLI that can be easily used by an agent to interact with a user's quilt
2. make it easy for an author to see and discover the feedback, suggestions, comments, explanations and general content produced by an ai agent
3. provide ways for the ai to provide ephemeral content (chat transcripts), feedback and comments and content tied to specific portions of the author's quilt which stay in place until manually addressed (annotations), and longer-lived richer content which persists independent of the session system and can be updated/modified over time across different sessions and upgraded to either items in the author's drafting/nodes or to a static document in the author's library.
4. make it possible for ephemeral chat content to link to the content in a user's quilt
5. provide a translation layer which recommends specific loom commands to be used in response to an author's english commands, in addition to longer "programs" (modes) that layout a procedure for an ai to follow in response to specific requests.
6. make the interaction with ai agents as easy as possible. If no agent is attached to the session when a message is submited, loom should attach one. As annotations are edited and reviewed, there should be a tracker listing which annotations have changed since the last submission to the ai. It should be possible to submit a "packet" to the ai without a message, and it should be obvious what that packet contains.

As loom stands it accomplishes almost none of this. There is decent support for annotations now, but the chat system isn't good and there is currently no way for an agent to create richer content which persists between sessions and can be upgraded to actual quilt content. Here are some concrete changes I think should be made.

| Tier | Owner | Lifetime | Enters the next tier by |
|---|---|---|---|
| chat | session | ephemeral | the agent writing an annotation or a workspace document |
| annotation | anchored to a place in the author's text or papers | until resolved | resolution, or becoming work in the workspace |
| AI workspace (the "AI quilt") | the agent, revisable across sessions | durable | the author promoting it |
| author's quilt / library | the author | permanent, reviewed | — |

- overhaul the chat box. Make it span the whole bottom of the workspace view, make it possible to control how much space it takes up (vertical resizing) make it collapsible/hidable. I envision the hidden view being a small little "folder tab" looking thing called "chat" at the very bottom of the page centered horizontally exactly where the 50 : 50 split line goes in split view, when you hover over it, the very first bit of the chat window is pulled up so it is visible, and clicking it reveals the chat box.
- there should be an easy way for an ai to include links in the chat transcript to various portions of the user's quilt. To specific locations in pdf, to specific nodes, to specific drafting documents, even possible to specific annotations. Following a link to a pdf from the chat should open up the pdf in the other panel, bring it into focus and jump to the locator -- exactly as following a link with a locator behaves now. A link to a drafting document should include a locator, which opens the drafting document at a specific location exactly as in the pdf case. It should also be possible to link to a node contained in the drafting document, in which case the view jumps to the node's position in the document. Links to annotations navigate to the location of the annotation and open the annotation automatically. For annotations on nodes it should be possible to open a view onto the node's own page OR to the node's position in a drafting document, it should be the ai agent's choice.
  - all links can contain locator information
  - clicking a link navigates to content in a document. if the document is already open in a tab in the workspace, that tab is put in focus and jumps to the specified location. if the document is not open then it is opened in a new tab in whatever panel is not currently in focus and then brings that panel into focus (necessarily this means that a link in the discussion to an unopened document will open the document in whichever panel does NOT currently contain the discussion, which is intended)
  - ai agents should be told to consider whether linking to a node page is better or linking to the node in context in a drafting document is better.
- it should be possible for an ai agent to propose NEW DEPENDENCY edges in the user's quilt. This is likely better suited to a graph view overhaul alongside a system which allows the user to view nodes side by side and then propose a directed edge themself in the viewer. The natural place for the agent proposals then would be in this view as a proposal queue.
- annotations shouldn't be shown in the discussion transcript. The discussion is a chat interface with extra loom features; annotations aren't linear and might be referenced at multiple points in a conversation. The ai agent can link to annotations, and if it wants to reproduce them in the chat it is free to copy their content and print it.
- there should be something resembling an ai-only quilt. This is the correct shape for longer, richer content created and maintained by the ai. It makes it easy to promote it into the quilt either as an individual node, a collection of nodes, a standalone document in the library, or a drafting document.
  - use case: an example of a phenomenon the user asks about in chat. The ai responds with the example, they workshop it, the user asks it to make it a permanent example so that it doesn't disappear in the transcript.
  - use case: tutorial/learning about something. The user asks the ai to teach him/her about the derivation of Black-Scholes. The ai creates a document with multiple nodes in it, the user reads through it, asks questions/makes points, the ai edits the document to incorporate the feedback. At the end there exists a single document tailored to the user, and it is promoted into the reference materials of the library once the user is sure it is mathematically correct.
- the chat interface should be improved. There should be a little indicator reading "n annotations modified" and clicking it should expand into a menu of rows, one for each annotation whose state has been modified by the user since the last submission. Each row should contain a link to the annotations so they can be reviewed easily in context, and the option to preview the actual text which will be sent to the agent. The preview button is something on every row, it is revealed on mouse hover on the row, and clicking it shows a little popup window displaying the verbatim text which will be sent to the ai.
