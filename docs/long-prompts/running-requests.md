## Open
- [x] the viewer could generally be sped up and optimized. Many things feel a little slow. Clicking buttons in the settings is laggy. Test out 6 potential optimizations, implement the top 3.
  Measured on a 145-node corpus rather than on the conformance fixture, which has twelve formulas and could never show a slow page. One document page is ~92,000 elements, 85% of them inside typeset math, and a settings click cost 308 ms before the next paint. Six candidates timed: (A) baseline, (B) the synchronous part of the click, which is 0 ms -- nothing JavaScript does is slow, (C) per-key annotation filtering, (D) the same answer from one index, (E) `contain: layout style` on blocks, 272 ms, (F) `content-visibility` on the math, 232 ms, (G) `content-visibility` on sections, 33 ms, (H) the flip with all math hidden, 217 ms. Implemented the top three: section-level `content-visibility` with `contain-intrinsic-size`, the same on math containers, and an annotation index built once per manifest instead of a full scan per key. A settings click is now **22 ms, from 308**. The index is the one of the three this corpus could not demonstrate -- it has no annotations -- and is justified by its complexity rather than by a measurement.
- [x] a toggle in settings for "paper" or "blog" format display, applied globally so that it affects the read display as well as the display of nodes.
  One switch on the root element, so the read view and a node's own page change together: a result should not read as a different kind of thing depending on which page it is standing on. Paper is the measured, numbered column; blog is wider, with sans headings, environments carried by a tinted panel in their taxon's colour rather than by a hairline accent, and no theorem numbers -- a paper points at a result by number and a website points at it by name.
- (FOR HUMAN) the modes should be reviewed and heavily modified. This likely needs to be verified and completed by a human.
- [x] color coding in the graph view: currently no color coding at all. should match the color of the taxons, and there should be one place to set these colors.
  Graph nodes were coloured by state, and since nearly everything is `draft` that read as no coding at all. They take the taxon's colour now, and it is the same colour the accent down an environment's left edge uses. One palette, declared once in `theme.css`; `$lib/taxonomy` decides which token a taxon gets and never knows a value. Assigned by the manifest's own `style` and the taxon's position rather than by name, so a corpus whose taxa are "Widget" and "Gadget" is coloured like one using Bourbaki's. Fill is the taxon and the ring is still the state: what a node is does not change while you work, and how it stands does.
