## Open
- [x] add a third view option to annotations: hover. Annotations open as expandable hover boxes, clicking outside of the box hides then, they can overlap the text or the gutter.
  A third value on the Comments setting, beside margin and inline. It is the same `AnnotationBox` and the same controller — the three differ only in where the box goes — so a hover box carries the quote, the severity, the replies and the typeset mathematics exactly as the other two do. The pointer opens it after 120ms, so passing over a line of marked text does not flash a box per mark; a click opens it too, and a click away or Escape closes it. Fixed to the viewport and appended inside the fragment rather than the page's root, because arras is a guest that writes only in its own subtree; a scroll closes it rather than letting it drift.
- [x] fix latex rendering in annotations, currently it fails. Take screenshots, diagnose, fix. Also notice the text size is small and hard to read in the annotations. Match text size to the size of the surrounding text, dependent on the size chosen in settings.
  Two causes, one in each tool. **Nothing ever typeset an annotation body**: fragments go through `Fragment.svelte` and titles through `Tex.svelte`, and the three places that show a published body — an annotation, a reply, a thread message — all did `{@html body_html}` and never called MathJax, so every `$…$` arrived as literal `\(n \le 2\)`. They share `math/Prose.svelte` now. And loom put display math inside the paragraph's `<p>`: an equation written on a soft line break between two sentences, which is how annotations are actually written, produced a `div` nested in a `p` that the browser repairs by closing the paragraph early. Every equation is lifted out of its paragraph, splitting it. The box takes `calc(var(--body-size) * 0.92)` instead of a fixed 11px, so it follows the size the reader chose.
- [x] where is the toggle for page render style, blog vs paper? This should be a row in settings.
  It is already there: the **Format** row, between Theme and Comments. Verified against the built viewer.
- [x] more latex processing errors: rl-000Y/proof fails for the following display math environment: "\begin{align*}S_{(j_1, \mathfrak E_1)}(\beta) &= e_T(E^0_1) \cap S_{C_{E^1_1}}(p'^*_1(\beta)) \tag{Equation \text{(9)}}\\ &= e_T(E^0_1) \cap e_T(E^0_2) \cap S_{C}(r_1^*p'^*_1(\beta)) \tag{Lemma~\text{3.11}}\\ &= e_T(E^0_2) \cap e_T(E^0_1) \cap S_{C}(r_2^*p'^*_2(\beta)) \tag{top square commutativity}\\ &= e_T(E^0_2) \cap S_{C_{E^1_2}}(p'^*_2(\beta)) \tag{Lemma~\text{3.11}}\\ &= S_{(j_2, \mathfrak E_2)}(\beta), \tag{Equation \text{(9)}}\end{align*}"
  `\text is only supported in math mode`, from MathJax. The author wrote `\tag{Equation \eqref{…}}` and `\tag{Lemma~\ref{…}}`; loom substitutes a reference for its number and wraps it in `\text{…}` to keep it upright, and a `\tag` argument is **already** text mode, so the wrapper is an error there and MathJax refuses the whole formula — which is why the aligned chain published as its own source on a yellow ground. A reference inside a text-mode argument (`\tag`, `\text`, `\mbox`, `\intertext` and their kin, brace-matched because they nest) is now substituted bare; everywhere else it keeps the wrapper.
- [x] the view for canon documents is broken. Investigate, take screenshots of the read view, diagnose, fix it.
  The read view opened on its own preamble: four kilobytes of `\renewcommand{\Ab}{\operatorname{Ab}}…` set as the document's first paragraph. A landmark renders with its own macro set, and arras prepended that set to the first formula on the page — **outside** its `\(…\)`, where MathJax reads it as prose rather than executing it. So the definitions showed as text and defined nothing. They now go inside the delimiter: 1,249 formulas on that document, of which exactly one was failing, and it was the first.
- [x] text size: small is too small, discard. The current Medium size should be S, the current L size should be M, and there should be a third size L larger than any current sizes.
  The scale moved up one step: S is 13.5px (the old M), M is 16px (the old L), and L is a new 19px. The old 11px is gone. Three names, three sizes, and a stored preference keeps its letter.
- [x] the document selection dropdown should display FILENAMES (draft1.tex) rather than tex titles (Relative Virtual Localization)
  The picker names both groups by file now. Two drafts of one paper share a title and differ only in their path, which is what you type and what `--master` and the read view's URL name them by.
- [x] the viewer could generally be sped up and optimized. Many things feel a little slow. Clicking buttons in the settings is laggy. Test out 6 potential optimizations, implement the top 3.
  Measured on the relloc paper: 160 nodes, 1,254 formulas, 44,000 elements. Six candidates, measured before choosing.
  **Taken.** (1) Typesetting batches from 160 formulas to 48 — one pass was a 90–100ms stall and a first screen holds about 25. (2) `content-visibility: auto` on the read view's environments, so the browser stops laying out and painting the 44,000 elements nobody is looking at. (3) Changing where comments stand re-keyed the fragment, which re-rendered its HTML and re-typeset every formula in it; the marks read their options live now, so the slots are taken out and put back the other way instead. **That one click went from 787ms to 45ms**, and long tasks during a read-view load went from eight of 50–100ms to one of 51ms.
  **Not taken, and why:** the manifest is 0.5MB and parses in 1.4ms; client-side navigation dispatches in 2–4ms; the cold load is 18ms of DOM work with the assets an afterthought. None of the three is what feels slow — typesetting was, and the first two changes are about not doing it in one bite.
- [x] a toggle in settings for "paper" or "blog" format display, applied globally so that it affects the read display as well as the display of nodes.
  One switch on the root element, so the read view and a node's own page change together: a result should not read as a different kind of thing depending on which page it is standing on. Paper is the measured, numbered column; blog is wider, with sans headings, environments carried by a tinted panel in their taxon's colour rather than by a hairline accent, and no theorem numbers -- a paper points at a result by number and a website points at it by name.
