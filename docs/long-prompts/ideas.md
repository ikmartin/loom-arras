# Ideas

- how do I "link Zotero to loom" and what does that look like/mean?
- Would be nice for a quilt directory to be mostly empty and up to the user to define, unlike the way it exists today. Ideally it would come empty for a single exposed config file, a `.quilt/` directory containing the loom managed files and maybe a readme which is generated on `loom init` and functions as a loom tutorial which is safe to delete. This requires rethinking the functionality of loom, the display of the docs sidebar, and the restrictions on agent write rules. Perhaps there could be a section of the config which explicitly lists directories the ai is NOT allowed to write in following the same rules as a .gitignore?
- loom should be more format/content agnostic. Perhaps the docs view should be more of a file viewer in the style of vscode than a list of tex files in two specific directories. It'd be nice, for example, for loom to provide tools for streamlining the creation of a custom course (see the ~/notes/quilts/quant quilt), where the user and agent might want the freedom to create a course homepage, a topic list, problem lists with solutions, highlights from course material, a lesson outline that says "read this then do this problem" with links to the locations in the pdfs, an HTML artifact that displays progress and topic progression, the ability to see jupyter notebooks alongside course modules and link to them with the link opening the notebook in the user's preferred application, etc. Is this a completely separate product or not? I think no -- it still fits the framework that loom is a tool for ai assisted mathematics learning and research, but it certainly loosens aspects of it. The id system can still work here to great advantage, but the review system doesn't make sense. It should likely include a rethinking of the review system and what it is. My thought is that the review view is a place to see changes and edits in one place and accept them or throw them away. It's like the "meta view" of the quilt, whereas the "docs view" is like the "working view" of the quilt. I go to docs when I want to engage with the quilt and I go to review when I want to understand the broader state of the quilt itself.
- a running "working memory" editable and readable by both human and ai, sort of a research state keeping track of current open questions and notation and decisions and whatnot
- remove graph from sidebar and the home button and the search so that the whole leftmost rail can be removed. Rework nodes and literature to move off of the contents/documents side bar and give each their own more useful view (rarely if ever need to look at a node on its own).
- make all links to references go to the source pdf, can't think of a single case a human would ever want to look at the digest version
- the current graph page should be accessed through the graph button on the bottom of the page
