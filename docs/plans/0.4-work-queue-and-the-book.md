# 0.4: the work queue, and the book as a description of what exists

## Context

The book plays two roles at once: it specifies what loom should be, and it describes what loom is. That worked while the project was being built to a plan, but every milestone is now demonstrated and the seams show — 23 `[deferred]` and 35 `[assumed]` statements scattered across the chapters and specs, several of them stale (already settled by implementation but never unmarked), and 22 "Open questions" sections whose bullets are mostly "settled in 8.5.3". Meanwhile nothing records *when* deferred work should be picked up, and the only "what's next" pointer — `docs/demonstrations/README.md`, which AGENTS.md sends an agent to first — has no incomplete rows left, so the onboarding path dead-ends.

This plan splits the two roles apart. **The book describes the implemented state and carries no unfinished business.** Deferred work moves to a new work queue where each item carries an *observable trigger* saying when it becomes worth doing. The demonstrations directory, which is entirely historical, folds into the queue's closed record so there is one place to look.

Nothing in loom or arras changes. This is documentation structure, one commit's worth of prose, plus a small check script.

## 1. The queue

```
docs/work-queue/
  README.md              purpose, how to use it, the active table, the cap
  WQ-01-<slug>.md        one file per active item
  closed.md              index of retired items and the milestone record
  closed/                the migrated demonstration files
    M0.md … M7.md, 0.3-round.md, book-revision.md
  check.py               the guard, run during the round walk
```

Deliberately the shape of `docs/demonstrations/` — a README holding a table plus one file per entry — because that idiom is already proven here and needs no explaining.

**`README.md`** opens by saying the queue is *not ordered*: items come out when their trigger fires, not in sequence. Then the rules (ids are `WQ-NN`, never reused; every item needs an observable trigger; the cap), then the table of active items with columns id, item, repo, trigger.

**Cap: 20 active items.** Seeding lands near it, which is the discipline working — a twenty-first item means promoting, merging or dropping one.

**Item file** (`WQ-04-library-dependencies.md`), fixed sections so items stay comparable:

- **Trigger** — the observable condition, repeated so the file stands alone.
- **Why deferred** — what is missing today. This must be the trigger inverted: deferred *because* X is missing, trigger *is* X existing. If they do not invert cleanly the item is vague and has not earned a place.
- **Rough design** — parameters, not a plan.
- **Blast radius** — which chapters, specs and repositories it touches when it lands. Cheap now, expensive to reconstruct later.
- **Related** — decision records, chapters, sibling items.

**Graduation:** an item leaves the queue for `docs/plans/` when the author commits to building it, not at any size threshold. Item files may be long; the reference-corpus items are.

**`closed.md`** is append-only, one line per retired item — id, title, date, and either a pointer to the plan or record that carries it, or one sentence on why it was dropped. It also carries the twelve milestone rows migrated from the demonstrations table. The epitaph, not the corpse: if an item was built the design lives on in its plan; if it was dropped, the one line is the part worth keeping. `WQ-04` stays resolvable forever and the active table stays short.

**`check.py`** asserts, in the idiom of `loom/scripts/gen_cli_reference.py --check`:

1. every active row has an id, a non-empty trigger and a file that exists; every `WQ-*.md` has a row
2. ids are unique across active and closed, and no closed id reappears
3. active rows ≤ 20
4. every relative pointer in an item file resolves to a real file
5. zero `[deferred]` and zero `[assumed]` in `docs/book/` and `docs/specs/`

Rule 5 is what makes the book's new role permanent: it cannot quietly regrow a deferred block. The workspace repository has no CI workflows (14.4), so `check.py` runs during the end-of-round walk alongside `docs/deviations.md`; a workflow comes later if it earns one.

## 2. The book

**Marker vocabulary.** `[decided]` is kept and redefined in the front matter as *normative: this is what loom does; changing it is a decision-record event*. `[assumed]` and `[deferred]` are retired. The 460 `[decided]` sites are untouched, so the diff shows the actual change rather than a mechanical rename.

**Triage first, delete second.** One pass over `docs/book/` and `docs/specs/` dispositions all 58 marked statements. Five dispositions, each observed in the current text:

| | disposition | action |
|---|---|---|
| A | implemented as assumed | drop marker, state what is |
| B | implemented differently | verify the decision record and deviations row exist, then state what is |
| C | not a deferral at all — a cross-reference, a stale marker on a sentence that *is* the decision, or a conditional inside a `[decided]` statement | rewrite in place, no queue item |
| D | genuinely deferred, still wanted | `WQ-NN` with a trigger, deleted from the book |
| E | deferred, no longer wanted | one line in `closed.md`, deleted from the book |

Then, in order:

1. **Front matter**: redefine `[decided]`, delete the `[assumed]` and `[deferred]` definitions, delete the sentence promising an "Open questions" section per chapter, and rewrite the status line (it lists the GitHub remotes as outstanding, which is stale).
2. **The 22 "Open questions" sections** (16 chapters, Appendix B, 5 specs): triage the bullets, then delete the section heading and its contents entirely. Most bullets are already "settled in §x" and simply go.
3. **Inline markers outside those sections**, rewritten in place per their disposition.
4. **Appendix B**: the file is kept so that C, D, E, F lettering and every cross-reference survive; its body becomes one paragraph pointing at `docs/work-queue/`.
5. **Repoint every reference** to `docs/demonstrations/` at `docs/work-queue/closed/`: `13-plan.md` (the bulk), `14-tests.md`, `B-open-questions.md`, `00-front-matter.md`, `F-colophon.md`, `AGENTS.md`, `CLAUDE.md`, both historical plan files, and one line inside `M0.md`. A path that no longer resolves is a bug, not testimony.

Chapter 13 stays as the historical record of how the project was built; only its paths change.

## 3. Demonstrations

What is in those eleven files that lives nowhere else: the **nine build commands** for the real-paper quilts (`demos/refresh.sh` rebuilds only `demo` and `synthetic`; `relloc`, `acgs` and `man12` were built by hand and the only record is the command blocks in `M4.md` and `M5.md` — already stale, since every one passes the withdrawn `--no-git`), the **four blocked items** in `M7.md`, and the **measured baselines**. Duplicated elsewhere and not worth migrating: "Book says" (13.2), test counts (Chapter 14, and already stale), the decision-record lists (`docs/deviations.md`, Appendix A), and the import numbers (6.10 carries M4's breakdown verbatim).

`docs/demonstrations/` ceases to exist as a directory, but only one of its eleven files is deleted:

| file | fate |
|---|---|
| `M0.md` … `M7.md`, `0.3-round.md`, `book-revision.md` | `git mv` to `docs/work-queue/closed/`, contents unchanged, history preserved |
| `README.md` | deleted — but first its twelve-row status table migrates into `closed.md`; its prose is superseded by the queue's own README |
| the directory | gone, because it is empty after the move |

Alongside the move:

1. **The nine build commands migrate into `demos/refresh.sh`**, de-staled (`--no-git` dropped) and guarded to skip when `tests/fixtures/` is absent, since the paper sources are uncommitted and the script must degrade the way the paper tier does. This is the one piece of demonstration content that belongs somewhere operational rather than archival.
2. **The four blocked items become queue entries** with triggers.

## 4. AGENTS.md and CLAUDE.md

`AGENTS.md`'s reading order sends an agent to `implementation-plan.md` and then to the demonstrations status table, "continue with the first milestone that is not `demonstrated`", which is now vacuous. It becomes: the work queue first, then the book (with `docs/specs/` winning on shapes), then `docs/deviations.md`, then `docs/plans/` for work in progress with the older plans marked history. Two rules join the non-negotiable list: the book carries no `[deferred]` or `[assumed]` statements and no "Open questions" sections, and closing a queue item means deleting its file and row and adding one line to `closed.md`, ids never reused.

`CLAUDE.md`'s "This workspace" reading order is repointed the same way. Everything else in it stands.

## 5. Seeding

From three sources: the book's D-disposition statements (`--relative`, `% !TEX root`, `\part`/memoir sectioning, the library-quilt flag, non-English locator normalization, the Codex permission file, LSP rename, the Emacs client, client-side versus precomputed graph at scale, the man12 bundle run); the demonstrations' blocked items (Overleaf, the external user, the Codex session, publishing); and the reference-corpus discussion of 2026-09-16 (reference identity and the `reached` primitive, the recursive crawl, library dependencies, the contracted work-graph view, network identity resolvers, the machine-global byte cache).

Several triggers are numbers loom already prints or is about to, which is the property to aim for: a port is discovered to be ready by running `loom doctor`, not by remembering to read a file. If seeding exceeds twenty, the excess is merged or dropped before the commit.

## 6. Records

A decision record for the book's change of role, a row in `docs/deviations.md`, this plan committed before execution, and an entry in `docs/records/`.

## 7. Verification

`python docs/work-queue/check.py` passes; no `[deferred]` or `[assumed]` survives in `docs/book/` or `docs/specs/`; no reference to `docs/demonstrations/` survives anywhere; no "Open questions" heading survives outside Appendix B's replacement paragraph; `sh demos/refresh.sh` rebuilds the two generated quilts and skips the paper quilts with a clear message when the fixtures are absent; `AGENTS.md` read top to bottom leads a new agent from "start here" to a first action without a dead end; and both repositories' suites still pass, since nothing in the docs tree should be load-bearing.

## Outcome

Executed 2026-09-16, in one pass, as written. DR-107 records the decision; `docs/records/record-2026-09-16.md` records the execution.

What the triage found, which the plan anticipated only in outline: of the 23 `[deferred]` statements, fewer than half were genuine deferrals. Three were cross-references or conditionals inside a decided statement, several were stale markers on sentences that *were* the decision, and the 22 "Open questions" sections proved to be mostly lists of things already settled — so the sections deleted wholesale, with exactly one fact in them (that `.loom/snapshots/` is committed) needing to be folded into a chapter body first. 23 statements were rewritten in place, 2 paragraphs describing unbuilt options were removed, and 19 items were seeded, one under the cap of 20.

Three things surfaced that the plan did not foresee:

- **`docs/specs/runner.md` specifies a subsystem that does not exist.** Under the new rule a specification of unbuilt work cannot sit unmarked beside specifications of what ships. It is kept, because `config.toml`'s `[ai] runner` key points at it, but now opens by saying it is not implemented and naming WQ-15.
- **The check had to match the marker's *form*, not the word.** DR-107's own text names `[deferred]` and `[assumed]` in prose, as does Appendix B's replacement. Matching `**[deferred]**` rather than `[deferred]` lets a record describe what it withdrew.
- **`demos/demo` and `demos/synthetic` were stale in the workspace**, behind loom's own fixtures by plan 0.2's outline master, candidate taxa and `see:` relations. Running the rewritten `refresh.sh` revealed it; committed separately.

Not done, deliberately: `refresh.sh`'s paper-quilt path was verified for syntax and for its skip branch, but not run, because rebuilding `demos/relloc` would destroy untracked local ledger state from M7 that no repository holds. The first person to rebuild it should expect the nine commands to be exercised for the first time since they were de-staled.
