# 0.8 — The reference crawl: building a library

## Context

WQ-02 was redesigned with the author on 2026-09-17 and graduates here: the author asked for its implementation plan with the trigger set aside. This plan carries the whole design; the item's file leaves the queue.

The crawl builds a **library**: starting from a quilt's bibliography, the works it cites, the works those cite, and so on to a chosen depth, restricted to chosen subjects, with the downloadable ones fetched under a hard cap. The same machinery builds a project's working library or, with the cap raised, a corpus. It produces works and citations, never digests. Connecting one quilt to another's library is WQ-03, deferred until a library exists to connect to.

Everything below that names a service's behaviour was checked against the live service on 2026-09-17.

## Scope

**In:** the `\bibitem` parser promoted from the plan 0.5 study; clients for zbMATH Open, OpenAlex and arXiv; the MSC families and the MSC-to-arXiv table; per-work records; the metadata-only plan; the capped fetch; `loom refs crawl plan | fetch | status`; the `[crawl]` config table; hermetic tests; documentation.

**Out:** showing the library in arras (the work graph of plan 0.7 is where it will go, as its own plan); Unpaywall and the journal archives (Numdam, EuDML, Project Euclid), assessed in §9 and left for a measurement; bulk sources (arXiv's S3 buckets, the OpenAlex snapshot), which matter only past tens of thousands of works; digests of crawled works; WQ-03 and WQ-06.

## 1. Controls

```toml
[crawl]
depth = 2
subjects = ["14N", "14D", "14C"]   # MSC families
cap = 1000                          # works downloaded
```

- **Depth.** The bibliography is depth 1. A work at depth *d* < `depth` is expanded, its references read; a work at `depth` is included and not expanded. The plan also counts the next level's works where their references are already known, at no cost, as information.
- **Subjects** are MSC families: the first three characters of a code (`14N35` → `14N`; `14-02` → `14-`). When `subjects` is absent, the default is the families of the depth-1 works' MSC codes. The plan prints the families it used and the TOML line that fixes them, so the author reviews them before anything downloads.
- **Depth-1 works always pass**: the author cited them.
- **The arXiv fallback.** A work with no MSC codes passes if its primary arXiv category is one the chosen families admit, through the table of §4. A work with neither is excluded and listed.
- **The cap** counts downloads, not works known or lookups made. It is raised only in `config.toml`; there is no flag. When more works are downloadable than the cap allows, fetch takes them in order — shallowest depth first, then by in-degree among the works found — and reports how many it left out.
- **Consent** reuses the existing keys: the plan makes lookups, so it needs `[refs] resolve = true`; fetch downloads, so it also needs `[refs] fetch = true`.
- `[crawl] depth` never shares a name with the graph view's "depth around selection".

## 2. The commands

```
loom refs crawl plan      walk metadata, apply depth and subjects, write refs/crawl/plan.json, print the summary
loom refs crawl fetch     download what the plan selected, in order, under the cap; resumable
loom refs crawl status    what is recorded: works, downloads, what is left, the plan's age
```

`fetch` reads the saved plan and refuses one made under different `[crawl]` settings or a changed bibliography (the plan records a hash of both), naming `plan` as the command to run. Illustrative summary:

```
depth 2 · subjects 14N 14D 14C (default: families of depth 1) · arXiv math.AG · cap 1000
  612 works: 431 downloadable (arXiv 402, open copies 29), 181 metadata only, 38 excluded by subject
  references not yet known for 57 works (preprints with no reference list in either index)
  ~1.4 GB · ~40 min of downloads · 1,900 lookups
  identified by lookup: 213 strong (followed), 24 possible (listed, not followed)
  to fix the subjects: subjects = ["14N", "14D", "14C"]
```

## 3. The sources

Each client lives in `loom/src/loom/refs/crawl/`, takes an injected transport like `resolve.Resolver`, spaces its requests, caches raw answers under `refs/cache/crawl/<service>/`, and is tested against recorded responses.

| client | used for | how, as checked |
|---|---|---|
| `zbmath.py` | MSC codes; resolved reference lists | `_search?search_string=doi:…`, `arxiv:…`, or `ti:… & au:…`; `/document/{id}` for a reference's `zbmath.document_id`. A record's `references` carry `doi` and `zbmath.document_id` with MSC codes where zbMATH matched them (Aranha et al. 2025: 46 references, 30 resolved). Old papers often have none (Graber–Pandharipande 1999: 0). One request a second. |
| `openalex.py` | reference lists zbMATH lacks; open-access copies; DOIs | `/works/doi:…` for one work (free); `/works?filter=openalex_id:W1|W2|…&per-page=50` for a reference list in one call ($0.0001): Graber–Pandharipande's 19 references came back as 18 works, 16 with DOIs, 5 with an open PDF. An arXiv preprint's record lists no references (Aranha et al. preprint: 0). A key comes from `LOOM_OPENALEX_KEY`, never from a tracked file; without one, requests draw on the $0.10 anonymous allowance and the plan warns. |
| `arxiv.py` | primary categories; e-print sources | `export.arxiv.org/api/query?id_list=a,b,c` returns several primary categories in one request; the e-print fetch already in `digest/fetch.py` is reused. Requests three seconds apart, as arXiv's API terms ask. |
| `bibitem.py` | a preprint's references, once its source is on disk | the parser from `scripts/bibliography_parse_rate.py`, promoted: `\bibitem` wherever it sits, arXiv ids and DOIs read from the text, and the rest resolved by `resolve.Resolver` from a free-text `Query`. |

A work's references are the union of the three, deduplicated by identifier. An arXiv identifier is compared without its version (`2207.01652` and `2207.01652v2` are one work); the version fetched is recorded.

## 4. MSC families and arXiv categories

`loom/src/loom/refs/crawl/msc.py` holds the family rule and a table from MSC areas to arXiv categories, at the two-digit level with three-character exceptions where one area splits across categories (`14` → `math.AG`; `55` → `math.AT`; `18` → `math.CT`; `53D` → `math.SG`; `81T` → `math-ph`, `hep-th`; …). No published mapping was found. The table is written by hand and checked once by `scripts/msc_arxiv_table.py`, which tallies the author-given MSC codes against primary categories on a sample of arXiv records and reports disagreements; the script is a measurement, like the parse-rate study, and nothing consumes its output.

## 5. Identification

- A depth-1 work is identified by its bibliography entry's declared identifier; failing that, by lookup.
- A deeper work exists only as a reference: a DOI or zbMATH id when an index resolved it, otherwise formatted text, identified by lookup.
- A **strong** lookup match (loom's score ≥ 0.9) is followed at every depth and listed in the plan as found by lookup. A **possible** match is listed and not followed. An unmatched reference is kept as text in its citing work's record and not followed.
- A work known by several identifiers is filed under the first in the resolution order of 8.4 (DOI, arXiv, MR, Zbl), and its record lists the rest.
- When a lookup identifies one of the author's own entries, the work is filed under the matched identifier while the citekey stays filed under its synthetic `work:<hash>`; the record names the citekey, so the two can be joined.

## 6. Records

**Per work**, `refs/<scheme>/<id>/work.json`, beside whatever is downloaded (`src/`, `paper.pdf`):

```json
{
  "record": 1,
  "ids": ["doi:10.1007/s002220050293", "arxiv:alg-geom/9708001", "zbl:0953.14035"],
  "title": "Localization of virtual classes",
  "authors": ["Graber, Tom", "Pandharipande, Rahul"],
  "year": 1999,
  "msc": ["14N35", "14L30", "14N10"],
  "arxiv_category": "math.AG",
  "references": [{"id": "doi:10.1090/s0894-0347-98-00250-1"}, {"text": "D. Mumford, Geometric invariant theory ..."}],
  "reached": {"depth": 2, "from": ["arxiv:2207.01652"], "by": "lookup", "citekeys": []},
  "download": {"kind": "source", "from": "https://arxiv.org/e-print/alg-geom/9708001v2", "fetched": "2026-09-18"},
  "sources": {"zbmath": 1275767, "openalex": "W2034404907"}
}
```

A metadata-only work's directory holds only its record. **Per crawl**, `refs/crawl/plan.json`: the parameters, the hash of `[crawl]` and the bibliography, the counts, and the ordered selection. Everything is under the ignored `refs/`; what makes a library reproducible is `[crawl]` in the tracked `config.toml`. A tracked export of the graph is left for when sharing it through version control matters, and would carry zbMATH's CC-BY-SA data.

## 7. Planning

1. Identify the depth-1 works (§5).
2. Breadth-first by depth: for each work to expand, fetch its records (§3), take the union of its references, identify each, and apply the subject filter to works not yet seen.
3. Count in-degree as references accumulate; order each depth's works by it.
4. Classify each included work: downloadable from arXiv, downloadable as an open copy, or metadata only.
5. Estimate: download sizes from a running average of fetched artifacts, starting at 3 MB per source and 1 MB per PDF; time from the services' spacing; lookups counted.
6. Write `plan.json`, the per-work records, and print the summary.

The plan is exact wherever an index lists a work's references and a floor where none does: a preprint's references are known only once its source is downloaded, and the summary says how many works are in that state. A later `plan` after a `fetch` reads those sources and closes the gap.

## 8. Fetching

In the plan's order, up to the cap: an arXiv source through the existing fetcher (reusing its retries and path confinement), otherwise the open copy's PDF. Each success updates the work's record at once, so an interrupted fetch resumes by skipping what is on disk. A failed download is recorded and reported, and does not stop the crawl. After fetching, the downloaded sources' `\bibitem`s are parsed into their records, ready for a deeper plan.

## 9. Download options assessed

| option | decision in this plan |
|---|---|
| arXiv per-paper e-print | **built**: the default, three seconds apart |
| OpenAlex open-access locations | **built**: the way to a published paper with no preprint; free by DOI |
| OpenAlex content endpoint ($0.01 a PDF) | not built: open-access locations reach the same files free |
| Unpaywall | assessed after the first real crawl: count the metadata-only works it would make downloadable |
| Numdam, EuDML, Project Euclid | as Unpaywall; each is one archive's API |
| arXiv S3, OpenAlex snapshot (~750 GB) | past tens of thousands of works, with WQ-06 |

## 10. Steps

1. Promote the `\bibitem` parser to `refs/crawl/bibitem.py` with tests on the two fetched relloc sources' bibliographies (46 and 57 entries); the parse-rate script imports it.
2. `zbmath.py`, `openalex.py`, `arxiv.py` with recorded responses (Graber–Pandharipande, Aranha et al., Romagny 2022, a reference batch).

6. `fetch.py`: ordered downloads under the cap, resumption, failure recording.
7. The CLI, `[crawl]` in `QuiltConfig`, the consent checks.

## 12. Risks

- **Rate and cost.** A depth-2 plan on relloc is on the order of a thousand lookups; at a request a second that is tens of minutes, which is why the plan caches every answer and a rerun is fast.
- **OpenAlex's key requirement** was announced for all requests but was not enforced on 2026-09-17; the client must fail with a clear message when it is.
- **zbMATH's references are uneven** (none for Graber–Pandharipande 1999), so the union of sources is load-bearing, not a nicety.
- **The MSC-to-arXiv table is loom's own.** A wrong entry admits or excludes a whole category; the plan prints the categories admitted so the author sees it.
- **Versions.** Treating arXiv versions as one work is right for identity and wrong for locators; records keep the fetched version, and digests, when they come, keep using `extracted-from`.
