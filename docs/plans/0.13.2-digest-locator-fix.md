# 0.13.2 — a digest node locates its page, and the page selects like a page

## Context

Two faults found by reading the showcase, both of which make the reading layer lie about where something is.

**A digest node has no page.** Hovering a citation like `[1, Proposition 2.1]` was meant to show that part of the paper. It shows the digest's transcription instead, because `Node.locator` reads `Proposition 2.1` with no page and every result publishes `page: 0`. The information is not missing: `loom digest extract` compiles the cited paper and parses its `.aux` for result *numbers*, and LaTeX writes `\newlabel{lab}{{2.1}{7}}` — number **and page** — into the same record. `AuxNumber` (`loom/src/loom/tex/aux.py:21-23`) carries `page`; extraction reads `.number` and drops `.page` on all but one narrow branch. The locator string even has the code to print it: `extract.py:588-589` already appends `, p.~{r.page}` when `r.page is not None`. It is None.

**The page does not select like a page.** `arras` hand-rolled the PDF.js text-layer CSS and never applied PDF.js's own per-span geometry. The result: spans take the browser's default 16px with no horizontal scale, so their boxes sit above and beside the glyphs they stand for. Three visible symptoms, one cause — a highlight that obscures the text and misses it, a stray block up and to the left, and an *annotate* chip in the wrong place. This was invisible until the text layer's `opacity: 0.2` was removed earlier today; removing it did not break the alignment, it exposed it.

## Part A — a result knows its page

**What is already there.** `Extracted` (`digest/extract.py:112-124`) carries `.page`; the locator is composed at `extract.py:585-589` and already prints the page when it has one; `Result` (`refs/proposals.py:34-77`) has no `page` field because the page lives on its `Anchor` (`loom/anchors.py:29-40`), which is what `manifest.py:84` publishes as `"page": r.anchor.page`. `Node.locator` reaches the manifest through `_locator()` (`manifest.py:203-207`), which regex-extracts the `\cite[...]` optarg. So the whole channel exists end to end and is fed zeros.

**1. Keep the aux page.** `extract.py:434-446` takes `an.page` only on the branch that also takes `an.number`. Widen it: a label with a page contributes its page whether or not it also settles the number. First establish *why* the showcase's results have none — whether `digest extract` ran without `--compile` (`extract.py:387`, which sets `report.numbering = "emulated"`), or the labels are absent from the aux. The generator is `loom/scripts/gen_quilts.py`.

**2. Confirm the page against the filed PDF, never assert it.** The aux page is the page of the PDF *that compile produced*, which need not be the artifact in the store — precisely what DR-109 and `loom:unverified-locators` exist for. So the aux page is a **hint that narrows the search**, and the recorded anchor is what loom verified:

- take the statement's text and the aux page `p`;
- `read_page(home, p)` (`refs/pages.py:354`) and `locate_offsets(page_text, text)` (`refs/search.py:267`) — if the statement is on that page, record it;
- if not, try `p±1` (pagination drifts by a page between versions) and then give up rather than guess;
- on a hit, `anchor_on_page(home, p, text=…)` (`refs/anchoring.py:30-36`) returns a `Placed` whose `Anchor` carries `basis: text`, `start`/`end` and quads against the filed artifact's own `sha256`.

This is the same mapping `locate`, `loom comment` and `refs locate` use, so a digest node's anchor ends up the shape DR-209 gave every other anchor.

**3. Record it.** `record_extracted` (`refs/proposals.py:344-388`) currently writes `Anchor(kind="tex", sha256=sha, path=rel)`. Where step 2 found the statement, write the pdf anchor instead and keep the tex anchor's `path`/`sha256` as provenance. Where it did not — no PDF filed, no page in the aux, text not found — keep today's tex anchor unchanged. **Extraction must still work with no PDF at all** (DR-198), so every part of this is additive.

**4. The locator follows for free.** With `r.page` set, `extract.py:588-589` writes `Proposition 2.1, p.~7` into the node title, `_locator()` publishes it, and `pageOf()` in `arras/src/lib/worklink.ts:127` parses it. The hover preview wired earlier this session then shows the right part of the paper with no viewer change.

**5. Say what is unverified.** Where the digest's source and the filed artifact are different versions of the work, the page is recorded but the existing `loom:unverified-locators` warning must still fire; do not let a located page silence it.

**6. Regenerate.** `loom/scripts/gen_quilts.py showcase` and the demo, so Arden24's results carry pages and the showcase demonstrates the thing.

## Part B — the text layer matches the glyphs

**The cause, measured.** `PdfPage.svelte:227` sets `--scale-factor`, but this `pdfjs-dist` reads **`--total-scale-factor`** (`node_modules/pdfjs-dist/web/pdf_viewer.css:680`). Our CSS then never consumes the per-span variables PDF.js emits — a span's inline style carries `--font-height: 17.22px` and `--scale-x: 0.888`, and our rules set neither `font-size` nor `transform`. Spans therefore render at 16px unscaled. Measured on page 1: a four-line selection yields 9 client rects, of which 3 are zero-width boxes at the layer's top-left, 250px above the text.

**1. Adopt PDF.js's own text-layer rules** in `arras/src/lib/pdf/PdfPage.svelte`, rather than approximating them:

```css
.text { line-height: 1; transform-origin: 0 0; }
.text :global(span), .text :global(br) {
	color: transparent; position: absolute; white-space: pre;
	cursor: text; transform-origin: 0 0;
}
.text :global(> :not(.markedContent)) {
	font-size: calc(var(--total-scale-factor) * var(--font-height));
	transform: rotate(var(--rotate, 0deg)) scaleX(var(--scale-x, 1));
}
```

and rename the variable set at `PdfPage.svelte:227` to `--total-scale-factor`. Take the exact declarations from the installed `pdf_viewer.css:669-693` rather than from this sketch, and keep them marked as PDF.js's so the next upgrade is a diff.

**2. `br` is positioned too.** PDF.js styles `:is(span, br)`; ours styles only `span`, leaving every `<br>` in normal flow at the layer's top-left. Those are the zero-width rects and the stray block. The layer is `SPAN, BR, SPAN, BR…` for 216 children on page 1.

**3. The selection is the source of three things, so filter it once.** `readSelection` (`PdfPage.svelte:160-168`) feeds every client rect into both the recorded quads and `union()`, which places the *annotate* chip — so a phantom rect corrupts the **stored anchor**, not just the view. Drop rects with no area and rects outside the page's own box before mapping to points. With Part B.1 there should be none; filtering keeps a mis-sized layer from writing a bad anchor.

**4. Keep the selection visible.** The `::selection` colour added earlier stays; once the boxes match the glyphs it hugs the text the way the Digest tab does.

## Ledger

**2026-09-22 · A digest node locates its page.** The page was never missing: `digest extract` compiles the paper and parses its `.aux` for numbers, and `\newlabel` carries the page in the same record. But the showcase extracts with `--no-compile`, so there was no aux at all — which is why widening the aux branch would have fixed nothing. The page is now found where it can always be found: in the work's own committed page text, by searching for the printed label (`Proposition 2.1`) and, where several pages carry it, preferring the one that also carries the statement's prose (`_page_of`, `digest/extract.py`). The aux page is kept as a hint and checked first, because it is exact when it exists and wrong when the filed copy is another version. `record_extracted` then writes a **pdf anchor** against the filed artifact's hash rather than a tex anchor, so `results[].page` stops being 0 and `Node.locator` reads `Proposition 2.1, p.~1`. Every part is additive: a work with no readable copy, no page, or no bibliography entry keeps the tex anchor it had (DR-198).

**2026-09-22 · The page selects like a page.** Three symptoms, one cause. The text layer was styled by hand and never applied PDF.js's own per-span geometry: the variable was `--scale-factor` where this build reads `--total-scale-factor`, and the rules set neither `font-size: calc(var(--total-scale-factor) * var(--font-height))` nor `transform: scaleX(var(--scale-x))`, so every span rendered at the browser's default 16px unscaled and its box sat above and beside the glyphs it stood for. `<br>` was left in normal flow, piling empty line boxes at the layer's top-left — the stray block up and to the left. The declarations now come from `pdfjs-dist/web/pdf_viewer.css` and are marked as its, so an upgrade is a diff. Two consequences found on the way: the selection colour had to become translucent, because the glyphs are on the canvas *under* the layer and a solid wash covers the very words being selected; and the overlays (`.marks`, `.links`, `.ticks`) needed a z-index above the layer, because PDF.js gives its spans `z-index: 1` and the invisible text then sat over every mark and made it unclickable — caught by the reading suite, not by reading the code.

**2026-09-22 · What the rectangles were doing to the record.** `readSelection` fed every client rectangle of the range into both the recorded quads and the union that places the composer. A range over a text layer yields one rectangle per element it crosses, degenerate ones included, so a note's anchor carried phantom rectangles hundreds of points from the words it named, and the *annotate* chip opened where they were. One filter now serves both: no area, or outside the page, is not part of what the reader selected.

**2026-09-22 · The locator is the statement, not the sheet.** Recording the page was not enough to preview a result: a card showing a whole page is a card showing everything but the thing that was cited. The anchor now carries the statement's own span — `basis: text` with offsets into the page's committed text — found by `statement_span` (`refs/search.py`), which takes the printed label for the start and, for the end, the last run of three prose words that survives stripping the mathematics out. The two ends need different evidence because the page offers different evidence: a label is on the page exactly as the reader sees it, and a statement is LaTeX whose mathematics the page does not carry as typed. `_attach_spans` then derives the line rectangles from the span rather than from `source_text`, which was the LaTeX and never matched — the reason an extracted digest had no geometry at all. The hover card is sized to those lines plus one either side and scrolls when the statement is longer, and `PdfDoc`'s `focus` now waits for its mark to exist before scrolling: one frame was enough while every caller focused a mark on a page already drawn, and the card asks for one on a page it has just mounted.

**2026-09-22 · Two lines, and a dot rather than a box.** The preview's crop settled at two lines either side of the statement rather than one: one line reads as a slip of the scissors, two read as a deliberate window, and the card scrolls anyway when the statement runs long, so the cost of the extra pair is nothing. The marks themselves are drawn differently in the card than on the page. On the page a result's outline says *this is the extent of the thing*; in a card cropped to that same thing the outline says nothing the crop has not already said, and boxing three of four visible lines makes the card look like a table. The card therefore suppresses the transient outline and draws a translucent amber dot to the left of the first line's start — a marker for where the result begins, which is the only fact the crop leaves ambiguous.

**2026-09-22 · A postnote names a place, and an unknown place previews as nothing.** Hovering `[1, Lemma 5.9]` in the showcase opened a card on the front page of Arden24 — the title, the author, the abstract — as though that were the lemma. Three cases were being collapsed into one. A citation with a digest node behind it previews that result, and did. A bare `\cite{Arden24}` names the work, so its front page is a fair answer. But a citation carrying a postnote names a *place*, and the viewer was falling back to page one whenever it could not find it, which is the same fault the rest of this plan exists to remove: the reading layer asserting a location it does not have. The postnote is now consulted — `pageOf` reads `Corollary 3.2, p.~2` and opens page 2, which the viewer previously threw away even though the author had written the page down — and where it yields no page the card does not open at all. `Lemma 5.9` is the case that cannot be rescued: the fixture cites it deliberately and says so in the sentence around it, and Arden24's filed copy runs to Remark 4.2, so no search will ever find it. Nothing is the correct preview of a place that does not exist.

**2026-09-22 · The card is the frame.** The preview was a rounded tooltip with padding, holding a bordered page box a few pixels inside it — two boundaries drawn around one thing. The page now runs to the tooltip's own edge, which keeps the radius and clips the page to it, and the tooltip drops its padding for a page preview only, since a node or reference preview is text and still wants the inset. The window grew by half, 24rem to 36rem wide, and the page inside it is drawn at 115% of that width rather than fitted to it: a paper's margins are not what the reader hovered, so spending the card on them made the text smaller for nothing.
