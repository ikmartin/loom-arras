# 0.21 — MCP: how agents attach to loom

## Context

Agents work in a quilt today through loom's command line. Loom writes a permission file listing which `loom` shell commands an agent may run, and a prose orientation tells the agent what they do. Relloc's session of 2026-10-12 to 10-28 showed what that costs: permission rules that matched nothing (DR-275-ikmartin, DR-343-ikmartin), LaTeX mangled by shell quoting (an agent wrote `y^\prime` to get past it), an orientation of about 48 KB read five times in twenty seconds by subagents, and 874 KB of mode reports, scripts and diffs the viewer never showed. This plan makes MCP the way agents attach, and first cuts what agents are told and settles where their work goes, so that what the server serves is right.

It rests on two discussions. The author discussed MCP with the Quilt review session and loom-arras on 2026-10-26; the design is `docs/design/agents.md`. The modes were studied on 2026-10-27, after a discussion with the author, in [`docs/reports/modes-study.md`](../reports/modes-study.md): the evidence, from both relloc quilts, is there, and this plan cites its parts as "the study". Principles are cited by name from `docs/design/principles.md`.

The author decided on 2026-10-26, in their words where quoted:

- **MCP is the intended way for agents to attach.** It "should be the intended way for agents to 'attach' or 'interact' with loom", and "agents attaching to loom should have the full capabilities provided by the MCP".
- **No vendor is assumed.** "Chat GPT, Claude Code, Gemini and local agents should all be able to use loom."
- **Shell permissions for agents are generated on request,** for an agent without MCP such as Aider. Loom keeps both settings variants, and `loom doctor` checks whichever applies.
- **Two bridge tools replace the chat composer** as the way the person points an agent at something:
  - *where the person is looking*, down to the selected words or the PDF page and region, from the viewer tab touched last;
  - *what the person did since this agent last looked*: their annotations and replies, and their acceptances (including keys gone stale), with one marker per agent name.
- **Code execution is out of scope.**
- **Order:** the viewer plan (0.20) comes first, and this plan follows it. 0.20.1 deleted the launcher, the `--settings` preset and `ai-config.toml`, and left `session next`, `session watch` and the inbox to this plan.

And on 2026-10-27, with the study (its part four has the full list):

- **A mode is like a skill**, for legibility, mathematical accuracy and mathematical clarity. The agent reaches for one on its own when it fits, says in one line of its reply which it used, and the modes must not become restrictive.
- **No new modes.** Flow, the author's own mode 8, is restored, with flow and clarity as one mode; brainstorm is scrutinized, and the study retires it.
- **The transcript is what the author reads**, so a mode writes its report there.
- **The pipeline is not enforced**: no mode objects to being run out of order.
- **On an agent document an agent has full privilege** — it edits, annotates with intention and resolves annotations there — except that it never merges one into the author's documents.
- **Short changes are suggestions, and so are drop-in paragraphs.**
- **A work's overview is a page of its own**, attached to the work and built in this plan, beside the research-state page.
- **Folded in from the exploration discussion:** dead ends, counterexamples and decisions are `note` annotations where they were found; a research-state page; agent work counted in `loom status`.
- **WQ-59, the re-grade's partials,** graduates into this plan.
- **Agent documents stay as built.** They are redesigned, if at all, only after this plan has been tested on relloc in real research.

What this plan is not: loom calls no model and holds no key (P9); the MCP server is a client of loom, and no command requires it (P8); and nothing about the author's own command line changes beyond WQ-59's fixes.

## How this plan is carried out

One master document, as 0.20 is. Each phase starts in plan mode: the code is explored, the concrete changes are proposed and the author approves them. When a phase is built and `scripts/verify full` passes, what was built is appended to **Implementation** at the bottom, with anything that departed from the phase as written. Arras changes are re-vendored into loom after their commit. A phase that changes what loom generates for an agent client is also tried against the real client (the `client` test tier) before its commit. Each phase brings the agent contract up to date with what it built, so the contract never describes something that does not exist yet. Nothing is committed until the author says so.

## 0.21.1 · The agent contract cut

The orientation becomes the MCP server's instructions, so it is cut before the server is built. In `loom/src/loom/assets/ai/`, following the study's part five.

**What every agent is told** (the study, §7):

- **Kept, and stated once:** standing rules 1–7; `--as` on every write; the author's acts, which refuse an agent; never claim a result proved with a step missing; never invent a locator; quotes copied exactly; one change per suggestion; what was asked kept apart from what was noticed. The author's acts are listed once, where today they are listed three times.
- **Added:**
  - define every symbol an answer introduces, or link the node that defines it;
  - reach for a mode when one fits, compose blocks when none does, and say in one line which;
  - the exploring habits brainstorm carried (the study, §5);
  - **the notes rule:** a dead end, a counterexample or a decision is a `note` annotation on what it concerns, written when it is found;
  - **where work goes** (the study, §1): the report in the transcript; on an agent document, changes made directly and listed in the report, and an annotation only where the author must look; on the author's text, suggestions, objections and questions;
  - **suggestion or agent document** (the study, §2): a suggestion is a change the author can take or refuse on its own, at one place, however long; changes that only work together, or that move, merge, split or reorder results, are an agent document of the passage;
  - **full privilege on an agent document,** another agent's annotations included, and never a merge into the author's;
  - the transcript instruction from the design: written so that someone coming back later sees the main points, what was decided or found, what is open, and links to what came of it.
- **Cut, as ceremony:** "follow the template exactly" and every checklist; `MODE-TARGET` file names and numbered passes; per-mode `MODE-TARGET.check.py` (a script is saved where it can be cited, named for what it computes); `## Before you begin` in each mode; "ask which the author wants" when no mode is named; dividers. Epistemic labels stay on claims in reports and annotations, not on every sentence of conversation.
- **The orientation becomes pointers:** what a quilt is, the boundary (what only the author does), and where everything else lives (`loom status`, the tools, `loom --help`). It stops restating the command tree and the list of modes, which the index replaces.
- **Bugs fixed:**
  - `--kind conf` is advertised and refused (`full_kind`);
  - "the session's directory is your scratch directory" contradicts `build/SESSION/`;
  - "you may remove what you created" contradicts the rule that nothing is deleted from a session;
  - two different rules are both called rule 7;
  - orientation §8's "The author asks for a mode by name" contradicts `rules.md` §When no mode is named;
  - every mode's "Never edit source", true only on the author's text, contradicts the agent document;
  - review is called the mode "the author reaches for most";
  - `ingest.md` numbers two checks 6, and cites a decision record in a shipped string.

**The modes** (the study, §§3–6):

- **Each mode file holds** when it fits, in one line; what it is for, with its guards; its core and optional blocks; and where its changes go, where that differs from the rule. Its target is whatever the author named: a key, a passage, a section or a document.
- **quick, question, audit, referee, review, simplify:** rewritten to that form, with the blocks of the study's table. Question opens with `[intuition]`.
- **flow:** restored from the author's mode 8, with a named reader, structure before sentences, a rubric with good and bad examples when the pass is large or asked for, and a fresh reader at the end (the study, §4).
- **draft:** the plan is the author's message; on an agent document the node is written there, on the author's text it is a suggestion or an agent document; `draft-ID.tex` goes.
- **ingest:** the verification half, its corrections as suggestions on the digest's nodes rather than a diff. Its comprehension half arrives with the work's page in 0.21.3.
- **brainstorm:** removed.
- **The index:** each mode's name and its "when it fits" line, in one place, generated into the orientation now and the server's instructions in 0.21.5.
- **`loom ai mode NAME`** prints a mode's full text, from the quilt's copy, so no agent reads `ai/modes/` by path. It is an agent command, so 0.21.5 generates the tool.

**Commands the modes want,** carried from WQ-32's reverse pass: every key whose proof cites a given hypothesis; what changed in a key since an annotation was written; a document's results in order with their states; a section of a document as a selector (`section 2 of drafting/main.tex`); and a key's text at the version under review. Plan mode decides for each whether it is a flag, a command, or something the agent composes itself, and says which.

**The design.** `docs/design/agents.md`'s "What an agent is told" becomes the contract as cut, and the README's not-yet-built entry for it closes.

## 0.21.2 · Where agent work lands

The code that makes 0.21.1's homes true.

- **Reports are transcript messages.** The viewer folds a long message after its first block, with one control to open it, and remembers nothing about which are open. The publisher's notes-file reports go, since the viewer never read them: `render/reports.py`, the notes-file pipeline in `render/threads.py`, the report rendering in `render/build.py`, `PipelineStep` and `Thread.pipeline` in arras's types and `docs/specs/manifest.md`, and their tests.
- **Agent work in `loom status`.** Today status counts only the author's documents, so placeholders in an agent document go unseen. Each agent document's incomplete keys and open annotations are counted under it, apart from the author's to-do list, in the text report and in `--json`.
- **Annotations on an agent document:** confirm that nothing stops an agent resolving, editing or discarding another writer's annotation there, and that the author's acts still refuse it (`adopt` among them).

## 0.21.3 · Pages: the research state and a work's overview

A **page** is a Markdown file loom keeps for one thing, written as messages and annotation bodies are: `$…$` mathematics typeset with the quilt's macros, and links that `loom link` prints. The author edits it directly; an agent writes it through one command; it is shown where its thing is read (V7). Two pages are built here.

- **The research state**, one per quilt: a short page of goals, open problems, conventions and decisions, so that any session picks up quickly (relloc's "ξ is the type of a fixed map" was buried in chat). An agent keeps it and the author edits it; the contract asks an agent to update it when a decision governs the work, a problem opens or closes, or a convention is fixed. `loom ai orient` prints it, 0.21.5's instructions carry it, and 0.21.7 serves it as `quilt:state`.
- **A work's overview**, one per cited work: what the paper proves and how, its dependencies, and a plan to reconstruct its proofs — the author's mode 1, written by ingest's comprehension half, which this phase adds to the mode. It links the work's results. It is shown at the top of the work's Info view, and the digest's own `\section*{Overview}`, the paper's first paragraphs, stays in the digest as the paper's words.
- **A page is a reading, never a source.** It says who wrote it, it is never cited as the paper, and nothing in it looks checked (P15). A link in it to a result that no longer exists is refused when it is written, as in a message, and a result it links that changed since is said where the page is read.
- **Writing.** One command (named in the phase) writes a page from stdin under `--as`, and refuses when the page changed since the agent last read it, so an agent never overwrites the author's edit unseen. Every write is recorded so the author can see who changed what.
- **Settled in the phase:** where each page lives (the research state in the quilt, at a path `config.toml` can set; a work's overview beside the work in the library store, committed with its page text, and never in `digests/CITEKEY.tex`), how a write is recorded, and where the research state is shown in the viewer's frame.

## 0.21.5 · The server

`loom mcp` runs a stdio MCP server for the quilt it is started in, found the way every command finds one. The `mcp` package is an optional extra (`loomtex[mcp]`), so a quilt without agents installs nothing new.

- **Tools.**
  - One tool per entry in `AGENT_COMMANDS`, generated from the click command tree and named by its path (`loom_status`, `loom_library_propose`, `loom_ai_mode`), so each tool keeps its command's name (K7).
  - Left out: `serve`, and `session next` and `session watch` (0.21.8).
  - The schema is derived from the click parameters. Rules between options stay refusals at run time (K3), so `annotate` gets a flat schema.
  - The author's acts are not tools at all.
- **Results.**
  - Text by default, as T1–T5 shape it for this reader, with a `json` flag on each tool that prints JSON.
  - Exit 0 and 1 are results, and 1 carries a flag, since lint and check exit 1 with a complete report. Exit 2 is an error carrying the refusal's text.
  - A result over a size threshold (to be set from measurement, below every client's own limit) is written to a file under `build/SESSION/`, and the tool returns its path, so the agent's own file tools can search it.
  - Every result, and `run.log`, carries the equivalent `loom …` command, so a person can rerun it.
- **Read-only.** Read-only tools carry `readOnlyHint`, from the same table, so a client can skip approval prompts for them.
- **Identity.**
  - The server is started with the agent's declared name (`--as`) and sets `AI_AGENT` for every command it runs, so K5's guard sees an agent.
  - It refuses to start under a name that does not say it is an agent.
  - `--as` is then no longer a parameter of any tool.
- **Instructions.** The server's instructions are 0.21.1's orientation, with the mode index and the research state, so an agent attached over MCP is oriented, and can choose a mode, without a shell. The full text of a mode is one `loom_ai_mode` call away, which is what makes the choice automatic on every client: a tool is chosen by the model, where a prompt is chosen by the person.
- **Tests:**
  - the tool list equals `AGENT_COMMANDS` minus the exclusions;
  - no author command is reachable;
  - the exit-code mapping;
  - a schema snapshot, so a changed flag shows as a diff;
  - identity is refused for a non-agent name;
  - a large result goes to a file;
  - the instructions carry every mode in the index.

## 0.21.6 · Configuration

`loom ai init` (and `loom upgrade`) generate what each client needs, from the same table, and never a file someone else committed.

- **Project-level config, written and gitignored:**
  - `.mcp.json` for Claude Code;
  - `.gemini/settings.json` for Gemini's CLI, if it still reads project settings when this phase is explored.

  Each names `loom mcp --as "<Client> Agent"`, so each client has its own agent name. A clone carries none of them, so cloning someone's quilt never runs their command.
- **User-level config is printed, never written.** For a client whose MCP config lives in the user's home (Codex's `~/.codex/config.toml`, Cursor, VS Code, LM Studio and others), `loom ai init --client NAME` prints the snippet. Loom writes nothing outside the quilt.
- **Permission files have two variants:**
  - **The MCP variant** (default): allow `mcp__loom__*` and the agent's write directories; deny `Bash(loom *)` as a guard against mistakes. It is never described as the boundary, which stays the orientation's statement of the author's acts plus K5.
  - **The shell variant**, on request (`--shell`): today's allow list of `Bash(loom …)` rules, for an agent without MCP.

  `loom doctor` works out which variant a quilt uses and checks that one.
- **Vendor pointer files.** `CLAUDE.md`, `AGENTS.md`, and `GEMINI.md` (new) keep one line of loom's: use the loom tools, or `loom ai orient` from a shell.
- **The `client` tier** (opt-in, `LOOM_CLIENT_TESTS=1`, never in CI) gains a test per configured client: the real client starts the server, calls a read tool and a write tool, and is refused an author command.

## 0.21.7 · Prompts and resources

- **Modes as MCP prompts.** Each mode is offered as a prompt (`/loom:flow` in Claude Code), taking a target where the mode does. A prompt is the person's explicit shortcut; the index and `loom_ai_mode` are what let an agent choose a mode unasked.
- **Resources,** read-only, at the addresses `loom link` already prints (`quilt:KEY`):
  - a key's own text;
  - its closure;
  - a document, flattened;
  - a page of a cited work's text;
  - the research state, `quilt:state`, and a work's overview page.

  An agent can then `@`-mention a result instead of asking for it. A client that does not read resources loses nothing, because the same reads are tools.

## 0.21.8 · The bridge

The bridge is two new commands. They are commands rather than MCP-only tools, so that the server generates them like the rest, a person can run them, and their results carry a command (K1, P8). Their names are proposed here and settled in the phase.

- **`loom here`: where the person is looking.**
  - The viewer reports the reader's place to `loom serve` through a new write-API action, debounced, on every change of focus, scroll or selection: the focused pane's active item (`workspace.current`), the block at the top of the pane, the selected words or PDF page and region, and the selected session (plan 0.20, "For plan 0.21").
  - `loom serve` keeps it in memory and never writes it to disk: it is where the person is, not a record (P2).
  - The tab touched last wins. A selection in Review is reported as the block under review, not as a reading place.
  - `loom here` reads it back over the local API with the token in `.loom/serve.json`. With no viewer open, it says so and points to `loom serve`.
- **`loom since`: what the person did since this agent last looked.**
  - It reports annotations and replies written by people, with their quotes and proposed text, acceptances, including keys that went stale, and edits to the research state, since the agent's marker. It groups what it reports by kind of record, so notes can join later without a new command.
  - The marker is kept per agent name in a cursor file loom owns and does not commit, as the inbox's cursors are today, and moves forward when the report is read.
  - "By a person" means a declared name that does not say it is an agent.
- **`session next` and `session watch` are retired.** With the composer gone, only agents write to a session's inbox, so there is nothing to wait for, and `loom since` answers the question `next` used to. `loom session say` stays: it is how an agent writes the transcript. The inbox stays as the transcript's store.
- **The design.** `docs/design/agents.md` loses its open question on these points.

## Out of scope

- **A document read with its open suggestions folded in** ([WQ-62](../work-queue/WQ-62-suggestions-folded-in.md)); each suggestion's own in-place view exists (plan 0.20.7).
- **A redesign of agent documents,** until this plan has been tested on relloc in real research.
- **Mode 1 as more than a work's overview,** such as help reading a textbook chapter, until a quilt exists where someone is learning a field.
- **An HTTP transport,** for front ends that cannot start a stdio server such as Open WebUI, until someone needs one.
- **Claude Code's channels** (a research preview), which could later push a viewer message into a running session.
- **Cloud agents,** which would need loom installed where they run.
- **A notes tool and a running notes view,** which arrive with the notes plan (`docs/ideas/friction-and-exploration.md`); this plan's notes rule uses the `note` annotation as it is, and leaves room in `loom since`.
- **Code integration,** which is deferred; a trial's script is cited by path.

## Behaviour that must survive

- The author's acts refuse an agent in any shell, whatever name it declares (`refuse_under_agent`, K5), and an agent never merges an agent document into the author's.
- Every command runs from a terminal with no server (P8).
- `loom session say` and the transcript.
- Annotations land in the selected session.
- One allow table, from which every permission file and every tool list is generated.
- Generated agent configuration is never tracked and never one someone else wrote.
- An agent's writes stay within its session's directory, `build/SESSION/`, `drafting-ai/`, and the pages it writes through loom.
- A digest holds only the paper's words.
- An edited mode file or orientation is kept, with the shipped text written beside it as `.new`.

After 0.21.3, the study's fifteen requests (its §9) are put to an agent over the contract as cut, and what it picks and produces is recorded in **Implementation** against the study's table.

  - A target is checked with `loom link`, whose refusal is the prompt's error. The mode is then read with `loom ai mode NAME`, so an edit to the quilt's copy is what the prompt carries.
  - The prompt is one user message: work in the mode on the target and its link, call `loom_ai_orient` first if it has not been called, then the mode in full. With no target, it says to work on what the conversation names, or to ask.
- **Resources at the addresses `loom link` prints** (`loom/mcp/resources.py`, no SDK). `reading` maps an address to the reading command it stands for, by syntax alone, so a key that names nothing is the command's own refusal:
  - `quilt:KEY` is `loom source KEY`, `?closure` adds `--closure`, and `quilt:DOC.tex#PLACE` is `loom source PLACE`;
  - a landmark, by path or name, is `loom history show NAME`;
  - `cited:ID` is `loom library read ID`, the overview or else the digest's opening, and `?page=N` adds the page; `quote` is ignored;
  - `quilt:state` is the block `loom ai orient` prints under its research state (`orient.research_state`), with `loom ai orient` as its command, since no command prints it alone;
  - keys and works are percent-decoded, a word starting with `-` goes after `--`, and an annotation or session id is refused, naming the tool that reads it.
- **The list** is read off a scan in the server: the research state where the page exists, each document and landmark, each statement and section of the quilt's own titled by taxon and title, and each cited work with a declared identifier. Proofs and a digest's results are left out; the four templates (`quilt:{+key}`, `quilt:{+key}?closure`, `cited:{+work}`, `cited:{+work}?page={page}`) reach them. The showcase lists 36.
- **The server** (`mcp/server.py`) serves both through `_run`, under the agent marker like a tool call. An exit 2 is an `MCPError` with loom's message, and a result over `LARGE` goes to `build/agent/<session>/`. Every result carries `loom/command` and `loom/exit` in `_meta`. The run.log line says why the command ran: `(over MCP, for the quick prompt)`, `(over MCP, reading quilt:dm-0002)`.
- **Every WORK argument takes a work's identifier** (`cli/library/_works.works`), matched as a link's is, case-insensitively, so `cited:` maps to a command syntactically and every command that takes a WORK accepts what `loom link` prints. The library help and the tools' `work` description say so.
- **The design.** `agents.md`'s How an agent attaches gains the prompts and resources. `invariants.md`'s one-table rule says the prompts and resources run only reading agent commands, and names its guard. The agent contract did not change: an expanded prompt and an attached resource explain themselves.

### 0.21.8 · The bridge — built 2026-10-30

- **`loom here`** (`cli/here_cmd.py`, an agent command that reads) says where the person is looking.
  - **The viewer reports the place** (`arras/src/lib/here.svelte.ts`). One reporter, started by the layout, composes it with `placeOf`:
    - on a reading route: the focused pane's item, the block at the pane's top as `{src, key}` (from `Pane.svelte`'s `remember()`), the words selected (`keyOf` and `quoteOf`, whatever tool is in hand) or a paper's selection or box region with its page and rectangles (`Reading.svelte`), the paper's page in view, and the other pane's item;
    - on `/review`: the block under review and its cause in the viewer's words (`ReviewWorkspace.svelte`);
    - on any other page: `elsewhere` and the path;
    - and the selected session, in every case.

    It posts to the new write action `here` 300 ms after the place settles, and at once when the tab gains focus or comes back into view, so the tab touched last wins.
  - **The publisher holds it in memory only** (`render/api.py`, `_HERE`). `here` is a read, so nothing rebuilds after it, and it is handled outside the publication lock. A place without a route, or over 64,000 bytes, is refused. `GET /_api/here` serves `{place, when, age}` only with the token and to the server's own origin. Stopping the server forgets the place.
  - **The command** reads the token from `.loom/serve.json` and resolves the place against a scan. Each thing is named by its taxon and title and given the link `loom link` prints, and a key the quilt no longer has is marked. With nothing serving the quilt, or no tab reported, it says so and exits 0.
