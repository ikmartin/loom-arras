# 0.18.2: speed, and a rebuild proportional to the change

## Context

On 2026-10-02 the author could not open a session in the viewer on `~/Desktop/relloc`, which holds 64 results of their own and 3,204 from cited papers. The cause: every write waited for a full rebuild. Two caches added that day took a cached build from about 55 s to 14 s.

Exploration for this plan found more:
- **Every API write builds twice.** `LoomHandler.do_POST` (`render/serve.py:193-235`) builds before answering. Then the watcher, whose `rebaseline()` (`render/watch.py:67`) nothing calls, sees the same files on its next poll and builds again.
- **Nothing is reused except fragment rendering.** `build()` (`render/build.py:333`) re-scans and recomputes everything on every rebuild:
  - acceptance states, twice (`store.py:721`, `review_compare.py:80`);
  - every review preview, even though each one's path is already content-addressed;
  - spans for every cited work;
  - annotation payloads;
  - every session's transcript pages.
- **Review previews are rendered for cited papers' machine-made results**, which nobody reviews. Their digest nodes have no acceptance row, so every build previews all of them (`review_compare.py:90-94`).
- **A cold build of relloc took 880 s**, nearly all of it `latex d.tex` runs, one at a time:
  - **One process per figure.** `compile_svg` (`render/fallback.py:83-170`) caches by content in `build/cache/svg/` (sha1 of preamble, border and body). But each figure inside a fragment compiles in turn, and the whole document is one fragment.
  - **Previews miss the fragments' cache.** Review, incoming and adoption previews pass the closure's raw text as the preamble, not the fragments' prepared one, so they compile every figure again. They may also fail under `-halt-on-error`, because the macros get defined twice (`fragments.py:175`); this is to be confirmed.

**Decided with the author on 2026-10-03:**
- **The manifest stays current when a write answers.** That is the rule in `test_the_manifest_is_current_when_a_write_answers` (`tests/unit/render/test_write_api.py:77`). The publication becomes fast instead of being skipped.
- **The on-disk per-file scan cache is built only if the benchmark shows a one-shot command still over its target.** On the relloc copy, `status` and `lint` already take about 2 s.

**The outcome:** every change rebuilds only what it feeds, a write in the viewer answers in under a second, and a cold build compiles each figure once, in parallel.

## The work

### 1. A benchmark, first

`scripts/bench` follows the shape of `scripts/verify`: argparse and a printed table. It runs on the demo quilt, and also on a copy of a quilt when a path is given. It never writes the original.

It measures:
- a cold build, with `build/` removed;
- a cached build;
- an edit to one result's `.tex`, until it is republished;
- `status`, `lint`, `deps`, `ai orient` and `accept KEY`;
- in a `serve`: `session-new`, `annotate` and `message`, each until it answers;
- `serve`'s first build of an already built quilt.

The baseline on the relloc copy is recorded before any change.

### 2. Figures: compiled once, in parallel, and shared

- **Parallel.** The converter's fallback (`ctx.fallback`, called from `convert.py:567, 610, 657, 1203, 1365, 1377`) returns a placeholder and registers the compile. The renderer then compiles every placeholder of the fragment at once and substitutes the results. This happens in `FragmentRenderer` (`render/fragments.py:182-244`) and in every preview's `_render`.
- **One shared pool.** Compiles run on a module-level pool in `render/fallback.py`, sized to the core count. In-flight compiles are deduplicated by the existing cache key, so a figure that appears in a node, a document, a landmark and a preview is compiled once. The fragment pool (`build.py:427-440`) is unchanged; its threads wait on figure futures from the separate pool.
- **Previews use the fragments' preamble.**
  - A preview of current text (review, incoming, adoption) compiles through the same fallback as the fragments (`FragmentRenderer._fallback(master, file, key)`), so it hits their cached SVGs.
  - A preview of an accepted text keeps the preamble recorded with it, since that is what it shows.
- **The cache stays content-keyed** in `build/cache/svg/`, keyed on preamble, border and body as now. Failures stay cached as `.failed`, and `build --force` clears them.

**Tests:**
- two fragments containing one figure compile it once (count compiles through a fake `latex`);
- a fragment's three figures run concurrently (a fake `latex` that sleeps, with more than one running at a time);
- a review preview of a node with a diagram reuses the fragment's SVG and compiles nothing.

### 3. Every derived step is keyed by its inputs

A build takes an optional `BuildMemo` from the previous build in the same process (`serve` keeps one) and reuses each step's output while its inputs are unchanged:

| step | key |
|---|---|
| the scan | reused when no changed path is source (`.tex .sty .cls .bib`, `config.toml`) |
| `key_states` (and per-author states in `Records.apply`) | the scan's identity, and the ledger's stamp (`(mtime, size)`, as `load_history` already uses) |
| review previews (`review_compare.py`, `incoming.py`, `prose_changes.py`) | the content-addressed path the preview already has; a path in the previous publication is not rendered again |
| spans of a cited work (`_attach_spans`, `build.py:96-169`) | the work's `results.json` bytes, its map's hash, and the annotations on it; kept in `build/cache/spans.json` so a one-shot build reuses them too |
| annotation payloads (`attach_payloads`) | the payload text |
| transcripts (`_write_transcripts`) | each session inbox's stamp |

- **No previews for machine-made results.** A digest node whose result is `mechanical` (`load_results(root, n.digest)[n.id].cls`) gets no review preview. Nobody reviews it; 0.18.5 makes that state explicit.
- **`key_states` is computed once per build.** `attach_comparisons` stops computing it a second time.

**Tests:**
- one per step: with unchanged inputs, a second build does not recompute (the step's function is patched to count calls);
- a changed input does recompute.

### 4. The write path and the watcher

- **Writes are classified.** Each API endpoint (`render/api.py`) writes one of these kinds:
  - **records**: sessions, the annotation log, messages, citation notes, adoption decisions, reviewer settings;
  - **source**: `sync-incorporate`, `adopt-finish`, `digest-verify` (which writes the digest file);
  - **ledger**: `review-finish`.
  
  The handler passes the kind to `rebuild`. A records write reuses the scan, and with step 3 it publishes in well under a second. The manifest is still current when the write answers.
- **The watcher does not repeat an API publication.** After the API's publication, `ServeSession` calls `watcher.rebaseline()` under the publication lock.
- **The watcher folds a burst into one publication.** On a change it waits for one quiet poll and then rebuilds once with the union of changed paths. A change that arrives during a rebuild queues one more rebuild, not one per change.
- **Heartbeats publish nothing.** Check that `.loom/sessions/*/attached.json` stays outside the watched set (DR-265-ikmartin), and add a test if not.
- **`_compile_default`** (`serve.py:440`) reuses the serve's scan instead of scanning again.

**Tests**, in `test_serve.py` and `test_write_api.py`:
- a session, annotation or message write answers with the manifest current, runs no scan (the scan is patched to count), and is followed by no watcher rebuild;
- three edits within one poll produce one rebuild;
- `test_the_manifest_is_current_when_a_write_answers` still passes.

### 5. Commands that need no scan don't run one

`refs path` (`cli/refs.py:89`) and `refs page` (`:741`) need only the bibliography. A helper `open_bib(quilt)` parses only `digests/bibliography.bib` (`scan.py:229-230`). `link` (`cli/link_cmd.py:25`) keeps its scan: it resolves nodes, documents and annotations as well as works.

**Test:** the two commands run with the scan patched to raise.

### 6. The build cache key

`_code_hash` (`build.py:204-213`) hashes every `.py` in loom. It becomes the hash of the modules a fragment's output depends on: `render/`, `scan/` and `tex/`. Editing the CLI or the refs layer in a checkout then no longer re-renders everything.

**Test:** `test_a_change_in_looms_own_code_re_renders_everything` (`test_build.py:163`) splits in two:
- a change under `render/` re-renders everything;
- a change under `cli/` re-renders nothing.

### 7. Only if the benchmark misses

If, after 2–6, a one-shot command is still over its target on the relloc copy, `scan` gains a per-file cache in `build/cache/scan/`, keyed by path, content hash and the code hash. Otherwise it is not built, and the Delivery says so with the numbers.

## Order

1. The benchmark and its baseline.
2. Figures. These are the cold build, and they are independent of the rest.
3. The keyed steps.
4. The write path and the watcher, which depend on 3.
5. The scan-free commands.
6. The cache key.
7. The benchmark again, then step 7 of the work if a target is missed.

Each step's module tests run after it. The whole suite runs at the end.

## Delivery

Built on 2026-10-03: steps 1 to 6. Step 7, the on-disk scan cache, was not built: every one-shot command is under its target without it.

**Measured** with `scripts/bench` on a copy of `~/Desktop/relloc` (64 results of the author's, 3,204 from cited papers), on the author's 8-core machine. The "before" column is a frozen copy of the last commit (`scripts/bench --loom`).

| operation | before | after | target |
|---|---|---|---|
| cold build (no `build/`) | 687.6 s | 329.1 s | 180 s, missed |
| cached build | 8.25 s | 2.74 s | 5 s |
| `status` | 2.22 s | 1.82 s | 3 s |
| `lint` | 2.08 s | 1.81 s | 3 s |
| `deps KEY` | 1.25 s | 1.41 s | 3 s |
| `ai orient` | 2.12 s | 1.81 s | 3 s |
| `accept KEY` | 1.97 s | 1.60 s | 3 s |
| `serve`: first build of a built quilt | 8.87 s | 2.84 s | 10 s |
| `serve`: `session-new` answered | 7.57 s | 0.79 s | 1 s |
| `serve`: `annotate` answered | 15.30 s | 0.80 s | 1 s |
| `serve`: `message` answered | 13.93 s | 0.88 s | 1 s |
| an edit to one result, republished | 4.09 s | 2.94 s | 3 s |

The edit is timed from the write to `serve`'s own "rebuilt after change" line, so it includes up to a second of the watcher's poll.

**The cold build missed its target**, and the reason is filed as WQ-56. Figures are now compiled on one pool, each once. But the author's cold build still runs 1,020 compiles at about 2.2 s each, because every compile loads the paper's whole preamble. And 739 of those compiles fail: cited papers' blocks whose macro blocks clash with the quilt's preamble, or which use packages that are not installed. Before this plan the same build ran 1,286 compiles, 1,110 of them failing. A preamble format built once per preamble is the remaining lever. The cost is rare, since the SVG cache is keyed by content and survives rebuilds and upgrades.

**What the plan did not foresee:**
- **The previews' figures failed outright.** Compiled against the closure's raw text, a review or incoming preview's diagram failed under `-halt-on-error` with "\Hom already defined": the fixture's own incoming prose preview showed the error. It now draws the diagram, and that fixture change is the one regenerated file.
- **The scan cost was mostly tokenizing.** About half of it went to tokenizing every file again, the cited papers' digest files included. `tokenize` and `blank_comments` now remember a long text's result, so a served quilt re-tokenizes only the file that changed.
- **A records-only rebuild was dominated by bookkeeping, not by rendering:**
  - `publish` read back every one of ~4,100 published files to compare them; it now compares with what the process last wrote, and walks for stale files only when the set of paths changed;
  - `_input_hash` hashed each file's text once per node that draws on it;
  - quote anchoring was repeated for every annotation (`find_quote`, now cached);
  - a deep copy of the kept acceptance states cost 0.26 s; a shallow copy is enough, since the review facts are the only fields written afterwards.
- **The write API scanned on its own.** `annotate` read a full scan before writing, and that scan was most of a write's time. `loom serve` now offers its last scan to the write API while nothing the scan reads has changed (`api.offer_scan`).
- **`link` keeps its scan.** It resolves nodes, documents and annotations as well as works, so only `refs path` and `refs page` read the bibliography alone.
- **`xy` diagrams.** A cited paper's `\xymatrix` failed every attempt in a quilt that draws with tikz-cd, and an "already defined" failure was retried with a preamble that keeps the clash. A block that uses `xy` now loads it, and that retry is skipped.
