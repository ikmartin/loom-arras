## 1. WQ-04 — identity candidates

`loom refs resolve [CITEKEY...]` looks up the works whose bibliography entry states no identifier, in zbMATH Open first and Crossref second, and reports **candidates**: an identifier, the service that found it, what it matched and how well. It never changes a work's identity and never writes the bibliography, which is the author's (said on 2026-09-16, and narrower than the item's "offered as a visible diff"). A candidate becomes an identity when the author adds the field in their reference manager, at which point it is `declared` like any other. Automatic binding of a strong match — provenance `resolved` feeding `identify` — waits on WQ-23's question about where a confirmed identity lives, since it changes the `refs/` directory a work is filed under.

- **Consent.** Nothing is looked up unless `[refs] resolve = true`, a key of its own beside `fetch`, since it sends bibliography text to two services rather than fetching a declared paper.
- **Services, terms checked 2026-09-17.** zbMATH Open's REST API needs no key, licenses its data CC-BY-SA 4.0, and asks for a reasonable request rate; `_search` with `ti:` and `au:` found three of `demos/relloc`'s five unresolved works. Crossref's `query.bibliographic` needs no key, reports a public-pool limit of one request per second, and routes to its polite pool when a contact address is given, which loom sends only if `[refs] contact` is set.
- **Matching.** Loom scores every returned record itself — title similarity, first-author surname, year within one — so the confidence means the same thing whichever service answered: `strong` at 0.9 and above, `possible` from 0.75, discarded below.
- **Where results live.** In the work's own directory, `refs/work/<hash>/resolved.json`, which is ignored and keyed by the entry's content, so editing the entry invalidates it. `loom lint` reads it and names the candidate in `loom:unresolved-work`; lint never touches the network. The manifest gains an additive `candidates` list per reference, which arras shows as unconfirmed.
- **The core takes a reference string**, not a `BibEntry`, so the crawl can later resolve a `\bibitem` with the same code.
- Tests are hermetic: the HTTP call is injected, responses are recorded fixtures, and the network is never touched.

## 2. WQ-21 — PDFs and links into them

- **The link form** `loom:<scheme>:<value>#page=N` or `#quote=TEXT`, in a comment's Markdown, already survives into `body_html`. It names the global identifier, never the citekey. The dialect specification records it.
- **Arras opens it in a viewer**: a dialog with the browser's own PDF renderer in an `iframe` at `/refs/<dir>/paper.pdf#page=N`, the work's title and identifier, the page, and a link to open the file in a tab. `#quote=` is accepted and shown as "look for …", because finding text needs a text layer, and PDF.js is left to its own item if page-level linking proves insufficient.
- **Only the artifact the link names.** A local copy is used only when the link's identifier is the one the copy is filed under; a link to a published DOI does not open a preprint at "page 9". Otherwise, and when nothing is fetched, the dialog says there is no copy on this machine and links out to the identifier's own resolver — arXiv's PDF at that page where it can.
- **Digest page numbers become links.** A digest result's locator carries the page in the version it was extracted from (`Proposition 3.1, p. 18`); where that artifact is on file, the page opens in the viewer.

## 3. WQ-05 — the contracted work graph

The graph's "cited results" control gains **as papers**: the corpus's own results stay expanded and every cited work becomes one node. An edge runs from an own result to a paper when it depends on any of the paper's digested results or cites it, weighted by how many; an edge runs between two papers when one digest's result depends on another's. Undigested works appear too, from `cited_by`, which the expanded graph never showed. A paper node is drawn distinctly in both layouts, its inspector shows the work and its links, and double-clicking opens its reference page. Nothing is published that the manifest does not already carry: a node's source is its `digest` field.

Contracting the corpus's own results as well — the item's pure quotient — gives a single node and a star for one quilt, so it waits for a corpus spanning several quilts (WQ-03). The naming hazard in the item is respected: no control is called depth.
