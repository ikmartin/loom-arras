# 0.10 — Annotations as a log, review mode, reference notes

**Status: reminder**, written 2026-09-17 alongside [0.9](0.9-workbench.md); becomes the plan once 0.9 is built and tested. Everything here depends on 0.9's ledger and content hashes and on nothing else that is undecided.

## The annotation log

`annotations/log.jsonl` replaces `comments/` (the per-author files were an accident; "comment" is one kind of annotation). One append-only, event-sourced table: events `created`, `replied`, `edited`, `resolved`, `discarded`, each a line, current state by replay. Columns: `id`, `event`, `when`, `author` (a person's name, or `claude`, `codex`), `kind` (`human` | `agent`), `run` (the run's directory name — its id), `target` (a key, or a document path for a whole-document annotation), `against` (the sha256 of the text it was written against), `anchor` (the quote selector), `annotation-kind` (`suggestion`, `objection`, `question`, `ok`, `citation`), `severity`, `body`, `payload`, `placement`, `status`, `reply-to`. JSONL, not CSV (quotes hold newlines and commas) and not a database (two people appending in parallel merge as two lines; an index can be derived later).

Encoding the kind into the author (`"AI-Claude"`) was rejected: three columns make "everything from this run" and "everything any agent said about `rl-0002`" filters rather than string parsing.

**Who writes it.** Only `loom comment` (and the agents through it, which is how they write today); the rule that an agent's own file writes stay under `ai/runs/` is unchanged, because the CLI does the appending. Decide in the plan whether a run directory keeps a per-run cut for the agent's own reading.

**In-run edits** are `edited` events superseding the body, history kept, one current body shown — which answers WQ-23's open question 2 — and `referee.md`'s re-check convention (`referee-KEY.2.notes.md`) is dropped, since a re-check is new events against the same ids (question 5).

**Severity** is Major / Moderate / Minor and grades the *fault* a finding names, not the enthusiasm of the suggestion: mandatory in review mode, where every item is grouped; optional elsewhere, where a suggestion with nothing wrong behind it carries none. A grammar note is Minor because the fault is small.

**Payload and placement.** A suggestion may carry text — a proof, a paragraph, a rewritten passage — as `payload`, a string in the record (a file in the run was considered for editability and rejected once nothing applies it), with `placement` one of `replace` / `after` / `before` relative to the anchor as a *hint* for where arras shows it. Everything is preview-and-copy: the author flips the verbatim toggle, copies, pastes where they decide. A suggested proof is the same object — the agent's proof with `\begin{proof}[Proof of Theorem~\ref{rl-0012}]`, previewed and pasted — not a promotion; the author chose this over `loom ai promote` for its intentionality and simplicity. Applying anything is WQ-27.

**Anchors, frozen on edit.** Loom keeps a last-seen copy of every key's text as of the last scan (bounded: one copy of the quilt, rewritten in place; also gives serve "what changed since the last scan"). When a scan sees a key's hash move and annotations point at the old hash, the old text is written into `.loom/history/texts/<sha256>.tex` then. Annotations against text never touched again cost nothing; a text loom never saw (two edits between scans) leaves the annotation **unanchored** — "written against a text loom never recorded" — rather than pretending. At canonize, the step directory's `annotations.json` is a cut of the log: the records that stood against the versions the step replaced, so a step explains itself alone and survives a run being discarded. The wording is *stood against the version you changed*, never *caused the change*: the author may ignore every suggestion; causation is an explicit act (resolving as applied) for the rebuilt review system.

**`[R1]`, `[R2]`…** are per-report display numbers in report order, for talking about points in chat; annotation ids are never shown to readers (WQ-23, settled).

## Review mode

Mode 7 of the author's global rules, which the copy in `docs/source/global-rules.md` predates. It grew out of nested referee → audit → simplify → referee runs. The author's text, verbatim, to be pasted into `docs/source/global-rules.md`:

> **Mode 7: Review Mode.** When I wrap a source in [review] [/review], adopt the role of a referee aiming to improve the source. Produce a latex/pdf pair which is a reproduction of the provided text with interjections and criticisms inserted in red. Number suggested revisions and comments as [R1], [R2], etc. and group them into Major, Moderate and Minor categories. Include a list of all revisions at the beginning of the document. Specifically look for the following revision/suggestion opportunities:
> - new citations: opportunities to replace an argument with a citation. Verify the citation source, if the citation source is made from memory FLAG IT EXPLICITLY AS "WARNING: memory grade, citation not verified"
> - bad citations: check citations are correct/applicable.
> - unnecessary hypotheses: extraneous or unneeded hypotheses
> - merge-or-delete: redundant lemmas, duplicated arguments, scaffolding to remove
> - sharpenings: places in a proof which give more than the statement claims or where a hypothesis can be weakened without touching the argument
> - self-containedness: every theorem, lemma, and definition which fails to parse standalone
> - mathematical errors: false statements, incorrect claims. Always explain WHY the statement is false/incorrect, and attempt to fix it.
> - grammar and wording: flag issues with grammar, punctuation and awkward wording
> - clarity: flag unclear writing, suggest fixes

Loom's parallel, `ai/modes/review.md`, is a separate mode beside audit and simplify (the author will use it almost always). It writes annotations with severity and payloads plus a report; **no compiled LaTeX/PDF artifact** (declined; WQ-28 for those who want one). Category → block mapping: new citations → `[simplifications]` type `new-citation` plus `[citation-ledger]`; bad citations → `[citation-ledger]`; unnecessary hypotheses → `unnecessary-hypothesis`; merge-or-delete → `merge-or-delete`; sharpenings → `[sharpenings]`; self-containedness → `[self-containedness]`; mathematical errors → a new block (the existing modes deliberately don't hunt errors); grammar, wording, clarity → a new block (nothing in loom covers prose). The memory-grade warning is the citation ledger's `memory-grade` field. The completeness check learns the two new blocks. Appendix C gains the mode; Chapter 11's table too.

Also: **quick mode is dropped** (a parallel added later if wanted); **severity per finding replaces the referee's `[decision]`** (WQ-23, settled).

## Reference notes

The cheap stand-in until `refs/` settles (the identity question — where a confirmed guess lives — is deferred with the crawl's overhaul and must be noted as such in the plan). `reference-notes.jsonl` at the quilt root, append-only, one object per accepted suggestion: `work` (free text as the agent described it), `for` (keys), `claim`, `identifier` with `verified: false`, `accepted` (`when`, `who`), `from` (`run`, annotation id). No dedupe, no resolution, never touches `refs.bib` or `refs/` or the manifest. The agent's suggestion is an annotation of kind `citation`; accepting is `loom refs note --from RUN --accept ID`, which appends and resolves; rejecting is doing nothing. Read in arras later (WQ-26). The overhaul's migration is mechanical: entries with identifiers become candidate records with provenance `asserted`, keys become `cited_by`, the file becomes a view.

## Arras in this plan

The **verbatim toggle**: per node and per payload, in the box's upper right, revealed on hover and focus with a preference to always show; flips the body between rendered and source; paired with **copy** and **copy for chat** (the key in the author's tag syntax plus the text). Source comes from `build/source/<key>.tex` fetched lazily — the manifest is already 772 KB on relloc and would nearly double with source inline. "Source" is the node's own text before macro expansion; for a payload, the payload; for a digest node, the digest's statement. Needs no write API.

Payloads rendered inline in red beneath their anchor are WQ-26, not this plan.
