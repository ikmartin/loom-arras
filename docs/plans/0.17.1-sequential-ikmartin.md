# 0.17.1 — the foundation: `drafting-ai/`, derived ids, and the copy

The first of plan 0.17's four parts, and the one the others wait for. It makes `drafting-ai/` a second drafting directory an agent may write in, gives a copy's nodes derived ids, writes the copy with a base per node, lists which copies are stale, and fixes the interface that [0.17.2](0.17.2-luisa.md) (adoption), [0.17.3](0.17.3-ikmartin.md) (canon) and [0.17.4](0.17.4-ikmartin.md) (compare) build on. The decisions, the studies and the interface are in [0.17-ai-drafting-and-compare.md](0.17-ai-drafting-and-compare.md); this plan names them by number and does not restate them.

Work is on its own branch from `main`. Each phase is implemented, verified with `scripts/verify full`, recorded under Delivery, and summarised before the next begins, stopping only on a halting question. Phase 4 merges into `main` so the other plans can start.

## What it builds

Decisions 1–8 and 19's panel half, 27, 28, and the whole of "The interface 0.17.1 fixes". Not adoption, `ai refresh`, `adopt --as` (0.17.2), canon (0.17.3) or compare (0.17.4).

## Settled in planning

- **Derived ids are ids to the scanner, not to the history.** `scan/labels.py` learns `<prefix>-<LOOMLOCAL>-ai` with the quilt's own prefix only (`split_id`, `:16`; `is_id_shaped`, `:25`); `PAPERLOCAL` (`:11`), which would accept `0001-ai` under a citekey slug, never makes a derived id. `NodeRec` (`scan/nodes.py:53`) gains `derived_of`. So `duplicate-id` covers them (`_conflicted_ids`, `:209`), references resolve (`scan/edges.py:128`), and `loom id` leaves them alone. `versionable` (`history/steps.py:41`) is false for a derived node and `recorded_ids` (`history/ledger.py:262`) leaves them out, since `drafting-ai/` is never stamped or accepted: a derived node's history is its base. The allocator needs nothing: `\b<prefix>-([0-9A-Z]{4})\b` (`scan/alloc.py:14`) already reserves the number inside a derived id.
- **One diagnostic for a derived id where it may not be**, `loom:derived-id-in-drafting`: defined or cited by a document in `drafting/`, in `lint()` (`scan/lint.py:61`).
- **The copy writes a step** *(to confirm with the author)*. A base must be a text loom can read back, for refreshing, adoption's merge and compare's "changed on both sides". `loom draft DOC --ai NAME` freezes, as a stamp does (`plan_freeze`, `history/steps.py:50`), every reached key whose text no step records yet, and writes a `copy` step (`STEP_ACTIONS`, `history/ledger.py:19`) with the flat source as `document_text` (`write_step`, `steps.py:125`) and the line the interface names.
- **A live document's stem is unique across both directories** *(to confirm with the author)*. arras routes by stem (`arras/src/lib/nav.ts:12-19`) and loom writes PDFs to `build/<stem>/` (`render/manifest.py:284`): a new diagnostic `loom:document-stem-taken` reports two live documents with one stem, and `draft --ai` refuses a `NAME` whose stem is taken.
- **The permission file takes the quilt.** `permissions_json(quilt)` (`ai/layout.py:126`) builds the `Edit` allow list from `AGENT_WRITES` (`:46`) plus the configured `drafting_ai`, and the read-only list from the configured `drafting` and `canon` rather than the literals in `AGENT_READONLY` (`:49`), which closes a gap in any quilt that renames them. Its callers — `vendor_files` (`:171`), `init_layer` (`:230`), `upgrade_layer` (`:257`), `settings_deny_paths` (`:324`) — and `check_permissions` (`doctor.py:461`) pass the quilt. `loom ai check` stops reporting `drafting-ai/` as an outside write (`ai/check.py:11`).
- **Sync never selects a `drafting-ai/` document.** `_selection` (`sync.py:130`) and `update_documents` (`:665`) refuse it; `exact_renames` (`:255`) pairs only `drafting/` documents.
- **Whole-quilt views leave derived nodes out** (decision 27): `loom status`'s totals and rows, and in arras the Graph's Whole quilt (`arras/src/lib/graph/layout.ts:307`), the node counts, search and Review, by `derived_of`. Review's tabs (`arras/src/routes/review/+page.svelte:178`) list only `drafting/` documents.

## Phase 2 · The copy, and whether it is stale

- **`loom draft DOC --ai NAME`** (`cli/history_cmds.py:76`, rewritten): author-only; refuses a `DOC` that is not a live `drafting/` document, a `NAME` that exists or whose stem is taken, and a `DOC` that already has a copy, naming it. Flattens with `flatten` (`reshape/linearize.py:31`), derives every defined id and rewrites the references to it (`_relabel` and `_rewrite_refs`, `reshape/fork.py:63-78`, over the whole document), writes `drafting-ai/NAME`, and writes the `copy` step. Its old job, canon to drafting, stays until 0.17.3 replaces it.
- **`History.bases` and `History.copy_of`** as the interface names them; `loom history verify` checks `copy` lines (`history/checks.py:145-175`), and `_detail` prints them (`cli/history_cmds.py:794`).
- **`loom ai drafts`** (`cli/ai.py`): each copy, its source, and when stale what moved on the person's side — nodes, the prose between them, the preamble — against the copy step's document text, "moved" meaning decision 28's mathematical change. `--json`. An agent command (`AGENT_COMMANDS`, `ai/layout.py:31`).
- **The orientation** (`assets/ai/orientation.md`, the layout at `:15` and the commands at `:46`): `drafting-ai/` as a path read from the quilt; check `loom ai drafts` before a large instruction and suggest refreshing a stale copy. `assets/ai/rules.md` and the draft mode (`assets/ai/modes/draft.md`).
- **Manifest:** a copy's `copy_of`; a derived node's `base`.
- **Book:** 4 (the copy; one copy per document), 7 (bases and staleness), 11 (the agent's commands and the orientation), 12 (generated). The copy half of ai-drafting §6's worked example.
- **Tests:** `tests/unit/history/test_commands.py` — the copy is flat, every id derived and every reference to it rewritten, references to uncopied nodes plain; the step freezes the unrecorded keys and records every base; a second copy is refused; a taken stem is refused. `ai drafts` fresh, then stale after a change to a node, to the prose, to the preamble, and not stale after a display name alone changes. `test_json_output.py`'s table; `test_ai_layer.py` (`ai drafts` is an agent command, `draft` is not).

## Behaviour that must survive

- A quilt with no `drafting-ai/` behaves exactly as today.
- Every existing acceptance stays as fresh as it is, for every reviewer.
- The document workspace sees the same documents; nothing in `drafting-ai/` is ever published.
- An agent still cannot write in `drafting/`, accept, stamp or draft.
- A whole-quilt view counts each of the person's nodes once.

## Risks

- **The stem rule** refuses a name a person might want (`drafting-ai/main.tex` beside `drafting/main.tex`); the refusal names the collision and the fix.
- **The fixture's agent copy** changes every fixture-driven test's counts; each such change is checked, not re-baselined blind.

## Verification

After each phase `scripts/verify full`; after phase 2, a copy of the demo quilt's `main.tex` edited on both sides reports stale as expected; after phase 3, a quilt with a renamed `drafting_ai` passes `loom doctor`.

## Delivery

### Phase 1 · A second drafting directory, and derived ids (done, 2026-09-27)

- **The id grammar** (`scan/labels.py`): `DERIVED`, `derived_of` and `plain_key`; `is_id_shaped` accepts a derived id under any prefix that is not a citekey slug. The interface's "the quilt's prefix" was read as that, since loom-local ids take any such prefix. `NodeRec.derived_of` is a property of the key, so a derived proof (`zk-0001-ai/proof`) names `zk-0001/proof`.
- **The directory:** `[quilt] drafting_ai` (config, user config, init's template, the skeleton, and the gitignore's artifact lines for it); `ScanResult.document_role`; the default master is always a `drafting/` document.
- **Diagnostics:** `loom:derived-id-in-drafting` (defined in or cited from a document the drafting directory reaches) and `loom:document-stem-taken`; `loom:no-live-document` counts only `drafting/` documents.
- **Refusals:** `loom accept` (a derived key, `--master` on an agent's document, `--all-live` counts only the person's keys, and `_acceptance_master` never picks an agent's document), the write API's review-finish, and the document workspace's selection and `documents add`.
- **The border:** `permissions_json` and `vendor_files` take the quilt's config (`agent_dirs`, `quilt_config`); the read-only list names the configured `drafting` and `canon`; `CLAUDE_LINE` names the documents `loom ai orient` gives the agent; `loom ai check` leaves the agent's drafting directory alone; `loom doctor` checks against the quilt's own config. The shipped demo and the test quilts were regenerated (`scripts/gen_quilts.py all`, `demos/build.py --skip-papers`).
- **Counted once:** `loom status` leaves derived keys out; the manifest leaves them out of `tags` and `search` and marks `directory` and `derived_of`; arras leaves them out of the Graph's Whole quilt, the panel's Nodes, the home page's counts, taxon pages and reachedness, lists the agent's documents as a subsection under their directory's name, and gives them no Review tab.
- **Book:** 3.2, 3.3, 4.1, 4.2, 4.4 (new item 9), 5.3.1, 5.14, 7.3 (item 6), 11.8, 15.2, 15.3.5, 15.5; `docs/specs/manifest.md` §2a and §3, `docs/specs/diagnostics.md`; DR-307-ikmartin and DR-308-ikmartin; two deviations rows.

### Phase 2 · The copy, and whether it is stale (done, 2026-09-27)

- **`loom draft DOC --ai NAME [--json]`** (`cli/history_cmds.py`, `reshape/copy.py`): refuses a source that is not a live `drafting/` document, a name that exists or whose stem is taken, and a second copy of one document; writes the copy flat with every label it defines suffixed — equation labels too, since labels are claimed quilt-wide — and every reference to one rewritten.
- **The `copy` step** (`STEP_ACTIONS`): freezes the reached keys no step records yet, maps each derived key to its base, and keeps the source's flat text under the source's own name; `versionable` is false for a derived node and `recorded_ids` leaves derived ids out. `History.copies`, `copy_of` and `bases` (the last already reading `adopt` and `refresh` lines); `loom history verify` checks every base; the manifest carries `copy_of` and `base`.
- **`loom ai drafts [--json]`** (`loom/drafts.py`), an agent command: a copy is stale when a based node changed mathematically (a display name alone does not count) or left the source, or the prose between nodes or the preamble moved; comment lines are not prose, so a node's directives never make a copy stale.
- **The agent's documents:** the orientation's layout names `drafting-ai/` and how to label within a copy, the commands name `loom ai drafts`; `rules.md` and the draft mode allow a node drafted into the copy the author names. The appendices, the test quilts and the demos were regenerated.
- **Book:** 17.6 (the `copy` line), 17.7.1 (the copy, its bases, staleness), 11.3; the CLI reference regenerated; DR-309-ikmartin; a deviations row.
- **Tests:** six more in `tests/unit/test_drafting_ai.py`; `test_json_output.py`'s table; `test_ai_layer.py` names `draft` among the author's verbs the documents mention. `scripts/verify full`: every lane green but `test_nothing_shipped_is_untracked`, which lists the new modules until they are added at commit.

### Phase 3 · The interface, and the fixture's agent copy (done, 2026-09-27)

- **The fixture's copy** is made by `scripts/gen_quilts.py`, not by hand: `loom draft drafting/main.tex --ai aidoc.tex` in the synthetic quilt, then the agent's edits — `sy-0002-ai` changed, `sy-0001-ai` changed and `sy-0001` changed again by the author after it, `sy-000A-ai` moved unchanged, `sy-0202-ai` deleted, and `sy-999C-ai` written new, last, so that it takes the author's next number after the doubly defined `sy-999B` rather than shifting it.
