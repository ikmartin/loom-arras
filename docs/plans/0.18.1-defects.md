# 0.18.1 — defects that lose data or report a failure as success

## Context

Part two of the CLI study (`docs/reports/cli-study.md`) lists twelve defects that lose the author's data or report a failure as success. A thirteenth comes from the agent critique `docs/issue-reports/refs-audit-critique-from-agent-2026-10-02.md` §3.

The author decided on 2026-10-02 how agent guards should work: under an agent marker, an author-only act refuses whatever name the caller declares. That reverses DR-203's "a declared identity wins" for those acts.

The outcome:
- every defect below is fixed;
- each has a test that reproduced it first;
- the book says what the code now does.

## The fixes

### 1. `sync init` publishing over the quilt's own branch

**The defect.** `--remote` defaults to `origin` and `--branch` to `main` (`cli/sync.py:47-48`). With no flags, `sync publish --push` replaced the quilt's own branch with the source-only projection.

**The fix.**
- Both options become required, with help text.
- `configure` (`sync.py:229-247`) refuses a pair that is the current branch's upstream. It compares `git rev-parse --abbrev-ref --symbolic-full-name @{upstream}` with `remote/branch`; a branch with no upstream counts as safe. The refusal names the pairing chapter 4.6 shows: `--remote overleaf --branch master`.

**Test.** In `tests/unit/test_sync.py`, a quilt whose branch tracks `origin/main` is refused. The existing `_paired` setup has no upstream, so it still passes.

### 2. `sync incorporated` verifying nothing

**The defect.** `mark_incorporated` (`sync.py:698-706`) checks only that the selected sources are clean. After `--yes`, the next push reverted a coauthor's edit.

**The fix.**
- The command and `mark_incorporated` are removed. `sync finish` is the checked path, and the viewer's Incorporate already uses it: `sync-incorporate` → `incorporate_pull` → `finish_incorporation`.
- Book 4.6's sentence about renames (`04-the-quilt.md:208`) and 12.2 are rewritten.
- The agent permission files are regenerated (`scripts/gen_quilts.py`).

**Test.** `sync incorporated` is an unknown command.

### 3. `refs build --force` deleting verified results

**The defect.** `_extract_step` (`refs/build.py:395-420`) overwrites `digests/CITEKEY.tex`.

**The fix.** After the write, every result in `load_results` whose `state` is `verified` and whose class is not `mechanical`, and whose label is no longer in the new text, is appended back with `append_to_digest` (`refs/proposals.py:308`). A mechanical result the author edited (an `edited` act in its origin) gets its edit back with `rewrite_in_digest` (`proposals.py:320`). The build's report names each result it restored. A restored result that the new extraction contradicts (an extracted node of the same label with a different statement) is listed for the author.

**Test.** In `tests/unit/test_refs_layer.py`, verify a proposal into the demo's `Calloway14` (whose store has `src/`), run `refs build --force Calloway14`, and the node is still in the digest.

### 4. `refs scan` adopting the same document on every run

**The causes,** in `adopt_orphans` (`refs/scan.py:402-481`):
- `claimed` reads only `primary(entry).path` and ignores `loom-file`;
- `came in sources` compares the ledger's raw path with `parse_bib`'s whitespace-collapsed `loom-source`;
- a nested seed file is recorded as `refs/x.pdf` but ledgered as `refs/sub/x.pdf`.

**The fix.**
- `claimed` includes every entry's `loom-file` directory.
- The comparison is by the ledger's `"to"` (the store directory), with the paths whitespace-normalised on both sides.
- `copy_documents` writes the relative seed path that it ledgers.

**Also fixed alongside.**
- `refs build` runs its argument checks (`--only`, citekeys) before the scan (`cli/refs.py:364-379`).
- `--dry-run` writes nothing: no copy, no map, no ledger line (`copy_documents` with `write=False`, `scan.py:526-533`).
- The dry run's lines are marked `(dry run)`.
- `--json` builds still scan, as they must, but are refused like any other build when their arguments are bad.

**Existing duplicates.**
- `refs scan` reports once that two or more entries name the same stored document, listing the keys and the fix: keep one, delete the others from `digests/bibliography.bib`. That file is append-only for loom, but the author may edit it (8.15).
- For the author's quilt (`~/Desktop/relloc`), the commands are handed to the author.

**Tests.**
- In `tests/unit/refs/test_scan.py`: a seed file with two spaces in its name, and one in a subdirectory, each adopted at most once over three runs.
- A dry run leaves the store and ledger byte-identical.
- A refused build writes nothing.

### 5. `revert` recording reverts that never happened

**The fix.** `cli/history_cmds.py:309-312` no longer appends a ledger line. `revert` prints the patch and says the author applies it. `revert` stays in `ACTIONS` (`history/ledger.py:20`) so that existing ledgers parse, and `history verify`'s dangling-ancestry check keeps reading old lines. Nothing reads a revert line to learn a key's text: that is found from content (`versions.matching_version`).

**Book.** The book's ledger table drops the `revert` row (17.6, `17-the-workbench.md:89`).

**Generated quilts.** `scripts/gen_quilts.py`'s synthetic and showcase quilts are regenerated, since they lose their revert line, and so are the demos.

**Test.** `test_revert_prints_a_patch_and_records_it` (`tests/unit/history/test_commands.py:137`) becomes "prints a patch and records nothing".

### 6. `inline` leaving every id defined twice

**The fix.** The command is removed:
- `cli/paper.py:364-393` and its registration;
- `reshape/atomize.py:363-385` `inline`, which only this command calls;
- `_single_node_file` and `shift_sectioning` stay, because others use them.

`linearize` writes a flat copy and supersedes the source, and `source DOC` prints one.

**Book and records.**
- Chapter 6 (6.6 and the identity-test rows), chapter 3's vocabulary entry, 2, 13 and 17.13's comparison now point at `linearize`.
- The decision records stay as written.
- `loom/README.md` follows.

**Tests.**
- `test_paper.py:377` and `:396`, `tests/tex/test_reshape_real.py:94`/`:150` and `test_node_names.py:93` move to `linearize`.
- `test_ai_layer.py:435` loses `inline` from its set.
- The reference and the permission files are regenerated.

### 7. `ai discard --before` discarding everything

**The defect.** The string is compared lexically, so `yesterday` sorts after every date (`cli/ai.py:47-56`).

**The fix.** `--before` takes a `YYYY-MM-DD` date (a click type). Anything else is refused by name, with exit 2.

**Test.** `--before yesterday` exits 2 and discards nothing.

### 8. Agent guards that follow the act

**The fix.** `refuse_under_agent` (`cli/_common.py:182-195`) refuses whenever an agent marker is set, whatever name is declared. A declared agent name is still refused with or without a marker.

**Commands that call it:**
- **Already guarded:** `accept`, `refs verify`, `refs discard`, `refs unreadable`, `refs forget`, `history restore`.
- **Newly guarded:**
  - `refs drop`;
  - `refs cite --accept/--reject`;
  - `session delete --purge` (the tombstone stays open to agents);
  - `ai discard`, which leaves `AGENT_COMMANDS`;
  - `sync publish --push`.
- **`refs unlink`:** refuses an agent removing a link someone else asserted. An agent may still remove its own, so it stays in `AGENT_COMMANDS`, and the removal is recorded with who did it.

**The write API** (`render/api.py`) has no shell marker to check, so it keeps the declared-name guard and extends it to `refs-cite` and `sync-incorporate`, which have none (the `adopt-*` endpoints already have it, at `api.py:164`).

**Book and agent files.**
- Book 11.8 (`11-ai-layer.md:118-124`) is rewritten: the marker decides for these acts, and the reason is that a declared name cannot be checked.
- `ai/rules.md` (`:29`, `:88`) and its demo copy list the guarded acts.
- The orientation and appendices C and D are regenerated.

**Tests.**
- `tests/unit/test_writer.py`'s "declared wins" cases change for the guarded acts.
- New: each guarded command refuses under `AI_AGENT=1` with `--author Isaac`.
- `refs unlink` of the author's link refuses an agent, and of its own does not.

### 9. `refs add` filing any PDF under any work

**The fix.**
- The first-page title check in `_fetch_url` (`refs/fetch.py:381-391`) is factored into `refs/fetch.py` as `carries_title(pdf, entry) -> (ok, best line)`. It uses `title_ratio` (`:210`), `title_lines` (`refs/ingest.py`) and `TITLE_MATCH`.
- `refs add` refuses a PDF whose first page does not carry the entry's title, naming the best line it found and `--force`.
- A filed PDF is then mapped (`write_map`, `refs/pages.py:291`), so `refs add` no longer needs a separate `refs map`.

**Test.** `test_refs_add_…` (`test_refs_layer.py:1693`) uses a PDF that carries the title, with a second case for refusal and `--force`.

### 10. Verdicts that are false

- **`ai refresh` with conflicts** (`adopt.py:799-805`, `cli/ai.py:364-368`):
  - It says "N result(s) changed on both sides: ID, …; reconcile them in your editor, then run `loom ai refresh COPY` again".
  - It exits 1.
  - Its `--json` is unchanged apart from the message.
- **`adopt` with an empty patch while `document_changed` is true** (`cli/adopt.py:57-63`). It says "No result changes to incorporate; the document's prose or ordering changed: run `loom adopt COPY --document-changes` to see it". The same goes for `incorporate`'s message.

**Tests.** In `tests/unit/test_adopt.py`, `:235` also asserts the message and exit code, and a new case covers the document-only change.

### 11. Conflicted ids that `status` hides

**`status`.** `status_payload` (`cli/review.py:940-1046`):
- skips demoted nodes (`n.conflict_of`);
- adds one row per conflict placeholder (`kind == "conflict"`), shaped like the manifest's `_conflict_key` (`render/manifest.py:539-583`): state `conflicted`, its files, and the fix `loom fork ID --in FILE`.

The text printer shows the files. `summarise` counts `conflicted`, and `filter_keys` and `ai/orient.py` accept it.

**`live`.** `live` (`history_cmds.py:317-331`) rescans after recording. Each id it made conflicted is named, with its files and the fork command, as `history restore` already does at `:728-731`.

**Tests.**
- Synthetic's `sy-999B` shows as one conflicted row (`test_review_commands.py`).
- `test_live_makes_a_superseded_document_define_again` (`test_paper.py:331`) asserts the warning.

### 12. `refs overview` picking a work at random

**The defect.** `next(iter(resolve_works(...)))` (`cli/refs.py:1657`) picks from a set.

**The fix.** A helper `one_work(result, needle)` wraps `resolve_works` (`cli/refs.py:560-586`). It refuses more than one match by naming them, in the shape of `find_session` (`cli/_common.py:55-86`). `overview` uses it, and so does every command that takes a single work.

**Test.** The `refs overview` test in `test_digest.py:356` gains an ambiguous fragment, which is refused with both names.

### 13. A sibling entry losing its PDF

**The defect.** The sibling branch of `copy_documents` (`refs/scan.py:511-518`) never passes `filed=`, so a sibling without an identifier resolves to the synthetic `work/<hash>` directory, possibly the original's, and not `file/<sha16>`.

**The fix.** The sibling gets `loom-file` like the unnamed branch (`:524`). `copy_documents`'s `claimed` (`:506-507`) uses `work_dir`, not `primary`.

**Test.** In `test_scan.py`, a second PDF for a work with no identifier is reachable from its sibling's entry and shows its own PDF.

## Order

The fixes are built in the order 8, 1, 2, 5, 7, 11, 10, 6, 13, 4, 3, 9, 12:
- **the guard first**, since later fixes add callers;
- **then the history and status fixes**;
- **then the removals**, which regenerate files;
- **then the `refs` store fixes**: 13 before 4, because the adoption check depends on `loom-file`;
- **then the `refs` reports.**

After each one, its module's tests run. At the end comes one regeneration (`gen_quilts.py`, `demos/build.py`, `gen_cli_reference.py`, `scripts/checks/appendices.py --write`), with the TeX-noise fixture fragments restored as usual.
