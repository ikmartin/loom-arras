# 0.32 — v0.1, the version other people use

The master plan for getting loom to two to four pilot mathematicians. A workstream's agent reads this file, then its heading in `docs/reports/v0.1-study/register.md`, then the reports its row cites. Where a later report corrects an earlier one the later wins, and each row says which. Where loom stands today is `docs/reports/v0.1-study/state.md`; the code evaluated is `codebase.md` beside it.

## What v0.1 is

Mathematicians do not finally care whether a theorem is true so much as understand why it is. Loom uses AI to deepen that understanding: it weaves the results in a person's drafts and in what they read into a network that mirrors the one in their head. AI-written mathematics and documents are welcome in it, and loom's part is a clear boundary around what an AI may change.

v0.1 is that, for people who are not its author:

- **An application.** A person launches loom, opens a quilt or starts one, and drags things in. It runs in a browser tab. After installing, no human types a loom command.
- **Not an editor.** People keep writing in their own editor, or on Overleaf. Loom is where they read, annotate, decide and manage.
- **Their own agent.** Loom calls no model. The person's agent app works in the quilt through loom's tools. v0.1 is built for Claude Code; Codex and Gemini get a manual check before shipping, and their setup files are still written until then.
- **One quilt at a time.** Nothing crosses between quilts.
- **Alpha, among friends.** Breaking changes stay allowed. A quilt carries a format number so that an old one says so instead of misbehaving, and an upgrade never deletes.
- **macOS.** Linux is expected to work from the same install line and is not a gate. Windows waits.

It ships when it meets the bar, not on a date.

## Decisions

Made by the author: everything under "What v0.1 is"; Overleaf over git with no zip path; Zotero a nice-to-have and every other library fix a must; formalization built for v0.1, with the person touching Lean as little as possible; the graph draws the structure of a single paper, with a result from another paper appearing only where something in that paper uses it; a person need not review their own changes (plan 0.31); loom may run Lean to check a proof, and re-running an agent's script or a notebook from the viewer waits for the pilot.

Recommended by the study, and built unless the author strikes one:

1. **Three zones.** The person's documents: agents read them and propose changes, and by default are refused writing them. The agents' places (documents an agent writes or copies, session files, a Lean project): agents write freely, the person reads, annotates and takes from them, and loom keeps versions there. Loom's records: only loom writes. A quilt with no paper has the same zones over its lessons and notes. The refusal is a default that Claude Code enforces and a careless or hostile agent can get round, so loom also shows what changed.
2. **Review is two lists.** *Changed*: what changed in the person's documents since they last looked, other than by their own hand (a pull, a document taken in, an agent's edit where one is allowed). One row per file listing its changed statements and proofs or Markdown passages; more than twenty blocks at once, or a new file, is one row; "Seen all"; an author named only from loom's records. For someone whose edits arrive by pull from Overleaf, their own are left out by matching the pull's author. *Proposed*: suggested edits, kept or discarded and undone in one step, each drawing the change; later the attest card and the Overleaf variant.
3. **AI documents.** An agent's copy or new document sits in the file tree with "Take into my document" on it, and leaves Review. Suggested edits are for local changes; a rewrite, a move or a new text is an AI document (relloc relies on these: `raw/cuts.md` CUT-1).
4. **Accept is hidden for v0.1**, the ledger kept. Neither of the author's quilts has an acceptance, and hiding it removes the confusion with Keep.
5. **Sessions** stay as the agent's report, reached from the activity page; the footer and picker go (CUT-3). **MCP** is the default for new quilts; the shell route stays, unshown (CUT-6).
6. **Launch** is a home server supervising one server per quilt on a remembered port.
7. **Install** is a script, a release wheel and loom's own TeX shipped as an archive. What a Mac without Homebrew lacks for diagrams, PDF figures and page text is **open**: Install settles it first by a short trial.
8. **A save shows the new words first and typesets after**, with only the changed fragment republished so that typesetting is not delayed. A write from the viewer answers when it is recorded, and the page marks itself as updating until the publication lands.
9. **The library**: an agent suggests and the person adds; one key scheme with the person's own key winning; the network asked about once per quilt.
10. **Formalization** is the smallest cut as the trial amended it, with loom doing what spares the person Lean. One control turns it on: loom installs the toolchain, makes the project and fetches Mathlib, and from then the agent may build in the quilt's Lean folder without asking each time. The agent does the proving in its own app. Loom runs the certifying check itself (a clean rebuild of the declaration, its axioms, the checker's replay) and again when the statement or a definition changes, so that "Lean accepted this" is something loom saw and not something an agent reported. A result reads "formalized" only after the person attests, from a rendering in ordinary mathematics, that the formal statement and the definitions under it are theirs. The author agreed on 2026-11-13 that loom may run Lean for this. The switch is kept on the machine and never in the quilt's shared files, so that opening a co-author's quilt runs nothing. Whether the check can run fenced on macOS (no network, writes confined to the Lean folder) is untested and is settled first.
11. **Files** that are not UTF-8 are refused, not rewritten; line endings are kept byte for byte.
12. **Records are checked, not trusted.** A record found by its label is still compared with the text it was filed on before anything is written or shown there.
13. **Links open in the same pane** unless the person asks for beside.
14. **Names** are corrected once (one "restore", the annotation type "Suggestion", "kept" against "accepted") and then frozen.
15. **The viewer is vendored at release and in CI**, not by workstreams; the command reference is generated at release.
16. **Loom may run code, on the person's word.** Looking runs nothing: opening a quilt, a file or a link executes nothing the quilt carries, which the two existing invariants guard and which stays. A run is the person's own act in the viewer, or follows from a feature they turned on on this machine whose description says it runs code. It is fenced, and loom records what ran, on what, and what it said, so that a result of a run is shown as loom's own observation and goes stale when its inputs change. The Lean check is the first use and is built as this general mechanism; re-running an agent's script or a notebook is the second and waits for the pilot.

## Order of work

At most four agents at once: the files collide (`raw/redteam-execution.md` appendix B is the ownership map, and part of this plan), the machine reached a load of 50 with a dozen sessions, and the disk has about 20 GB free with a worktree costing 1 GB.

**Stage 0, serial, about three sessions. No workstream branches before it ends; Security runs beside it.** Errors, identity and `key_hash` out of `cli/`. The write API's `handle()` and its test file split by family, so that each workstream owns its handlers. `Column.svelte` and the root layout split into owned children. A list of hooks in `build()` for what each workstream adds to the manifest. One commit reserving the new manifest fields, record kinds, paths, commands, diagnostic codes and refusals. `scripts/regen` and the merge rule below. The development proxy from the viewer to a running `loom serve`. A worker budget for checks. The write-safety test in the unit tier, the anchoring harness extracted from its patch, and the interim placement guards that protect the author's own quilts meanwhile.

**Wave A.** Safe's door, steps 1 to 3, with the lock and the write contract designed once. Speed's safe changes. Install. The back ends of Attach and Library. Fitted between: Problems by class, the Markdown fixes, Formalization's scan pruning and evidence record.

**Wave B.** Safe: undo in the viewer, then anchoring, then adoption and pulls through the door, the new-quilt defaults, one look per person. Speed: the early answer. The viewer halves of Attach and Library; Legibility's panes, toolbar and selection comment.

**Wave C.** Review's two lists and AI documents. Overleaf. Suggested edits and annotations on Markdown. The rest of Formalization.

**Wave D.** Legibility's sweep, the name freeze, the showcase, the introduction; then every gate's check.

The critical path is stage 0, the door, undo, Review, the sweep and the gates: about twenty to twenty-five sessions in series at the study's sizes. The whole is about 105 to 145 sessions and 45 to 70 merges at those sizes, which have run high in the author's experience.

**Merging.** One integrator, the author or a session he names, merges. A workstream never commits generated files (test quilts, demos, the fixture, the permission files, the tool list): the integrator runs `scripts/regen` after each merge. Merges that touch `render/`, `scan/` or `tex/` are batched, because each invalidates every cached page and costs the author's large quilt minutes of TeX. A workstream reports in its pull request; only the integrator edits this file.

## Implementation

The integrator appends here what landed and what it changed in this plan.
