# 0.18.3: one output layer

## Context

The CLI study (`docs/reports/cli-study.md`, Part two C and H) found the terminal principles T1–T8 broken across the command line:
- **The verdict is not first** on about a third of the commands that report: `status`, `lint`, `check`, `doctor`, `build`, `refs build`/`coverage`/`match`/`verify`, `adopt`, `import`, `init --from`, `upgrade`, `ai check`, `sync publish`/`status`.
- **Lines run to 1,397 columns**, and identifiers are cut.
- **One sentence is printed up to 88 times**, and cited works' diagnostics drown the author's.
- **Counts don't add up.**
- **No command shows it is alive**, though some run for minutes.
- **56 of 91 commands have no `--json`.** Where it exists it is often thinner than the text, and 20 commands build it with a bare `json.dumps`.

Each command prints its own way: `format_diagnostic` (`cli/lint_cmd.py:29`), doctor's `Report` (`doctor.py:103`), `ScanReport.lines()` (`refs/scan.py:74`) and the refs `BuildReport.lines()` (`refs/build.py:168`) are four renderers. `check`, `build`, `digest extract` and `compile` each format diagnostics differently again.

**Decided with the author on 2026-10-03:**
- **JSON is one envelope that keeps each command's data.** Every `--json` is an object carrying `verdict`, `ok`, `exit`, `groups` and `notes`, beside the command's own data under its existing keys: `status` keeps `keys`, and `lint`'s bare list becomes `diagnostics`.
- **One landing.**
- **Book 12.1's promise is dropped.** It says ids in output carry their number (`rl-0004 (Lemma 3.4)`), and nothing implements it; the sentence goes.

**The outcome:** every command reports through one layer, so T1–T8 hold by construction, and a check in the test suite keeps them holding.

## The work

### 1. `loom/src/loom/cli/report.py`

```python
Item(text, key=None, command=None)     # key: an identifier, placed last and never cut
Group(heading, items, count=None, limit=12, next=None, problem=False)
Report(verdict, ok=True, exit=0, groups=[], notes=[], data={})
Report.render(width=100) -> str        # the text
Report.to_json() -> dict               # the envelope
Report.emit(as_json) -> int            # prints, returns the exit code
```

**The text:**
- the verdict line comes first;
- each group is `heading (count)` with its items indented two spaces under it, sorted as given;
- a list longer than `limit` is cut, with `… and N more; <next>`;
- an item's `key` goes last on its line, and a line over `width` wraps at a space with a hanging indent, never inside an identifier;
- `notes` go to stderr;
- a dry run's verdict reads `dry run: …`.

**The JSON envelope** is `{verdict, ok, exit, groups: [{heading, count, items, next}], notes, …data}`. The items are never cut, and each item is `{text, key?, command?}`. `emit` writes it with `emit_json` (sorted keys), and stdout holds only that, on failure as on success.

`Report` replaces `doctor.Report.render` (its ok/warn/fail model is kept, as items with a status), `ScanReport.lines` and the refs `BuildReport.lines`, each of which gains `report() -> Report`.

### 2. `Progress`, in the same module

- **Usage:** `with Progress("extract", total=18) as p: p.item(name)`.
- **On stderr only:** stage, item, `n/total` and elapsed time.
- **Silent for the first 2 s,** so a fast command prints nothing; T6 is about what is slow.
- **On a long item:** it adds "still working, 40 s" after 15 s on one item, from a timer thread.
- **Terminal or not:** on a terminal it is one line that rewrites itself; otherwise one plain line per item.
- **Where it is used:**
  - `build`, `check` and `compile`;
  - `serve`'s first build (its "building the quilt ..." line becomes a `Progress`);
  - `refs build`, per stage and per work, through a callback that `build_refs` (`refs/build.py:496`) gains;
  - `refs map` and `accept --stale`.

### 3. One diagnostics formatter

`diagnostic_groups(diags, result) -> list[Group]` sits beside `format_diagnostic` in `cli/lint_cmd.py`, which keeps the one-line form:
- one group per code, headed `code (count)`;
- each item is the location `file:line` with the message and `keys`, and its fixes as `fix:` lines;
- the author's diagnostics come before those in cited works (a location in `result.assembly.digest_files`, or an external key). Cited works' diagnostics are summarised under one heading, `in cited works (N)`, one line per code with its count, and `loom lint --json` named for the whole list.

It is used by:
- `lint`;
- `build`, which today prints errors without locations;
- `check`, which today prints to stderr without locations;
- `digest extract`, with its own column widths today;
- `history verify`;
- `compile`'s missing-package notes.

### 4. One error style

- **Every refusal is an exception.** It is an `EnvError` (exit 2) or a `ContentError` (exit 1), printed by click as `Error: …`.
- **The hand-written ones go:**
  - the `ERROR:` lines and `ctx.exit` calls in `cli/paper.py` (:73-74, :280-281, :296-297);
  - `SystemExit(1)` at `agent_cmd.py:44`, `ai.py:377` and `history_cmds.py:789`;
  - the literal `ctx.exit(2)`.
- **Exit codes follow 12.1 where the study found them wrong:**
  - **G1, exit 1 where 2 is due:** `link` with an unknown key, `revert KEY@9`, `refs why`/`verify`/`discard` with an unknown id, every `sync` environment error, and `agent check` in its normal unconfigured state.
  - **G2, exit 1 where nothing is wrong:** `stamp` with nothing to stamp exits 0. `delete`, which only refuses, exits 2.

### 5. Every command reports through the layer

Each command builds a `Report` and returns it through `emit`:
- **Write verbs** (`new`, `accept`, `annotate`, `fork`, `mv`, `init`, the `session`/`ai`/`sync`/`digest` writers, the `refs` writers) report a verdict naming what they wrote, and the next command where there is one.
- **Raw-content commands are allow-listed:** `source`, `id` and `revert` patches, `sync patch`, `history show`, `refs page`/`overview`/`path`/`locate`, `link`, `ai orient`, `session next`. Their bodies stay as they are, and their refusals still go through the error style.
- **Commands that run until stopped are allow-listed:** `serve`, `session watch`.
- **Every command that reports gains `--json`.** That includes `check`, `build`, `review`, `compile`, `agent check`, `ai check`, `sync status`, `refs map`/`scan`/`fetch`, `digest extract`, and every write verb. The 20 raw `json.dumps` calls (15 in `cli/refs.py`, 2 in `ai.py`, 2 in `adopt.py`, `session.py`'s `_json`) and the unused `nodes._json_dump` go.
- **Output faults fixed as each command moves**, from the study's C list:
  - unsorted lists (C4);
  - columns that collide (C8);
  - counts that do not add up (C7), each now a sum the layer can check;
  - implementation words, storage paths and hashes in text (C9, C10). A hash stays only in `--json`;
  - `init` and `import` writing their summary to stderr (C13);
  - dates without their day (C14).

The order is the umbrella's:
1. `refs`;
2. `status`, `lint`, `build` and `check`;
3. `doctor`;
4. `init`, `import` and `history`;
5. `session`, `ai` and `sync`;
6. the rest.

Each module's tests move with it, since `exits`, `refused` and `json_of` match output text (`tests/helpers.py`).

### 6. The output check

**A deviation from the umbrella:** it lives in the unit tier rather than `scripts/checks/`, because there it runs hermetic under the fake TeX shim and `isolated_env`, and 0.18.4 reuses its case table for K3.

- **`loom/tests/output_cases.py`** holds the case table: `command -> (args, setup, expected exit)`. It has normal and refusal cases for every leaf command, with stub inputs for the prompting commands (`--yes`). Raw-content and long-running commands are marked as such.
- **`tests/unit/test_output.py`** runs each case on a fresh demo quilt and checks:
  - the first stdout line is the verdict;
  - no line is over 100 columns, outside the raw-content allow-list;
  - no `digests/storage/` path, and no hex run of 12 or more characters, in text;
  - the exit code is the case's, which follows 12.1;
  - `--json` parses as one object holding `verdict`, `ok` and `exit`, with nothing else on stdout, on failure as on success;
  - a test covers every leaf command (the walk of the click tree that `test_json_output.py` already does).
- **`Progress` gets unit tests** with a fake clock: silent for the first 2 s; one line per item off a terminal; "still working" after 15 s.
- **`tests/unit/test_json_output.py` folds into `test_output.py`.**

## Delivery

Built on 2026-10-03, as one landing.

**The layer:**
- `loom/cli/report.py`: `Report`, `Group`, `Item`, `table`, `counted`, `wrap` and `Progress`.
- `loom/cli/diagnostics.py`: diagnostics as groups.
- The four old renderers fold into it:
  - doctor's `render` becomes `report()`;
  - `ScanReport.lines()` and the refs `BuildReport.lines()` now come from their `report()`;
  - `lint`'s list.

**The commands:** every leaf command (93 with aliases) has a kind and cases in `tests/output_cases/`:
- `report` for 79;
- `raw` for `source`, `id`, `revert`, `fork`, `sync patch`, `refs page`/`overview`/`path`/`locate`, `link`, `ai orient` and `session next`;
- `running` for `serve` and `session watch`.

Every `report` command takes `--json`, which is the envelope. The 20 hand-built JSON documents are gone, along with the `ERROR:` echoes, `SystemExit(1)` and the literal `ctx.exit` codes.

**Progress:**
- `build` and `serve`'s first build report scanning, rendering per fragment with its count, recording and publishing, through a callback `render.build.build` gained.
- `refs build` reports per stage and per work, through `build_refs`'s callback.
- `refs map`, `resolve` and `fetch` report per work.
- `check`, `compile`, `accept --stale`, `review` and `digest extract` report as they compile or read.

**Exit codes fixed by 12.1:**
- **Now 2:**
  - `link` with nothing linkable;
  - `refs why`, `verify` and `discard` with an unknown id;
  - `refs drop` of an unknown work;
  - `revert KEY@9`;
  - `delete`;
  - every `sync` environment error;
  - malformed `annotate --batch` input.
- **Now 0:** `stamp` with nothing to stamp, and `agent check` with no agent configured and launching off.
- **Sync:** `sync.py` gained `SourceError`, so its refusals about the author's own source exit 1 and the rest exit 2, by type rather than by message.

**What the plan did not foresee:**
- **Groups of summary lines.** Some groups hold summary lines rather than things: a bibliography's state, a document's counts. `Group(counted=False)` leaves the count out of the heading, since a count must say what it counts.
- **Editor clients.** The Neovim plugin, the VS Code extension and the language server's test read `lint --json` as a list. They now read `diagnostics`.
- **`ai start`.** It prints a verdict that begins with the session id. `gen_quilts.py`, the orientation and book 11.10 read or describe it so, and its `--json` carries `session`.
- **Counts.** `atomize --sections` counted sections as results; it now counts results, proofs and sections apart. `check` said "1 document compile".
- **A test leak.** A scratch script run while the commands were moved wrote a test author name into the author's real `~/.config/loom/config.toml`, because it set `HOME` and not `XDG_CONFIG_HOME`. It was found and removed the same day. The test suite isolates `XDG_CONFIG_HOME` and was not the cause.

**Left as it is:**
- **`adopt`'s preview token.** Its next command, printed when there is no terminal to confirm on, carries the 64-character preview token, which exceeds 100 columns and is a hash in text. The command needs it to name exactly the preview that was inspected. Shortening it is a change to how `adopt` resolves a token, which is Luisa's.

**Checked by hand on a copy of `~/Desktop/relloc`:**

- **Progress:** `build --force` (3 min 35 s) printed its progress on stderr every 2 s.
- **JSON:** `lint --json` and `status --json` are envelopes with `diagnostics` and `keys` beside them.

**Tests:**
