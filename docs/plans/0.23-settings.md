# 0.23 — Settings as a window

## Context

Settings is a small dropdown today (`arras/src/lib/shell/Settings.svelte`): the display preferences, the aux-files checkbox and the reviewer name. Everything a quilt is configured by lives in `config.toml`, which the person edits by hand.

The author asked for Settings to open a larger floating window like the Claude app's: a left panel organising the settings, and a main pane for the settings themselves. It should grow to hold most of what `config.toml` requires today. The author approved the design, shown as a mockup in the browser pane, on 2026-11-02.

**The author's decisions (2026-11-02):**
- **The left panel groups sections by where a setting is saved,** and each page says so under its title:
  - **This browser:** Appearance, Reading, Files.
  - **You:** Profile, the reviewer name in the user config.
  - **This quilt:** General, Documents, Agents, Library, Problems, Overleaf, all in `config.toml`.
- **Quilt settings wait for Save.** A bar counts the unsaved changes to `config.toml`, with Revert and Save, because the file is committed and shared. Browser settings apply at once, as today.
- **Every quilt setting shows its `config.toml` key** in small print.
- **Overleaf shows the pairing only.** Pairing stays `loom sync init DIR`, which the page shows.
- **Agents shows each app as set up or not,** with the command that sets one up. Its one action is **Update Claude Code**, which rewrites the permission file to match the deny list, as `loom upgrade` does.
- **The history folder and the research state's path are shown read-only,** with "change in config.toml, and move the files with it", since changing either alone would lose them.

This document is the plan, and its Implementation entry records what was built. Plan 0.22 is complete.

## 1 · The publisher says what the config holds

- **A new additive manifest section, `config`** (interface stays 2):
  ```
  config: {
    quilt:   {name, main, home, prefix, engine, history, research_state},
    library: {online, contact},
    lint:    {disable, codes},          // codes: what may be silenced (scan/diagnostics.can_disable)
    agents:  {deny, protected, clients},
    sync:    {directory, documents, published_main} | null,
    warnings: [...]                      // the config's own warnings, as lint reports them
  }
  ```
  - `protected` comes from `agents.always_protected`.
  - `clients` is `[{key, label, set_up, refuses}]` from `ai/clients.PROJECT`. `set_up` means the client's file holds loom's entry (`is_loom_file`); `refuses` means it refuses an edit by path, which only Claude Code does.
  - `sync` comes from `SyncState.read`, null when nothing is paired.
- A static viewer reads the same section and shows the quilt pages read-only.

## 2 · One writer for `config.toml` (a new `loom/config_edit.py`)

- **`set_values(quilt, changes) -> QuiltConfig`** edits lines, so the person's comments and order survive:
  - **A key that exists** in its table has its value replaced, and a trailing `# comment` kept.
  - **A template line** `# key = …` in that table is replaced by the active line.
  - **Otherwise the line is inserted** after the table's header, and a missing table is appended.
  - **`None` removes the key's line.**
  - **Values are written** as TOML basic strings, booleans and one-line arrays of strings.
- **Validated before writing:** the new text must parse with `tomllib` and give a `QuiltConfig` with no warning the old one lacked. The write is atomic: a temporary file, then `os.replace`.
- **Only these keys are editable, each checked:**
  - `quilt.name` (non-empty);
  - `quilt.prefix` (an id prefix's shape);
  - `quilt.engine` (pdflatex, xelatex or lualatex);
  - `quilt.main` (a master, or empty);
  - `quilt.home` (a shown file, or empty);
  - `library.online`;
  - `library.contact`;
  - `lint.disable` (codes `can_disable` allows);
  - `agents.deny` (each entry through `agents.compile_pattern`).
- **`importer.set_main` and `set_main_forced` call it,** so loom has one writer of the config.

## 3 · The write API

- **`POST /_api/settings-save {changes: {"quilt.name": "…", …}}`:**
  - the author's: refused to a declared agent with 403 `author-only`, since `config.toml` is the person's and an agent never changes a protection (`agents.py`);
  - answers each refused key with its reason (`bad-value`), and writes nothing then;
  - rebuilds, so the manifest's `config` and everything the config drives is current.
- **`POST /_api/agents-update {}`:**
  - rewrites the permission files from `ai/layout.vendor_files`, in the quilt's current variant, as `loom upgrade` does for that part;
  - the author's, likewise;
  - clears `loom:agent-permissions-stale` at the rebuild.
- **`reviewer-settings`** gains the agent check it lacks today: a declared agent is refused with `author-only`, like every other author act over the API (K5).
- Both new endpoints are in `CAPABILITIES`, `write-api.md`'s table and the write-API test's cases.

## 4 · The window (arras, re-vendored)

- **`shell/Settings.svelte` becomes the window:**
  - the ⚙ in the column's head opens it, through `Popover`'s `modal` mode, which closes on Escape and on a press outside;
  - inside: a left panel (`SettingsNav`) and a pane per section (`settings/*.svelte`);
  - the last section opened is remembered per browser, inside try/catch.
  - **Below 720px wide,** the left panel becomes a row of sections above the pane.
- **The left panel:**
  - a search box that filters settings by name, description and key;
  - the three groups;
  - a dot on a section that needs attention (Agents while Claude Code is behind its list);
  - the development links at its foot, as today.
- **The pages:**
  - **Appearance, Reading and Files:** the `prefs` controls as rows (name and what it does on the left, the control on the right), and a preview of the typeface and size.
  - **Profile:** the reviewer name with its Save, as today.
  - **General:**
    - editable: name, id prefix, TeX engine;
    - read-only: the history folder.
  - **Documents:**
    - editable: front door (a select over shown files), default document (a select over masters);
    - read-only: the research state's path.
  - **Agents:**
    - the deny list as chips, with Add and remove;
    - the always-protected paths as fixed chips;
    - the stale warning with **Update Claude Code**;
    - each app, set up or not, with its `loom ai init --ai KEY` line.
  - **Library:** the network switch, and the contact address.
  - **Problems:** the silenced codes as chips, and a select of codes to silence.
  - **Overleaf:** the paired folder and its documents, or how to pair.
- **Quilt pages edit a draft.**
  - The save bar counts the changes, Revert drops them, and Save posts `settings-save`.
  - A refusal is shown beside the setting it names.
  - The pages read `config` from the next manifest.
  - With no write API, the quilt pages are read-only and say "change these in config.toml".
- **Today's dropdown and its rows go.** `tests/e2e/settings.e2e.ts` is rewritten for the window.

## Implementation

### 0.23 · Settings as a window — built 2026-11-02

The author decided before it was built: Overleaf shows the pairing only; Agents shows each app and offers Update Claude Code; the history folder and the research state's path are shown read-only.

**What was built:**
- `loom/config_edit.py`: `config.toml` edited line by line. A key's value is replaced in place with its trailing comment kept, a commented template line (`# home = …`) becomes the setting, a new key goes after its table's last key, and a missing table is appended. The result is parsed and compared with what was asked, and must give no configuration warning the file did not, before it is written through a temporary file. `check` holds each editable key to what the CLI reads; `save` writes every change or none. `importer.set_main` and `set_main_forced` write through it, so loom has one writer of the config.
- The manifest's `config` section: the editable and read-only keys, the values, the codes that can be silenced, the deny list with what is always protected, the agent layer and its variant, whether Claude Code's permission file is stale, each app's file and whether it is set up, and the sync pairing.
- The write API's `settings-save` and `agents-update`, both the author's; `reviewer-settings` now refuses a declared agent too. A refusal can carry `fields`, the reason for each field it refused. `ai/layout.py` gained `write_permissions` and `permissions_stale`, which `loom upgrade`, the lint and the endpoint share.
- The viewer: Settings is a window over the page (`Popover` modal). Its left panel has a search box and three groups, a dot on Agents while Claude Code lags, and the development links at its foot. Each page says under its title where its settings are kept. The quilt's pages edit one draft, kept while the window is closed, with a save bar (count, Revert, Save); a refusal is shown beside its setting. A viewer with no publisher shows the quilt's settings disabled, with "Change these in config.toml". Below 720px the sections are a scrolling row above the page. The words of every setting live in one catalog, which the rows draw and search reads. Re-vendored.
- The specs (`manifest.md`, `write-api.md`), the design (`model.md`, `agents.md`, an invariant's dated line) and the init README describe it. The fixtures were regenerated.

**Departures:**
- **Commands come from the publisher.** The viewer names no loom command (its boundary test forbids it), so the commands Agents and Overleaf show (`loom ai init`, `loom ai init --client KEY`, `loom sync init DIR`) are in the manifest as `command` fields. Each app entry is `{key, label, file, set_up, command}` in place of the planned `refuses`; that Claude Code alone refuses by path is said once, in the Apps row.
- **`loom serve` re-reads `config.toml` at each rebuild.** It had built with the config it read when it started, so a config edited while serving, by hand or in Settings, never took effect until a restart. What the viewer shows stays as serving began, since it follows `[quilt] history`, which Settings never changes.
- The Profile page shows the name read-only without a publisher, rather than hiding it.
- An unanchored deny pattern renders as `/**/notes/**`, not `/notes/**` as the plan's hand check guessed.

**Found on the way:** quant's `.claude/settings.json` predates 0.22.8, which protected `.loom/looked/`, so Claude Code there holds agents to a boundary without it; relloc's is current. `loom upgrade` in quant, or Update Claude Code in its Settings, catches it up.

**Checked by hand** on a copy of quant served in the browser pane: the window opened on each section; the name, front door and a deny pattern were drafted, and the save bar counted three changes. The browser pane closed twice before Save was clicked, so the saving itself was checked through the same endpoint the window posts. `config.toml` kept every comment: the name changed in place, `home` went in after the `[quilt]` table's last key, and `[agents]` was appended. The manifest carried the new name and front door, and Agents showed stale. Update Claude Code rewrote `.claude/settings.json` alone, which then denied `/.loom/looked/**` and `/**/notes/**`, and the stale flag and its diagnostic cleared. A save declared by an agent was refused with `author-only`. The window was also checked at phone width.

**Verification:** `scripts/verify full` passed but for steps each fixed or rerun: loom 2,146 unit and 16 TeX tests; arras 217 vitest, 330 e2e, 15 minimal, 40 write, 24 reading, 6 shots and 1 floor; the docs checks.
- `ruff format` reflowed four files, and mypy wanted one helper's return typed; `scripts/verify fast` then passed;
- the tracked-files test failed until the new files were added to git with `--intent-to-add`;
- the write suite's patch test missed its timing budget under the parallel suites' load, as in every phase since 0.22.4, and passed alone.

### After 0.23 · Two groups, no search — 2026-11-02

The author asked, after seeing it built, for Settings without search, with Reading merged into Appearance, and with two groups: **Loom** (Profile at its head, then Appearance and Files) and **Quilt** (the six sections of `config.toml`). Each page still says under its title where its settings are kept, which the groups no longer do. The window opens on Profile when the browser remembers no section.

The same day the author asked for a setting that hides the agents' config documents. Files gained **Hide agent config documents**, a browser preference off by default, which leaves `AGENTS.md`, `AGENT.md`, `CLAUDE.md`, `CLAUDE.local.md` and `GEMINI.md` out of the project's tree wherever they stand. It was first built as hiding the agent's copies of documents, a misreading of the request, and changed the same day. Docs' tree also moved under a **Files** shelf, open by default and folding as Library's does, so that Files reads as the quilt's directory and Library as what loom keeps; and a project PDF's quote chip now goes when its words are let go of, as a cited work's did.
