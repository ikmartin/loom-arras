# 0.18.5: the library

## Context

The CLI study (Part six) and the agent's refs audit (`docs/issue-reports/refs-audit-critique-from-agent-2026-10-02.md`) found the reference layer is where loom's command line is worst:
- **Too many commands.** 29 commands (27 `refs`, 2 `digest`), and none lists what waits for the person.
- **Flags broken against K2.** Flags mean different things on different commands: `--author` and `--as` on one option, `--reason` beside `--why`, `--fetch` and `--resolve` as consent.
- **Search.** It is unranked, truncates ids, and `grep` is case-sensitive.
- **Dishonest states.** A mechanically extracted result is stored `verified`, even from a preprint the bibliography does not cite.
- **Duplicate works.** The author's own PDF of a paper loom already fetched becomes an unrelated sibling with a second digest, and a sibling with no identifier loses its PDF.
- **Ingest on weak signals.** It filed a wrong PDF on two weak signals and does not say what it skipped.
- **Lint swamped.** About 129 of the author's 139 lint errors are inside machine-made digests nothing cites.
- **Stale paths.** Chapter 8 and the orientation give store paths the code stopped using.

**Decided with the author on 2026-10-03:**
- **Two landings.** 0.18.5a is the command surface. 0.18.5b is the data model: states, versions, and lint by citation.
- **States.** `extracted` and `verified` now. `checked` (numbering confirmed against the cited version) waits for WQ-39, which keeps its trigger.
- **States are derived on read.** A result is `verified` only when a person verified it. A mechanical result without that reads `extracted`. No file is rewritten: the author's live quilt and its 3,140 results stay as they are.
- **Write API.** It takes library names, and `reason` becomes `why`. Only arras calls these endpoints, so Luisa is not consulted.

### One name per work and per id

`_works.py` resolves every `WORK` the same way:
1. an exact citekey;
2. a fragment of a citekey, author or title, via today's `resolve_works`/`one_work` (`cli/refs.py:674, 703`); an ambiguous fragment is refused, listing the matches;
3. a result id or its prefix, mapped to its citekey by a new inverse of `Assembly.prefix_of` (`scan/nodes.py:139`).

An `ID` is a result id (`<prefix>-<local>`, via `proposals.find_result`) or a citation suggestion's annotation id (`a-…`). The id's shape says which.

### Flags (K2)

- `--author` becomes `--as`, and `--reason` becomes `--why`.
- `refs link`'s alias `--author/--as` goes.
- `--from ID --to ID` become positionals, keeping `--to` for files.
- `--refresh` and the `--force` flags of `build` and `map` become `--redo`.
- `--fetch` and `--resolve` become `--online`. The config keys `[refs] fetch`/`resolve` merge into `[library] online`. A config with the old keys is refused by name, exit 2, naming the new key; the author is given the edit for relloc as a command to run.
- `refs add --force` replaced a document, against 8.16. `add` never replaces: a second document is filed beside the first.

### Behaviour

- **The bare report.** Its verdict is "N works cited, M digested; X need you, Y wait for review". Then these groups, each with its `next:` command:
  - **Need you**, by cause:
    - no document and no identifier → `add --for` or `ignore`;
    - the title did not match on fetch → `add --for`;
    - needs the network → `update --online`;
    - a wrong document → `add --for`.
  - **Waiting for review** → `library review`.
  - **Need an agent** (pages but no digest) → ingest mode.
  - **Done** (one count).

  Advice is tested: a work with no PDF is never told to map (study D1–D5).
- **`update`** runs today's pipeline (`refs/build.py` `build_refs`) with its progress. Its final report is the bare report plus a "this run" group.
  - `--redo` is today's `force`. Verified results are already kept by `_restore_verified` (`refs/build.py:522`, the study's defect 3), and a test pins it.
  - Gathering becomes idempotent: a document already offered an entry is not offered another.
  - The sibling branch of `refs/scan.py` writes `loom-file` (audit §3).
- **`add`** takes files and folders.
  - A match is strong only when either:
    - an identifier found in the document's text equals the entry's; or
    - the full normalised title matches and the entry's first author leads the byline.
  - Anything weaker is skipped, with its reason. A document matching another entry more strongly is refused, naming that entry.
  - The report lists every file as filed, skipped or refused (audit §4). Map runs at once.
- **`search`** is case-insensitive and needs every term. It is ranked (WQ-41):
  - a term in the locator, local name or title counts ×3, and one in the body ×1;
  - a level-1 result scores +2;
  - each of the author's citations of it scores +1;
  - ties go by citekey.

  Each hit gives the work, locator, a snippet and the full id last. `--pages` ranks page hits by count. WQ-41 closes.
- **`ignore`** acts by what the work has:
  - a stored document is set aside, as `forget` did;
  - no document is declared unreadable;
  - two versions are refused, naming them.

  `--undo` withdraws whichever applies.
- **Who may run what.** `add` and `import` become author-only, since filing a wrong PDF is the audit's harm. Today neither is in `AGENT_COMMANDS` and neither is refused. `AGENT_COMMANDS` gains the agent rows of the table and loses every `refs`/`digest` entry.

### One citation decision, two callers

`refs/notes.decide_citation(root, annotation, decision, why, who, session)` serves `verify`/`discard` and the write API. It records the CLI's mapping: `work` is the payload and `claim` is the body (`cli/refs.py:347`). The API's mapping (`render/api.py:642`, the body as the work and the quote as the claim) is a defect, fixed by sharing the function.

The endpoints are renamed in loom (`render/api.py`) and arras (`lib/write.ts:12`, `review/VerbRow.svelte:123`, `review/ProposalBox.svelte:103-111`):
- `refs-cite` becomes `library-cite`;
- `digest-verify` becomes `library-verify`;
- `digest-discard` becomes `library-discard`;
- the `reason` field becomes `why`.

## 0.18.5b: honest states, one work with its versions, lint by citation

### States

- **Derived on read.** `refs/proposals.state_of(result)` returns:
  - `proposed` or `discarded` as stored;
  - `verified` when the result's origin carries a person's `verified` or `edited` act, or its class is not `mechanical`;
  - `extracted` otherwise.

  Every reader goes through it: lint, `library`, `review`, `why`, search, the manifest, and `_restore_verified`, which then also restores a mechanical result a person verified.
- **New writes.** `record_extracted` writes `extracted`.
- **Verifying.** `library verify` on an extracted result appends a person's `verified` event.
- **Preprints.** A result whose digest came from a version other than the one cited carries `version: {extracted_from, cited}`. This builds on `scan.digests.other_version_of` (`scan/digests.py:77`). A candidate-fetched preprint records `published-as`, so it is flagged too (audit §5).
- **The manifest.** `references[ck].results[id].state` takes `extracted`, and `version` is added. `docs/specs/manifest.md` §13 gains `results` and `proposed`, which it never documented. `interface_version` is bumped.
- **The fixture** is regenerated first, then arras:
  - the Library counts and filters extracted, verified and proposed results;
  - a result shows "extracted" or "verified by NAME", and "from arXiv v2; the bibliography cites the published version" where that applies;
  - `badges.ts`' "transcription verified" follows the state.

### One work, several documents

- **The model.** A work is a citekey together with the siblings whose `loom-copy-of` names it. That field is written by `refs/scan.py:632` and read nowhere today.
- **The manifest.** The primary entry gets `references[ck].versions` (its siblings' citekeys, each with its identifier and document), and a sibling gets `version_of`. 8.16's rule stands: a second document is filed beside the first.
- **Deduplication** happens in `add` and `update`:
  - a document identical to a work's (same identifier, or same title and authors and the same page count) is recorded in the copy ledger as a duplicate and not filed;
  - a document that is another version is filed as a sibling, and it is not extracted unless it is the version the bibliography cites.
- **Citations.** `\cite[Thm 3.2]{key}` matches `key`'s own digest. When `key` has none and a version does, it matches that one, flagged as another version's numbering.
- **Presentation.** Search reports a hit once per work, naming its versions. The Library shows one row per work, its versions inside the work item. Existing duplicates are reported once, by `library check`.

### Lint by citation

`cli/diagnostics.in_cited_work` sorts each diagnostic by whether the author's documents cite the work, not by digest file:
- diagnostics of cited works keep their counted heading;
- those of works nothing cites become one line, "N in works nothing cites; see `loom library check`";
- a diagnostic on a result the author's text reaches stays among the author's own.

### Lazy digests

A study, `docs/reports/lazy-digests-study.md`, measures relloc's reached share (2.5%) and the cost of the other 97%. It lays out promotion on citation, and the full extraction as a search index outside the graph. **WQ-58** is filed with its trigger: lint or status time dominated by unreached digest nodes on a real quilt.
