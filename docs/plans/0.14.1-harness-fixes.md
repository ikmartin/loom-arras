# 0.14.1 — the harness, and the suite rebuilt on it

Plan for the test and verification system, from the audit in `docs/reports/test-audit.md` and its seven slice reports in `docs/reports/test-audit/`, settled with the author on 2026-09-23. The audit's §1 faults, its product faults, the section 3 legacy removals, and two of its §5.7 checks (the tracked-file guard, book 12.2 generated and tested) are already done and are not repeated here. Each phase is planned in plan mode, implemented, verified and stopped for review. Phases are recorded under Delivery.

## Context

The suite is large, and much of it cannot fail. loom's `EXIT_CONTENT` is 1, and click's `CliRunner` also reports an uncaught exception as 1, so every `exit_code in (0, 1)` and every bare `!= 0` accepts a traceback as a pass. About 150 `assert run(...).exit_code == 0` lines print `assert 1 == 0` and nothing else when they fail. Twenty-five test files each carry their own `run()`, every one of which `chdir`s, which makes the suite unsafe to parallelise. The arras write and reading suites share one quilt per suite and depend on each other's side effects. Verification is a block pasted into each plan, the copies differ, and local green has not meant CI green.

The outcome wanted: one command that runs everything, in about a third of the time; a failure that says what went wrong; no test that passes on a crash; tests filed by the feature they test; and a `loom doctor` that is the one command to run when something is off.

## Settled in planning

- **The harness comes first.** Every later phase is cheaper and safer on it: a merge is a few `ok()` calls rather than another copy of `run()`, and a deletion justified by "subset of X" is only safe once X can fail. The dependency runs one way; nothing in phase 2 needs phase 3.
- **The editor clients are out of scope.** They are deprecated and breakable (WQ-49). `scripts/verify` has no clients lane in `fast` or `full`; `clients.yml` stays as it is, path-scoped to the clients. The audit's client items (shared key/argv tables, the lsp `demo` fixture, the nvim probes, doctor's `loom-lsp` check, "vscode skips disallowed") are dropped, not deferred.
- **Behaviour is preserved.** A deletion names the surviving test that holds its property, in the commit and in the Delivery note. A merge keeps every assertion of both tests unless one is shown to be a subset.
- **Where the slices disagree,** the feature file wins: S5 and S6 disagree over `chat:88` and `requests:620`; `requests.e2e.ts` is dissolved in phase 3, so `chat:88` stays and `requests:620` goes.
- **The audit's two open decisions are closed:** `migrate.py` and the `basis: definition` alias are removed (DR-285, DR-286).

## Phase 1 · One entry point (§5.1)

`scripts/verify` at the workspace root, in Python, standard library only.

- **Lanes:** `loom` (ruff lint and format, mypy, pytest unit tier, TeX tier), `arras` (svelte-check, vitest, every Playwright config), `docs` (the work-queue check and, from phase 4, the agreement and hard-wrap checks).
- **Tiers:** `fast`, the inner loop (ruff, mypy, loom unit tier, svelte-check, vitest, the docs lane, the tracked-file guard); `full`, before a commit (`fast`, the TeX tier, every Playwright config, the fixture agreement); `paper`, manual; `--only loom|arras|docs`.
- **Output:** lanes run in parallel; one table of suite, result and seconds; the failing suites' output after it; last, `gh run list --branch <current> --limit 3`, so CI's state is on screen when the test output is.
- **Deselections and skips live in the script with their reasons,** never in a plan or in session history. The hand-deselected biber test is fixed or given a stated skip here.
- **Plans point to it.** AGENTS.md and book 14 name `scripts/verify full` as the verification step; 0.14.1's own Verification section is the first to do so.

Files: `scripts/verify` (new), `AGENTS.md`, `docs/book/14-tests.md`.

## Phase 2 · The harness (§5.2, §5.6)

**loom:** one shared `loom/tests/conftest.py` section (or `tests/helpers.py` it imports), replacing the 25 local `run()` copies:

- `run(*args, quilt=None, cwd=None, env=None, stdin=None)`: passes `--quilt` rather than `chdir`, invokes with `catch_exceptions=False`, and keeps stdout and stderr apart. The variants the audit found (`env=`, a `FIXED` env default, `input=`, optional `cwd`) become its keyword arguments.
- `ok(...)`: asserts exit 0; on failure prints the command, stdout, stderr and the exception.
- `refused(..., code, match)`: asserts the exit code and the message, and fails if Python raised.
- `json_of(...)`: parses stdout only.
- `edit(path, old, new)`: asserts `old` is present before replacing it.
- Session-scoped templates for the expensive setups only: a drafted-and-canonized shim quilt, a built demo, a drafted Manolache paper. Not `init --demo`, which takes 15 ms.
- `isolated_env` also clears `expand._probe`'s cache. A `poppler` marker replaces `tex` where poppler is what a test needs, so those tests skip rather than fail without it.

Every existing test is converted mechanically in this phase: `run(...).exit_code == 0` becomes `ok(...)`, `in (0, 1)` becomes `ok` or `refused` as the test means it, a bare `!= 0` becomes `refused` with its code and message. A conversion that turns a test red has found a crash the test was hiding; each such case is fixed or brought to the author.

**Better failures (§5.6):** fixture and quilt trees compared per file, naming the first differing path and the regenerate command; the manifest compared per top-level section; the launch tests' `finish()` fails with `agent.log` in the message; every "cannot happen" check an `assert` carrying the value it saw; bare `next(...)` over manifest rows replaced by a helper that names the key.

**arras:**
- `evaluate()` returns the value and the test asserts it, so a failure shows what was on screen; no `expect(bool).toBe(true)` over a computed value.
- Each fixed `waitForTimeout` (40, of which 16 are in the suites that run) replaced by the condition it waits for.
- The write and reading suites take their quilt from a clean committed source (`git archive` of the quilt, not `cp -R` from the working tree), one copy and one `loom serve` port per worker, and no test depends on another: the order dependences S6 found (`reading:257`, `:198`, `:219`, `write:275`, `write:242`, `intoASession`, `log().at(-1)`) each get their own setup.
- Fixture ids read from the fixture where a test depends on them.

Files: `loom/tests/conftest.py`, every `loom/tests/**/test_*.py` with a local `run` (e.g. `test_ai_layer.py`, `records/test_review_commands.py`, `render/test_canon.py`), `arras/playwright.write.config.ts`, `arras/playwright.reading.config.ts`, `arras/tests/e2e-reading/reading.e2e.ts`, `arras/tests/e2e-write/write.e2e.ts`.

## Phase 6 · `loom doctor` (§6)

Doctor becomes the one command to run when something is off: machine-level by default, with a quilt section when run inside one, reusing the checks other commands own.

- **Three states per item,** each with a one-line remedy: `ok`; `warn` (works, but something the user will hit); `fail` (a command the user needs will refuse). Exit 0 when nothing fails, 2 when anything fails, 1 for warnings under `--strict`. The summary names every failing item; the JSON carries `status`, `severity` and `remedy` per item; the columns size to their contents.
- **Machine checks added:** `latex`, `xelatex`, `pdftocairo`; `claude` and `codex` as `warn`, only when an agent is configured or `--agents` is given; capability probes (`pdftotext -bbox-layout` works; `biber --version` runs and, with biblatex present, the versions match).
- **Machine checks changed:** no author is `warn`, with the command that sets one; no bundle is `fail` ("`loom serve` will refuse"); an invalid `LOOM_ARRAS_BUNDLE` is named; the bundle's interface is compared with loom's, a mismatch `fail`, and in a checkout a `-dirty` or behind-HEAD bundle `warn`s naming `vendor_arras.py`.
- **Quilt section:** the configured `engine` is present; the agent configuration (complete, untracked, ignored, launch on or off) by `loom agent check`'s own functions; `.claude/settings.json` and `.codex/rules/loom.rules` current, by a dry run of `vendor_files`; the modes version and `loom.sty` current, pointing to `loom upgrade`; the `.gitignore` lines `loom init` writes; config warnings, pointing to `loom lint`.
- **Tests:** one table-driven test per item and state on the fake toolchain, including the hang timeout and each bundle source; a JSON schema test; a clean PATH, so nothing depends on `/usr/bin`; the CI step asserts with `jq` that the bundle is `vendored` at the expected interface, that the missing tool is named, and that `loom serve` on the demo starts.

Files: `loom/src/loom/doctor.py`, `loom/src/loom/cli/` (the doctor command), `loom/src/loom/agent.py` (reused checks), `loom/src/loom/ai/layout.py` (`vendor_files` dry run), `loom/tests/unit/test_doctor*.py`, `.github/workflows/loom.yml`.

## Risks

- **Phase 2 turns tests red.** A converted test that fails was hiding a crash; the phase stops for review with the list rather than weakening the assertion.
- **xdist exposes shared state** beyond `chdir` (module caches, fixed ports). Each is fixed at its cause; a test is marked serial only with a stated reason in `scripts/verify`.
- **Moving tests loses history.** Moves are made as moves, one feature file per commit, so `git log --follow` still finds them.

## Verification

After each phase: `scripts/verify full`, and the phase's own measures: phase 2, the count of `in (0, 1)`, bare `!= 0` and local `run()` is zero; phase 3, the test count before and after with each deletion's survivor named; phase 5, the timed table against the 260 s baseline.

### Phase 5 · Speed and CI (done, 2026-09-24)

| | before | after |
|---|---|---|

The plan's 65–80 s is not reached here: with the arras suites running at once, the machine is the limit, and giving every suite every core traded seconds for timeouts.

- **loom:** pytest-xdist (`-n auto --dist loadgroup`); nothing needed serialising. `templated(name, dest, make)` and `Once`/`copy` in `tests/helpers.py` build an expensive quilt once per worker inside the isolation (the imported-and-drafted papers in `test_paper.py`, `history/test_commands.py`, `render/test_canon.py`); a module's `once` tests share an xdist group. The serve watcher and the launch tests wait on conditions, not sleeps. ### Phase 6 · `loom doctor` (done, 2026-09-24)

`loom doctor [--json] [--strict] [--agents] [--quilt PATH]`, rewritten in `loom/src/loom/doctor.py` (DR-288-ikmartin, book 12.1).

- **States and exits.** Every item is `ok`, `warn` or `fail`, and every item that is not ok has a one-line remedy, the command where there is one. Exit 0 when nothing fails, 2 when anything does, 1 under `--strict` when only warnings exist. The summary names every failing item (`failing: latexmk, dvisvgm (2 warnings)`), and every warning under `--strict`. The JSON is `{python, loom, interface_version, quilt, ok, failing, warnings, items}`, each item `name`, `status`, `severity` (`required`, `optional`, `quilt`), `detail`, `remedy`, a tool adding `path` and the bundle `source`, `path`, `interface`. The text columns size to the ok lines' contents, with the remedy under the item.
- **Machine items.** `latexmk`, `pdflatex`, `dvisvgm` required; `latex`, `xelatex`, `lualatex`, `bibtex`, `biber`, `kpsewhich`, `pdftotext`, `pdfinfo`, `pdftocairo`, `git` optional (missing warns). `latex` is optional because without it the SVG fallback shows a block's source with a `loom:converter-fallback` warning and nothing refuses; `pdftocairo` because `dvisvgm --pdf` stands in for PDF figures. A present tool that hangs, will not start, or lacks what loom uses fails, since loom runs it when it is there: `pdftotext` must write `-bbox-layout` boxes for a one-page PDF doctor writes (xpdf's cannot; `loom refs locate` and build's page geometry need them). `biber --version` must answer, and with a biblatex that `kpsewhich` finds, the two must pair: since biber 2.15 and biblatex 3.15 the minor numbers match release for release, so a mismatch there warns; older pairs are reported and not compared. `claude` and `codex` with `--agents`, and a configured agent's command inside a quilt, are looked for on `PATH` and never run. No author warns with the line that sets one. The bundle fails when missing (`loom serve` refuses), when `LOOM_ARRAS_BUNDLE` names no bundle (saying which bundle serve uses instead), or at another interface; an unstamped one warns; a vendored one in a checkout warns when stamped `-dirty` or built before arras's sources last changed, naming `vendor_arras.py`.
- **Quilt items**, only inside a quilt: `engine` (fails when the configured engine is not installed, warns on a name loom does not know), `agent` (`loom agent check`'s findings: a fault fails with `launch` on and warns with it off), `permissions` (the files against `vendor_files`, remedy `loom upgrade`, or `loom ai init --permissions` where there is no `ai/`), `ai files` (a dry run of `loom upgrade`: what it would refresh, and an edited file whose newer shipped version is not beside it yet), `loom.sty`, `.gitignore` (the lines `loom upgrade` adds), `config` (the warnings `loom lint` reports, pointing to it). An unreadable `config.toml` is a failing `quilt` item.
- **Reuse, not restatement.** `agent.diagnose` is what `loom agent check` now prints from; `upgrade_layer` and `ensure_root_line` take `write=False`; `lastseen.ignores_cache`; `arras_bundle.parse_stamp`, `staleness`, `checkout_of` and `env_problem`, which `scripts/checks/bundle.py` now imports rather than keeping its own copy.
- **Speed.** 1.3 s on this machine, biber's own start about 1 s of it. Every probe is started before any is read and all share one 10 s deadline, so doctor takes as long as its slowest tool.
- **Tests.** `tests/unit/test_doctor.py`, 59 cases on a `PATH` holding only the shim, a fake `git` and the scripts a case writes: each tool missing, found, hung, unable to start; xpdf's `pdftotext`; four biber and biblatex pairs; the bundle from each source; each quilt item in its states, with `loom upgrade` shown to clear what it is named for; the JSON schema inside and outside a quilt, clean and broken; the exit codes and summary with and without `--strict`; the columns. The three old tests in `test_cli.py` are gone, the one that leaned on `/usr/bin` among them. The shim answers `-bbox-layout` and skips `-f`/`-l` values.
- **CI.** `install-from-clone` asserts with `jq` that `ok` is false, `latexmk` is among `failing`, and the bundle is `vendored` and `ok` at `src/loom/version.py`'s interface; then starts `loom serve --no-compile` on a `loom init --demo` quilt in the background, polls for the manifest and the viewer, and stops it. `actionlint` is clean; the job has not run on GitHub.
