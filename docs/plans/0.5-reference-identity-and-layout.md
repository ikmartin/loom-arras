# 0.5: reference identity, the `reached` primitive, and the reference layout

## Context

WQ-01 is the one queue item whose trigger was already met, and the design discussion of 2026-09-16 settled how it should be built. The problem it solves is that loom has no durable name for a cited work: `_source_ident` resolves a citekey to `arXiv:…` or `doi:…` and writes it into the digest header, where nothing ever reads it again. Everything else keys on the citekey, which is local to one quilt and changes whenever the author re-exports their bibliography.

Two concrete faults in `demos/relloc` show what that costs. Its Manolache digest records `source: doi:10.1090/S1056-3911-2011-00606-1` — the published article — while its statements and locators were extracted from the arXiv source, so `\cite[Definition 2.1, p.~4]{…}` points a reader at page 4 of a document that begins on page 201. And every `\uses` in the quilt reads `\uses{manolacheVirtualPullbacks2012-constr-3.13}`, because the id prefix is mechanically derived from a Zotero key.

The slogan the discussion produced: **local identifiers are for authoring, global identifiers are for joining.** This plan makes that true.

WQ-01 graduates to this plan — its row leaves `docs/work-queue/README.md` and `closed.md` gains a line, the queue's lifecycle exercised for the first time.

## Scope

**In:** the reference layout and its migration; identity, including the declared prefix and the `extracted-from`/`published-as` split; the `reached` primitive; the manifest's artifacts block; `loom refs add`; a `refs/` route on the server; the bibliography parse-rate study.

**Out, deliberately:** the PDF viewer in arras, which becomes its own queue item now that 0.5 publishes what it needs. `works.toml`, proposed in discussion and then **cut** — it duplicated `refs.bib`, and the author's override mechanism is to add a `doi`/`eprint` field to their own bibliography, which loom may offer as a visible diff and must never write silently. The crawl, network resolvers, libraries and the byte cache stay deferred with the triggers they carry.

## 1. Layout

```
digests/                     authored, tracked, keyed by citekey
  Man12.tex
refs/                        fetched, ignored, keyed by global id, at any scale
  arxiv/0805.2065v2/
    src/                     the unpacked e-print, the .bbl included
    paper.pdf
  doi/10.1090_S1056-3911-2011-00606-1/
  work/ab12cd34/             synthetic id, for the unresolvable tail
```

One rule replaces three: **nothing under `refs/` is ever authored.** `SKIP_PREFIXES` in `scan/source.py` collapses from `("ai/", "refs/src/", "refs/pdf/")` to `("ai/", "refs/")`, and `assets/init/gitignore` loses two lines for one. The scheme directory keeps sanitization rules local and stops two schemes colliding on one string.

Keying `refs/` on the global id rather than the citekey is forced by the crawl: at depth ≥ 1 a work has no citekey at all, having been reached through an intermediate paper's bibliography. Nobody navigates there by hand — loom and arras surface it — so readability costs nothing.

The scanner does not change: a digest is recognised by its `% !LOOM digest:` directive within `HEAD_LINES` (`scan/nodes.py`), never by its path. The path literals are five: the default `--to` in `cli/digest.py`, the promotion target in `ai/promote.py`, the two destinations in `digest/fetch.py`, and `GITIGNORE_NOTE` in `cli/quilt.py`.

**Migration** extends `loom upgrade`, which already brings a quilt to the installed loom's shape and already writes `.new` beside an edited file rather than clobbering. It moves digests to `digests/`, re-files `refs/src/<citekey>/` and `refs/pdf/<citekey>.pdf` under the resolved global id, and rewrites headers per §2. Fixtures regenerate through `docs/specs/tools/refresh-fixture.sh` and `demos/refresh.sh`; `loom/tests/quilts/` and both vendored conformance snapshots follow.

## 2. Identity

The header gains two keys and loses one, because the artifact parsed and the work cited are different facts:

```
% !LOOM digest: manolache_VirtualPullbacks2012
% !LOOM prefix: Man12
% !LOOM extracted-from: arXiv:0805.2065v2
% !LOOM published-as: doi:10.1090/S1056-3911-2011-00606-1
```

`loom upgrade` copies an existing `source:` into `published-as:` when it is a DOI and `extracted-from:` when it is an eprint, then emits the new diagnostic saying the other is unknown. On `demos/relloc` that surfaces the real fault rather than migrating it silently.

**The declared prefix** has one load-bearing line: `scan/nodes.py` adds the declared prefix to `asm.citeslugs` instead of the derived slug, and that set is what `is_id_shaped` consults to choose between the `PAPERLOCAL` grammar (`prop-3.2`) and `LOOMLOCAL` (`0006`). Everything else is call sites that compute `citekey_slug(ck)` today and ask for the digest's prefix instead: `digest/extract.py`, `scan/postnote.py`, `render/manifest.py`, `scan/lint.py`. Changing a prefix is the operation `digest import --as` already performs in `digest/importer.py`, so nothing new is needed to support it. The guard in `scan/lint.py` against a citekey slug shadowing the quilt prefix matters more once a human picks the string, not less.

**Resolution** extends `_source_ident` to the order `doi` > `eprint`+`archiveprefix` > `mrnumber` > `zbl` > `url` (parsed for an arXiv id or DOI), keeps the `scheme:value` shape so later schemes are free, and is **read back** rather than write-only. `BibEntry` already keeps every field in a dict. The `local:<filename>` fallback becomes a deterministic `work:<hash>` over normalized author surnames, title and year; determinism across machines is the load-bearing property, because it is what lets two corpora merge later.

**Provenance** on every binding: `declared` (a field in the bib), `resolved` (a fuzzy match, deferred to WQ-04), `asserted` (the author said so). A wrong automatic match and a hand-checked one must stay distinguishable or the corpus can never be audited.

**Two diagnostics**, in `scan/diagnostics.py` and `scan/lint.py`:

- `loom:unresolved-work` (info) — a cited work with no identifier, with the fix inline: add `doi = {…}` or `eprint = {…}` to the entry.
- `loom:unverified-locators` (warning) — `extracted-from` is a preprint and `published-as` is published, so the digest's numbers and pages are unverified against the document a reader will open.

`report_counts` in `reshape/importer.py` already prints a `References:` line assembled from lint codes; the resolution count joins it there. Not `loom doctor`, which is environment-scoped and takes no quilt.

## 3. The `reached` primitive

The manifest already carries `keys[k].closure`, the full transitive closure per key, so **no publisher change is needed**. The reached set is the union of closures over the quilt's own non-external keys, intersected with external nodes, plus the closure within each digest of anything so reached — a statement whose standing assumptions are off-screen is not shown.

Spent three ways: the review page's row filter excludes external nodes nothing depends on (they already count as settled as dependencies, 7.6.3, so this removes noise without unblocking anything); the graph's `hideExternal` filter becomes a three-way default of reached-only with external nodes visually distinct; and a full digest folds what nothing reaches.

Together these make `loom digest extract --all` usable, which it has always been mechanically — the extraction loop walks every theorem environment with no filter — and unusable in practice, because 96 Manolache results arrive and three carry weight.

## 4. Publishing what exists

- **The manifest's `references[ck]`** gains the work's global ids and which artifacts are on disk. Additive, as `relations` was in 0.2, so **the interface version stays 1**. `slug` keeps its shape and changes its value when a prefix is declared — a value change, not a shape change, so the dialect validator and the vendored fixture comparison are unaffected.
- **`loom serve` gains a `refs/` route.** It serves the bundle at `/` and `build/` at `/build/` today; this is the first time it serves something not generated. Localhost-only makes it defensible, and it takes a decision record.
- **`loom refs add CITEKEY FILE`** files a manually obtained PDF under the resolved global id. Publisher PDFs sit behind subscriptions loom cannot and should not automate past, so the human supplies the bytes and names the citekey they know; loom does the global-id filing. Without this the verification the `extracted-from`/`published-as` split records is unreachable.

## 5. The parse-rate study

A script under `loom/scripts/`, not a command, because it is a one-off measurement: parse the `.bbl`/`.bib` of every source already unpacked under `refs/` and report what fraction is parseable and how many entries carry a usable identifier. No network, nothing consumes its output. Its number is WQ-02's trigger and the parser it leaves behind is what WQ-02 promotes — the cheapest work measuring the most expensive.

## 6. Queue bookkeeping

- **WQ-01 graduates** to this plan: row deleted, file deleted, one line in `closed.md`.
- **WQ-06 is rewritten.** There is no store: a store would be a second kind of place with its own keying rules, which is the library-quilt/project-quilt split in disguise. It becomes `[refs] cache = …`, a setting for where fetched bytes physically live, with `refs/` unchanged as the quilt concept at every scale.
- **WQ-12, the Emacs client, is dropped** — one line in `closed.md`; `eglot` needs only the server and a root function whenever someone wants it.
- **Two items added:** *arras displays PDFs and resolves reference links into them* (trigger: 0.5 has landed — a decision, not an observation, and the intended comment feature of linking to a place in a reference PDF depends on it), and *digest extraction shares the node model* (`scan_paper()` lifting the quilt requirement off the node model, plus caching the `.aux` beside fetched sources, the only optimisation that matters at corpus scale since LaTeX compiles dominate by two orders of magnitude).
- **WQ-02 and WQ-03 gain a note**, not a trigger change: the crawl's payoff is far larger once libraries exist, so if both fire, do WQ-03 first. The crawl automates discovery and fetching, never digesting; a library is a large corpus quilt with a complete citation graph and selective digests.

## 7. Records

A decision record for the layout and identity model, one for the server route, rows in `docs/deviations.md`, chapters 4 and 8 edited to the new layout and header, `docs/specs/manifest.md` for the additive fields, this plan committed before execution, and an entry in `docs/records/`.

## 8. Verification

`uv run pytest` across all three tiers; `ruff`, `mypy`, `gen_cli_reference.py --check`; `npm run check`, unit and e2e in arras; `python docs/work-queue/check.py` with the queue at 20 of 20 and two closures recorded.

New tests: the synthetic id is deterministic for the same work normalized independently (what makes corpora mergeable, and exactly what an optimisation of the hash would silently break); the digest header round-trips through write and read; `reached` is stable under adding an unreached digest node, so adding 93 Manolache nodes changes the review queue by nothing; a declared prefix is accepted by `is_id_shaped` where the derived slug would not be; `upgrade` migrates a fixture quilt and rewrites its header.

End to end on `demos/relloc`: `loom upgrade` migrates it, `loom:unverified-locators` fires on the Manolache digest naming the arXiv/published discrepancy, `loom lint` reports the resolution count, and the review queue drops from every digest node to the three the quilt actually uses. By eye: serve it, and confirm a reference's artifacts appear in the manifest and the `refs/` route returns the PDF.

## Outcome

Executed 2026-09-16, as written, with four findings the plan did not anticipate and one cut made during the design discussion that preceded it.

**`works.toml` was cut before any code was written.** It duplicated `refs.bib`: the identity of a depth-1 work is already in its bibliography entry, and the author's way to correct loom is to add a `doi` or `eprint` field to their own file rather than maintain a parallel one. The two cases that genuinely need storage — a resolver's answer with its confidence, and a crawled work with no citekey — belong to WQ-04 and WQ-02.

**An arXiv DOI is not a publication.** arXiv mints DOIs under `10.48550`, so `doi:10.48550/arXiv.2207.01652` and `arXiv:2207.01652` name one artifact. Found by migrating the real `demos/relloc`, where two works file under `arxiv/` only because the normalisation was added; without it one artifact takes two directory names depending on which bibliography field happened to carry it, and a preprint counts as published, which would have made `loom:unverified-locators` say the opposite of the truth.

**A migration cannot infer what it was not told.** Where a digest's old `source:` named a published work, writing it as `extracted-from:` would assert something false — statements are not extracted from a DOI. The migration records only `published-as:` and leaves the artifact blank, and the diagnostic then asks for it. On `demos/relloc` that surfaces the real fault rather than migrating it silently, which is what the end-to-end check in §8 was for.

**The parse-rate study measured the wrong half, and said so.** Its trigger for WQ-02 was a parse rate above 70%. Run on the two fetched works in `demos/relloc` it reports **100% of bibliographies parseable and 9% of 103 entries carrying a usable identifier** — because a formatted `\bibitem` is display text and mathematics styles rarely print a DOI. It also found that **neither paper ships a `.bbl` or a `.bib`**: both inline `\begin{thebibliography}` into a `.tex` file, so the unit a crawler must handle is `\bibitem` wherever it occurs, not a file extension. Both findings are now in WQ-02, whose trigger becomes "WQ-04 has landed": resolution is the crawl's precondition, not a later refinement, because you cannot follow a citation you cannot identify. This is the queue working as designed — the cheapest piece of work measured the most expensive one and reordered it, before anything was built on the wrong assumption.

Two smaller departures. `loom refs path` was added alongside the planned `loom refs add`, because the shipped agent prompts had to tell an agent where a work's PDF is and no longer could name a path it could compute. And the resolution count went into `report_counts`'s `References:` line rather than `loom doctor`, which is environment-scoped and takes no quilt.

The queue is 19 active of 20, not the 20 the plan's §8 predicted: two items left (WQ-01 graduated here, WQ-12 dropped) and two arrived (WQ-21, WQ-22), so the arithmetic was mine, not the queue's.

**Not done, and visible:** `loom status` on the migrated `demos/relloc` lists 241 nodes, almost all of them external results of three digested papers. The `reached` primitive fixes this in the viewer — review queue, graph and digest page — but the CLI has no equivalent filter, so `status` is still dominated by other people's theorems. That is beyond what this plan scoped and is worth a queue item if it grates.
