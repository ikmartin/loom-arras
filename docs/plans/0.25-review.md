# 0.25 — Review that acts

## Context

The author found Review broken in parts on 2026-11-03: Incoming's "Use all proposed edits" and "Use proposed version" appear to do nothing, the second sits beneath the change and moves, a document's history can't be paged through or gone back to, and Problems is full of errors the author can't fix. The study (`docs/reports/review-panel-study.md`, same day) drove every section on scratch copies of relloc and the synthetic quilt and found 66 failures. Five causes account for most of them:

1. **A choice is not an act**, and the page doesn't say so (Incoming).
2. **The answer lands far from the press**: refusals at the top of long pages, controls that move.
3. **The person is shown what only loom or an agent can fix**: none of relloc's 174 errors is in the author's files.
4. **History is a ledger of explicit stamps**: two rows for a month of work, and no way back.
5. **The viewer mostly reads**: no accept, apply, dismiss, restore or fix.

**The author's decisions (2026-11-03, from four mockups):**
- **Incoming is one pass.** Each change is taken or left in a bar that never moves, with "accept as checked" beside it; one Apply at the top does it. The separate preview stage goes.
- **A version at every act.** The import, each Keep and Undo in Changes, each change taken in from a copy or a pull, and any version the author records by hand. Each is an explicit act, never a save, so P13 holds. Any version can be paged back to, compared both sides in step, and restored.
- **Needs review holds every unaccepted block**, grouped as changed since accepted, taken in, and never reviewed, with Accept in each row and for a selection.
- **Problems shows the author's own first, and counts only those.** The agent copy's problems and loom's own are folded beneath, each said to be theirs to fix, and loom's bugs behind them are fixed at the source.

**What stays:**
- Only the author accepts, takes changes in, restores or applies (P15, K5); an agent is refused every one.
- Loom writes the author's file only on the author's act, and keeps the old text first (P7).
- The viewer names no loom command (forbidden-words test); a command the person must run reaches it as data.

## How this plan is carried out

One master document, this one, beside the study it answers (`docs/reports/review-panel-study.md`); the finding ids (FR1, IN7, …) are the study's. Each phase starts in plan mode: the code is explored, the concrete changes are proposed, and the author approves them. When a phase is built and `scripts/verify full` passes, what was built is appended to the **Implementation** section. Arras is re-vendored into loom with each phase; a phase that changes the manifest regenerates the fixtures (`docs/specs/tools/refresh-fixture.sh`).

## Phases

### 0.25.1 · One kit for Review, and Changes fixed

The shared pieces every later phase uses, proven on the smallest section.

- **A kit in `lib/review/`:**
  - a pinned action bar that stays in reach while its content scrolls (patterned on the pane toolbar, `ItemToolbar.svelte`);
  - an answer line drawn in the bar, beside the control that was pressed, in place of alerts at the top of the page;
  - buttons in one style, the Settings `.btn` moved into the theme;
  - one empty state.

  Changes, Sessions, History, Suggestions and Problems move onto the kit (FR4); Needs review and Incoming keep `review.css`, whose buttons are now the kit's, until their phases rebuild them.
- **Headers:** a quilt-wide page drops the default document's title (FR5, `ReviewHeading`).
- **Counts mean "this waits for you"** (FR1, `sections.ts`):
  - Sessions shows no count;
  - Library's count is its page's "needs you";
  - Problems and Suggestions follow their phases (0.25.3, 0.25.6).
- **Opening an item opens it where it lives.** A block, a suggestion and a problem open in their document at their place (V7), through `readUrl` and `DocumentItem`'s existing `?review=`, not as a result alone in a tab (FR3).
- **Changes:**
  - Keep and Undo stay busy until the page has redrawn, and answer in the bar (CH1).
  - Keeping one file leaves the time of the person's look alone (CH2, `looks.keep`).
  - Undo asks first, as K5 requires, and afterwards says where its text went (CH5).
  - A new file can be undone, which removes it once its text is kept (CH6).
  - The file name opens the file (CH7).
  - Keep and Undo per change as well as per file (CH3): a change is one of the diff's `@@` groups, numbered from 0, and each act names the file's hash as the page drew it, so a file that moved since is refused rather than acted on blind.

### 0.25.2 · Incoming in one pass

- **The fixed bar** (decision 1):
  - ‹ n of N ›, Take it, Leave it and "accept as checked" in a bar above the change, which never moves (IN3, IN10);
  - the contribution's bar on top: "12 taken · 3 left · 87 to go" and one **Apply n changes** (IN1, IN2, IN4).
- **Apply is one act.** It previews and finishes in one press (`adopt-preview`, then `adopt-finish` with the accepted keys), and answers in the bar, refusal included (IN5).
  - The two-stage preview workspace goes (IN14).
  - Two states, taken or left, plus undecided (IN15).
- **"Take all" takes what the changes need**: the preamble when it changed and doesn't conflict, and the prose (IN6; `AdoptionContribution.svelte:70` passes the saved preamble choice today).
- **Names, not keys:** a change is listed by its result's name, grouped by section, with a filter (IN16). The intro is said in plain words (IN17).
- **Loom: no refusal over what the person did not choose.** Each is a rule drawn too wide:
  - **References to another document's results** (IN7): loom has no notion of `\externaldocument`, so all 211 of the copy's references to `draft5.tex` are "loose" (`scan/lint.py:262-284`, which `adopt.prepare` re-runs at `adopt.py:556-569`). A master whose stem the source's preamble names in `\externaldocument{…}` counts as reaching the target. This also clears the copy's 70 `loom:reference-to-loose` errors.
  - **A duplicate id the document doesn't reach** (IN9): `plan_document_stamp` (`history/steps.py:174-178`) and its copy in `sync.py:741-746` refuse any conflicted key the document touches. They should refuse only when the document's own flat text holds two definitions; `plan_freeze` already skips conflicted keys.
  - **A macro the paper already has** (IN6): the preamble check (`adopt.py:522-536`) reads preamble text alone, so the copy's `\renewcommand{\incomplete}` looks new. It subtracts the source's closure macros, which include its `.sty` files, and ignores redefinitions.

  Each refusal that remains is a list in the bar, one line each, said in the viewer's words.
- **Conflicts merge per result** (IN8; the author's decision): a result both sides changed is merged line by line with `adopt._merge`, offered as merged when the edits fall apart, and shown but never offered when they clash, with Refresh the copy in its place.
- **Pulls** get the same bar, names and "accept as checked", but are still taken whole: loom applies a pull as one patch, and taking part of one is WQ-63.
- **Fixes:**
  - The comparison that never finishes (IN11) is `Fragment.svelte` resetting `mathReady` on every manifest hash, while `place()` returns early on identical markup. The reset moves into `draw()`.
  - A change only in its `% !LOOM` lines counts as a change to the mathematics (IN13, `adopt.py:66-73,238` against `own_text`); `math_changed` ignores those lines.
  - The preview's counts are worded as "changes taken" against "blocks to review" (IN12).

### 0.25.3 · Problems that are yours

- **Loom: each diagnostic says whose it is.** `Owners` moves from the CLI to `scan/owners.py` and gains the agent copy. Each diagnostic carries `owner`: the person's, an agent copy's (`.loom/copies/`), or a cited work's (`.loom/digests/`). It is stamped once over the manifest's whole list in `render/build.py`, and in `loom lint --json`. A digest's problem is the work's even where the person's text reaches it. Records' diagnostics keep their locations, keys and fixes in the build's report.
- **Loom: fix the scanner and the digest writer**, behind 103 of relloc's 104 digest errors:
  - a section that starts inside an environment (a `\part` set in the `-setup` theorem) ends with it, and a parent's own text skips each child's whole subtree (`scan/nodes.py` `_partition`; 84 duplicate ids and 15 duplicate labels, all in one digest);
  - `_conventions` stops at `\part` and drops a paragraph whose braces do not balance;
  - section labels follow `\setcounter{section|subsection}`, and a section label is written once (4 errors);
  - a label holding braces (`…-Def: Q_{tau tau'}^vee`) is read whole and written plain (the dangling link).

  The duplicate-id fix "give one copy a fresh id by hand" is attached only to the person's files.
- **Loom: fixes a viewer can do.** A `Fix` may carry `act: {endpoint, body}`: `loom:undigested-citekey` → `library-update`, `loom:agent-permissions-stale` → `agents-update`, and a digest's problem → "digest it again" (`library-update`, `redo`, `steps: ["extract"]`), where that can mend it. `library-update` takes `steps`.
- **The viewer** (decision 4):
  - four parts by owner: the person's first, open and counted; an agent copy's, the cited works' (by work, with Digest it again) and the remarks folded beneath, each said to be whose it is (PR1, PR6);
  - each problem titled in words, `duplicate-id` and `loom:duplicate-label` one group (PR4);
  - each with Open at its place, and its location a link to the file at its line;
  - filters in the page (PR5);
  - a fix with an `act` is a button whose answer is said beside it; any other stays a command to copy (PR2);
  - the help dot names no command (PR7), and a doubly defined id says "Defined twice" (PR3).
- **The section's count is the person's errors and warnings.**

### 0.25.4 · Needs review that accepts

- **Loom: the queue holds every unaccepted block** (decision 3). Today `review_queue.rows_for` (`review_queue.py:79-83`) lists only keys taken in, keys already decided, and keys whose acceptance went stale; a never-accepted block has no acceptance and can't enter, so `review-decision` refuses it (`not-unresolved`). It gains the never-accepted statements and proofs, grouped as changed since accepted, taken in, and never reviewed (NR1).
- **Accept in the row and for a selection** (NR2). Acceptance already works from the viewer for queue rows: `review-decision` marks one OK, and `review-finish` runs `write_acceptance`, refusing the blocks loom can't accept. Accept becomes one press that does both, for one block or a selection.
  - A block loom cannot accept (no proof, cited, incomplete, unclassified) says why in its row.
  - The help dot is rewritten.
- **Read** opens the block in its document at its place, with the cause beside it (`?review=`, FR3).
- **The Documents table loses** the empty Reason column and its per-row Details (NR3); a document with no blocks isn't offered (NR5).

### 0.25.5 · History you can page and restore

- **Loom: a version at every act** (decision 2):
  - `keep` appends a ledger line naming the path and the text it took. Today it stores the text under `texts/` but records neither path nor time, so earlier keeps are lost to the timeline (`looks.py:142-158`). `undo` already appends one (`looks.py:182`).
  - Taking changes in already stamps the document first (`kept_for: "adopt"` or `"sync"`).
  - `page-write`'s per-path lines (`pages.writes()`) are the pattern to follow.
- **Loom: two endpoints.**
  - **Record this version** of a document: `stamp_document`, author-only.
  - **Restore a version**: writes it back into the document on the author's act, first keeping the current text as a version, so a restore can itself be undone.

  P7's consequence list ("`history restore --to FILE`") gains this, and the book is corrected in the same change.
- **Loom: the manifest publishes each document's timeline**: every version, from every act, with when, who and what. Comparing two versions renders them through the existing `compare` endpoint.
- **The viewer:**
  - a timeline per document in its `history ▾` and in Review › History: step older and newer, compare against now with both sides in step (HI6), and Restore;
  - Review › History lists every act, not steps alone (HI2).
- **Landmarks render as the live document does** (HI4). Today a landmark takes its numbers and citation labels from its own `.aux` (`render/canon.py:161-162`), which is empty when it was never compiled, so citations fall back to their keys; it falls back to the live document's instead.
- **Compare** counts and steps by source pairs (`compare.ts:130-240`). A result the old version lacks has only a wedge, at the head of the fragment when nothing earlier is shared, so the old side never moves (HI6). The wedge stands beside the nearest pair the two versions share, and the count leaves out pairs a landmark never versioned (HI5).
- **WQ-25 (the history view) closes into this phase.**

### 0.25.6 · Suggestions and Sessions

- **Suggestions act in the row:**
  - **Apply** one with proposed text. A new endpoint writes `records.suggestions.taken_file` into the source on the author's act, keeping the old text first (P7), and resolves it as applied. `write-api.md`'s "Nothing in the write API applies a suggestion" is corrected.
  - **Resolve** and **Dismiss**, through `resolve` and `discard` (SU1).
- **Suggestions are honest about what they are:**
  - each row names its document, the agent's copy said as such (SU4);
  - a prose suggestion is "to consider", not "to apply", and not counted (SU2, SU3);
  - doubled reference names (SU5) and raw LaTeX in quotes (SU6) are fixed.
- **Sessions:**
  - opening a session to read it no longer changes where writes go, and the footer says which it is writing in (SE1); `ChatView`'s rule, that the footer and the transcript never name two sessions, is replaced;
  - "What it did" groups repeated commands and links what each changed (SE2);
  - a blank transcript says so (SE3), and the table's columns are named for what they hold (SE4).
