## A1. Tokens, typography, preferences

Both get a decision record.

Preferences (15.7) are typeface, size, line width, and theme, held on the existing `ui.svelte.ts` singleton, written to `localStorage` inside try/catch, applied as `data-*` attributes on `<html>` by one `$effect` in `+layout.svelte`. `app.html` gains a small blocking script so a stored theme does not flash, since `ssr` and `prerender` are both off. Add `color-scheme` so native controls follow.

## A2. The shell

One component tree, three arrangements, per 15.8:

```
NavShell({ views, currentView, masters, currentMaster, contents, counts, search })
  renders RailSections | TopBarTabs | IconStrip
  renders <slot> and <slot name="rail">
```

Default C. Chosen by `?shell=` or the stored preference. Pages import no shell module and render no navigation; a page needing a right rail fills the named slot. Every rail is a scroll container — `max-height: calc(100vh - <offset>)`, `overflow-y: auto`, `overscroll-behavior: contain` — which is the **contents-scrolling fix**; it must be part of the shell, not one page's stylesheet, so no view can regress. Accessibility per 15.10: the icon strip is a `nav` with a list and `aria-label` per icon, the contents tree carries `aria-current`, focus order runs shell, page, right rail.

## A3. The contents tree

Build it from **`manifest.inclusion`**, the ordered tree the publisher already writes and the viewer reads nowhere. That gives true document order and true depth, replacing both the sort by `numbers[master] ?? id` (which is why `…#paragraph:1` sorts above `man-0001`) and the binary `? 1 : 0` indent. Filter to sectioning levels 1–3 so `\paragraph` units leave the rail. Link with `nav.ts::nodeUrl`, never string concatenation, so a key containing `#` or `/` resolves.

## A4. Read view, node page, home, tables

The right rail appears only when a node on screen carries non-discarded comments.
- **Node page** (15.3.2): header of title, number, id chip, state badge, tags; body of statement then each proof as its own block with its own state line; right rail in the chapter's order — in `<master>`, depends on, used by, **see also**, comments, detached comments, diagnostics. "Dependents" becomes **used by**, and the ancestry list becomes the "in `<master>`" breadcrumb, which resolves the earlier Context/Backlinks question in the chapter's vocabulary.
- **Home** (15.3.4): four metric cards then needs-attention, blockers, and views. It becomes the landing route.
- **Tables** (15.3.5): review, problems, blockers, threads, indexes as table pages with filters in the rail, a row expanding in place to show the stale cause and its diff as a two-column tinted diff. The review panel gets the explanatory sentence and the `?` panel defining each state and naming the command behind it.

## A5. Anchors and links that resolve

Add a real `id` in `loom/src/loom/render/fragments.py`, slugged as display equations already are (`convert.py::slug`), and in arras: scroll to `location.hash` after the fragment mounts, and wire `section[data-id]` in `mount.ts` so the heading links to its node page on hover, the Stacks-project affordance. Fix `mount.ts:22`, which builds an equation hash as `#eq-fix` where the DOM id is `#sy-0001-eq-fix`, so equation references have never resolved. Add `nav.ts::keyUrl(manifest, key)` resolving a key with no node entry through `manifest.keys[k].node` to its owner, so an unlabelled proof key links to its statement rather than to "Unknown key" — your instruction that a node with no id should not get a link of its own. Style `figure[data-error]` as a fault so a failed block reads as a problem, not as the paper's text.

# Part C — `loom-lsp`

A local git repository at `loom-arras/loom-lsp/`, a Python package `loom-lsp` depending on `loomtex` and `pygls`, entry point `loom-lsp` speaking LSP over stdio. It is a *client* of loom, so P8 holds: no loom command requires it.

## C1. Preparing loom

Small, separately useful changes in the loom repository first:

- **Memoise `kpsewhich`** (`scan/expand.py:82`). One `lru_cache`. It is 86 ms of the 166 ms `man12` scan — over half — because it is a subprocess run once per unresolved inclusion.
- **Thread offsets through** where they are computed and discarded: `labels_in` already returns `(label, offset)` but `nodes.py:152` and `nodes.py:307` drop it with `_`, and `edges.py` has `m.start()` in hand but passes only a line to `_resolve`. Carrying them gives token-precise ranges for ids, labels and `\ref` sites.
- **Populate `Location.column`**, declared in `model.py:57`, serialized when present, and never set. `SourceFile.col_of` is written, correct and called from nowhere; every call site has the offset. This turns line-granular diagnostics into precise ranges.
- **Let `scan()` take an overlay** of `{path: text}` for buffers the editor has not saved. Today it re-reads every file from disk and cannot see an unsaved buffer. The stages it calls are already pure functions over `dict[str, SourceFile]`.

Each is small and improves loom alone; each gets a test.

## C2. The server

Reuse rather than reimplement: `scan(quilt)` for everything, `Assembly.labels` as the definition table, `cli/_quilt.py::resolve_key` for key resolution, `cli/nodes.py::search_entries` for symbols, `cli/lint_cmd.py::all_diagnostics` for diagnostics (it merges record-derived codes on top of `result.lint`), and `records/store.py::Records.key_states` for states.

- **Lifecycle**: find the quilt by walking up to `config.toml`; refuse politely outside one. Debounce 250 ms, rescan fully, publish diagnostics; answer hovers, definitions and references synchronously from the last good `ScanResult`. Measured full scans are 100–170 ms on real papers and drop further once `kpsewhich` is cached, so this is comfortable; per-keystroke scanning is not, and is not attempted.
- **Diagnostics**: `all_diagnostics` mapped to ranges, severity from the code table, `code` and a `codeDescription` pointing at `docs/specs/diagnostics.md`.
- **Definition**: `\ref`, `\eqref`, `\cref`, `\uses`, `\cite`, `\input`, `\nest` — labels and ids through `Assembly.labels`, citekeys to the digest file, inclusions to the file.
- **References**: every `\ref`/`\uses` site plus the ledger and annotation targets, the answer `unravel --json` already computes.
- **Hover**: taxon, title, number in the default master, state and staleness cause, open comment counts, and the first lines of the statement.
- **Document symbols**: the file's nodes as a tree, sections containing environments containing proofs.
- **Completion**: ids and aliases with titles, citekeys from the bibliography, taxa from the preamble closure, `% !LOOM` directive keys, and digest node ids after `\cite[`.
- **Code actions** (your choice): insert a `loom new` skeleton, add a `\uses` entry the proof references but does not list (`loom:uses-missing` already finds these), atomize the node under the cursor, accept the key, open the node in arras. Each shells out to `loom` and each confirms first, since these write to the quilt.

**Encoding**: loom's offsets are code-point indices into CRLF-normalised text; LSP defaults to UTF-16. The server negotiates `positionEncoding` and converts, with a test over a file containing an astral character and a CRLF file.

## Testing Part C
