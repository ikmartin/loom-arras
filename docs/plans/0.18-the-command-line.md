# 0.18 — the command line

## Context

The CLI study of 2026-10-02 (`docs/reports/cli-study.md`, 788 transcripts) measured every loom command against the terminal principles (book 1.10). Its findings:
- **Output.** It fails the principles nearly everywhere except the refusals. Verdicts come last. Lines reach 322–1,397 columns. Output is full of storage paths and hashes. No command reports progress, and there were silences of up to 955 s.
- **Defects.** Twelve defects lose data or report a failure as success, among them `sync init`'s defaults publishing over the quilt's own branch, `refs build --force` deleting verified results, and `refs scan` appending a duplicate entry on every run.
- **Speed.** One function, `records/dependencies.py:display_span`, causes most of the slowness: it re-tokenises a whole file once per key.
- **Shape.** The command surface grew by accretion: 96 names for 91 commands, `refs` with 27 subcommands, and flags whose meaning changes from command to command.

An agent's audit of the same day, `docs/issue-reports/refs-audit-critique-from-agent-2026-10-02.md`, adds four things for the cited-works layer:
- result states that tell an extraction from an author's check;
- one work holding several documents;
- ranked search;
- digest diagnostics kept out of the author's lint.

It also finds one more bug: a sibling entry without an identifier loses its PDF.

The author decided on 2026-10-02:
- an umbrella with sequential sub-plans;
- the principle revisions written into Chapter 1 first, so every sub-plan is measured against them;
- the library redesign takes the CLI of the study's part six plus the critique's core, while lazy digests get a study and a later plan;
- the group is named `library`, the viewer's word.

The outcome: a command line where the defects are fixed, everyday commands answer in seconds on a real quilt, every report reads by T1–T8, the commands obey K1–K7, and the cited works are reached through one `library` group, about ten commands a person needs plus the agent's tools and upkeep, instead of 29.

## 0.18.1 · Defects that lose data or report a failure as success

The study's part two and the critique's bug, each fixed with a test that reproduces it first:

1. **`sync init`.**
   - `--remote` and `--branch` become required, with no defaults.
   - It refuses a remote that is the quilt's own upstream (`cli/sync.py:47-48`).
2. **`sync incorporated`** is removed. `sync finish` is the checked path.
3. **`refs build --force`** re-extracts and keeps every node the author verified. It merges them back from `results.json`, and reports any that the new extraction contradicts (`refs/build.py:395-420`).
4. **`refs scan` becomes idempotent**:
   - a stored document already offered an entry is not offered another;
   - refused and `--json` builds write nothing;
   - existing duplicate entries are reported once, with the command that silences them.
   - For the author's own quilt (`~/Desktop/relloc`), the one-off cleanup is given to the author as commands; loom never touches it unasked.
5. **`revert`** only prints. It never records (book 17.11).
6. **`inline`** is removed. `linearize` writes a flat copy, and `source DOC` prints one.
7. **`ai discard --before`** validates its date.
8. **Agent guards follow the act** (K5), through one guard. An author-only act refuses under an agent marker whatever `--author` or `--as` names. That covers:
   - `accept` and `refs verify`, so the `--author` bypass closes;
   - `session delete --purge`, `refs drop`, `refs unlink`, `refs cite`, `ai discard` and `sync publish --push`.

   Book 11.8 is amended.
9. **`refs add`** checks identity: the PDF's first page must carry the entry's title. Otherwise it is refused with the reason, and `--force` overrides. A filed PDF is mapped at once.
10. **Honest verdicts.**
    - `ai refresh` reports a conflict as a conflict, exiting 1 and naming the reconciliation.
    - `adopt` says when only document-level changes remain, and names `--document-changes`.
11. **Conflicts are visible.** `status` shows conflicted ids as conflicted, with their files. `live` warns when it creates a conflict.
12. **`refs overview FRAGMENT`** refuses an ambiguous fragment by listing the matches.
13. **The sibling bug.** A sibling entry without an identifier keeps its `loom-file`, so its PDF is found (`refs/scan.py` near `_free_key`). `library check` in 0.18.5 also covers it.

Tests: one unit test per defect, in the module's existing test file.

## 0.18.2 · Speed

1. **`display_span`.**
   - Take the comment-blanked text from `SourceFile.clean`.
   - Build `env_tree` once per file, not once per region.
   - Cache it on the `Dependencies` object, as `records/store.py`'s `_resolved_cache` holds its own for one `ScanResult`.
   - The code is `records/dependencies.py:20`, :42 and :61, and `scan/tokenize.py:172`.
2. **Commands that need no scan don't run one.** `refs path`, `refs page` and `link` read a single file. `open_scan` costs 1.3–5 s per call.
3. **The build cache key.** Rendering stops re-running everything after any change to loom's code in a checkout: the key covers the render modules' code, not the whole package (`render/build.py:204` `_code_hash`).
4. **Measured before and after**, on a copy of the author's quilt: `status`, `lint`, `accept KEY`, `ai orient`, `review`/`build` (cached), `deps`, `serve` start. The targets are:
   - under 3 s for `status`, `lint`, `deps`, `ai orient` and `accept`;
   - under 10 s for a cached `build`.

   The results are written into the sub-plan's Delivery.

## 0.18.3 · One output layer

1. **`loom/cli/report.py`**, the layer every command reports through:
   - `Report`: a verdict line, groups and notes.
   - `Group`: a heading, a count, sorted items, a limit with `… and N more`, and the next command that clears it.
   - **Rendering:**
     - the verdict comes first;
     - lines stay within 100 columns, with an identifier never truncated: it goes last on its line, or the line wraps;
     - text goes to stdout, notes to stderr;
     - `--json` comes from the same `Report`, so the two cannot drift (T8).
   - `Progress`, on stderr only:
     - stage, item, `n/total`, and elapsed time;
     - "still working" after 15 s on one item;
     - a self-rewriting line on a terminal, one plain line per item otherwise.
2. **One error style.** Every refusal is an `EnvError` or `ContentError`; the four hand-written `ERROR:` lines in `cli/paper.py` (:74, :281, :297, :380) go. The `emit_json` from `_common.py` replaces the 20 raw `json.dumps` calls.
3. **One diagnostics formatter**, from `cli/lint_cmd.py:29` `format_diagnostic`, used by `lint`, `build`, `check`, `digest` and `history verify`:
   - always with locations, and with `fix:` lines;
   - grouped by code, with a count per code;
   - the author's diagnostics before those in cited works, which are summarised under a heading of their own.
4. **Every reporting command moves to the layer**, module by module:
   - `refs`, `status`/`lint`/`build`/`check`, `doctor` (`doctor.py`'s `Report` folds in), `init`/`import`, `history`, `session`/`ai`, `sync`;
   - `ScanReport` (`refs/scan.py:55`) and `BuildReport` (`refs/build.py:93`) produce `Report`s.
5. **Progress** for `build`, `check`, `compile`, `serve`'s first build, `refs build` (per stage and per work), `refs map`, and `accept --stale`.
6. **`--json` on every command that reports.** `tests/unit/test_json_output.py`'s table grows to match, and stdout stays pure on failure (`refs propose`).
7. **`scripts/checks/output.py`, run by `scripts/verify`.** It runs every command on the demo quilt, in its normal and refusal cases, from a case table, and checks:
   - the verdict line comes first;
   - no line over 100 columns, outside an allow-list of commands that print the author's own text (`source`, `refs page`, patches);
   - no `digests/storage/` path, and no 12-plus hex hash;
   - exit codes follow 12.1's rule;
   - `--json` is valid and pure;
   - `Progress` behaves under a fake slow step.

## 0.18.5 · The library

The study's part six together with the critique's core. `loom library` replaces the 27 `refs` and 2 `digest` commands with these:

| command | what it does |
|---|---|
| bare `library` | state and queues, verdict first |
| `library update` | gather, resolve, fetch, extract and map, with progress; `--online`, `--only STEP`, and `--redo`, which keeps verified results |
| `library add` | file and ingest, with an identity check, then map |
| `library review` | the queue of pending proposals and citation suggestions, with their ids |
| `library verify` | author-only |
| `library discard --why` | author-only |
| `library ignore` | replaces `unreadable` and `forget` |
| `library read WORK [PAGES]` | pages, overview, and `--where` for the location |
| `library search` | ranked, case-insensitive, full ids and snippets; `--pages` for page text |
| `library why` | where a result came from and its state |
| `library propose`, `library locate` | the agent's tools |
| `library relate` | `--list` and `--remove` |
| `library check` | anchors, wrong PDFs, empty digests, section maps, duplicate versions |
| `library import`, `library drop` | upkeep |

Beyond the commands:

1. **Honest states.** A mechanical result is `extracted`. It is `checked` once its numbering is confirmed against the cited version, and `verified` only by the author. Results from a preprint carry that fact. The states touch `refs/proposals.py` `record_extracted`, the manifest's result state, and arras's Library view, which shows the new words.
2. **One work, several documents.** The decision in 8.16 stands: a second document is filed beside the first, never over it. But the command line, the manifest and the viewer present them as versions of one work.
   - `library add` and `update` deduplicate by identifier and title.
   - A citation is matched against the version the bibliography cites.
   - A fragment names the work.
   - Search reports a hit once, with its versions.
3. **The author's lint is the author's.** Diagnostics inside machine-made digests are counted under a "cited works" heading, in `lint` and in `library`, and never mixed into the author's errors. A cited result that is affected still surfaces.
4. **One name per work.** Every command takes the citekey or a fragment of it, and the result-id prefix resolves to its citekey.
5. **Lazy digests** are not built here. A study goes into `docs/reports/`, and a work-queue item WQ-56 with its trigger.
6. **Everything that names `refs` or `digest` follows:**
   - book Chapter 8, rewritten for the commands and for the store's real paths, fixing the critique's §11;
   - book 11.8 and 12;
   - `ai/rules.md`, the orientation and the ingest mode, with their demo copies and appendices C and D;
   - arras's write-API names;
   - the fixtures, the demos, and the tests.

   WQ-41 (ranked find) closes into this sub-plan. WQ-55 (digest review in the viewer) gets its queue from `library review`.
