# 0.22 — The open quilt: a quilt the person lays out

## Context

A quilt today is a directory loom lays out: `loom init` puts twelve visible entries and six hidden ones at its root before the person writes anything, documents may live only in `drafting/` and `drafting-ai/`, and every document compiles from the quilt root. The author began learning quantitative finance in `~/quilts/quant` on 2026-10-30 and asked, in `docs/long-prompts/ideas.md`, for a quilt that comes nearly empty and holds whatever the person works with, with loom a layer over it rather than its shape. The design is [`docs/reports/open-quilt-study.md`](../reports/open-quilt-study.md), cited here as "the study". It was revised from a read-only map of the code, whose findings ("What the code says") this plan relies on for every file it names. Principles are cited by name from `docs/design/principles.md`.

The author decided on 2026-10-30:

- **Loom hosts the project; it does not shape it.** How a project is designed and carried out, a course among them, belongs to the person and their agent. Loom does not enforce it.
- **A quilt comes nearly empty:** one config file, loom's hidden directory `.loom/`, and a README that teaches loom and is safe to delete. `drafting/` is deleted, and the person makes their own directories, which loom shows.
- **A document compiles from its own directory,** as LaTeX and Overleaf do.
- **A document is named by its path,** kept as a path: `paper/main.tex` is `paper/main`.
- **Docs is the project's tree,** collapsible like VS Code's explorer.
- **The viewer displays more than LaTeX and PDFs:** Markdown and HTML at least, with embedded content (a video, say) coming with HTML. Links can open another application ("open Anki"); an agent reaches Anki through its own access, and loom need not know Anki exists.
- **Agents may write anywhere a deny list allows,** gitignore-style, in the config. A fresh quilt's list protects only loom's records.
- **Review is the meta view** (changes and edits in one place, kept or thrown away); Docs is the working view.
- **Annotations serve two purposes,** discussing a passage with the agent, which every person wants, and review on a draft, which is mostly the Author's.
- **Overleaf is a matter of backing off, not new features.** For now sync stays and works in a directory the person names, with loom running git there as it does in its own clone today.
- **Undoing an agent's edit to an open file** (where Review gets the old text) is left open.
- **A way for outside tools to link in** is not built until someone wants it.

What this plan is not: loom learns nothing about courses, runs no code, and calls no model (P9). Mathematics is LaTeX (P1), and the trust machinery (acceptance, staleness, verification, K5) is unchanged.

## How this plan is carried out

One master document, as 0.20 and 0.21 are. The phases are the study's, numbered from 0.22.1 (the study's phase 0) to 0.22.8 (its phase 7). Each phase starts in plan mode: the code is explored, the concrete changes are proposed and the author approves them. When a phase is built and `scripts/verify full` passes, what was built is appended to **Implementation** at the bottom, with anything that departed from the phase as written.

- **The fixture is the contract** (C3). A phase that changes loom's output regenerates the fixture quilts and the spec fixture.
- **Arras changes are re-vendored into loom** after their commit.
- **Each phase brings the design and the specs up to date** with what it built, so they never describe something that does not exist yet.
- **No migration is written** for old quilts. The author's two quilts are re-laid with existing commands when a phase needs it ("Behaviour that must survive").
- **Nothing is committed until the author says so.**

## Before 0.22.7: the write-API fix

A page served in the viewer's origin can act as the author today. `GET /_api` hands out the write token, and `/build/*` and `/digests/storage/*` are served from the viewer's origin with a type guessed from the extension (the study, "Found along the way"). The fix is its own session, "Close the write-API path past K5". It lands before 0.22.7, which shows HTML, and 0.22.7's plan starts by confirming it has.

## 0.22.1 · One owner for loom's paths

About forty modules encode the layout and nothing owns it (the study, "Who owns the layout").

- **One module** holds every path loom uses:
  - the quilt's settings (`drafting`, `drafting_ai`, `history`, `research_state`);
  - loom's directories (build output, digests and the store, annotations, `ai/`, `retired/`, sessions);
  - its record files (`state.toml`, `reference-notes.jsonl`, `serve.json`, `review-decisions.json`, `review-origins.json`, `review-observations.json`, `adoption-decisions.json`, `source-sync.json`, `last-seen.json`, the `since` markers).
- **Every module that hardcodes one reads it instead:** `build/` in 22 modules, `ai/` in 8, `nodes/` in 5, and the rest the study lists.
- **The four copies that ignore `[quilt] history` are fixed:** `records/snapshots.py:12`, `records/lastseen.py:28`, `ai/layout.py:68`, `cli/quilt.py:167,180`.
- **No behaviour changes:** the fixture is byte for byte the same.
- **Settled in the phase:** the module's name and shape, and whether the tree walkers' exclusion sets (`scan/source.py`, `section_drafts.py`, `reshape/importer.py`, `render/watch.py`) come from it too.

## 0.22.2 · Overleaf: the person names the sync directory

The person clones their Overleaf project into a directory and names it to loom; everything else in sync carries on (the study, "Now: sync works in a directory the person names").

- **`loom sync init DIR`.** It checks that `DIR` is a git repository with a remote, and records it. It never clones, replaces or removes it.
  - It refuses a `DIR` that is the quilt's own repository, holds a quilt, or sits under `.loom/`.
  - A URL is refused, and the refusal names the commands that clear it: clone, then `sync init DIR` (T3).
- **`workspace()`** (`sync.py:174-186`) returns the recorded directory. `WORKSPACE` and the `.loom/workspace/` lines in `gitignore.py` and the init asset go.
- **Every tree walker skips the directory:** the scanner (`skipped_dirs`), the watcher, section drafts' context, the importer's mirror and the copies `cli/paper.py` and `cli/history_cmds.py` make. Inside the quilt it holds copies of the quilt's sources, and scanning it would leave every key conflicted.
- **Unchanged:** publish, fetch, review in Incoming and incorporate. Publish and fetch already move only `refs/loom/*` through a temporary index, and touch no working tree or branch.
- **Documents:**
  - `docs/design/model.md` (Coauthors);
  - `invariants.md`: sync's git runs only in the directory the sync record names, with a dated line;
  - `docs/specs/manifest.md` (`incoming.workspace`), if what it names changes;
  - the init README's paragraph, and `loom/docs/cli-reference.md`, regenerated.
- **Tests:** `loom/tests/unit/test_sync.py` makes its own clone and names it, and gains a test that the scanner skips a sync directory inside the quilt.

## 0.22.3 · Documents anywhere, named by path

- **One master rule.** Any file with `\documentclass` is a document unless it is ignored, superseded, under `.loom/`, under a skipped directory or the sync directory. This replaces the seven restatements of the drafting-directory rule (`scan/scan.py:202-216` and its six copies). `loom:documentclass-outside-drafts` goes.
- **Whether a document is an agent copy** is read from the history (`copy_of`, `written`), not from the directory. `drafting_ai` still holds the copies until 0.22.6.
- **The name is the path without `.tex`.** It replaces the stem in:
  - the build directory (`build/paper/main/`);
  - the fragment (`fragments/masters/paper/main.html`) and the landmark's fragment;
  - the `.aux` lookup (`tex/aux.py`);
  - the manifest's `pdf`;
  - the viewer's routes (`/master/paper/main`), through `masterUrl`, `canonUrl` and `itemFromPath`.

  `loom:document-stem-taken` goes.
- **`masters[].directory` goes.** The viewer's six files that read it use `copy_of` (`docs/specs/manifest.md` §2a rewritten).
- **`[quilt] main`** keeps meaning the default LaTeX master and stops defaulting to `drafting/main.tex`. Settled in the phase: what the default master is when `main` is unset (the only document, or none).
- **`destination()`** (`cli/_common.py:130-180`) accepts a path anywhere in the quilt outside `.loom/`, skipped directories and the sync directory, still never overwriting (P7). The same goes for `import`, `history restore` and `adopt --to`.
- **Compiling still happens from the root** in this phase, so `drafting/` keeps working as an ordinary directory, and fixtures that use it need only their names changed.
- **Churn:** the spec fixture, and the viewer's 149 lines of `/master/<stem>` routes in 26 test files. The phase measures how many loom tests change.

## 0.22.4 · Own-directory compile and the macro block

- **A per-document base.** `compile_tex` (`tex/runner.py:136,151`) runs in the document's directory. These resolvers take the same base, and a resolved path stays relative to the quilt root, since the scanner's file table is keyed that way:
  - the scanner's expansion, and `flatten` with its 22 callers;
  - packages (`scan/preamble.py`), the bibliography (`refs/scan.py:302-323`), graphics (`render/assets.py`) and `.aux`;
  - the SVG fallback's `TEXINPUTS` (`render/fallback.py:183-186`).

  Digest extraction and import already compile a paper from its own directory with the same resolvers, and the phase reuses that.
- **`..` stays refused,** because Overleaf cannot follow it.
- **Derived texts compile from their source's directory:**
  - landmarks, read from the history;
  - agent copies;
  - sync's projection.
- **Destinations follow the document:**
  - `loom new` writes `nodes/<id>.tex` in the default document's directory, with `--to` for another place;
  - atomize and fork write relative to the document they work on;
  - import writes the draft and the paper's figures and styles together, in a directory of their own.
- **Section drafts** take their context from the document's directory (`section_drafts.py:146-156, 226-262`), not a copy of the whole quilt.
- **The macro block.**
  - Documents loom starts, imports or restores carry the marked block of `reshape/linearize.py` in place of `\usepackage{loom}`.
  - `loom init` and `loom upgrade` stop writing `loom.sty`.
  - A `loom.sty` the person keeps beside a document keeps working.
  - Closures copy the block with the preamble rather than forcing the package (`tex/bundle.py:40-41`).
  - The two lints recognise the block (`scan/lint.py:353-380`), and `loom doctor` finds an old block and prints the patch that brings it up to date.
- **Documents:**
  - P12 in `principles.md` reads "compiles from its own directory";
  - `model.md`, `docs/specs/source-contract.md` §1 and `diagnostics.md` (`loom.sty`'s codes).
- **After this phase** a person can work in the Overleaf directory directly. Whether to delete sync is then a decision of its own (the study's open question 8), outside this plan.

## 0.22.5 · Loom's files into `.loom/`, and a near-empty `loom init`

- **What moves:** digests and the store, `annotations/`, `reference-notes.jsonl`, `ai/`, build output and `retired/` move under `.loom/`. After 0.22.1 that is a change of constants. The server keeps its URLs (`/build/*` and the store's) wherever the directories now sit.
- **`refs/` goes.** A PDF anywhere becomes a work with `loom library add FILE`, and a bibliography is wherever a document's `\bibliography` names it.
- **The `notes/` exclusion goes.**
- **`.loom/` carries its own `.gitignore`,** separating shared records from local ones, and the root `.gitignore` shrinks. The stale summary in `cli/quilt.py:122-125` goes with it.
- **`loom init`** writes `config.toml`, the tutorial README and `.loom/`, and nothing else. `--demo` and `--from` follow. `loom:no-live-document` and the viewer's how-to-start page drop the drafting directory.
- **Settled in the phase:**
  - the research state's default place (the study's open question 6);
  - the layout under `.loom/`;
  - how the agent permission files name the moved directories until 0.22.6 replaces them.

## 0.22.6 · Agents: the deny list

- **The deny list.** Gitignore-style patterns in the config (the name settled in the phase; the study's open question 7). A fresh quilt's list holds `.loom/` and `config.toml`.
- **Enforcement, said plainly.** The list is generated into each permission file a client has. Today only Claude Code's restricts file writes, and the orientation says plainly which clients enforce the list (P15).
- **Agent copies move into `.loom/`.** `loom draft DOC --ai NAME` writes there; the scanner reads them on purpose, as it reads landmarks; and the viewer nests each under its source by `copy_of`. `[quilt] drafting_ai` goes, and so do `loom:agent-document-unrecorded` and `loom:plain-id-in-drafting-ai` in their present form.
- **Agent documents written from scratch go:** `loom draft --ai NAME --new`, `loom adopt NAME --to FILE` and the write API's `adopt-start`.
- **The instruction line** in `CLAUDE.md`, `AGENTS.md` and `GEMINI.md` changes. `ensure_root_line` learns the old line and replaces it rather than appending.
- **The orientation, rules, formatting notes and modes** stop naming directories an agent may write, and name the deny list.
- **Settled in the phase:** whether each project-level client keeps `--quilt` in its MCP entry or finds the quilt by walking up.
- **Testing:** the `client` tier runs, with the client versions recorded.

## 0.22.7 · The viewer: files, the tree and the front door

Starts by confirming that the write-API fix has landed.

- **The publisher publishes the project's files:** what each is, and which the tree hides (loom's, dot-directories, and what the person's `.gitignore` ignores). Settled in the phase: their shape in the manifest.
- **A file item kind** opens any shown file in a pane. `links.py` lets a link name a file and a place in it.
- **Docs is the collapsible tree.** Documents sit in their directories, agent copies under their source, the research state where it lives, and the Library as today.
- **The front door,** a setting naming the file a quilt opens on when the browser remembers no place (`home` is a candidate; the study's open question 1).
- **Markdown** is rendered by the publisher as pages are, raw HTML escaped.
- **HTML** goes in a sandboxed frame, served from its own origin or under `Content-Security-Policy: sandbox`:
  - a navigation-only bridge for `quilt:` links;
  - a selection reporter, so HTML can be quoted;
  - embedded content shown when the network is there.

  `docs/specs/dialect.md` §3 says frames belong to file items, never to fragments.
- **PDFs and images** are shown as files. A PDF becomes a work only when the person adds it.
- **Settled in the phase:**
  - notebooks: rendered read-only, or only opened in their application (the study's open question 3);
  - how a link names another application (open question 4).

## 0.22.8 · Review and quoting

This phase waits until the author answers two of the study's open questions: where Review gets the old text of an open file (open question 2), and whether a discussion quote and a fleeting note are one mechanism (open question 5).

- **Review as the meta view.** Its sections (the study, "Review as the meta view"):
  - changes to open files since the person last looked, each kept or undone;
  - agent copies to adopt and pulls to incorporate;
  - suggestions and library proposals;
  - acceptance, kept apart, with a verb of its own for keeping an edit (K7);
  - Sessions, History and Problems.
- **The person's marker:** a "since you last looked" marker for the person, as `loom since` keeps one for each agent.
- **Quoting:** anything shown can be quoted into a discussion. A passage of text, a region of a PDF or image, or a transcript message is quoted with one gesture and no kind or severity, and the quote fades. Review annotations keep their kinds and lifecycle.

## Out of scope

- **Loom knowing about courses,** or any one way of organising work.
- **Deleting sync,** a decision for after 0.22.4.
- **Links in from outside** (a web address an Anki card could open), until someone wants it.
- **Zotero,** the first item of `ideas.md`, which concerns the library rather than the layout.
- **Running code,** which is deferred. A notebook is shown or opened, never run.
- **Notes as their own record,** except as far as 0.22.8's answer to open question 5 takes them.

## Behaviour that must survive

- **Author files are written only by an incorporation the author chose,** after a stamp (P7). An agent writing an open file acts on the person's permission to the agent, not loom writing.
- **States are computed** (P3), and an accepted key edited by anyone shows as stale with its cause (P15).
- **The author's acts refuse an agent** in any shell, whatever name it declares (K5).
- **Every command runs from a terminal with no server** (P8).
- **Overleaf sync keeps working** through every phase.
- **Relloc's acceptances survive its re-lay.** Relloc's documents move to a layout of the author's with `loom mv`, which every record follows. A document that keeps `\usepackage{loom}` with a `loom.sty` beside it keeps its preamble unchanged, so its keys stay fresh.
- **One allow table** generates every permission file and every tool list, and generated agent configuration is never tracked.

## Verification

`scripts/verify`: `fast` while working, `full` before each phase's commit. The `client` tier by hand for 0.22.6, with the client versions recorded.

Each phase is also checked against copies of the author's two quilts made in the workspace, never the quilts themselves:

- **relloc:** the Author loses nothing. Its accepted keys stay accepted, its documents compile, and Review shows what it showed.
- **quant:** the person and their agent can build what they choose without loom in the way. From 0.22.7, its files are shown in the tree.

## Implementation

Each phase appends an entry here when it is built: the date, what was built, its commits, and anything that departed from the phase above.

### 0.22.1 · One owner for loom's paths — built 2026-10-30

- **`loom/src/loom/paths.py`** names every path loom uses inside a quilt: loom's directories, the author directories it names (`NODES`, `REFS`, `NOTES_DIR`), and its record files, as quilt-relative POSIX strings.
- **52 modules read it.** A script made the switch, checking every replacement's count. The constants other modules import keep their names and take their values from `paths` (`STORAGE`, `LOG`, `NOTES`, `DIR`, `SERVE_JSON`, `MARKERS`, `WORKSPACE`, `BIBLIOGRAPHY`, `FILE`, `CACHE`, `CLOSURES`, `STY`, `SEED`). The tree walkers kept their membership.
- **The server's addresses** are now constants of their own, `BUILD_URL` and `STORE_URL` in `render/serve.py`, so a directory can move without changing an address. The start message `loom serve` prints names the build address through `BUILD_URL`.
- **`[quilt] history` is honoured wherever the history is reached:**
  - the snapshot and last-seen functions take the history directory as a required argument;
  - `freeze_moved` reads it from the scan;
  - `agent_dirs` puts the configured history among the agents' read-only directories;
  - `loom init` writes its ledger under the history directory a person's user config names;
  - `QuiltConfig`'s default comes from `paths.HISTORY`;
  - `Records(root)`, given no history directory, reads it from the quilt's config.
- **`comments/` is gone from the watcher,** since the annotation log replaced that directory.
- **The guard is `loom/tests/unit/test_paths.py`.** It reads loom's source with `ast` and fails on a path join with a literal directory name, or on a string that starts with a quilt path or names a record file. Docstrings are exempt, and an allow-list holds three exceptions with their reasons. A second test checks a quilt whose `[quilt] history` is `hist`: its agents' read-only list, its records and `init`'s ledger are all there.
- **`docs/contributing.md`** says a path loom uses inside a quilt is named once, in `paths.py`.
- **Departures from the phase:**
  - Modules import the names (`from loom.paths import BUILD`) instead of the module, because several (`sync.py`, `adopt.py`, `reshape/fork.py`, `doctor.py`) use `paths` as a local variable.
  - mypy found eight more places that ignored `[quilt] history`: calls of `Records(root)` with no history directory, whose snapshot reads fell back to `.loom/history`. `Records` now reads the setting, which also fixed them.
  - The guard found a fifth copy, `QuiltConfig.history`'s own default.
- **The fixture:**
  - `loom/scripts/gen_quilts.py all --check` passes byte for byte.
  - The spec fixture, refreshed, differs only in three landmark cache keys, because `_canon_hash` (`render/build.py`) includes a hash of loom's code. Its fragments are unchanged.
- **Verification:** `scripts/verify full` passed: loom 2,068 unit and 15 TeX tests; arras 199 vitest, 316 e2e, 15 minimal, 32 write, 24 reading, 6 shots and 1 floor.
- **The write-API fix** (`7647fc1e`, on its own branch) also edits `render/serve.py` and `render/api.py`, so whichever lands second resolves a small conflict.
