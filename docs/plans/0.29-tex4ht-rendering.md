# 0.29 — Documents rendered from a real compile

## Context

`render/convert.py` translates LaTeX to HTML by reimplementing LaTeX, and cannot converge. Comparing `hull_ch1` with its PDF found twelve differences; a 42-feature test against the real compile scored the translator 20 correct, 10 wrong and 12 turned into pictures, and TeX4ht 41 correct. The author chose: documents are HTML generated by TeX4ht from a real compile, and the compiled PDF "can be viewed by clicking the PDF in the file tree". The author also ruled that the loom/viewer distinction is deprecated: "Where integration buys flexibility, speed, optimization, power or expressibility the viewer should be integrated." MCP changes are acceptable. There are no users to migrate, so no shims.

Measured so far, on copies: one TeX4ht pass takes 8–10 s on real papers (1–2 s on a chapter) and about 1 s for `pdflatex`; result numbers matched the PDF on four papers; a generated `.cfg` stamped every proof and theorem with its file and line; a missing package or missing `\end{document}` yields no HTML.

## How this plan is carried out

This file is the one master plan. Each phase is planned concretely in plan mode when it starts and recorded in `## Implementation` below once `scripts/verify full` passes.

## Decisions

1. **TeX decides what the document says.** The scanner still decides what a node is (C1, P5). Loom adds identity and source offsets to TeX4ht's output and reinterprets nothing it can avoid.
2. **Fragments stay as the viewer's internal format**, because about 35 viewer files and `render/marks.py` consume them, but the format is no longer a contract: either side changes it freely.
3. **TeX-authored HTML is untrusted.** `\HCode` can write any tag and `Fragment.svelte` assigns `innerHTML` in the page holding the write token. The normaliser rebuilds every element from an allowlist, as `raw_html.py` does; nothing passes through as written.
4. **TeX4ht runs no quilt-carried command** (the invariant "Loom never runs a command the quilt carries"). It runs on a stage outside the quilt with `.mk4`, `.make4ht` and `tex4ht.env` removed, a loom-written build file, and an isolated `HOME`. The author's approval of this plan extends that invariant to TeX tooling; a dated line goes in its entry.
5. **No document stale-and-silent, none blocked** (P13, V3): see the table below. A document with no HTML shows per-node source, not an approximate rendering. **2026-11-10, the author:** until snippets exist, a document with no HTML, and one whose sources changed since its HTML was made, keep the translator's rendering, which the HTML replaces as soon as a compile lands; the viewer's suites run in CI without TeX, and an edit should show at once. Per-node source arrives with 0.29.5, when the translator goes.
6. **The compiled PDF is view-only**, a row under its document in the file tree. Marks stay on the HTML, since a recompile replaces the PDF's bytes. An author's own same-named PDF remains an ordinary file (P7 forbids loom writing beside it).
7. **Annotation work on PDFs is the annotation plan's**, including page crops for agents. The word-to-source alignment in `tex/align.py` is shared with it.
8. **`latexmk` reads no rc file** (the author, 2026-11-10). Loom's one call to it, `compile_tex` in `tex/runner.py`, passes `-norc`. A `latexmkrc` is a Perl program, and one in a document's directory runs today because the stage copies it. The author's `~/.latexmkrc` adds `-shell-escape`, so on that machine a `\write18` in any `pdflatex` document runs a command as well. With `-norc`, on scratch documents, neither did and each still made its PDF. This covers loom's compiles only: the author's editor and their own `latexmk` runs still read their rc. A document that needs shell escape waits on WQ-66.

## What a reader sees

| State | Shown |
|---|---|
| No HTML yet (never compiled, no TeX, first compile failed) | Per-node source with `data-src`; annotating works |
| Compiling | Last HTML, with status on the stream |
| Edited since | Last HTML; nodes that no longer align are marked edited |
| Failed | Last HTML; first error and line in a banner and Problems |
| Degraded | HTML; unstamped nodes counted and shown as source |

## Phases

### 0.29.0 · Stopgaps in the translator

It stays live until 0.29.3, and these two are verified or owed. Make `render_range` (`render/convert.py`) cut only at claimants not inside an open environment. Give an unattached proof its `title` in `scan/nodes.py`, and print a proof's optional argument instead of the word "Proof" (`fragments.py _proof_html`, `convert.py inline_env`). No other translator fixes.

*Accept:* `hull_ch1` publishes 40 items with each answer inside its item, headed "Answer".

### 0.29.1 · Compile queue and the PDF row

New `render/compiles.py` replaces `_compile_default` in `render/serve.py`: every live document whose closure changed, one run plus one queued rerun, debounced, bounded workers, the open document first (`render/api.py reading_place`), process-group kill on timeout and stop. A run that produces no PDF leaves the last good output in place, and runs no longer halt on the first recoverable error. The PDF becomes a row under its document in `shell/FileTree.svelte`, beside the `copiesOf` rows, with its URL versioned by `masters[].compiled`; `pdf/document.ts`, `PdfDoc.svelte` and `FileItem.svelte` reopen it when that changes, minding the `paperPlace` trap in `place.svelte.ts`. The toolbar's "open the PDF" goes (V2). `compile_tex` passes `-norc` (decision 8), and the dated line of decision 4 goes in the invariant's entry. MCP and the stream carry compile state. P11 and C5 are rewritten here, because this phase already contradicts them.

*Accept:* ten saves during a compile cause at most two runs; an open PDF updates unprompted at its place; a document with a recoverable error such as `\hlind` still has a PDF; with `-shell-escape` in a home rc, neither a quilt's `latexmkrc` nor a `\write18` runs a command.

### 0.29.2 · TeX4ht, unpublished · go/no-go gate

New `tex/tex4ht.py` (one `-m draft` pass, a further pass only when the `.aux` changes, output in `.loom/build/<name>/html/`, engine from `engine_for`, `extractbb` in the stage), `tex/align.py` from the prototype, and `render/normalise.py` into fragment markup. The `.cfg` is generated from the scan's taxa and stamps environments, files and references. `loom compile --html` writes the result and nothing reads it yet. `make4ht` joins `doctor.py TOOLS`; check whether CI's TeX Live image carries it.

Known defect to fix here: TeX4ht's MathJax mode steps `equation` once per `align` and records only the first `\label`, so later labels print `??` and counters shared with results can drift (seen in `acgs` and `relloc`). Override it in the generated `.cfg`. The numbers in formulas keep coming from the `pdflatex` aux (`read_numbers`, `_tag_lines`).

*Go if,* on the real papers plus two the code has not seen: every paper that makes a PDF makes HTML (three fail today); 99% of nodes are stamped; 90% of blocks align exactly; every printed reference agrees with the aux; a hostile document's `\HCode{<script>}` is neutralised; 40 of 42 features on the test document, which joins the fixtures; and no paper-specific code was needed. *No-go* returns to the author before anything is published.

### 0.29.3 · Documents read from HTML

`master_fragment` and `node_fragment` (`render/fragments.py`) consume the normalised tree; node fragments are cut from the default master's tree, else the first document reaching the node (`_numbers_for`), with children as `div.include`. `data-src` is computed at publish against the current scan, so stale HTML keeps true offsets. `_input_hash` takes the HTML's digest. The queue runs HTML too, and the states above are computed at publish (P3). The viewer draws real item labels, proof heads run in with tombstones, tables have rules and alignment, and heading styles follow the document's class rather than always imitating `amsart`. `place_marks` and `quote.ts` keep working through `.math`, `data-tex` and `data-at`. Refresh the fixture and seed e2e-write quilts with compile output, keeping `--no-compile`.

*Accept:* the twelve differences found on `hull_ch1` are gone, apart from the reader's chosen font; relloc's annotations fall to block level no more often than today; a failed compile leaves the document readable; `scripts/verify full` passes.

### 0.29.4 · Snippets · go/no-go gate

New `render/snippets.py`: text that is never compiled runs through TeX4ht under its owning preamble, one run per preamble with texts between stamps, bisecting when one breaks the run, cached as `_render` is.

*Go if* 1000 statements take under 60 s cold and a bad snippet costs only itself. *No-go:* `Converter` stays for previews alone, and the design says so.

### 0.29.5 · Never-compiled text moves; the translator goes

Landmarks and digests compile once by content hash at lowest priority. Loose nodes, proposals, comparisons and section drafts become snippets, with changed-word marks applied afterwards through alignment in place of `highlight_spans`. Move the tables `records/selectors.py` imports, then delete `convert.py`, the SVG fallback and `test_convert.py`.

*Accept:* no `Converter` remains and `scripts/verify full` passes.

### 0.29.6 · The boundary machinery

Independent of 0.29.2–0.29.5. Remove what only kept the two apart: the `forbidden-words` and `host-neutrality` specs, `fixture-minimal` and its suites, the interface version handshake, and `loader.ts` defaults for absent sections. Keep what does real work: atomic publish, the generated fixture for TeX-free viewer CI, the validator as a safety check, the token, CSP and frames, and the bundle freshness check.

*Accept:* `scripts/verify full` passes with those suites gone.

## Risks and what would falsify this

1. The normaliser regrows `convert.py`. Falsified if unseen papers keep needing new branches; the 0.29.2 gate measures this.
2. Edit-to-view lag of 8–10 s per pass proves unacceptable in use. The reserve is recompiling only changed nodes as snippets (about 1.3 s).
3. TeX Live differs between CI and local machines and breaks byte-compared fixtures.
4. MathJax mode fails on a paper that compiles without it, as `3waveZKnew` did. That document then shows as degraded or source until handled.

## Implementation

### 0.29.0 · built 2026-11-09

**Loom.** `Converter.render_range` takes its cut points from a new `_cuts`, which leaves out claimants inside a list, so `list_env` meets them item by item and a list is no longer left unclosed. Only lists count: containers and unknown environments keep their behaviour, so a theorem inside an unknown wrapper does not become part of a picture. An unattached proof's `NodeRec` carries its `title` (`scan/nodes.py`). In `fragments.py _proof_html` and `convert.py inline_env`, a proof's optional argument is the whole head, plain inside `summary`, and the word `Proof` appears only when there is none.

**Docs.** `docs/specs/dialect.md` §2.5. The fixture is refreshed; its diff is proof heads and the manifest's digests, and heads such as `Proof Proof of Lemma 2.3` now read `Proof of Lemma 2.3`.

**Left for 0.29.3.** Item labels stay `1.`, `2.` and restart per section, and in Paper format the first line of each question is indented.

**Checked.** `scripts/verify full` passed in the worktree, every lane. Two new tests fail with the fixes disabled. On a scratch copy of `hull_ch1.tex` through the real scan and renderer: 40 items plus the 2 of the sublist, all 40 proofs inside an item, every head `Answer`.

### 0.29.1 · built 2026-11-10

**Loom.** `render/compiles.py` is the compile queue `loom serve` runs: two workers started on first use, a document asked for while it compiles runs once more afterwards however often it was asked, one asked for while it waits waits 0.4 s again, and the document the reader has open (`reading_place`, as text or as its PDF) goes first. `needs_compiling` asks for the documents a change reaches (the master, what it inputs, its local styles, and any bibliography, figure or data file under its directory), and on starting for every document never compiled or edited since its PDF. A run that made a PDF rebuilds the manifest. `tex/runner.py compile_tex` passes `-norc`, runs latexmk in a scratch directory beside the build output seeded with its files, and moves the run's output in only when it made a PDF, so a failed run keeps the last good PDF and aux and only its log; the run is a process group of its own, killed whole on timeout and on the server's stop (`stop_run`). The queue compiles with `halt_on_error=False`. How each compile stands goes on `/_api/stream` as a `compiles` event and into `.loom/build/compiles.json`, which `loom status` reads while a server runs: `--json` carries it under `compiles`, and the text lists a document compiled with errors or into no PDF under "did not compile cleanly", with the line TeX stopped at and `loom compile` as the fix.

**Viewer.** A document's row in the tree has a `PDF` row beneath it, and each agent copy's its own, saying "compiling", "waiting to compile", "did not compile" or "compiled with errors", the error under the pointer. It opens a new item kind, `pdf`, at `/pdf/<name>`: the compiled PDF to read and not to mark, with a line above it when the last compile failed or reported errors. Its URL carries `masters[].compiled`, so a new compile opens it again, and `paperPlace` takes a fourth argument, the paper's address, so it opens again where the reader is rather than where the last link sent them. The row is named `PDF` and the tab `main.tex · PDF`, never `main.pdf`, since an author's own PDF beside the document is a file of that name. The document toolbar's "open the PDF" is gone.

**Docs.** P11 and C5 are rewritten for one tool; the design README's warning against teaching the viewer what an event means goes with them. The invariant "Loom never runs a command the quilt carries" has its dated line and guard. `docs/specs/README.md` obligation 3, `write-api.md` (the `compiles` event), `manifest.md` (`compiled` changes with each compile), `model.md` (the PDF row), `contributing.md` (C5), and `loom serve`'s help.

**Checked (0.29.1).** New tests: the queue (ten asks during a run make two runs, a burst before one makes one, the open document first, a raising compile is a failed run, `needs_compiling`), the TeX tier (`-norc` with `-shell-escape` in a home rc, a failed run keeping the last good output, a recoverable error making a PDF, a run that never ends killed with its group), `loom status` listing a failed compile, the viewer's `pdf` item and compile words, and an end-to-end test where a new compile reopens the PDF on the reader's page; with `paperPlace`'s fourth argument removed it reopens on page 1 and the test fails.

### 0.29.2 · built 2026-11-10, gate passed

**Loom.** `tex/tex4ht.py` runs `make4ht -m draft` with a generated configuration on a copy of the document's directory outside the quilt, with an empty home and its `.mk4`, `.make4ht` and `tex4ht.env` removed, seeded with the PDF's aux and bibliography so one pass prints the PDF's numbers; `extractbb` runs on the copy's figures; a run that makes no page keeps the last good one in `.loom/build/<name>/html/`, and a run is killed with its process group. The configuration stamps every taxon and proof with its environment, file (`\CurrentFile`) and line, marks where an included file starts and ends, wraps the kernel's and hyperref's `\@setref` so each reference names its label, and numbers every row of `align`, `gather`, `alignat`, `flalign`, `xalignat`, `xxalignat` and `eqnarray` as amsmath does, each with its own label, which fixes the MathJax mode's one step per display. `render/normalise.py` rebuilds the page from an allowlist (code-bearing elements dropped with their contents, stamps kept only in the shape loom writes them, every value escaped), takes each MathJax-mode formula whole as TeX, marks what TeX made (`data-made`: heads, numbers, references, citations, footnote marks), and gives every block `data-at="FILE:LINE"`. `tex/align.py` places a block's words in its source: words folded (ligatures, accents, case), mathematics and the arguments that print nothing left out, the author's own macros and environments read as the words their definitions print, the nearest exact run first, else the cluster of matches round the largest. `loom compile DOC --html` writes the page and `fragment.html` beside the PDF and counts nodes stamped and blocks placed; nothing else reads them. `make4ht` and `extractbb` join `loom doctor`; CI's TeX install adds `make4ht`, `tex4ht`, `luaxml`, `enumitem` and `float`, unrun from here.

Against the criteria: every paper that makes a PDF makes HTML; nodes, references, the census, the hostile document and no paper-specific code pass; blocks pass at 97–100% on five papers, and `relloc` misses at 84% because its copy reaches no bibliography, so every citation prints its raw key without TeX4ht's citation markup. The author chose to repair the display (2026-11-10): `repair_displays` replaces, in the copy TeX4ht reads, each display whose braces do not balance with `\loomdisplay{N}` on the same lines, stepping `equation` and labelling each numbered row as the display would; `repaired.json` beside the page holds its TeX as written, which the normaliser puts back for MathJax to set as best it can, and `loom compile --html` names the line. One TeX4ht pass on that paper, 9,100 lines with 844 equations and 49 PDF figures, takes about 80 s, of which loom's configuration adds 8 s and `pdflatex` takes 2 s: risk 2's edit-to-view lag, which the snippets of 0.29.4 answer.

### 0.29.3 · built 2026-11-10

**Loom.** `render/fromhtml.py` reads a document from the page TeX made. `page_for` takes a document's page only while every source file it read hashes as `sources.json` beside the page recorded; otherwise, and when there is no page, the document keeps the translator's rendering (decision 5, as the author amended it). `DocumentHtml` reshapes the normalised page into the dialect: a heading whose words are the next of the scan's sections opens that section, run-in heads included; an included file's start and end marks become its `div.included`; each stamped node becomes the statement or proof the scan knows, with its key, label, pair and hash, its upright words emphasized when its style sets it in italic; a display is set by the translator's `display_env` from its source, found near the line TeX4ht gave by what it says and never taken twice, so its label, number and anchor are as before; an inline formula takes the source's own TeX when TeX4ht's differs only in spacing, which is what a quote copies; a reference or citation carries the command its block's source wrote, matched in order, and an equation's parentheses go inside its link; a block takes the span of its words, widened over the formulas, references and citations at its edges, and a list or table the span of its environment; a picture TeX4ht drew is addressed beside its page, and an included graphic is published as the translator publishes it. A page with any node of the document unstamped is not complete, and the document keeps the translator's rendering. `master_fragment` and `node_fragment` (`render/fragments.py`) read from it and say so with `data-from="tex"`; a node's fragment is cut from the default document's page, else the first document reaching it; a master's first element carries `data-documentclass`. The fragment cache's input hash takes each page's digest. The normaliser keeps the space TeX4ht writes inside a formula's span after it, keeps `\maketitle`'s author and date as `p.author` and `p.date`, says which paragraphs TeX set without an indent (`p.noindent`), and reads the EC fonts a T1 document uses. `loom serve`'s queue runs TeX4ht after each PDF it makes, when `make4ht` is installed, and the page replaces the translator's rendering at the next publication.

**Viewer.** A list whose labels TeX printed is a grid of labels and items; a ruled table row is ruled and a cell aligned as its column; `div.center` is centred. In the paper formats a proof's head runs into its first line, italic with its full stop and no disclosure marker; a document of a standard class (`article`, `report`, `book`) has its title large and centred over its author and date and bold heads at the margin, while the `ams` classes keep centred small capitals; and a paragraph TeX set without an indent has none, a list's paragraphs a small gap between them.

**Docs.** `docs/specs/dialect.md` §1.2, 1.4, 2.1, 2.6, 2.7, 2.11 and 2.12; the validator allows `sup`, `sub`, `div.center`, `sup.footnote-mark`, `tr.rule`, `p.author`, `p.date` and `p.noindent`, and asks a fragment made from TeX for `data-src` only on sections, nodes and displays. `refresh-fixture.sh` compiles both documents with `--html`, so the committed fixture's `main.tex` is read from TeX's page; `talk.tex`, a beamer document, has two of its six nodes unstamped and keeps the translator's.

**Not done.** The end-to-end write suites still start their quilts with `--no-compile` and no compile output, so they exercise the translator's rendering, which stays until 0.29.5; the static suites run on the TeX-made fixture.

**Checked.** In the running viewer on a scratch copy of `hull_ch1`, all twelve differences are gone apart from the typeface: 40 questions numbered `1.1.` to `1.40.` with the practice questions from `1.11.` and the sublist `(a)`, `(b)`; heads reading *Answer.* run into their first line, each answer ending in its tombstone; sections numbered; tables centred with their rules and column gaps; answers' paragraphs flush with a small gap; the title large over its date and the heads bold at the margin. On a scratch copy of relloc's `draft5.tex`, the same 20 annotations are marked in the text and the same 6 on a whole block as with the translator's rendering, its 94 displays each have a source of their own, its 12 diagrams draw, and amsart's centred heads stay. New tests: the space after a formula, each formula as the source writes it, every picture held by the build, a citation at a paragraph's end finding its target, and the document's class; the fixture test compiles as the refresh script does. `scripts/verify full` passed: unit and TeX tiers, vitest 316, the static suite 389, write 73, reading 48.
