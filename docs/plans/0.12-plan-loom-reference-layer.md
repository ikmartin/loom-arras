# Plan 0.12: loom's reference layer

A quilt-local reference layer, built into loom, so that an agent can ground its reasoning in what the cited papers actually say, and so that an author can navigate a growing web of other people's results without reopening the PDFs. The seed is what a quilt already has and what loom can fetch for it: `refs.bib`, whatever sources and PDFs the cited works turn out to have, and the digests loom extracts from them mechanically. There is no crawl, no scheduler, no background process, no database. The digest grows as the quilt is used, and only as it is used.

Markers: **[decided]** settled in the design conversation of 2026-09-18 and to be implemented as written; **[assumed]** the drafter's default, to be implemented unless it conflicts with a decided rule or the live code; **[open]** to be resolved by the implementer against the code, or by an experiment.

---

## 0. Corrections this revision made against the live code

The first draft specified seven things that already exist in loom under other names, and one that the shared contract already governs. They are listed here rather than silently fixed, because the draft's file layout and command tree followed from them.

1. **`refs/` is keyed by the work's global identifier, not by citekey.** `refs/<work-id-path>/paper.pdf` and `refs/<work-id-path>/src/` are live today, reachable through `loom refs path [--pdf|--src]` and written by `loom refs add`. The draft's `refs/pdf/<citekey>.pdf` and `refs/store/<citekey>/` would build a second tree beside a working one. This plan adds `pages/` and `sections.json` **inside the existing directory** and invents nothing.
2. **`loom refs` already exists**, with `path`, `add`, `resolve` and `note`. The draft's new `loom ref` group would sit one letter from it, which is a trap rather than a distinction. Every new verb in this plan goes into the existing `loom refs`.
3. **`loom digest extract` is the draft's `ref extract`**, and is more capable than the draft assumed: it compiles the reference for its own numbers, emulates counters when it will not compile, prefixes ids, drops proofs, and lints the result.
4. **loom already fetches, and already asks services.** `loom digest fetch` takes an arXiv e-print and, with `--pdf`, the PDF, into `refs/<work-id>/`, gated on `[refs] fetch = true`. `loom refs resolve` asks zbMATH Open and Crossref for identity candidates through a cached client with per-service spacing (`refs/resolve.py:35`, `SPACING = 1.0`). §5.2's "one client with per-host spacing" is not built because there are two already.
5. **The digest contract §8.2 already places the results-as-data file beside the digest.** The draft's `refs/store/<citekey>/results.json` is that file in a second location. The contract wins; §4 below follows it.
6. **`work.json` duplicates the manifest.** `manifest["references"][<citekey>]` already carries the bib fields, the identifiers, what is on disk, the digest's provenance, `version_mismatch` and `cited_by`, all derived. A second hand-maintained record of the same facts is the sort of restatement that rots.
7. **Citation edges are already parsed.** `result.edges.cites` gives citekey and source key for every `\cite`, which is what §11.3 of the draft left open. The reference layer reads it; it does not recompute it.
8. **`loom accept` does not refuse a digest key.** It accepts it and prints `verified <key> as a faithful transcription of <citekey>` (DR-172, `cli/review.py:142-149`). The refusal asked for on 2026-09-18 was not what shipped; the label was. **§5.6 finishes the job**: `loom accept` refuses external keys outright, and the claim it was making about them moves to a command whose name says it.

Two measurements the plan rests on, taken on 2026-09-18 against `demos/relloc`:

- **The LaTeX path covers 9% of a real bibliography.** 22 entries; 2 carry an arXiv identifier. Four entries have an `eprint` field, but two of those are JSTOR stable ids. A reference layer that only ingests LaTeX stays empty, which is why reading is the main path here and why verification has to be structural.
- **The gap is loom's to close, not weft's.** weft resolved the same 22 entries and found arXiv sources for 15 of the 20 works they became — 75% against the 9% the bibliography declares. The gap is not a boundary between the tools: **`refs/resolve.py:157` already pulls `arxiv:` candidates out of zbMATH's preprint links for entries that declare no identifier.** So a resolve pass over the author's own bibliography, expanding no work set and asking no new service, should raise loom's mechanically-extractable fraction from 2 works to something near 15. §10 stage 0 is that pass, and it comes first because mechanical extraction beats reading a page on every axis: exact statements, real numbers from a compile, and the internal `\ref` edges a PDF cannot give up.
- **15 of the 22 entries are actually cited.** Extraction and proposal work is ordered by `cited_by`; the other seven are not worth a page of anyone's attention yet.
- **Page text costs 2.2 KB a page plain, and 59.7 KB a page under `-bbox-layout`.** Over the draft's own 47-work, 612-page example that is 1.4 MB against 36.5 MB. Plain text is what gets committed (§4.2).

## 1. What this is for

**[decided]** Two purposes, and both must hold or the design is wrong.

1. **An agent grounds its reasoning in mathematical fact.** Finding what a cited paper actually states is a few cheap calls rather than reading a PDF into context and forgetting it.
2. **An author navigates other people's results.** The digest becomes more navigable as the quilt is used: related definitions link to each other, and a theorem links to the results across papers it depends on or generalises.

The second is the one the first draft was missing, and it is why §7 exists. A store that only serves an agent is a cache; a store an author reads is a library.

**[decided]** The store is safe to delete. Nothing in the paper depends on it: deleting every digested result costs re-reading, never correctness. This is the invariant that makes everything else affordable.

**[decided]** Only anchored, machine-checkable records are stored as results. A stored result carries the verbatim text of the page span it came from; if that text is not at that anchor, the record is rejected and never written. The one exception is §7's typed links, which are not results, are never citable, and say on their face that they are assertions.

## 2. The boundary with weft

**[decided]** **loom works whether or not weft is installed, and always keeps its own reference layer.** A quilt must scan, lint, compile, serve and build with no weft, no gallery, no network. Nothing in this plan may introduce a dependency in either direction.

**[decided]** **weft is an optional upstream, never a replacement.** In the future a quilt may *connect* to a gallery: a larger library that weft maintains across projects, from which a digest can be imported instead of read. The quilt-local layer does not shrink when that happens — it is where the author's own reading, acceptance and links live, and those are properties of this project.

**[decided]** **The seam is an identifier, a BibTeX entry, and the digest contract.** loom never reads a gallery's files and weft never reads a quilt's. What crosses is a work identifier (`doi:…`, `arxiv:…`), a bib entry, and a digest plus its `results.json` in the contract's format. Neither tool's absence changes the other's formats.

**[decided]** **A digest imported from a gallery arrives as proposed, never as verified** (§5). A gallery's anchored result is verified against the artifact weft holds; it is not thereby something this author has read and vouched for. This is the single most important consequence of the seam, and it is why §5's machinery is worth building before weft exists.

**[decided]** **The invariant is that loom never expands the set of works.** The work set is exactly what `refs.bib` cites, the author puts it there, and no loom command adds to it. This is DR-144 as written — *"loom fetches only what its own bibliography cites; the crawl, its table and its commands are removed and go to weft"* — and it is a rule about the shape of the data rather than about mechanism.

**[decided]** **Fetching was never the line, and loom already crosses it freely.** `loom digest fetch` downloads e-prints and PDFs; `loom refs resolve` queries two services. Both are about works the author already cites, so both are fine, and this plan uses them rather than working around them. An earlier draft of this section banned "service clients" and was simply contradicted by two live ones.

**The test to apply**, wherever this plan or a later one is unsure: *does this command add a work the author did not cite?* If yes it is weft's, whatever it costs. If no it is loom's, however much network it uses. What that rules out is a frontier — expansion by subject or category, ranked neighbourhoods, hauls, a queue of proposed new works — and what it permits is everything about the twenty-two papers in front of you.

**[decided]** The consequences that follow from a bounded work set, and not from any ban: **no database** (tens of works, so search is a scan), **no rate budget** (you fetch a bibliography once, not a thousand-work neighbourhood), and **no scheduler** (there is no queue to drain).

## 3. Three tiers of record

**[decided]** Every record this layer stores falls in exactly one tier, and the tier decides who may write it and what is checked.

| tier | what it holds | who writes it | what is checked |
|---|---|---|---|
| **derived** | page text, section maps, the citation edges a paper states | a machine, eagerly | nothing; it is recomputed from its inputs |
| **anchored** | a result: verbatim source text plus a LaTeX rendering | an agent proposes, an author verifies | the source text appears at the anchor |
| **asserted** | a typed link between two results, with a short why | anyone, freely | nothing, and it says so |

**[decided]** **Anything a machine can derive, a machine derives — eagerly, in full, and again whenever its inputs change.** This is weft's §2.1 rule, adopted here for the same reason: re-deriving costs seconds and buys correctness, so when a rule changes everything mechanical is recomputed rather than migrated. Tier 1 is never ranked, never queued, never partial and never waits for permission.

**This is auditable.** Wherever this plan mentions a gate, a queue, a cap or a person's attention, check what is being rationed. If it is not an agent reading pages or an author's judgement, the rationing is a mistake and should be deleted.

**[decided]** A note on vocabulary, because the two plans nearly collided. **A tier is a property of a record; a class is a property of a result.** The digest contract's classes are `mechanical` (parsed from LaTeX; the statement is the source), `anchored` (read from a page; the source text is re-checkable) and `declared` (a rendering with no check available). Where a tier and a class are both called *anchored*, they mean the same thing.

## 4. Where things live

**[decided]** On the shapes that already exist. The reference layer adds files inside two directories a quilt already has, and creates no third tree.

```
<quilt>/
  refs.bib                              the author's bibliography; read, never written
  digests/
    <citekey>.tex                       the digest; contract §1.1. Accepted nodes only.
    <citekey>.results.json              the same results as data; contract §8.2 and §9
    <citekey>.proposals.jsonl           append-only: proposed, verified, edited, discarded
    links.jsonl                         §7's typed links; quilt-level, because both ends are rarely in one digest
  refs/<work-id-path>/                  exists today (`loom refs path`)
    paper.pdf                           exists today; gitignored
    src/                                exists today; gitignored
    pages/0012.txt                      new: deterministic page text, committed
    pages/0012.boxes.json               new: token geometry, written only where `locate` needed it
    sections.json                       new: the section map, committed
```

### 4.1 What the `.tex` holds and what it does not

**[decided]** `digests/<citekey>.tex` holds **verified nodes only**.

**[decided]** **A proposal lives in `digests/<citekey>.proposed.tex`, which loom scans and nothing ever `\input`s.** No bundle names it, no master reaches it, and `loom refs verify` is the only thing that moves a node out of it. So a proposal cannot enter a closure, cannot be cited and cannot reach a compile — a structural guarantee, not a check.

**[decided]** The reason it is a `.tex` at all, rather than rows in `results.json`: **a proposal exists to be looked at, and the pipeline that turns LaTeX into something a person can look at is the one that reads `.tex` files.** Scanning it gives nodes, fragments, macro sets and lint for free, and §5.3's requirement that the author see the proposed LaTeX *rendered* beside the page text is the whole point of the surface. Keeping proposals as data alone would mean rebuilding that rendering path for them.

**[decided]** The manifest carries a proposal as an ordinary node with `state: "proposed"`, because it is an ordinary node in a file loom scanned. `manifest["references"][<citekey>]["digest"]` gains a `proposed` list beside `nodes`, derived the same way — from the scan — so nothing in the manifest describes a node that no file defines.

**[decided]** `results.json` is the index's source and carries what the document cannot: both texts, the anchor, the level, the provenance, the verification record and the state. The contract's §9 (added by this plan) governs its shape, so a digest weft wrote is readable here and one loom wrote is readable there.

### 4.2 What is committed

**[decided]** **Everything but the PDFs and the sources.** `paper.pdf` and `src/` stay gitignored — they are other people's files. `pages/`, `sections.json`, the digest and its `results.json` are committed, which answers the draft's §11.4 outright: **a coauthor who clones the quilt can re-verify every anchor without holding a single PDF**, because the page text the anchor names is in the repository.

**[decided]** **Plain page text, not `-bbox-layout`.** Measured at 2.2 KB against 59.7 KB a page; over 612 pages that is 1.4 MB against 36.5 MB, and the geometry is needed only by `locate`. So `map` writes plain text for every page, and `locate` writes `pages/<n>.boxes.json` for the one page it was asked about, the first time it is asked. The expensive representation is produced on demand and kept, rather than produced for every page against the chance one is wanted.

**[decided]** The licence posture is recorded in the digest's header, per contract §7.3, and enforced by nothing. A quilt's digest is the material the paper already quotes; that stays true whether or not the repository is public, and it is the author's call, stated on the file's face.

### 4.3 Getting sources for works whose bibliography does not name one

**[decided]** This is the cheapest large win in the plan, and the first draft missed it entirely because it assumed the LaTeX path was closed at 9%.

**[decided]** **A resolver candidate is enough to fetch with, and never enough to be an identity.** DR-122 keeps identity with the author: a candidate becomes a work's identity when the author's own bibliography entry says so, and `loom refs resolve` never writes `refs.bib`. But fetching is not identifying. Downloading an e-print on a strong candidate is reversible, costs one request, and is checkable on arrival — so `loom refs fetch` uses a declared identifier where the entry has one and a strong candidate where it does not.

**[decided]** **The arrival check is the guard.** A fetched source's title and first author must fuzzy-match the bibliography entry's, or the artifact is discarded and the work is listed by `loom refs match` for a person. This is what stops a plausible-but-wrong candidate attaching the wrong paper to the right entry, and it is why fetching on a candidate is safe when identifying on one is not.

**[decided]** **Where a source arrives, `loom digest extract` runs and the reading path is not used at all.** Mechanical extraction beats an agent reading a page on every axis that matters: statements are verbatim rather than rendered, numbers come from a real compile rather than off a page, and the internal `\ref` edges exist. A work with a source needs no proposal, no acceptance and no anchor check — its digest is `mechanical` (contract §9.6) and is correct by construction.

**[decided]** So §5's machinery is for **the tail, not the trunk**: the classical literature, the theses, the journal-only papers. That is a smaller job than the first draft assumed, and it is still the job that makes the layer work at all, because the tail is where the hard citations live.

### 4.4 `loom refs build`: the one command that starts it

**[decided]** **The entry point to the whole mechanical half is one command, and the seed is `refs.bib`.** Everything §3 calls *derived* is what this command makes, and it makes all of it.

```
loom refs build [--all | CITEKEY…]
```

It runs, in order, each step a no-op where its work is already done:

| step | what it does | skipped when |
|---|---|---|
| **resolve** | identity candidates for entries declaring no identifier | the entry declares one |
| **fetch** | source and PDF, on a declared id or a strong candidate, title-checked on arrival (§4.3) | `[refs] fetch = false`, or the artifact is present |
| **extract** | `loom digest extract` on every source that landed | the digest is current against the source's hash |
| **map** | page text and the section map, for works with a PDF and no source | `pages/` is current against the artifact's hash |
| **report** | what is done, what needs a person, what needs an agent | never |

**[decided]** **This is §3's rule made executable, and without it the plan contradicts itself.** §3 says anything a machine can derive, a machine derives eagerly and in full — and then a four-command ritual would ask the author to remember the order and to notice when an input changed. The ritual is the bug. `loom refs build` is the whole of the derived tier and nothing else: it never proposes, never accepts, and never writes a link.

**[decided]** **Re-run it whenever `refs.bib` changes.** A new entry is resolved, fetched, extracted and mapped alone; everything else is untouched because everything else is current. This is why each step is keyed on a hash rather than on a flag — a resumable pipeline needs no state of its own.

**[decided]** **The individual verbs stay**, for forcing work after a rule changes and for running one step over what is already on disk. They are not steps in a ritual, and the orientation tells an agent to run `loom refs build`, never a sequence.

**[decided]** **It is not run automatically, and the watcher does not trigger it.** `loom serve` rebuilds on a file change; this reaches the network, so it waits to be asked. Without `[refs] fetch = true` it still does every local step, so a quilt with no network opt-in gets extraction and mapping from one command like everyone else.

**[decided]** **The report is the handoff**, and it names the two things a machine cannot do:

```
$ loom refs build
resolved   22 entries: 2 declared, 17 strong candidates, 3 unresolved
fetched    14 sources, 12 PDFs; 2 rejected on the title check
extracted  14 digests, 1,106 results, internal edges on all 14
mapped     6 works from PDF text; 486 pages; sections found for 5

needs you    5  loom refs match          (2 wrong-title, 3 unresolved)
needs an agent 6 works with pages and no digest — the tail (§4.3)
```

## 5. Proposed nodes: the heart of this plan

### 5.1 What a proposal is

**[decided]** An **anchored** result — a verbatim page span that verified against the page — together with a LaTeX rendering of it authored by an agent, is a **proposed digest node**. It is a complete result in every respect except that no person has looked at it.

**[decided]** `proposed` is a **state**, taking its place in the manifest's existing vocabulary beside `draft`, `accepted`, `stale`, `incomplete` and `conflicted` (`render/manifest.py`'s `STATE_LABELS`). It is not a queue, not a second store, and not a parallel review system. Everything that already reads a state reads this one.

### 5.2 Why it is not a queue

**[decided]** **Proposed nodes are merged into the digest as though they were real, and flagged.** Browsing the digest, an author sees links to a proposed node from the verified nodes around it, opens it, and finds it marked as proposed with both texts side by side and three things they can do about it.

The reasoning, which is the author's and worth preserving verbatim in the design: *an author accepts them at the moment he is already thinking about the subject matter the digest node pertains to, and is thus in a better position to make the assessment. Also it feels less like work and more like discovery.*

Two consequences follow, and both are load-bearing:

1. **A proposal nobody browses to is never seen.** That is acceptable for discovery and unacceptable as the only route, which is why §9.3's filter exists — the same data, listed rather than encountered.
2. **A discard must be visible to whatever proposed it**, or the next agent proposes it again. §5.5 is the whole of that story.

### 5.3 The three routes

**[decided]** At the moment of meeting a proposal, the author has three routes, and the surface offers all three together.

| route | what it writes | what it means |
|---|---|---|
| **verify** | the node into `digests/<citekey>.tex`; state becomes `transcription verified` | this rendering is faithful to that page |
| **edit, then verify** | the author's own `statement`, then the same | it was close; I fixed it; now it is faithful |
| **discard, with a reason** | a `discarded` event carrying the reason | this should not stand, and here is why |

**[decided]** **Verification shows both texts.** The verbatim page text beside the proposed LaTeX, always, on every surface that offers it. A surface that offers verify without showing both is a bug, not a shortcut: the entire claim being made is that these two say the same thing, and an author cannot make it without seeing them.

### 5.4 Edit, then verify

**[decided]** The common failure is a rendering that is slightly off, not one that is wrong. Take-it-or-leave-it makes the author throw away a nearly-correct transcription and wait for another; edit-then-verify lets them fix it in the second it takes and move on. It reuses the panel `VerbRow.svelte` already opens for editing an annotation.

**[decided]** **The author edits `statement`, never `source_text`.** The anchor names the source text — the verbatim page span — which an edit does not touch. So **an edit leaves the anchor intact and the node fully re-verifiable**, which is the thing that would be easy to get wrong and is therefore written down.

**[decided]** **An edited node records both parties in its provenance**: proposed by run X, edited and verified by the author. Without this the record says an agent wrote a sentence the author actually wrote, and a later reader cannot tell whose judgement they are trusting. It is the difference between a provenance trail and a rubber stamp.

**[decided]** An author's edited `statement` is not re-verified against anything, and does not need to be: it is the author's own text, and the author is the authority the whole verification step exists to consult.

### 5.5 Discards, and why the agent must see them

**[decided]** A discard appends to `digests/<citekey>.proposals.jsonl` with its reason. Three things read it:

1. **`loom refs propose` refuses a discarded work-and-local-id and returns the reason in the same turn.** An agent that re-proposes a discarded node learns why immediately rather than by silence, and can correct in the turn it failed.
2. **Re-proposal requires `--supersedes <id>`**, which records the chain. A proposal that answers a discard is a different act from a proposal that ignored one, and the record should be able to tell them apart.
3. **`loom refs coverage` reports discard counts per work.** A work with many discards is a work whose extraction is going badly, and that should be visible without reading a log.

**[decided]** A discard is not a deletion. The log keeps it, `loom refs why` reports it, and nothing is quietly lost.

### 5.6 Two claims, two commands

**[decided]** There are two different claims here and they must not share a word.

- **`loom accept <own key>`** says *I have proved this, or I am satisfied it holds.* It is the author's acceptance of the author's own mathematics.
- **`loom refs verify <proposal-id|key>`** says *this copy is faithful to the paper it came from.* It settles nothing mathematical, and someone else's theorem is not the author's to settle.

**[decided]** **`loom accept` refuses an external key outright**, and says which command to use instead. One word, one act. DR-172 noticed this collision and patched the *output* — printing `verified … as a faithful transcription` where the command said `accept` — which was right about the problem and too small a fix; `state_label()`'s `transcription verified` stays exactly as it is, and now a command's name agrees with it.

**[decided]** **`loom refs verify` takes either a proposal id or an existing digest key**, because both make the same claim and the difference between them is only which is the first time.

- Given a **proposal id**, it moves the node out of `digests/<citekey>.proposed.tex` into `digests/<citekey>.tex` and records the row. One act, not two: the author has just compared both texts on screen, and that is exactly what the row asserts. Splitting it into promote-then-accept would ask them to say the same thing twice.
- Given a **key already in the digest**, it records the row again. This is the case §5.7 creates: a transcription goes stale when the artifact or its page text moves, and re-verifying it is the author looking at the new page and saying it still says the same thing.

**[decided]** **Nothing moves a digest node into the author's own nodes**, and nothing should. Someone else's theorem is cited, not restated — contract §4.6 gives a digest node no proof obligation of its own, and an author who copies one has made a claim they now owe a proof for.

### 5.7 A verified node keeps its anchor

**[decided]** This is what finally gives DR-172's `transcription verified` something to be true or false about. Today it is a label with no check behind it. After this plan:

- **`loom refs recheck [citekey…]` re-reads the page text at each verified node's anchor** and compares it to the stored `source_text`, reporting what moved. It never re-verifies anything by itself: it raises the flag, and `loom refs verify` is the author answering it.
- **A changed span surfaces as `transcription-changed`**, the cause `records/store.py` already writes for external nodes.
- **A changed artifact surfaces as `version_mismatch`**, which `render/manifest.py` already computes and which arras already shows on both the references table and the digest page. Nothing new is needed for the case where the author swapped a preprint for its published version.

**[decided]** **A verified node's LaTeX is never re-checked.** Only the anchor's source text is. The rendering was judged by a person once; re-judging it mechanically would be claiming a check that does not exist.

## 6. Levels

**[decided]** `level` stays a field on every result. Two values are used.

- **Level 1**: the main results of the work. **Derived where there is a source** — results named in the abstract or introduction, highest in-degree in the internal graph, labelled "Main" — and **proposed where there is not**, because reading an abstract and judging which results are main is a model's judgement, which is tier 2 by §3 and not tier 1.
- **Level 3**: everything else.

**[decided]** **The level-1 gate stands, and it is a rule about order rather than about a derived fact.** `loom refs propose` refuses a non-level-1 proposal for a work with no level 1, saying to do level 1 first. For a PDF-only work the thing it waits for is *itself a proposal* — read the abstract, propose the main theorems — so the gate makes the opportunistic path start with a cheap bounded act rather than demanding something the machine could have derived. Reading it as a demand for derived data would make it circular, since the works needing the reading path are exactly the works with no source to derive from.

**[decided]** **Level 2 is not built.** It is the depth-1 closure of level 1 in the work's *internal* graph, and for a PDF-only work that graph is recovered from proof text ("by Lemma 2.3") — which is precisely the tier-2 work that has not been done yet at the moment someone would ask for level 2. A level-2 query against an empty graph either returns level 1 wearing a different name or reports emptiness, and a query with two failure modes and no successes is worse than no query. When internal edges exist in quantity, level 2 becomes a `--depth 1` flag over data already stored, and costs a day.

**[decided]** **Level 4 is dropped.** "The source itself" is not a level of digestion, it is `refs/<work>/src/`, and `loom refs path --src` already prints it.

**[decided]** Keeping `level` as a field while building only two of its values is deliberate: it makes level 2 a query later rather than a migration.

## 7. Asserted links: how the digest becomes navigable

**[decided]** The second purpose in §1 needs something the first does not: **a way for one paper's results to point at another's.** A digest of 22 papers that cannot say "this definition is the same notion as that one" is 22 separate documents in one directory.

**[decided]** A **link** is a typed relation between two identified results, with a reason.

- **A closed vocabulary**: `same-notion`, `generalises`, `specialises`, `depends-on`, `contradicts`. Closed because an open one becomes prose with extra steps, and because a viewer can only draw what it can name.
- **Two endpoints**, each a result id in some digest — verified or proposed, in this quilt.
- **One or two sentences saying why.** Not optional: an untyped, unexplained edge is noise, and the sentence is what an author reads six months later.
- **Attributed to the run that wrote it**, like every other record.

**[decided]** **Links are written freely, not proposed.** An assertion about a relation between two results has no page span to check it against, so a verification step would be theatre. They are tier 3, they say on their face that they are assertions, and they are never citable, never in a closure, and never in `digests/<citekey>.tex`. They are navigation, not mathematics.

**[decided]** **No standalone notes.** A record with one endpoint or none is a prose summary, and prose summaries are the thing this layer does not store. If it is worth saying, it is worth saying about a pair.

**[open, 12.4]** The author's observation, recorded because it is right and because it is the natural next step: *"these two definitions are identical" is actually verifiable by viewing the two source texts.* It is — by a person reading both, and eventually perhaps by a machine comparing them. What this version builds is the reading: **a link's two endpoints open side by side, each with its source text and its page**, so the judgement is cheap to make. That is a human check, and this plan claims nothing more.

**[decided]** `digests/links.jsonl` is quilt-level rather than per-digest, because a link's two ends are usually in two different digests and a record that lives in one of them is misfiled half the time.

## 8. The CLI

**[decided]** Every new verb goes into the existing `loom refs` group (§0.2). Everything prints JSON under `--json`; every list-returning command takes `--limit` and states truncation on its face.

| command | status | purpose |
|---|---|---|

## 9. arras

### 9.1 A seventh view

**[decided]** The rail carries six views today — home, read, graph, review, problems, references. This plan adds a seventh: **digest**, at `/digest`, for navigating what the quilt knows about other people's papers. (`/digest/<citekey>` already exists as a single work's page and becomes this view's detail route.)

**[decided]** What it holds:

- the works, with coverage and cited-by count, ordered by `cited_by`;
- one work's results in document order, each with its state;
- proposed nodes **merged in place among the verified ones, flagged**, with links to them drawn normally (§5.2);
- §7's links, both from a result and as the thing that makes two works adjacent;
- a filter.

### 9.2 The graph stops carrying the literature

**[decided]** **Nodes that are in a digest but not in the quilt no longer appear in the graph view.** The graph is what the author wrote and how it hangs together; a hundred external nodes from one wholesale extraction is not that.

`reachedExternal` is called from three routes today — `graph`, `review` and `digest/[citekey]`. This removes the first call. The function keeps deciding the other two: which external nodes belong in the review queue, and which of a digest's results fold away when reading it. Its docstring says it decides three things and must be corrected to two.

### 9.3 The bulk panel is a filter, not a surface

**[decided]** The backlog view of proposals is **the digest view with its filter set to `proposed`** — one route, one data path, two densities: browse mode for discovery, list mode for working through a pile.

**[decided]** **It is not `/review`.** That route is about the quilt's own keys and their acceptance states; its columns are state, cause, since, blocks and reached-by. A proposal needs both texts side by side, the anchor, the page and the proposing run, and shares no column with it. DR-172 has just finished separating the literature out of `/review`, and putting proposals there would remix exactly what was separated.

### 9.4 Writes

**[decided]** Two new write-API endpoints beside the existing six, and three routes through them:

- `POST /_api/digest-verify` with `{node}` verifies as proposed; with `{node, statement}` it is edit-then-verify.
- `POST /_api/digest-discard` with `{node, reason}` discards.

**[decided]** `VerbRow.svelte` is reused rather than reimplemented: it already opens its panel above the row so the body being discussed does not move, already puts undo where the button stood, and already folds to a `⋯` menu in a narrow container. A proposal's box gets the same component with a different verb set.

## 10. Build order

**[assumed]** Each stage is usable alone. Stop and use it before starting the next.

**[decided]** **The plan is not complete at stage 8.** §15's five iterations and §16's report both gate completion: the code is the middle of this plan, not the end of it.

0. **`loom refs build`.** The composite of §4.4 and the four verbs under it — `refs resolve`, `refs fetch`, `digest extract`, `refs map` — plus `refs match` listing what needs a person. *Done when relloc's mechanically-extracted work count has gone from 1 toward 15, and when a wrong candidate is rejected on arrival rather than filed.* **This stage comes first because it decides how much of the rest is needed**, and it is the only stage whose output makes later stages smaller.
1. **Map.** `refs map`, `pages/`, `sections.json`, `refs coverage` reporting "none" everywhere, over what stage 0 could not get a source for. *Done when `coverage` prints a section list for each work that has a PDF and no source.*
2. **Read.** `refs page`, `refs grep`, `refs locate`, boxes written on demand. *Done when an agent can find a phrase across the corpus and read the page it is on, and the committed page text is under 2 MB.*
3. **Propose and verify.** `refs propose`, anchor verification, rejection with the page text attached, the level-1 gate, `results.json` on contract §9, the `proposed` state in the manifest, the discard log, `--supersedes`, `refs why`, `refs drop`. *Done when a bad quote is rejected with its page in the same turn and a good one lands as a proposal that no compile can see.*
4. **The digest view.** The seventh button, the work list, results in document order, proposals merged and flagged, both texts on every verification surface, verify / edit-then-verify / discard through the write API, `?show=proposed` as the bulk filter, and the graph stops drawing external nodes. *Done when an author can walk relloc's digest and dispose of a proposal in place, and `loom lint` warns on a `\cite` to a proposed node.*
5. **Links.** `refs link`, `links`, `unlink`, `digests/links.jsonl`, links drawn in the digest view, and a link's two endpoints openable side by side with their source texts. *Done when the digest is navigable between papers rather than within one.*
6. **Re-verification.** `loom refs recheck` re-reading anchors, `loom refs verify` answering it, `transcription-changed` raised from a real comparison, `version_mismatch` surfaced on a verified node. *Done when `transcription verified` is a claim a command can falsify.*
7. **Find, and ordering by demand.** `refs find` over stored results with coverage in every answer; extraction and proposal ordered by `cited_by`. *Done when the worked example in §13 runs end to end.*
8. **Ingest.** `refs ingest` over a pile of PDFs, the matching signals, and `refs match` grown from stage 0's list into the full review surface. *Last, because a quilt's PDFs arrive a few at a time through `refs add` and `refs fetch`, so bulk matching is a convenience rather than the path.*

**[decided]** The minimal end-to-end path is stages 0 through 4: resolve and fetch what the bibliography can reach, extract those mechanically, map what is left, let an agent read and propose against it, and meet the proposals while browsing. Everything after that makes it better rather than making it work.

## 11. What this plan does not build

- **`index.sqlite`, or any database.** Files are the truth, and a quilt's bibliography is tens of works rather than thousands, so search is a scan over `results.json`. This follows from the bounded work set (§2), not from a rule against indexes.
- **A frontier.** Expansion by subject or category, ranked neighbourhoods, hauls, closed-neighbourhood extraction, a queue of proposed new works, a `rank` report. These are what DR-144 actually removed, and §2's test is what keeps them out: every one of them adds a work the author did not cite.
- **A rate budget, a scheduler or a background fetcher.** Not because loom may not use the network — it does, at §4.3 — but because a bounded work set gives nothing to schedule.
- **`hypotheses` splitting and `find --mode hypothesis`.** The sharpest search mode and the most error-prone extraction; deferred until whole-statement scoring is shown insufficient on a real digest.
- **`ref extract` and `ref cite`.** Both exist (§0.3, §8).
- **`ref propose edge` for PDF works.** Internal edges recovered from proof text are what level 2 would need, and level 2 is not built (§6).
- **Level 2 and level 4.**
- **Standalone notes**, and any store of agent-authored prose (§7).
- **An identity ledger.** weft keeps append-only identity assertions with evidence and a union-find over `same-as`, because nothing in a gallery declares what a work is. A quilt has an author, and **the bibliography entry is that declaration** — so loom keeps declared identity (`refs/identity.py`) and a service's answer stays a candidate (DR-122).
- **A crawl, a frontier, a ranked queue, a scheduler, a background process, or a proposal queue for new works.** All of these are weft's, and the boundary in §2 is what keeps them there.
- **Any path by which a proposal reaches a compile, a closure or a citation before an author has verified it** (§4.1).
- **Any sync with a gallery.** §2 fixes the seam's shape; the mechanism waits until weft exists and the quilt-local layer has been used for a while.

## 12. Open questions

**[open, 12.1] Ids for PDF-derived results.** Contract §3.2 answers the numbered case (`<prefix>-<abbrev>-<number>`) and the unnumbered one (`<prefix>-<abbrev>-star-<n>`). What it does not answer is per-chapter numbering, and books where "Theorem 4.1" recurs. Options: a chapter-qualified local part, or a content hash. Decide against a real book before a rule is written.

**[open, 12.2] The matching auto-accept threshold.** An experiment, not a decision: run the signals over a real pile, score by hand once, choose from the measured error rate. Two agreeing signals auto-accept until then, and everything else goes to `refs match`. Stage 8, so there is time.

**[open, 12.3] Whether section detection is good enough for books.** The section map is what turns "pages 210–240" into "chapter 4". Heuristics tuned on papers may not survive a monograph, and relloc's bibliography has at least one.

**[open, 12.4] Machine-checkable links.** §7's link kinds are asserted. `same-notion` between two definitions is in principle checkable by comparing two source texts; so, more weakly, is `contradicts`. Not this version — but the anchors this plan stores are what a later version would need, so nothing here forecloses it.

**[resolved, was 12.6] `loom accept` refuses external keys.** Decided 2026-09-18. The claim it was making about them moves to `loom refs verify`, whose name matches the `transcription verified` label loom already prints (§5.6). `loom accept` is left with exactly one job: the author's acceptance ledger for the author's own paper. This wants a deviation record against DR-172, which patched the output where the command needed splitting.

**[open, 12.5] What an author does with a proposal they neither accept nor discard.** Today it stays proposed forever, which is fine and is what a filter is for. If proposals accumulate faster than they are met, a staleness signal may be wanted. Measure before building.

**[resolved, was 11.1] Where the store lives.** §4, on the digest contract's own shapes.

**[resolved, was 11.3] How the layer learns what the quilt cites.** `result.edges.cites`, which loom already parses (§0.7).

**[resolved, was 11.4] What an anchor means to a coauthor with no PDF.** Page text is committed, so the anchor is fully re-checkable without one (§4.2).

**[resolved, was 11.6] Licensing.** Recorded in the digest header per contract §7.3, enforced by nothing (§4.2).

|---|---|---|

**[decided]** **The study quilt is built outside the repository and is disposable.** It is created in the session's scratchpad, destroyed at the end of every iteration, and never committed — 25 third-party PDFs are exactly what §4.2 says a repository does not carry, and a path inside `demos/` would need a new `.gitignore` rule to make that safe. Outside the tree it is safe by construction. `demos/relloc/` stays as it is: the small committed example, untouched by this.

**[decided]** **Hermetic, per AGENTS.md.** Every compile in the loop runs against the study quilt's own tree with `TEXMFHOME` pointed inside it. A digest must not extract because a macro happened to be defined elsewhere on the machine.

### 14.1 Why this seed and not a clean one

**[decided]** It is worth naming what makes this corpus a good test, because a tidier one would pass and teach nothing.

- **25 PDFs against 22 entries.** At least three match nothing. `relativelocalization.pdf` is the author's *own* paper, which is the adversarial case for matching: it will fuzzy-match half the bibliography on subject and none of it on identity.
- **Filenames that are not titles.** `Virtual_classes.pdf` says nothing. `Gross and Siebert - American Mathematical Society.pdf` and `Siebert - Punctured Logarithmic Maps  Contents  EMS Press.pdf` carry a publisher's page title rather than a paper's. Matching that leans on the filename fails here, which is the point.
- **Two arXiv ids declared, ~15 resolvable.** §4.3's whole claim, on the corpus it was measured on.
- **Two JSTOR `eprint` fields**, which is how the 2-versus-4 miscount happened in the first place. A signal that reads `eprint` without reading `eprinttype` gets this wrong, and this seed will catch it.
- **A book and several long papers**, so §12.3's question about section detection past a monograph gets asked for real.

## 15. The bug-testing loop

**[decided]** Run after the implementation is complete. **Five iterations**, each seven steps, each starting from nothing.

1. **Fresh quilt.** `loom init demos/.study/relloc`; copy in `refs.bib` and the 25 PDFs; `loom refs build`. Record what stage 0 produced before an agent has seen anything.
2. **Author's role, one agent.** Spawn a Sonnet-level agent at medium thinking with plausible-author instructions — real questions about the mathematics, not instructions about loom. The agent should have to *discover* the digest, not be told to exercise it.
3. **Three runs, 3–6 queries each, reattaching at least once.** The reattach is a second test riding along: a run resumed mid-conversation must see its own earlier proposals, and a `--supersedes` chain must survive the gap. **Two ways of spawning, and the order varies** (§15.1).
4. **Investigate** (§15.2).
5. **Findings, then a change list** (§15.3).
6. **Implement the fixes.**
7. **Delete the quilt** and return to 1.

**[decided]** **Each iteration starts from an empty quilt and a rebuilt loom.** The digest must not carry over: a loop that accumulates state stops testing the cold path, which is the path every new user is on.

**[decided]** **What carries between iterations is the record, not the data** (§15.4).

### 15.1 How the agent is spawned, and when to stop a run

**[decided]** **Both ways, every iteration.** Of an iteration's three runs, **one is a plain subagent** and **two are started through `loom ai start`**. The two are testing different things and neither substitutes for the other: a plain subagent tests whether the commands are usable by something that was told nothing, and a `loom ai start` run tests the orientation, the run directory, the permission deny-list and the reattach — which is where §15.3 expects the largest category of defect, and which a plain subagent cannot exercise at all.

**[decided]** **The order varies between iterations**, so that neither way is always the one meeting a cold digest. Three positions and one plain run give exactly three orders; five iterations cycle them:

| iteration | run 1 | run 2 | run 3 |
|---|---|---|---|
| 1 | `ai start` | plain | `ai start` |
| 2 | `ai start` | `ai start` | plain |
| 3 | plain | `ai start` | `ai start` |
| 4 | `ai start` | plain | `ai start` |
| 5 | plain | `ai start` | `ai start` |

**[decided]** **The escape hatch: kill a meandering or stalled run rather than burning compute on it.** Three to six queries is the plan, not a quota — if the agent starts wandering, or the loop hangs or freezes, stop the run there.

**[decided]** **A killed run still counts and still reports.** Its partial data goes into the measurement table, **the fix list is still compiled from it, and those fixes are still implemented.** A run that had to be killed is itself a finding: something made the agent wander or the machinery stall, and that is worth more than the queries it did not get to. The iteration continues; it is not restarted.

### 15.2 What the investigation asks

**Screenshots of the arras view are part of the answer, not an illustration of it.** A question about whether something is easy to do is answered by looking at it.

**[decided]** **What this loop cannot answer, and must not pretend to.** §5.2's central bet is that an author browsing the digest meets proposals in place and disposes of them where they stand, rather than working a list. **An agent impersonating an author is no evidence either way** — it does not read out of curiosity, does not wander, and does not have the subject on its mind for its own reasons, which are the three things the bet rests on. So the loop does not ask the question, and no result from it may be read as confirming or refuting §5.2. That decision needs the real author using the thing over real weeks, and until then §5.2 stands on its argument alone.

*The surface:*

1. Can you easily verify, discard and edit proposed nodes?
2. Was both-texts-side-by-side actually enough to judge by, at the sizes the viewer renders them?

*The agent:*

4. Does the agent know how to use the digest? Did it discover it unprompted, or never find it?
5. Did the agent reach for something it was unable to do?
6. What did it do when the digest was silent — fall back to `grep`, or answer from its own memory as though the digest had spoken?
7. Did it propose against works that **already had a mechanical digest**? That would mean §4.3's ordering is not reaching the agent, and effort is going to the trunk instead of the tail.
8. Did it re-propose something discarded, and was the refusal legible enough to act on in the same turn (§5.5)?
9. Did the level-1 gate help, or just get worked around?
10. How many pages did it read per proposal it produced? A bad ratio means `find` and `grep` are not steering.
11. What did the digest cost it in context? The caps in §8 exist for this and have never been measured.

*The claims:*

12. **Of the proposals verified, how many needed an edit first?** This single rate is the best evidence for or against §5.4, and for whether the anchor check is catching what it is supposed to catch.
13. Did anything false verify anyway — a `source_text` genuinely on the page under a `statement` that renders it wrongly? That is the failure the anchor cannot catch and the whole verification step exists for.
14. Did anything reach `digests/<citekey>.tex` that had not been verified? §4.1 claims this is structurally impossible; verify it rather than assuming it.
15. Were any links written, and was any link ever **used** to navigate? §7's entire justification, and the easiest thing in this plan to build and never need.
16. **Did run 3 benefit from run 1?** Ask a question in the same area early and late, and compare calls-to-answer. §13's closing claim is that the gradient is the point of the layer; this measures it or refutes it.
17. Did `loom refs build` re-run cleanly, and did adding one bibliography entry do work proportional to one entry?

### 15.3 The change list

**[decided]** Findings become a change list, and every item lands in exactly one category. The first three are the author's; the rest were added because iterations 2 through 5 are wasted without them.

| category | what it is |
|---|---|
| **bug fix** | it does the wrong thing |
| **new feature** | the capability is absent |
| **bad feature** | it works as designed and the design is wrong |
| **documentation defect** | the orientation, a mode template or a help string told the agent something false or left something out. The fix is prose, and CLAUDE.md's ten passes govern it. Expected to be the largest category, and the one most often misfiled as a bug. |
| **missing affordance** | loom can do it; the agent could not find it. The fix is discoverability — help text, the command tree, `loom status` — not code. Cheap, and invisible inside "new feature". |
| **wrong default** | the capability works and its default value made it useless. The cheapest class of fix there is. |
| **design decision to revisit** | the loop falsified something this plan asserts. **Goes to a deviation record and to the author, never fixed unilaterally** — an implementer quietly overturning a decided rule is how a plan stops meaning anything. |
| **confirmed good** | it worked, and must not break later. This becomes the regression list, without which iteration 4 breaks what iteration 1 fixed. |
| **won't fix, with the reason** | so iteration 3 does not rediscover and re-propose what iteration 2 rejected. |

### 15.4 What carries between iterations

**[decided]** The quilt is destroyed; the record is not. Three files live in the workspace and grow across all five iterations:

- **the change list**, cumulative, each item tagged with the iteration that found it and the one that fixed it;
- **the regression list** (`confirmed good`), checked at the start of every later iteration;
- **the measurement table**: one row per iteration carrying the numbers from §15.2 — works resolved, sources fetched, digests extracted mechanically, proposals made, verified, edited-then-verified, discarded, pages read per proposal, and calls-to-answer early against late.

**[decided]** **The measurement table is the real output of the loop.** Five rows of the same numbers say whether the layer got better, and a list of fixed bugs does not. If proposals-needing-an-edit does not fall across the five iterations, something in §5 is wrong that no individual bug report will name.

### 16.3 What the report must say plainly

**[decided]** Four things, each of which a report is tempted to soften:

1. **Whether the gradient is real.** §13 closes by claiming each question is cheaper than the last. Table 1's last column either shows that or does not, and the report says which in one sentence near the top.
2. **Whether proposals-needing-an-edit fell across the five iterations.** If it did not, something in §5 is wrong that no individual bug report will name (§15.4), and the report says so rather than listing the bugs it did find.
3. **Every claim the loop falsified**, with the deviation record it wants. A design decision overturned by evidence is the most valuable thing the loop can produce and the easiest to lose in a list of fixes.
4. **What was not tested and why**, §15.2's preamble included. A limit stated is a limit; a limit omitted reads as a claim.

**[decided]** **The report is written for the author, and says what it found rather than what was built.** A list of implemented features is the plan restated; the report exists for what the plan got wrong.
