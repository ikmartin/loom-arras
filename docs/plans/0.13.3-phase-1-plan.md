# Plan 0.13.3 · Phase 1 — the side panel

## Context

Plan 0.13.3 (first section, `docs/plans/0.13.3-reading-ui-improvements.md` §S1–S9, §Delivery Phase 1) redesigns reading mode in three phases. Phase 1 is the side panel: the session list leaves the scrolling column for a pinned footer that states the write target and opens a picker popover; the annotation filter moves out of the list to a rail above the content; the contents open by default; the explanatory paragraph and the counts line go; and one `Popover` component replaces six hand-rolled floating surfaces. It is self-contained and builds the `Popover` phases 2–3 reuse. The annotation filter will move a second time in phase 2 (into the frame's global rail) — expected, per the plan's risks section.

Decisions taken with the author (2026-09-22):
- **Filter home:** the layout draws one `ReadingRail` above the content on every reading route, filter at its left; pages register their own controls into it. No route loses the filter.
- **Row verbs:** ✎ ⏹ ✕ sit over the row's right end behind a gradient in the row's colour, shown on hover/keyboard focus and always on the selected row (the W4 pattern).
- **Leftovers kept quietly:** `display closed sessions` stays inside the picker's CLOSED fold; purpose / participants / attached go into the row's `title`, and `attached` also shows as a small marker.

Decisions I am taking (each small, stated so they can be overruled at review):
- `sessionView.pick` stops toggling; `select none` is the one detach path (`clear()`). A row click selects and closes the picker.
- **S6 + the refused mockup:** `NoSession` shows `writable()`'s sentence inline, permanently, beside the refused control, in warning ink; the control is truly `disabled`. The timed tip goes.
- **P2:** the discussion pane's `writing to <name>` line (`discussion-into`) is deleted; the footer is the one place that names the write target.
- **S9:** the `problems` view's icon moves to the strip's foot above settings, tinted red on errors / amber on warnings, with `N errors · M warnings` as its title and accessible name. The node count goes.
- **S2/S3, approximated until `workspace.current` exists:** the contents tree is open by default and drawn only on a document route (`/master`, `/canon`); elsewhere no tree.
- **Dead code:** `shell/RailSections.svelte` and `shell/DocumentPicker.svelte` are imported by nothing (shell A is retired); deleted, since the former imports `SessionPicker`.

## Work

### 1 · `Popover` — `arras/src/lib/components/Popover.svelte` (new)

One component, two modes, both closing through the existing `dismiss` action (`src/lib/dismiss.ts`), no animation.
- **anchored** (default): props `trigger: Snippet<[{ open: boolean; toggle: () => void }]>`, `children`, `open` (`$bindable`), `placement: 'above' | 'below' | 'right'`, `align: 'start' | 'end'`, `width?: number`, `label`, `testid`. Wrapper holds trigger + body so `dismiss` containment works; the body is `position: fixed`, placed from the trigger's `getBoundingClientRect()` on open and on resize, clamped to the viewport. Fixed positioning is what lets the 320px picker escape the panel's `overflow: hidden`.
- **modal**: `modal` flag, no trigger; renders backdrop + centred dialog through `portal` (`src/lib/portal.ts`), `role="dialog" aria-modal`.

Migrate the six call sites, keeping every `data-testid`: `shell/Settings.svelte`, `shell/DevShelf.svelte`, `components/HelpDot.svelte` (anchored); `sessions/DeleteSession.svelte`, the expanded dialog in `graph/LocalGraphPanel.svelte`, `components/PdfViewer.svelte` (modal). Their per-site box styles (shadow, radius, border) move into `Popover`; content styles stay.

### 2 · The rail above the content

- `shell/acts.svelte.ts` (new): registry `{ lead: Snippet | null; acts: Snippet | null }`, the same pattern as `shell/rail.svelte.ts`.
- `shell/ReadingActs.svelte` (new): a page's registrar, the `PageRail.svelte` pattern (set on mount, clear on leave), taking `lead` / `acts` snippets.
- `sessions/SessionFilter.svelte` (new): `showing annotations from [this session | all]`, one segmented control; `show-current` disabled with nothing selected; writes `sessionView.view` + `save()`. Logic lifted from `SessionPicker`'s `.showing` row.
- `shell/ReadingRail.svelte`: loses its props; renders `SessionFilter`, then `acts.lead`, then `acts.acts`.
- `routes/+layout.svelte`: renders `<ReadingRail />` above `children` when `page.route.id` is one of `/master/[stem]`, `/canon/[stem]`, `/node/[...key]`, `/library/[citekey]`, `/thread/[id]`. It stands outside `Beside`, as master's rail already does.
- `routes/master/[stem]/+page.svelte`, `routes/canon/[stem]/+page.svelte`: replace their `<ReadingRail>` with `<ReadingActs>` carrying the same snippets.
- `routes/library/[citekey]/+page.svelte`: the `.top` band's contents move into `<ReadingActs>` (`Tabs` as lead; `PdfTools` + `BesideToggle` as acts) so a work does not carry two bands; `.page.reading`'s full-height calc subtracts the rail's 36px.

### 3 · The session footer and the picker

- `sessions/SessionFooter.svelte` (new), pinned at the panel's foot outside `.sections`. A `Popover` (placement above, align start, width 320) whose trigger is one button: state dot, name, fresh count pill (`summary().fresh`), chevron. Tone from `writable()`: `''` → no fill, blue dot, ink name; otherwise amber fill, hollow ring, warning ink, name or `no session selected`. It carries only the state. `data-testid="session-footer"`.
- `sessions/SessionPicker.svelte` becomes the popover body (the `.showing` row, `.foot` paragraph and `DeleteSession` inline usage adjusted):
  - find field (narrows rows by title/purpose) + `+ new`, which swaps the field for the title input and calls `openSession` (`sessions/new.ts`); `session-new` / `session-new-title` testids move here from `IconStrip`.
  - `WRITING INTO`: open sessions via `grouped()` (already recent-first). Row: dot, name, `N open` / `nothing open`, `when(s.opened)` (`sessions/when.ts`). Click → `sessionView.select(id)` and close.
  - `CLOSED (n)`, folded (`show-closed`); inside it the `display closed sessions` control (`closed-no` / `closed-yes`) and the rows, each carrying `⟳` (reopen, then select — S8).
  - verbs ✎ ⏹ ✕ as an overlay (decision above); rename immediate by an optimistic local title shown until the manifest's title matches.
  - `select none` (`session-none`) → `sessionView.clear()`.
  - row `title` = purpose · participants · touched; `attached-{who}` marker kept.
- `sessions/sessions.svelte.ts`: `pick` → `select(id, m)` (no toggle, still admits closed); add `clear()`; header comment updated.
- `sessions/NoSession.svelte`: inline, persistent sentence while refused (`no-session-tip` testid kept); `say()` removed. Call sites `review/Composer.svelte`, `pdf/NoteAt.svelte` set `disabled` from `writable()`.
- `split/Discussion.svelte`: delete the `discussion-into` paragraph.
