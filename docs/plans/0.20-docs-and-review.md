# 0.20 — Docs and Review: the viewer's new frame

## Context

The author's ideas document (`docs/long-prompts/ideas.md`) and the open items in `docs/long-prompts/running-requests.md` asked for the leftmost rail to go, for nodes and the library to leave the side panel, for the graph to be reached from the small graph, and for reference links to open the source PDF. Discussed with the author on 2026-10-26, alongside the exploration rethink with the Quilt review session (no unnecessary friction, P14; the viewer is for reading and deciding, not conducting chat). Principles are cited by name; on the `design-rewrite` branch they live in `docs/design/principles.md`.

The author decided on 2026-10-26, in his words where quoted:

- **Retire the chat composer and agent launching.** "Retire both the viewer's chat box and agent launching. The viewer shows transcripts and takes annotations; conversations happen only in agent apps." `ai-config.toml` is deleted with them.
- **No icon strip, no Home.** "I have never once used Home, nor has anyone else as far as I'm aware." The viewer opens where the reader left off, else on the default draft, else, in an empty quilt, on a how-to-start page. Long term: "I'd eventually like to turn this into an application so that the CLI becomes completely optional for the human user."
- **Two primary views, Docs and Review,** as tabs at the top of the left column: "two tabs, 'Docs' and 'Review', and we expand 'Review' to really be 'review/management of everything in the quilt'." Review keeps its name ("easy to change later") and its page as built: "As built it is beautiful and should still be accessible."
- **The left column is for Docs.** Drafts and the agent's documents, a Library dropdown ("just make it a dropdown for now"; a dropdown whether or not the quilt has drafts), and the open document's outline in a section of its own.
- **Landmarks through a draft's history,** "rather than given a line in the toolbar".
- **One toolbar per pane,** under its tabs, each acting only on its own pane; the divider runs to the top of the window and the bar spanning both panes goes.
- **No view of all results.** "For nodes, I don't think a view is required; this is the function of the graph view. all nodes will be defined in exactly one document and should be viewed there." This became the viewer principle **V7, show a thing where it lives**: a statement is read in a document that holds it, a cited result on its paper's page, an annotation on the words it marks; a view apart from where a thing lives is only the fallback for a thing that lives nowhere a reader can open.
- **References open the PDF at the place.** A work's Digest tab leaves its views; "Digests are still useful to compute, and I think we'll use them for stuff later." Today's links are broken: they "often go to the digest which is not intended, or when they open the pdf they open the pdf at the beginning rather than at the proper location."
- **Agent documents written from scratch** (WQ-57, graduated here), taken in by starting a working document from one: "definitely (a), but I imagine the actual process will be closer to manually writing a document after learning from the ai document."
- **The annotation filter** splits: "this session / all" in the session picker, a one-word scope in the footer, "off" in each pane's view menu. **The development shelf** (threads, tags, taxa, not in a document) moves into settings.

## How this plan is carried out

One master document. Each phase starts in plan mode: the code is explored, the concrete changes are proposed and the author approves them; no phase gets a document of its own. When a phase is built and `scripts/verify full` passes, what was built is appended to **Implementation** at the bottom of this file, with its commits and anything that departed from the phase as written here. Arras changes are re-vendored into loom after their commit. Nothing is committed until the author says so.

## 0.20.1 · Retire the composer and agent launching

**Goes.** In arras: `sessions/Composer.svelte`, the composer and the marked-annotations tray (`PacketTray`) in `workspace/items/ChatView.svelte`, and every control that starts or stops a turn. In loom: the launcher in `agent.py` (the running-turn table, `PROMPT`, `AFTER_STOP`, the Claude and Codex presets), `[ai] launch`, `ai-config.toml` (the file, its template, the refusal of a tracked copy, its `.gitignore` line), `loom doctor --agents`, the turn handling in `cli/serve_cmd.py`, and the write-API actions only the composer and the launcher used. The orientation's and `ai/rules.md`'s sentences about being started for a turn go with them. The write suite's chat and launching tests are deleted with their features.

**Stays.** `loom session say`, which is how an agent writes the transcript; annotations written from the viewer into the selected session; the session footer and picker. A session's Chat view becomes its **transcript**, read-only, read beside the documents it discusses.

**Untouched here.** `loom session next`, `session watch` and the inbox: plan 0.21 (MCP) decides whether they survive. `.claude/settings.json` stays, since interactive sessions read it; the `--settings` preset goes with the launcher, and with it Quilt review finding 4 (a tracked settings file passed to a turn unchecked).

## 0.20.2 · Agent documents written from scratch

From WQ-57, which this plan carries. Every document in the agent's drafting directory (`[quilt] drafting_ai`) is an agent document, drafted or not, but loom refuses one no `copy` step made: `loom lint` reports `loom:agent-document-not-a-copy` as an error, and `loom adopt` and `loom ai refresh` refuse it for having no source. relloc fired the item's trigger: an empty `examples.tex` exists only so that an agent document could be copied from it.

- **Making one.** A command beside `loom draft DOC --ai NAME` (`--new`, or whatever plan mode settles under K1) writes a skeleton with the default document's preamble and records a step with no `from`, so the history still knows every agent document's origin. Writing the file by hand stays refused, which is what the lint guards.
- **Its ids.** Every result it defines is new, derived with no counterpart: the next free id plus `-ai`, as a result an agent adds to a copy is today.
- **Taking it in: start a working document from it.** A new document in the drafting directory with every derived id made plain, like `loom history restore`. Bringing it into an existing working document at a named place is not built. This is not WQ-53 (dropped 2026-09-28, adopting an agent's *copy* as a new document): a document from scratch has no draft to compare against, so a new document is the only place it can go. Since the author expects mostly to write his own document after reading the agent's, the action stays small, and reading the two side by side is what has to be good.
- **What does not apply.** `loom ai refresh` and `loom ai drafts`' "what moved" need a source; they skip such a document and say why.
- **The viewer.** It lists with the agent's documents; compare has no base for it, so it compares as two of the person's documents do; Incoming offers "start a working document from it".

Blast radius, from WQ-57: `scan/lint.py`, `history/ledger.py` (`copy_of`, a `copy` line without `from`), `reshape/copy.py`, `cli/history_cmds.py` (`draft`), `adopt.py`, `drafts.py`, the orientation and `ai/modes/draft.md`, arras's Incoming, `docs/specs/diagnostics.md`.

## 0.20.3 · The frame

**The left column** has two tabs at its top, **Docs** and **Review**, which choose the primary view; the column below is that view's.

- **Docs:** search (the palette, ⌘K, which also finds works), **Drafts** (the working drafts), the agent's documents under their directory's name, the **Library** dropdown (0.20.5), and the **Outline** of the focused pane's document in a section of its own below. Landmarks stay in this column until 0.20.6 gives them their home. Nodes and the library's full list leave it (V7). The graph page, opened from the local graph, registers its filters in the column as a page panel does today.
- **Review:** the page as built; the column's sections arrive in 0.20.4.
- **The header:** the quilt's name, the collapse control, and settings, which now holds the development shelf.
- **The footer,** in both views: the problems chip, coloured by the worst diagnostic and opening the problems page (Review's Problems section from 0.20.4); and the session footer. The annotation filter's scope, "this session / all", moves into the session picker beside the setting that admits closed sessions; the footer shows the scope in a word; "off" moves to each pane's view menu, with a key.

**The icon strip goes,** with its views list and home mark. **Home is retired:** `/` opens reading where it was left (DR-319-ikmartin), else the default draft, else, in a quilt with nothing in it, a **how-to-start page**: the steps to add a document or a paper, each showing its command now and built so that it can become a control once the viewer can take that step. The graph is reached from the local graph's expanded view.

**Each pane:** its tab strip at the top, the divider running to the top of the window, and beneath the tabs its own **toolbar**, drawn by every pane and quieter in the unfocused one, as its tabs are. The views (`Paper · Info`, a session's `Transcript · What it did`) move from the tab strip into the toolbar; the annotating tools, a work's fit, zoom and page, `view ▾` and the pin stand there as today. The bar across both panes goes. Compare-the-two-panes, the one control that reaches across panes, stays as a control in the focused pane's toolbar until 0.20.6 replaces it, so compare is never missing.

This reverses DR-299-ikmartin and DR-301-ikmartin (the toolbar drawn by the focused pane only, floating over the page; one rail above both panes), DR-118 (the panel never lists the views) and DR-229-ikmartin (the problems glyph carries the counts), and restates book 15.1 rule 1 as one persistent left column.

## 0.20.4 · Review: the quilt's management

Review's column lists its sections, each with a count of what waits for the author; the main area shows the chosen one.

- **Needs review:** the page as built, its queue included.
- **Incoming:** collaborators' pulls and agent documents to incorporate, and 0.20.2's "start a working document from it".
- **Library:** today's `/library` table (PDFs to file, unreadable works, proposed results, citation suggestions). A proposed result is verified against its quotation on the PDF page, since a work's Digest tab leaves its views (V7).
- **Sessions:** the transcripts, with close and delete.
- **History:** landmarks and steps, including landmarks no draft leads to.
- **Problems:** the problems page.

These are the author's own acts, the commands an agent may never run. They are moved here as they are today; making more of them controls belongs to the application direction, and each section is laid out so a command it names can become a button.

**Verifying proposed results is rebuilt here (WQ-55).** Today a proposal stands as a `ProposalBox` under its work's Digest view, which fails past a few proposals in one paper (the author, 2026-09-28, on Romagny's *Group actions on stacks*). Raw data leads: the result's id and the artifact's hash open each card. The rendering, which is what is being checked, is the narrow column beside the page image, and its text runs off and is clipped. A page image can draw blank, cause unknown; it is investigated first, and fixed on its own if it is a bug. The words the page does not have show as code chips under the card rather than marks in the text. Verify, edit and discard stand apart from what they judge, and discard asks for its reason only on the command line. And proposals are per paper, so the author finds them by opening each work. The section is designed against that list:

- one queue of every waiting proposal in the library, grouped by work, its count on the section;
- one result at a time at full width: the paper's words above, cropped to the region of the page that holds the statement, and the rendering beneath at the same width, compared by reading down;
- names, not ids ("Definition 2.3 · Romagny, *Group actions on stacks*, p. 7"), with the id and hash in a details fold;
- the words not found on the page marked in the rendering as compare marks changed words (DR-311-ikmartin), with one plain line ("3 words not found on the page");
- verify, edit and discard directly under the result, with keys to act and move to the next, and discard's one-line reason asked in place, since it is what `loom library propose` returns to the next agent that proposes the same result.

WQ-55 asked for a design study before code. This phase's plan-mode proposal stands in for it, drawing the states the study named: one proposal; one with mismatched words; a work with no readable copy (DR-198); a blank or failed page image; three works waiting at once; a result the author edited before verifying; a discard with its reason; at a full pane, a half pane and phone width, light and dark; and the keyboard path through ten proposals. It also settles whether the page crop comes from the quads the publisher already writes (`spans/…json`) or needs something new from `loom library update`'s map step.

**Applying a suggestion (WQ-27), whose trigger has fired:** relloc's simplify passes left 11–12 payloads each, and copying each by hand is now the slow part of a review. What is built today stops at preview and copy: a suggestion's payload shown beneath its anchor by its `placement`, with copy beside it. What this phase can add is what Review can show without loom writing the author's source (P7): the payload as a patch against the target's current text, refused when the text has moved since the annotation was written (WQ-27's `loom suggest show`), and the node compiled as if the suggestion were taken (`loom compile KEY --with ANNOTATION`, generalising `--with` from a proposal diff to a payload with a placement). Taking a suggestion resolves its annotation as applied with the resulting hash, so the next stamp records what changed and why. Applying the text itself stays the author's act outside loom, and WQ-27's editor code actions are not built here, since the editor clients are deprecated (WQ-49). Which of these pieces this phase takes is settled in its plan mode.

## 0.20.5 · References

- **The Library dropdown** in the Docs column: every work, filtered as it is typed, one row per work (a work cited under two keys is listed twice today), opening the work's PDF. Where it opens follows the one rule for every link (DR-269-ikmartin); plan mode settles whether a choice from the dropdown opens in the focused pane, as a side-panel click does, or beside it.
- **Every reference link opens the PDF at the place** (V7), and the digest only where there is no PDF or no located page. The phase starts with an inventory of every way a reference link is made and where each lands today: a citation's postnote in a document, `loom link` for a cited result or a work, `cited:` links with and without `#page=` or `#quote=`, links in annotation bodies and transcripts, and a hover against a click. Each case gets a test that it lands on the right page at the right place.
- **A work's views** become `Paper · Info`; digests are still extracted, verified and used to locate results.

## 0.20.6 · The history menu

- **loom publishes a landmark's draft.** The ledger's stamp line records the document stamped (`"in": doc`, `history/steps.py`); the manifest's landmark record (`CanonDoc`) gains it, additively in `docs/specs/manifest.md`. A landmark imported or put in the canon by hand has none.
- **A draft's toolbar** carries its history menu: the live text, then its landmarks, newest first. Choosing a landmark shows it in the same pane, read-only, its tab reading `main.tex · flows-v2`, with one choice back to the live text; and the menu compares the draft with any landmark, or with an agent's copy of it where one exists.
- **Then** the landmarks leave the Docs column: a landmark with no draft is reached from Review's History and from search; and compare-the-two-panes leaves the toolbar.

This is the smallest piece of WQ-25's history view, which stays open for the rest.

## For plan 0.21 (MCP)

The selection tool ("what am I looking at") reports where the reader is. In this frame that is one fact the workspace already holds: the focused pane's active item (`workspace.current`, an address in the reading routes' shapes), its place in that item (the block at the top of the pane, DR-319-ikmartin), the text selection if there is one, and the selected session. 0.20 keeps that one source of truth and reports it nowhere; 0.21 decides how it reaches `loom serve`.

## Out of scope

MCP and the bridge tools (plan 0.21); the fate of `session next`, `session watch` and the inbox (0.21); the agent's script rule (rule 7); code integration (deferred); a view of all results (V7: none); the library's thumbnail window; adding a paper from the viewer; the rest of WQ-25.

One rule for every link (DR-269-ikmartin) and a node opened where a document holds it (DR-280-ikmartin); reading is where it was left (DR-319-ikmartin); tabs accumulate and keep their place; the URL is the arrangement (DR-237-ikmartin); the select and box tools and the annotate chip; annotations land in the selected session; the settled control and `e`, `h`, `s`; and 0.19's speed: the divider drawn once a frame, a rebuild patching the page rather than replacing it.
