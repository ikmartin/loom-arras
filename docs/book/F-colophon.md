# Appendix F. Colophon

This book records a design, and it should record how the design was made, in the spirit of the paper that started it (arXiv 2609.05669, §1.2, "Use of artificial intelligence").

The design was developed over several days in September 2026 in a sustained conversation between Markas Hecht and Anthropic's Claude (Claude Fable 5.1), in a project workspace holding the relative localization paper and its references. The conversation began as a question about adapting one paper's block-based proof-development workflow and ended as the specification of two tools. Every decision recorded in Appendix A was made by the author; the model proposed, argued, checked names against package registries, searched for prior art (forester, the Stacks project, leanblueprint, org-transclusion, Quarto, MyST), and drafted. Several of the model's proposals were rejected outright by the author and are recorded as withdrawn terms and superseded records, which is the division of labour the source paper describes: strategy and judgement human, drafting and criticism machine.

The text of this book was drafted by the model from that conversation, in one pass, as a specification with every statement marked decided, assumed, or deferred. The author had not reviewed it at the time of drafting; the marks are there so that review can concentrate on what was assumed and what was deferred. Nothing in it had been implemented at that point. It was expected to be wrong in places that only implementation could find, and the plan (Chapter 13) made correcting it a recorded act rather than a silent one.

Tools used during the design conversation: Claude in a project workspace; web search for prior art and registry checks; a sandboxed shell for checking PyPI, npm, and GitHub name availability; the author's own site generator's documentation as the model of the marker protocol and of what a personal mathematical corpus needs.

No part of this book was produced by a hosted model on the author's behalf without the author present; the working method it prescribes for implementation (13.7) is the one used to write it.

The implementation followed on 2026-09-15 and 2026-09-16. It was carried out by the same model, Claude Fable 5.1, running as Claude Code in the workspace under the author's `/loop` directive: the agent woke, read the status table in `docs/demonstrations/README.md`, took the first milestone of Chapter 13 not yet demonstrated, built it, ran its demonstration, and recorded the commands, the output, and the test counts in that milestone's file before going on. Every departure from what this book said became a decision record, DR-39 to DR-80 in Appendix A, with a row in `docs/deviations.md`, before the code that made it was committed; the book was then revised, in the last step, to describe what was built, with each changed statement naming its record. The plan the agent worked from is kept verbatim in `docs/plans/implementation-plan.md`. The author's paper served as the acceptance test from a copy under the workspace, and nothing under the author's own notes was read or written.

Four things remained the author's, as the plan said they would, and are still open at the time of this revision: publishing to PyPI and npm, where the release checklist in `loom/docs/RELEASE.md` stops; the Overleaf test of the demo quilt (14.5); the external user's paper (criterion 10 of 2.3); and the Codex half of the M6 session, since Codex was not installed on the implementing machine. The tools used were `uv` for the Python side with `pytest`, `ruff`, and `mypy`; a fake TeX toolchain (`loom/tests/fake_latex/fake_tex.py`) that stands in for `latexmk`, `pdflatex`, `dvisvgm`, and `pdftotext` so the unit tier runs in seconds without LaTeX; TeX Live 2024 run in isolation, with an empty HOME and empty TeX trees, for the TeX and paper tiers and for every compile of the example quilts (`demos/hermetic.sh`); Node with SvelteKit, `svelte-check`, vitest, and Playwright on Chromium for arras; a headless Chromium script for the page check of the migrated paper; and GitHub Actions for both repositories, with the TeX tier in a TeX Live container.
