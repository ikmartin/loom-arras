# 14. Tests

This chapter lists the tests the MVP passes. It defines the tiers, the shim that makes the fast tier possible, the fixtures, the CI jobs, the Overleaf procedure, and then the tests themselves, grouped by chapter of the specification they verify. The names in 14.6 are the test functions and Playwright titles as they exist in the repositories, and `scripts/checks/book_tests.py` fails when one does not (14.7); where the book's original list named a test that was not written, the chapter says so.

## 14.1 Tiers

**[decided]** `scripts/verify` at the workspace root runs every tier that applies, and is the one verification command. `fast` is the inner loop: loom's ruff, format check, mypy and unit tier; arras's svelte-check and vitest; the docs checks: the work queue, and the agreement checks under `scripts/checks/`, each runnable alone and each printing what disagrees and the command that fixes it (`appendices.py`: appendices C and D equal the shipped `ai/rules.md`, `ai/modes/*.md` and `ai/orientation.md`; `fixtures.py`: the three copies of the conformance fixture, the two of `fixture-minimal`, and the committed demos equal their sources; `bundle.py`: every file the vendored arras bundle's `index.html` loads is present and not ignored, and `VERSION`'s interface is loom's, warning on an untracked file or a `-dirty` or outdated stamp; `book_tests.py`: 14.7; `hardwrap.py`: no prose added since the last commit, or in CI since the push's or pull request's base (14.4), is hard-wrapped, a ratchet rather than a sweep, since what is already wrapped is unwrapped when next edited). `full`, before a commit, adds loom's TeX tier and every arras Playwright suite. `paper` runs the paper tier by hand. `--only loom|arras|docs` narrows it to one lane, and `--steps` names the steps to run whatever their tier, which is how CI runs the TeX tier alone. Lanes run in parallel and the steps in a lane in order, except that arras builds once and then runs its four Playwright suites at the same time, each on its own copy of that build and its own ports; when loom's pytest runs beside those suites, it takes half the cores and the suites share the rest by weight, since each alone takes every core and together they starved the reading suite into timeouts; the result is one table of suite, result and seconds, the failing suites' output, and, outside CI, the branch's latest CI runs. Every deselection and skip is written in the script with its reason. The editor clients have no lane (WQ-49). The harness keeps `LOOM_PAPER_FIXTURES` and `LOOM_NETWORK`, the tier gates, and clears every other `LOOM_*` variable.

**[decided]** loom's tests run loom through one harness, `loom/tests/helpers.py`, and never through a local copy. `run` invokes the command in-process with exceptions let through, so a crash is a traceback and never an exit code; `ok` asserts exit 0, `exits(code)` an exit that is an outcome (a build or lint with an error diagnostic), `refused(code, match)` a refusal by its code and its message, and `json_of` parses stdout alone; each failure prints the command, its exit code, and its stdout and stderr apart. `edit` fails when the text it replaces is absent, `the` when the one row a test wants is missing or not unique, and `same_tree` names the first file in which two trees differ and the command that regenerates the expected one. A test never accepts a set of exit codes. The `poppler` marker gives a test the real `pdftotext` with TeX left as the shim. A test not marked `network` can open a connection only to this machine. `scripts/verify` runs every loom tier on pytest-xdist workers (`-n auto --dist loadgroup`), one process each, with nothing serialised. A setup that is expensive and repeated is made once per worker, lazily inside the first test that asks so that it stays inside the isolation, and each test changes its own copy: `templated` for the unit tier's imported-and-drafted quilts, and a TeX module's `once` fixture, whose tests are grouped onto one worker. arras's write and reading suites give every test that writes its own copy of the quilt's tracked files and its own `loom serve`, from a bundle built once per run (`arras/tests/served.ts`), so no test depends on another and both run on four workers.

**[decided]**

- Unit tier: `tests/unit/`, everything that needs no real LaTeX, run against the fake toolchain of 14.2; tests marked `poppler` run here too, with the real `pdftotext`, and skip where it is absent. `uv run pytest -m "not tex and not paper and not network"`, through `scripts/verify`, locally and in CI (14.4).
- TeX tier: `tests/tex/`, marked `tex`: bundles and the demo master compiled with the real toolchain, the reshape identity tests, the fallback preamble, the vendored fixture rebuilt and compared, and a smoke test of `latexmk`. `conftest.py` gives these tests the real `latexmk` and `pdftotext` directories on `PATH` and skips them when no `latexmk` is installed; HOME and every TeX tree still point at empty directories. In CI it runs in a TeX Live container (14.4).
- Paper tier: `tests/papers/`, the Manolache and ACGS fixtures. The module is marked both `paper` and `tex`, so its tests run only with the real toolchain and only when `LOOM_PAPER_FIXTURES` names a directory holding `0805.2065/` and `1709.09864/`; skipped otherwise, and never in CI.
- Network: one test, `test_fetch_writes_gitignored_dirs`, marked `network` and skipped unless `LOOM_NETWORK=1`; excluded from CI.
- Manual tier: the Overleaf procedure and the agent sessions. Run per release; results recorded in the release notes. The Claude Code session was performed at M6 on the demo quilt and at M7 as the referee runs of the relloc migration; the Overleaf procedure and the Codex session have not been performed (`docs/work-queue/closed/M7.md`).
- Arras tiers: unit (vitest: the specs beside the modules under `src/lib/` and the guards in `tests/unit/`); end-to-end (Playwright, `tests/e2e/`, on the vendored fixture, staged into the config's own copy of the built app by `scripts/bundle.mjs` and served by `scripts/serve-static.mjs`, which resolves paths as `loom serve` does; each config's directory and port are in `tests/sites.ts`, and `ARRAS_SLOT` shifts them so `scripts/verify` never meets a suite started by hand); minimal (`npm run test:minimal`, `tests/e2e-minimal/`, on `fixture-minimal`); write and reading (`npm run test:write` and `npm run test:reading`, `tests/e2e-write/` and `tests/e2e-reading/`, each test on a real `loom serve` over a copy of the synthetic quilt or the showcase, `tests/served.ts`); perf (`playwright.perf.config.ts`, by hand); screenshots (`npm run shots`, one run that writes the book's reference figures from the same fixture, 15.9); prerender (`npm run build:prerender` writes the static site of the fixture, but no test checks it and CI does not run it).

## 14.2 The fake `latex`

**[decided]** One script, `tests/fake_latex/fake_tex.py`, which `conftest.py` copies into a temporary directory under the names `latexmk`, `pdflatex`, `latex`, `lualatex`, `xelatex`, `dvisvgm`, `bibtex`, `biber`, `pdftotext`, `pdfinfo`, `kpsewhich`, and `pdftocairo`, and prepends to the test `PATH`. It parses the input enough to find `\newtheorem` declarations, sectioning, theorem-like environments, equations, and `\label`s through expanded `\input`, `\include`, and `\nest` (shifting levels under `\nest` as `loom.sty` does), emits a plausible `.aux` with sequential numbering by section, writes a placeholder PDF carrying the document's plain text so the fake `pdftotext` returns it (and a letter-sized page box for `-bbox-layout`), emits a fixed SVG for any `dvisvgm` call, and answers `kpsewhich` for a fixed list of system files. Every invocation is appended to the file `FAKE_TEX_LOG` names. `FAKE_TEX_FAIL=1` makes every engine call fail with a `! LaTeX Error` line and exit 12; `FAKE_TEX_FAIL_MATCH=<substring>` fails only the inputs whose path contains the substring, so a test can have the master compile while every bundle fails (`bundles/`). The shim is never found on the real `PATH`: it exists only in the per-session directory the fixture creates, and tests marked `tex` get the real toolchain instead. The shim is itself tested: `test_fake_latex_emits_aux`, `test_fake_pdftotext_round_trip`, `test_fake_latex_failure_injection`, `test_fake_dvisvgm_and_kpsewhich`.

## 14.3 Fixtures

**[decided]**

- `tests/quilts/sources/<name>/`: what an author wrote — the masters, the node files, the styles, the bibliography, the figures. Nothing under it is a quilt; it has no `config.toml`, so it is not picked up as one.
- `scripts/gen_quilts.py`: writes all three fixture quilts from those sources by running loom's own commands under a fixed clock, so that every record in a fixture — the acceptance ledger, the history, the sessions, the comments — was made by the command that makes one rather than typed. `--check` regenerates into a temporary directory and compares byte for byte; `test_the_checked_in_quilt_is_what_the_generator_writes` runs it for each, the demo and the showcase under the `poppler` marker because their generation reads page text with the real `pdftotext`. Editing a fixture by hand fails that test, and so does editing an asset the generator draws on (`assets/ai/*`, `assets/init/*`, `loom.sty`) without regenerating: that is the alarm it exists for. Nothing the generator writes may depend on the machine it ran on — no tool versions, no absolute paths, no author name from the environment — or the check could not run at all.
- `tests/quilts/demo/`: the quilt `loom init --demo` writes, asserted byte-equal to it by `test_init_demo_matches_fixture`; small; every command runs on it in well under a second on the shim. The generator writes it and `src/loom/assets/demo/` together, which is what keeps them equal.
- `tests/quilts/synthetic/`: the quilt described in `specs/fixture.md` §1; exercises every construct in the source contract and every diagnostic code the scanner emits on a quilt; the conformance fixture is generated from it. Its `EXPECTED-LINT.txt` is written by the generator from `loom lint --json`, and `test_the_synthetic_quilt_carries_the_intended_errors` pins the four errors it is meant to carry: two `dangling-link`, one `missing-include`, one `double-inclusion`, one `duplicate-id`.
- `tests/quilts/showcase/`: the quilt to open when you want to see what loom does, copied to `demos/showcase/` by the workspace's `demos/build.py`, as the demo and synthetic quilts are to `demos/demo/` and `demos/synthetic/`; `scripts/checks/fixtures.py` fails when a committed demo differs from the quilt it was copied from. Where the synthetic quilt exercises the source contract, this one exercises the records: an invented paper about balanced flows on finite quivers, two invented cited works whose PDFs are compiled by `sources/showcase-works/build.sh` and committed with the quilt (DR-194), a digest extracted from a source and a second built from proposals the author verified, annotations of every kind, severity and state with replies and `cited:` locators into both works, four sessions, one of them discarded, a landmark history with a stamp, a fork and a revert, and the three faults a quilt can be left in. `test_the_showcase_carries_the_faults_it_is_meant_to_show` pins those. It is regenerated after a feature lands, which is what keeps it a picture of loom today.
- `tests/quilts/edge/`: ten small quilts each isolating one hard case: `spanning-env` (an environment spanning files), `begin-not-alone` (a `\begin` not alone on its line), `cycle`, `double-inclusion`, `nested-nest` (a `\nest` inside a `\nest`), `macro-collision` (a digest with a nonempty macro block whose name collides with the quilt's), `taxon-conflict` (two masters declaring one environment differently), `beamer-talk` (a beamer master), `node-conflict` (two live files defining one id), `superseded` (a checked-in history ledger recording that a spine replaced its source).
- Every quilt above carries an `EXPECTED-LINT.txt`, the frozen `loom lint` output, which `test_lint_fixture_expected_codes` checks; `test_all_emitted_codes_are_known` checks that every code in those files is in loom's diagnostics table.
- `tests/fixture/`: the vendored conformance snapshot (`manifest.json`, `fragments/`, `svg/`, `diffs/`, `source/`, `transcripts/`, `VERSION`), refreshed by `docs/specs/tools/refresh-fixture.sh` in the workspace, which writes `docs/specs/fixture/` and copies it here and to `arras/tests/fixture/`; `scripts/checks/fixtures.py` fails when the three differ.
- `tests/fixtures/` in the workspace: the paper sources, uncommitted, with `NOTES.md` and `VERSIONS`.

## 14.4 CI

**[decided]** Five workflows in the workspace's `.github/workflows/`, each on push and pull request to the paths it names (`mirror-nvim.yml` on a push to `main` alone) and by hand. Three are the lanes of `scripts/verify` (14.1) and run nothing else, each with the arguments below, so CI and a terminal run the same steps; under `GITHUB_ACTIONS` the script prints a failing step's whole output and not the branch's CI runs.

- `loom.yml`, on `loom/**`, `scripts/**` and itself. The `unit` job runs `scripts/verify fast --only loom` over a Python matrix (`UV_PYTHON` from the matrix), with poppler installed so the `poppler` tests run rather than skip. The `tex` job runs `scripts/verify --steps "pytest tex"` in the `texlive/texlive:latest-medium` container, with poppler, and with the packages the TeX tier loads that the medium scheme lacks added by `tlmgr` (the job names them). The `install-from-clone` job runs `pipx install .` on a bare runner, then `loom --version`; checks that `loom doctor` exits 2 there because no TeX is installed, and with `jq` that its JSON says `ok` is false, names `latexmk` among the failing items, and finds the bundle `vendored` at the interface `src/loom/version.py` declares; then starts `loom serve` on a `loom init --demo` quilt in the background and checks that it serves the viewer and the manifest before stopping it.
- `arras.yml`, on `arras/**`, `loom/**`, `scripts/**` and itself; on `loom/**` because the write and reading suites serve with the real `loom serve` from the checkout, which the job installs (`uv sync` in `loom/`) with poppler, whose `pdftotext` the reading suite needs. Node 22 with npm's cache, `npm ci`, Chromium with Playwright's browsers cached under the locked `playwright-core` version, then `scripts/verify full --only arras`. The `bundle` artefact is the build that run's `build` step wrote, `arras/.tmp-e2e/slot-1/bundle`, which no suite stages a fixture into.
- `docs.yml`, on `docs/**`, `loom/**`, `arras/**`, `scripts/**`, `demos/**`, `AGENTS.md`, `CLAUDE.md` and itself: `scripts/verify full --only docs`. A clean checkout has nothing added since HEAD, so the job sets `HARDWRAP_BASE`, which `hardwrap.py` takes as its base: the pull request's base, or the commit the push moved the branch from, or where the branch left the default branch when there is neither (a new branch, a force push, a manual run).

`clients.yml` (on the three clients only) runs the loom-lsp, loom-nvim and loom-vscode suites of 14.6; the clients are deprecated and may break with any loom change (WQ-49), so a loom change does not run them. `mirror-nvim.yml` pushes `loom-nvim/` to its mirror repository only after calling `clients.yml` for the nvim suite. Not built: an Overleaf proxy job (compiling the demo and synthetic masters from the root with an empty environment), a publish job on tags, a prerender job, and a workflow running the dialect validator; the validator runs inside `refresh-fixture.sh` and in loom's `test_fragment_kinds_and_dialect_validity` instead.

**[decided]** CI checks out only what is committed, so a shipped file that is untracked or hidden by a workspace `.gitignore` line passes every local run and is missing in CI. `loom/tests/unit/test_tracked.py` fails locally on either, over `loom/src`, `loom/tests/quilts` and `arras/src`; a quilt's own `.gitignore` is exempt. `arras/tests/e2e-write/shots.e2e.ts` writes the committed pictures in `records/images/`, so `test:write` skips it and `npm run shots:write` runs it.

## 14.5 The Overleaf procedure

**[decided]** Manual, per release; not yet performed (`docs/work-queue/closed/M7.md`, "Blocked on the user"):

1. `loom init demo --demo`; `loom compile`; record `pdftotext` of the local PDF.
2. Zip the quilt without `build/` and the fetched artifacts under `refs/` (`refs/**/paper.pdf`, `refs/**/src/`); upload to a new Overleaf project; set `drafting/main.tex` as the main document; compile.
3. Download the PDF; compare `pdftotext` with the local one; equal modulo whitespace is a pass.
4. Record the Overleaf TeX Live version and the result in the release notes.

### Chapter 16: the editor clients

**[decided]** Each client keeps its own suite in its own directory of this workspace (`loom-lsp/tests/`, `loom-nvim/tests/`, `loom-vscode/src/test/`). The clients are deprecated and breakable until they are reworked (WQ-49): a loom change may break them and nobody holds it back for them. `.github/workflows/clients.yml` runs the three suites only on a push or pull request that touches a client; loom's own workflows and release checklist do not run them, and nothing in loom depends on them passing. `mirror-nvim.yml` runs the Neovim suite and publishes `loom-nvim/` only when it passes. Every suite opens the synthetic quilt's master at the path its `[quilt] main` names, never a fixed one, and fails once, naming the cause, when that file is missing.

- `loom-lsp` (`uv run pytest`): the server is driven in process against a copy of the synthetic quilt — the published diagnostics match `loom lint --json`, a dangling reference is an error at the command rather than at the line, an unsaved buffer produces diagnostics the disk does not justify and closing it takes them away again, definitions resolve for a reference and an inclusion, references find every site, hover carries the state, the symbol tree nests proofs under their statements, completion offers ids, directive keys, taxa and citekeys in the right places, a code action arrives as an edit for the missing `\uses` and as a confirmed command for the rest, Open in arras names the statement even from its proof, atomize and the id action are offered only where they apply and plan from the unsaved buffer, and workspace symbols, the call hierarchy and inlay hints answer. ## 14.7 Coverage rule

**[decided]** Every test named in 14.6 exists, and every diagnostic code in `specs/diagnostics.md` is emitted by at least one test on one fixture. A release with a missing test or an unemitted code fails the checklist.

The first half is mechanical: `scripts/checks/book_tests.py`, in the docs lane of `scripts/verify`, fails when a `test_*` name or a quoted Playwright title in this chapter names no test, when a test source it cites is missing, and when a test a "Not written" list names does exist. The second is held in part: `test_all_emitted_codes_are_known` keeps every code the fixture quilts emit inside loom's table (`loom/src/loom/scan/diagnostics.py`), and the fixture quilts' `EXPECTED-LINT.txt` files and the tests of 14.6 emit the codes; that the table equals `docs/specs/diagnostics.md` and that each code is emitted somewhere is checked by hand for a release. `loom:interface-version` is emitted by arras (`src/lib/manifest/loader.ts`), as the specification says, and tested by its loader spec. The codes no fixture carries have their own tests: `loom:documentclass-outside-drafts`, `loom:main-not-found`, `loom:foreign-annotations`, `loom:unknown-config-key` and `loom:non-utf8-source` in `test_lint_exit_codes`; `loom:bundle-failed` in `test_check_reports_a_bundle_that_fails`; `loom:atomize-target-exists` in `test_atomize_refuses_a_target_file_that_exists`.
