# 0.3: the arras redesign, loom 0.2, and the editor clients

The plan is `docs/plans/0.3-arras-redesign-and-editors.md`; the running record, including the design changes the work forced, is `docs/reports/record-2026-09-16.md`. This file is the demonstration: what was run and what came out.

## What was demonstrated

**Chapter 15 exists as software.** `arras` renders the three navigation shells of 15.2 from one component tree, with the default C and `?shell=` to compare. Every rail is a scroll container, which is the fix the ACGS paper needed: its contents rail holds 66 entries, 2765px of content in a 577px box, and scrolls. The contents tree is built from the manifest's `inclusion` record, which the viewer read nowhere before, with depth from a new `level` field on section nodes.

**Links into a document land.** The publisher emits a real `id` on `section`, `div.env` and `details.env-proof`; before this no fragment had a single anchor target. A contents entry scrolls the page, a heading carries the Stacks-project link to its node, and an equation reference lands on the equation rather than on nothing.

**The graph answers two questions.** Force, from `d3-force`, is the default and answers what sits near what; layered keeps ELK and answers what this rests on. One page, one selection, one filter set, with pan, zoom and drag. Two old faults died: a section that is an edge endpoint is no longer deleted along with its edges, and an edge's geometry is read from whatever container ELK placed it in.

**`see:` links two nodes and the mathematics never sees it.** On `demos/relloc`, `nodes/rl-000Y.tex` declares `% !LOOM see: lem:independence-for-honest-vector-bundles`; `loom deps` reports the relation from both nodes under "see also (not a dependency)", with no edge and no closure entry either way, and the viewer shows it on both pages with the documents that reach each.

**A plan is a master.** `demos/relloc/drafts/outline.tex` reaches two settled lemmas and one new conjecture; `status --master` reports the reach, `assemble` writes the whole plan into one 175-line file, and the conjecture's proof is `incomplete` until it is proved or refuted.

**Three editors.** `loom-lsp` answers diagnostics, definitions, references, hover, symbols, completion and code actions from loom's own entry points, with unsaved buffers as an overlay. `loom-nvim` attaches it beside vimtex, only inside a quilt; a headless Neovim asked the real server for a hover and a definition on the relative localization quilt and got both. `loom-vscode` activates only in a quilt, reaches *running* on that same quilt, and launches the browser rather than embedding a webview.

## What is not demonstrated

- The brainstorm mode's conversation. The mode file, the four blocks, the skill stub and `loom ai start brainstorm-residue` were all exercised; an agent session against them was not performed.
- The GitHub remotes for the three new repositories. They are local repositories with full history and are not pushed; the author creates the remotes.
- A hand-driven pass in the VS Code interface. The extension was packaged, installed from the `.vsix` into the real editor, and uninstalled again; everything else was driven by the integration harness in a real VS Code.
