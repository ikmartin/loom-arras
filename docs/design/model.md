# The model

What loom works with: the quilt, its documents, the nodes and graph read from them, the history, review and trust, annotations, the library of other people's work, notes, sessions, and the viewer that shows all of it. Formats are in `docs/specs/`; commands are in `loom --help`. This file says what the things are and why.

## The quilt

A quilt is a research project in a directory marked by a `config.toml` with a `[quilt]` table; every command finds it by walking up from the current directory. It may hold several documents, one, or none at all. A paper with a talk beside it is a quilt; so is a reading project with no draft, made of the papers and books someone is learning from.

What lives where:

- **The author's sources:** documents, node files, style files, the bibliography and figures, wherever the author keeps them. A document's files sit in its own directory or below, because a document compiles from its own directory (P12).
- **`.loom/`** holds everything loom writes: the acceptance ledger, the history and sessions; `annotations/log.jsonl`, the annotation log; `digests/`, the digests of cited works, the quilt's bibliography and loom's store of their documents; `reference-notes.jsonl`; `ai/`, what agents are given; `retired/`, sources `atomize --retire` set aside; `copies/`, the documents the author and an agent both edit (below), made when the first is; and `build/`, everything derivable, which can be deleted at any time.
- **`research-state.md`** at the root (the `research_state` setting) is the research state, written when an agent first keeps one.

`loom init` writes `config.toml`, a README that teaches loom, and `.loom/`, and nothing else. Every `.tex` file is scanned except under `.loom/` (whose digests and agent copies are read on purpose), the history and sync directories, tooling directories, and files whose first twenty lines say `% !LOOM ignore`. Nothing is inferred from where a file sits (P5); the exclusions are exclusions, not inferences.

**Open.** A quilt still assumes a paper in places: `status` counts "keys of yours". For the Learner, a quilt with only works and notes must be complete and unremarkable (not built yet, see [README](README.md#decided-not-yet-built)).

## Documents

A **document** is a `.tex` file with `\documentclass` anywhere loom reads, unless it is ignored or superseded. Every one is **live**: scanned, compiled, rendered and reviewable. There is no list of documents; the files are the list. A document is named by its path without `.tex`, kept as a path (`paper/main.tex` is `paper/main`), which keys its build output, its rendering and its address in the viewer, so two documents may share a file name in two directories. A document compiles from its own directory, so its `\input`, figures and bibliography are named from there and none reaches above it with `..`, and a node it reaches is numbered from that document's own compile. Its macros come from loom's marked block in its preamble, or from a `loom.sty` kept beside it. A document is read as TeX makes it: the viewer shows the HTML its compile made, with each node and block placed in the source by its words; after an edit, that HTML until the next compile, with each edited statement made again by TeX; and, until a compile has made any, or when its page lost a statement TeX4ht set where loom cannot find it (beamer's frames), its source, node by node, never an approximation of what TeX would print. Text no compile makes, a node no document reaches, a digest, a landmark, a comparison or a proposal, is made by TeX too, as snippets under the preamble of the document that owns it. `[quilt] main` names the **default document**, whose preamble and engine loom reads for its LaTeX work; unset, it is the only document, or none when there are several. `[quilt] home` names the **front door**, the file the viewer opens on when it remembers no place; unset, it is the quilt's `README.md`.

An **agent document** is one the history records as an agent's, kept in `.loom/copies/`. It is a flat copy of one of the author's documents, made by `loom draft DOC --ai NAME`, or of one labelled section and its descendants with `--section ID`, with every id it defines derived (`rl-0004-ai` for `rl-0004`) so it can never collide with the author's. Agent documents of one document may coexist when their scopes are disjoint: a whole-document copy overlaps every section and a section overlaps its descendants, and a section copy, or any later copy of a document, derives its ids with a numbered suffix never reused (`rl-0004-ai-01`). A section copy reads the rest of the paper in the context saved when it was drafted. The copy records the version of each node it began from, so loom can say when the author's side has moved past it (`loom ai drafts`) and refresh it (`loom ai refresh`). `loom ai close` retires one, keeping its text and annotations in the history and freeing its scope, and `loom ai reopen` brings it back. Nothing in an agent document is accepted or published. Taking its changes back is `loom adopt`, the author's act: it previews the changes, lets the author choose node by node, and the prose and the preamble each as a whole, stamps the working document first, and then writes (P7). A result both the author and the agent changed is merged line by line, and offered as merged when the edits fall apart; when they clash it can't be taken until it is reconciled. In the viewer, Review › Proposed Changes opens a copy's review, which is one pass: each change is taken or left in a bar that stays put, a block can be marked as checked so its acceptance is recorded as it is written in, and one Apply writes what was taken. A collaborator's pull is reviewed the same way but taken whole. A document written into `.loom/copies/` by hand, which no step made, is refused by `loom lint`. A document of an agent's own (a survey, a section to be placed later) needs no command: it is a file the agent writes where the quilt lets it ([agents.md](agents.md)), and is a document like any other. A copy is the way to work on a document the quilt protects from agents, or to give the author changes to choose among before any lands.

A **landmark** is a document as it stood at a moment worth returning to, and is a **version** of it: the paper as received by `loom import`, a working document kept by `loom stamp DOC -m NAME` or recorded by name in the viewer, and the version loom keeps at each of the author's acts on it (a change kept or undone in Your Changes, changes taken in, a restore). It keeps the document's flat text and, for a version kept now, each of its files' text. It lives in the history, is never scanned, and so defines nothing and collides with nothing. In the viewer each document's versions can be paged through, compared with now, and put back, the text a restore replaces kept as a version first; `loom history show` prints one, and `loom history restore` starts a new working document from it.

A conversion (`atomize`, `linearize`) records that its output **superseded** its input, which stops being scanned until `loom live` says otherwise. `loom mv` records a document's move, and every record naming it by path follows the move when it is read, without being rewritten.

## Nodes and the graph

A **node** is a theorem-like environment (declared by `\newtheorem`) or a section. It becomes addressable when its first label is id-shaped, `<prefix>-<local>` such as `rl-0004`; `loom id` prints the patch that adds one. Other labels on the same node are aliases. A **key** is what review is about: a statement (its id) or a proof (`rl-0004/proof`, `rl-0004/proof/2`).

An id is **defined once**. A file may be included by several documents, and its nodes then appear in each, numbered by each. But when an id is defined twice, by two files or within one, the key is **conflicted**: it has no text, loom reports both definitions and chooses neither, and `loom fork` gives one of them a fresh id. Loom never picks a winner, because any rule for picking one would let one definition's acceptance and annotations silently apply to another's text. An id that history has recorded is never allocated again.

**Edges** are read from what the author writes: `\ref` and its relatives, `\cite[Theorem 4.1]{key}` when a digest of that work has the result, and `\uses{…}` for a dependency the text does not name. The **closure** of a key is everything its statement depends on, transitively; `loom source KEY --closure` prints it as the exact context for reading, reviewing or drafting that key. A node no document reaches is **loose**, which is computed, never a directory. `% !LOOM see: ID` links two nodes for the reader and is never a dependency.

Two markers carry mathematical status in the source: `\incomplete{…}` marks a statement or proof as not finished, and `% !LOOM basis:` declares why a block may be relied on (a local proof, a cited result, an assumption, an open claim, or exposition). The exact rules are `docs/specs/source-contract.md`.

## History

The history (`.loom/history/`) records what loom was told, at the moments it was told: never on save, and never a claim about the filesystem (P13). A **step** is an import, a stamp, or the copy behind an agent document, numbered once across the quilt; each act of the author's that keeps a version (Review's Keep and Undo, taking changes in, recording one, restoring one) is a stamp of the document it concerns, unless the document is as its newest version holds it. Keep and Undo also write a line naming the file, so Review › The Record lists every act. A stamp records every key whose text moved since the last step; given a document, it also keeps that document as a landmark. A key's text at a step is a **version**, addressed `rl-0001@3` or `rl-0001@submitted`.

`loom revert KEY@N` prints the patch that puts a version back and records nothing, since the head's text says whether it was applied. `loom fork` gives one document its own copy of a node under a new id. Every divergence between the record and the files (an edited landmark, a missing step, an unreadable ledger, a step interrupted before it was recorded) is reported with the command that resolves it, and nothing stops a build. No step is recorded beside an interrupted one: every command that records a step refuses until its directory is removed.

## Review and trust

Two kinds of record say what has been looked at, and they never mix.

**Acceptance** is the author's claim that a key's mathematics is right. `loom accept` appends a row to the ledger (`.loom/state.toml`) holding hashes of the key's text, of every statement in its closure, and of the preamble, with snapshots of that text. Only the author accepts; an agent is refused whatever name it gives (`agents.md`). From the ledger and the current text, every key's state is **computed** (P3):

- `incomplete` when it contains `\incomplete`, whatever else is true;
- `accepted` when the latest row's hashes still match;
- `accepted, stale` when something has moved, with each cause named: its own text, a dependency (directly or through another), the preamble, its basis, or the document it was accepted in. `loom status --explain KEY` shows the diff;
- `conflicted` when two live files define it;
- `draft` otherwise.

On top of these, `proved` and `settled` are display states: a statement is proved when it and a proof are freshly accepted, and settled when everything it depends on is settled too. A cited result is a settled leaf by attribution.

Acceptance is personal: each reviewer's latest rows are their own, and a coauthor's acceptance never accepts for you. In the viewer, Review › Your Changes lists every block of the person's documents not freshly accepted, in dependency order, as changed since accepted, taken in from a copy or a pull, or, folded and uncounted, never accepted; **Accept** records an acceptance at once, for one block or a selection, and what loom cannot accept says why before anything is pressed. Overlooking a block never accepts it.

**A look** is the third thing Review keeps, and it says nothing about the mathematics: the text of every open file (one the viewer shows that is text, LaTeX included) as the person last saw it, kept in the history's texts and recorded by their name in `.loom/looked/`. Review's Your Changes shows what changed in those files since, with a diff, whoever made it, since loom cannot tell who: under the block a change touches, so a block is listed once with every reason it waits; apart, for text outside any block and for a file in no document. **Keep** takes a change into the look; **undo**, after asking, writes the file back as it was at the look, keeping its text now in the history first (P7), and removes a file new since it. Either acts on a whole file or on some of its changes. Accepting a block in the viewer also keeps the changes touching only the blocks accepted, since the page showed them; keeping accepts nothing, and `loom accept`, which shows no edit, leaves the look alone. A box ticked in the viewer goes into the look as it is written, since the person just made that change, and any other change to the file stays listed. Keep and undo are the author's (`agents.md`), and `loom serve` takes the first look when it finds none, so an agent's first edits are caught.

**Verification** is a different claim: that loom's copy of someone else's result is faithful to their paper. `loom library verify` records it, only the author can make it, and it settles nothing mathematical (below).

**Annotations** are the other kind of record: what anyone, person or agent, says about the text (next section). Annotations never change a state; a key with forty open objections and a fresh acceptance is accepted.

## Annotations

An annotation is the one record of review, written only by `loom annotate` and appended to `.loom/annotations/log.jsonl`. It has an author (a person, or an agent naming itself), a session, a target, and one of five kinds:

| kind | for |
|---|---|
| objection | something that must change |
| suggestion | something that could change, often with proposed text |
| question | something the writer could not decide |
| citation | a work worth citing |
| note | an explanation or aside that asks nothing |

Objections and suggestions carry a severity. A suggestion may carry a payload, the proposed text, and a placement: `replace` takes exactly the quoted words' place, and `after` and `before` go right beside them; a suggestion with no quote is about the key's body. The viewer shows the key with the suggestion in place and `loom suggestion` prints the patch that takes it. Applying it is the author's act: **Take it** in the viewer, or `loom suggestion apply ID`, writes it into the file, keeping a version of each document it changes first, and resolves it as applied, and **Leave it** resolves it without; what was taken then reads as an edit in Review until it is kept or accepted, so it can be undone; a suggestion the author takes by editing the source instead is resolved as applied once loom reads that it was done. A suggestion on an agent's copy is not applied: it comes in with the copy.

A **target** is a key, a labelled equation, a whole document, or a page of a cited work. An annotation on text is anchored by a quote: the exact words, with a little context before and after, resolved inside the target's own text, so moving text between files never moves an annotation. When the quoted words are gone, the annotation is **detached**: never deleted, never drawn at a guessed place (A3), listed with its quote. An annotation is **settled** when someone resolves or withdraws it; settled annotations are hidden until the reader asks for them (A6). A re-check edits its own earlier finding rather than replying to itself.

How an annotation is drawn is the A set of `principles.md`: hue for its kind, weight for its severity, shape for what it is attached to, and a mark never splits a formula.

**Open.** Annotations can target only addressable things today. Something said about an untagged statement, or about an open problem that is not yet a node, has nowhere to go; notes (below) are meant to close this gap.

## The library

The library is the works a quilt reads and cites, and what loom knows of them. A **work** is one paper, book, set of notes or anything else a person reads, named by a global identifier (a DOI, an arXiv id) where it has one, with whatever loom's store holds for it: its PDF, its LaTeX source, its page text, its digest. A work with no identifier is a work like any other: it opens and reads the same, and nothing asks for one while its document is held. `loom library update` gathers the bibliography, fetches what it may (only when the quilt allows the network, which an agent cannot grant), and maps pages. The viewer starts the same run, for one work from its Info or for every work from Review › Library, and follows it step by step while loom runs it; where the quilt has the network off, it asks the person whether to allow it for that run. A work opens on its Text, the document itself, beside its Info. Info opens on a status line saying whether its text and LaTeX source are filed, how many results its digest holds and how many the person verified, and whether it has an overview. Beneath it stand the overview, the results as cards under the paper's sections, a dozen before the rest fold, and the person's documents that cite the work; its bibliography entry and where its digest came from are folded at the foot. An overview is written lazily: the agent that first reads a work through writes it, and where none exists Info offers to ask for one, which leaves the person's note on the whole work for an agent to answer. Review › Library, also reached from the Library shelf under Docs, is where the works are worked on: each row says what the work holds and lacks, how much the person verified and what waits for them, and where they cite it; it names the work's problems with their fixes, from what stands on disk and from the last run on it; its menu runs on the work, uploads the person's PDF, asks for its overview, copies its entry, stops asking for its paper, or deletes it, or one copy of it; and selected rows run together or are deleted together. Deleting takes the work's entry, loom's copy of its document and everything read from it, for good, and says first what goes; a work a document cites or carries stays, since gathering would bring it back. Its proposed results and citation suggestions are decided in Review › Proposed Changes. A work is also added by hand: in the viewer a pasted DOI, arXiv id, zbMATH number or BibTeX entry is recognised and looked up, and in the viewer or by `loom library add` a PDF the person provides is copied into the store whatever is known about it. It is filed under the work it plainly shows it is, or under the one the person names, which a work's Info offers beside fetching; any other PDF becomes a new work, its metadata filled in from what the file gives, which the person may correct, and a lookup only adds to that entry where the network is allowed. Filing answers at once and the PDF opens; reading its text follows as a run, which says how far through the pages it is. Either way the work goes into loom's own bibliography marked as added, never into a document's `.bib`. An added work is the library's as much as a cited one, and one nothing cites can be taken out again.

A **digest** holds a work's results as digest nodes, each a statement verbatim with its locator (`Theorem 4.1, p. 12`), so that `\cite[Theorem 4.1]{Man12}` becomes an edge to a result someone can read and check. A digest's results are results whether or not any document declares their environments: each declares its own from its locator, so a quilt of digests alone already has them. A digest is **extracted** mechanically from the work's LaTeX source; nothing is typed from a PDF. For a work with only a PDF, an agent or person **proposes** a result with `loom library propose`, and loom refuses a quotation that is not on the page it names. Proposals wait in a file nothing inputs until the author verifies them, and citing one makes no dependency: the citation is reported, and verifying the proposal makes it one. A result's state is computed: extracted, proposed, verified, or discarded. A proposal whose quotation passed the page check is checked, never verified, and only the author verifies (P15).

A **relation** links two results (same notion, generalises, specialises, depends on, contradicts) with a reason. It is an assertion, never checked and never citable, and it is how connections between works are recorded and found from either end. A note on a page of a work (`loom annotate CITEKEY --page N --quote …`) says something about what is there.

The details are `docs/specs/digests.md`.

**Open.** The library is organised around what a draft cites: the bibliography is gathered from landmarks, fetching follows a work's own references, and uncited works are demoted. The Learner reads works nobody cites yet, so a work that is read must be as first-class as one that is cited. A work added by hand already is (plan 0.24.2); one only read, in no bibliography, is not yet (see [README](README.md#decided-not-yet-built)).

## Notes

The core is built (plan 0.22.8): one gesture, **quote**, writes a note on what is selected or drawn, on a key, a work or one of its pages, a shown file, a transcript message or the session, with no kind or severity; `loom note` writes one too; it fades after 14 days unless kept or linked, and an agent reads a person's with `loom since`. Claims and their evidence, promotion, and open problems as nodes are not built yet (see [README](README.md#decided-not-yet-built)); the rest of this section is the design as currently decided.

A **note** is something a person or an agent wants to remember about the mathematics: an explanation of a definition, an example, a question, an attempt, a claim and its evidence, a dead end and why it failed, a connection between two works. Notes are how exploration and learning leave a trace.

- **Capture costs one gesture** (P14). A note needs only its text. Its kind defaults to note, and its target to what the viewer has selected, else the session; an agent may set either. Loom infers nothing, since it has no model.
- **A note attaches to anything:** a key, a digest result, a work or a page of one, an `\incomplete` step, an open problem, or the session alone, to be filed later. It is found from what it is attached to.
- **Notes are fleeting by default.** A note fades after a while unless it is kept or something durable links to it. Fading is computed from age and links (P3): a faded note is hidden by default, shown with one toggle, found by search, and never deleted from the log. Nothing announces it.
- **Claims carry their evidence.** A note that claims something says how far it has got (conjectured, tested on examples, sketched, proved here, refuted), and every step past conjectured names its evidence. Who linked the evidence is shown, because a link is itself a claim (P15). Evidence is asked for when a note is promoted, not when it is taken.
- **What is worth keeping becomes durable.** A note that has proved its worth is promoted: to a node in a document of the author's (a problem, a lemma, a definition restated in their own words), or kept as a durable note linked to the mathematics it concerns. Promotion is where care is asked for.
- **Open problems are nodes.** A question the Explorer is working on is a `question` or `conjecture` environment in a research document, with an id, edges and a computed status, and the attempts and dead ends about it attached as notes. An agent proposes one as a node in an agent document.

Notes are records loom writes (P1, P2), through one command, and share the annotation log's machinery: append-only events, authors, sessions. They are a separate kind of record, because "resolved" means the text was fixed and "refuted" or "proved" means something else.

**A mark** (plan 0.28) is a note drawn on a page of a PDF, a project's or a cited work's: a highlight, underline or strike-through on words, a pin that holds a comment, ink, words on the page, a box, an oval or an arrow. It is what Preview and Skim give a reader: one press, there later, with a comment if it needs one, moved, changed or erased at will, with undo. It asks for no session and does not fade, since a highlight that vanished after two weeks would be a surprise (P14), and it stays out of transcripts; an agent reads a person's with `loom since`, and may draw its own with `loom note --mark`. Annotations stay the record of review, with kinds and threads, and a mark on a page says nothing to anyone but its reader unless they want it to.

**Loom's log is where a mark lives, and a PDF is what it is exported to and imported from.** A cited work's PDF is the document its anchors were checked against and must never change, a compiled PDF is replaced by the next build, and a mark in the log reaches coauthors and agents where one inside a file would not. So a mark never touches the file it is on. "Save a copy" writes a PDF with the marks in it as real annotations, after the file's own unchanged bytes, and this runs in the viewer, on a static site too. "Take in" makes marks from a PDF's own annotations: from another copy of the same paper, one marked in Preview say, matched by page, place and words so that taking it in twice adds nothing; or from the PDF being read, whose annotations a note then stands for and which are left off the page. A comment a PDF holds can be read by clicking it whether or not it is taken in. Nothing syncs with a file, because saving through Apple's PDFKit keeps no identifier on an annotation and rewrites the file's fonts and text layer; and Skim keeps its notes outside the PDF unless it is told to embed them, so they are exported from Skim first.

A mark records the hash of the PDF it was drawn on, so a changed file is noticed: words are found again on their page, and anything else is detached, listed and not drawn (A3).

**A mark's colour is its reader's.** A mark is the annotation neutral until its reader gives it one of five colours, yellow, green, blue, pink or purple, and loom gives none of them a meaning (A4). The viewer holds the colour last chosen, so a reader who colour-codes picks it once and keeps marking. A colour taken in from a PDF is drawn as the nearest of the five, and black, white and grey stay the neutral; the exact colour stays on the record, and a saved copy writes it back unless the reader has since changed the mark's colour.

**Open.** Where durable notes in the author's own words live (as nodes in a notes document, or as kept notes); and how a note cites a script by path and hash, until loom can run code.

## Sessions and transcripts

A **session** is a stretch of work, which a person and agents may share. Everything written in it records the session it belongs to and the author who wrote it, so the session is the audit trail: `run.log` lists every loom command run in it, and its directory holds what an agent hands the author, such as a script a report cites; the report itself is a message in the session's transcript.

Sessions are not what work is organised around. Work collects around the mathematics: annotations and notes are found from what they are about, whichever session wrote them.

A session's **transcript** is what its participants wrote deliberately with `loom session say`, not a copy of a conversation held in an agent app. An agent writes it so that someone coming back later sees the main points of the discussion, what was decided or found, what is still open, and links to everything durable that came of it. The viewer shows a transcript beside the documents it refers to, its links live, like a long-running annotation.

The viewer's chat composer and agent launching are retired (plan 0.20.1): conversations happen in agent apps, which own the model, the streaming, interruption and permissions.

## The viewer

Arras shows what loom publishes and lets a person read and decide: read documents and works, follow links between them, see annotations and notes where they belong, review and accept, verify library results. It writes nothing itself; every write goes through a control the publisher advertises, and only when the publisher serves it (P11). It works offline, from a static build, on any host.

The principles that govern it are the V and A sets. In short: open on the thing itself, show less, claim only what is known, and never lose the thing you followed a link from.

The frame is a left column and one or two panes. The column has two primary views: **Docs**, which holds the project's tree under **Files**, a shelf open by default and folding as Library's does, each shelf a rounded box holding its head and its rows, so that Files reads as the quilt's directory as it is and Library as what loom keeps of the cited works (its directories and the files the viewer shows, each directory folding as an explorer's does; a document opens as itself with its compiled PDF beneath it, to read and not to mark, saying while it compiles and when its last compile went wrong, and each agent copy beneath it, hung from it by an arrow pointing up into its name, the research state opens as its page where it lives, an included `.tex` file opens the document that reads it at its place, and every other file opens as a file; LaTeX's auxiliary files, such as `.aux`, `.log` and `.synctex.gz`, are left out unless the reader turns that off in Settings, and the agents' config documents, such as `AGENTS.md` and `CLAUDE.md`, when the reader turns that on; each row is marked "AI" where agents may edit it too and "AI" struck through where only the person does, its meaning shown under the pointer, and only Settings changes which), an agent copy whose document is not listed under Agent documents, with the closed ones folded beneath, the Library, folded until opened, each work by its author and title and sorted by author, and the focused document's Outline (search, which finds works too, is ⌘K); and **Review**, the quilt's management and the meta view, which opens on the first section where something waits and whose sections each count what waits for the author there and nothing else: Your Changes (one document at a time, what changed since the author's look and every block not freshly accepted, each block listed once with every reason it waits, its edit kept or undone and its mathematics accepted, which keeps the edit too; text outside any block and files in no document, kept or undone; blocks never accepted and those accepted, folded and uncounted), Proposed Changes (everything someone proposes that the person decides, one card each and counted: a pull or an agent's copy, whose card opens its review; a suggestion with text and a citation, each taken or left in its card; a work's proposed results, whose card opens the queue to check them; then, uncounted, suggestions in prose to weigh, each resolved or dismissed), Problems (what is wrong in the person's files first, the only part counted; then, folded, an agent's copy's, the cited works' with "Digest it again" beside each work, and the remarks; a work with no paper to read links to its row in the library), Library (the ledger: every work the quilt holds, what it has and what it wants of the person, its search and filters, the acts on a work from its row or on several selected together, adding a work and deleting one; the works wanting something beyond results to check are its count, and the Library shelf under Docs links here with the same number) and The Record (what has been done, on tabs: Versions, each document's, one kept at every act, to open, compare with now or restore; Sessions, every one, with when it was last active, a new one started and one chosen to write in, and rename, close, reopen and delete; and Everything recorded, each act the history holds). Each section's name carries a line saying what it is for.  The column's edge drags sideways to widen or narrow it, as the line above the Outline drags up and down, each remembered in the browser. In both, its foot carries the session footer, which says which session the person's writes go to and whose annotations the page shows; the session picker chooses both, and reading a session's transcript chooses neither. Each pane has its tabs and, beneath them, its own toolbar: the item's views, its tools, a document's `history ▾`, and `view ▾` (which can hide every annotation in that pane). A draft's history lists its live text and the versions that kept its text, newest first, each by the act it was kept at; a version is shown read-only in the draft's own tab, its toolbar stepping to the older and newer ones and putting the document back as it, and each version, and each agent copy of the draft, can be compared with the one shown, which is how compare starts; while comparing, the focused pane's toolbar counts the differences and stops. `/` opens reading where it was left, remembered per quilt in the browser, else the front door, else the default document; a quilt with nothing to read opens on how to start, drawn from the publisher's `loom:no-live-document` fixes.

A file item shows any file the viewer shows by its kind: a Markdown file or a notebook drawn by the publisher (a notebook from its saved cells; loom runs nothing), where the HTML a Markdown file holds is drawn too, a video embedded from another site among it, through an allowlist that lets nothing in it run as the viewer ([dialect](../specs/dialect.md#1-envelope)), an HTML page in a frame of its own origin, where its scripts and embedded players run and from which it can never reach the viewer, a PDF and an image as they are (a PDF with its marks, and pages to edit: turned, deleted, reordered and inserted from another PDF, always into a new file, P7), text as text. A task item in a Markdown file, `- [ ]`, is drawn with a box the person ticks in place, which writes that one character to the file, keeping its old text and recording the tick in the history (P7); a notebook's boxes are only drawn. An HTML file may read the project's shown files, list them at `/.loom/files.json` and open anything through `quilt:` links, so a quilt can build its own list or tracker; it cannot write, and its browser storage lasts only until `loom serve` restarts (`specs/write-api.md` §3). Anything else is named, with "Open in its application" for a document type (a spreadsheet, an Anki deck), which `loom serve` opens on the person's click and never for a file that runs code; an `app:NAME` link opens an application the same way. What the viewer shows is what a link may name, by the file's path, at a heading, a page or an anchor; only LaTeX is understood (ids, closure, states, acceptance). Not built yet (see [README](README.md#decided-not-yet-built)): a Library view.

A PDF opens where the person last was in it, a work's paper and a project's file alike, kept in this browser as the page at the top of the view and how far down that page, so it holds at another zoom or width. A link that names a place goes there instead, and where it lands is then where they are; once they have scrolled that page out of view by hand, the place comes off the address, so a reload stays with them. The place belongs to the file, known by its own identifier and page count: the same bytes opened from the Library and from Files are one place, and a different file behind a work opens at its start, since its page 12 is not the page they were on.

Settings is a window over the page with two groups of sections, each page saying where its settings are kept. **Loom** holds Profile (your name, in your user config, for every quilt), Appearance (how text looks and a document reads) and Files (what Docs shows of the project), the last two kept in this browser. **Quilt** holds the quilt's `config.toml`: its name, id prefix and engine, its front door and default document, where agents may not write, the library's use of the network, the problems it silences, and the Overleaf pairing, which is shown and never made there. This browser's settings apply at once. The quilt's wait for Save, since the file is committed and shared, and are written line by line, so the person's comments and order stay; each shows its key. The history folder and the research state's path are shown and never changed there, since moving either means moving files with it. Saving the quilt's settings and rewriting Claude Code's permission file to a changed deny list are the author's acts. A viewer with no publisher shows the quilt's settings as published, and a command the viewer cannot run for the person reaches it from the publisher, never in its own words.

Things are shown where they live (V7): a statement in a document that holds it, a cited result on its work's page, an annotation on the words it marks. A result included in several documents opens in the one the link stands in, else one on screen, else the one looked at last; a result in no document, or a work with no PDF, is the one case for a view of its own, and a project file is shown as itself.

## Coauthors

Coauthors clone the quilt. Sources, the history, annotations and digests are shared; `.loom/.gitignore` names what is not (the build output, runtime state, and the store's copies of other people's documents), personal settings stay in the user config, and identity is never stored in the quilt. Acceptance is per reviewer. Two coauthors who allocate the same id on separate branches get a conflicted key after the merge, which `loom fork` resolves. A coauthor who works in Overleaf edits a document workspace that `loom sync` exchanges with the quilt through the author's own clone of it, in a directory the author names: fetched changes are reviewed and incorporated by the author, who stamps each document first (P7).
