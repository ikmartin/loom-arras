# The model

What loom works with: the quilt, its documents, the nodes and graph read from them, the history, review and trust, annotations, the library of other people's work, notes, sessions, and the viewer that shows all of it. Formats are in `docs/specs/`; commands are in `loom --help`. This file says what the things are and why.

## The quilt

A quilt is a research project in a directory marked by a `config.toml` with a `[quilt]` table; every command finds it by walking up from the current directory. It may hold several documents, one, or none at all. A paper with a talk beside it is a quilt; so is a reading project with no draft, made of the papers and books someone is learning from.

What lives where:

- **The author's sources:** documents, node files, style files, the bibliography and figures, wherever the author keeps them. A document's files sit in its own directory or below, because a document compiles from its own directory (P12).
- **`.loom/`** holds everything loom writes: the acceptance ledger, the history and sessions; `annotations/log.jsonl`, the annotation log, and `annotation-types.toml`, the quilt's annotation types; `edits/log.jsonl`, the suggested edits; `digests/`, the digests of cited works, the quilt's bibliography and loom's store of their documents; `ai/`, what agents are given; `retired/`, sources `atomize --retire` set aside; `copies/`, the documents the author and an agent both edit (below), made when the first is; and `build/`, everything derivable, which can be deleted at any time.
- **`research-state.md`** at the root (the `research_state` setting) is the research state, written when an agent first keeps one.

`loom init` writes `config.toml`, a README that teaches loom, and `.loom/`, and nothing else. Every `.tex` file is scanned except under `.loom/` (whose digests and agent copies are read on purpose), the history and sync directories, tooling directories, and files whose first twenty lines say `% !LOOM ignore`. Nothing is inferred from where a file sits (P5); the exclusions are exclusions, not inferences.

**Open.** A quilt still assumes a paper in places: `status` counts "keys of yours". For the Learner, a quilt with only works and notes must be complete and unremarkable (not built yet, see [README](README.md#decided-not-yet-built)).

## Documents

A **document** is a `.tex` file with `\documentclass` anywhere loom reads, unless it is ignored or superseded. Every one is **live**: scanned, compiled, rendered and reviewable. There is no list of documents; the files are the list. A document is named by its path without `.tex`, kept as a path (`paper/main.tex` is `paper/main`), which keys its build output, its rendering and its address in the viewer, so two documents may share a file name in two directories. A document compiles from its own directory, so its `\input`, figures and bibliography are named from there and none reaches above it with `..`, and a node it reaches is numbered from that document's own compile. Its macros come from loom's marked block in its preamble, or from a `loom.sty` kept beside it. A document is read as TeX makes it: the viewer shows the HTML its compile made, with each node and block placed in the source by its words; after an edit, that HTML until the next compile, with each edited statement made again by TeX; and, until a compile has made any, or when its page lost a statement TeX4ht set where loom cannot find it (beamer's frames), its source, node by node, never an approximation of what TeX would print. Text no compile makes, a node no document reaches, a digest, a landmark, a comparison or a proposal, is made by TeX too, as snippets under the preamble of the document that owns it. `[quilt] main` names the **default document**, whose preamble and engine loom reads for its LaTeX work; unset, it is the only document, or none when there are several. `[quilt] home` names the **front door**, the file the viewer opens on when it remembers no place; unset, it is the quilt's `README.md`.

An **agent document** is one the history records as an agent's, kept in `.loom/copies/`. It is a flat copy of one of the author's documents, made by `loom draft DOC --ai NAME`, or of one labelled section and its descendants with `--section ID`, with every id it defines derived (`rl-0004-ai` for `rl-0004`) so it can never collide with the author's. Agent documents of one document may coexist when their scopes are disjoint: a whole-document copy overlaps every section and a section overlaps its descendants, and a section copy, or any later copy of a document, derives its ids with a numbered suffix never reused (`rl-0004-ai-01`). A section copy reads the rest of the paper in the context saved when it was drafted. The copy records the version of each node it began from, so loom can say when the author's side has moved past it (`loom ai drafts`) and refresh it (`loom ai refresh`). `loom ai close` retires one, keeping its text and annotations in the history and freeing its scope, and `loom ai reopen` brings it back. Nothing in an agent document is accepted or published. Taking its changes back is `loom adopt`, the author's act: it previews the changes, lets the author choose node by node, and the prose and the preamble each as a whole, stamps the working document first, and then writes (P7). A result both the author and the agent changed is merged line by line, and offered as merged when the edits fall apart; when they clash it can't be taken until it is reconciled. In the viewer, Review › Proposed Changes opens a copy's review, which is one pass: each change is taken or left in a bar that stays put, a block can be marked as checked so its acceptance is recorded as it is written in, and one Apply writes what was taken. A collaborator's pull is reviewed the same way but taken whole. A document written into `.loom/copies/` by hand, which no step made, is refused by `loom lint`. A document of an agent's own (a survey, a section to be placed later) needs no command: it is a file the agent writes where the quilt lets it ([agents.md](agents.md)), and is a document like any other. A copy is the way to work on a document the quilt protects from agents, or to give the author changes to choose among before any lands.

A **landmark** is a document as it stood at a moment worth returning to, and is a **version** of it: the paper as received by `loom import`, a working document kept by `loom stamp DOC -m NAME` or recorded by name in the viewer, and the version loom keeps at each of the author's acts on it (a change kept or undone in Your Changes, changes taken in, a restore). It keeps the document's flat text and, for a version kept now, each of its files' text. It lives in the history, is never scanned, and so defines nothing and collides with nothing. In the viewer each document's versions can be paged through, compared with now, and put back, the text a restore replaces kept as a version first; `loom history show` prints one, and `loom history restore` starts a new working document from it.

A conversion (`atomize`, `linearize`) records that its output **superseded** its input, which stops being scanned until `loom live` says otherwise. `loom mv` records a document's move, and every record naming it by path follows the move when it is read, without being rewritten.

## Nodes and the graph

A **node** is a theorem-like environment (declared by `\newtheorem`) or a section. It becomes addressable when its first label is id-shaped, `<prefix>-<local>` such as `rl-0004`; `loom id` prints the patch that adds one. Other labels on the same node are aliases. A **key** is what review is about: a statement (its id) or a proof (`rl-0004/proof`, `rl-0004/proof/2`).

An id is **defined once**. A file may be included by several documents, and its nodes then appear in each, numbered by each. But when an id is defined twice, by two files or within one, the key is **conflicted**: it has no text, loom reports both definitions and chooses neither, and `loom fork` gives one of them a fresh id. Loom never picks a winner, because any rule for picking one would let one definition's acceptance and annotations silently apply to another's text. An id that history has recorded is never allocated again.

**Edges** are read from what the author writes: `\ref` and its relatives, `\cite[Theorem 4.1]{key}` when a digest of that work has the result, and `\uses{…}` for a dependency the text does not name. The **closure** of a key is everything its statement depends on, transitively; `loom source KEY --closure` prints it as the exact context for reading, reviewing or drafting that key. A node no document reaches is **loose**, which is computed, never a directory. `% !LOOM see: ID` links two nodes for the reader and is never a dependency.

Two markers carry mathematical status in the source: `\incomplete{…}` marks a statement or proof as not finished, and `% !LOOM basis:` declares why a block may be relied on (a local proof, a cited result, an assumption, an open claim, or exposition). The exact rules are `docs/specs/source-contract.md`.

## History

The history (`.loom/history/`) records what loom was told, at the moments it was told: never on save, and never a claim about the filesystem (P13). A **step** is an import, a stamp, or the copy behind an agent document, numbered once across the quilt; each act of the author's that keeps a version (Review's Keep and Undo, taking changes in, recording one, restoring one) is a stamp of the document it concerns, unless the document is as its newest version holds it. Keep and Undo also write a line naming the file, so Review › The Record lists every act. A stamp records every key whose text moved since the last step; given a document, it also keeps that document as a landmark. A key's text at a step is a **version**, addressed `rl-0001@3` or `rl-0001@submitted`.

`loom revert KEY@N` prints the patch that puts a version back and records nothing, since the head's text says whether it was applied. `loom fork` gives one document its own copy of a node under a new id. Every divergence between the record and the files (an edited landmark, a missing step, an unreadable ledger, a step interrupted before it was recorded) is reported with the command that resolves it, and nothing stops a build. No step is recorded beside an interrupted one: every command that records a step refuses until its directory is removed.

## Review and trust

Two kinds of record say what has been looked at, and they never mix.

**Acceptance** is the author's claim that a key's mathematics is right. `loom accept` appends a row to the ledger (`.loom/state.toml`) holding hashes of the key's text, of every statement in its closure, and of the preamble, with snapshots of that text. Only the author accepts; an agent is refused whatever name it gives (`agents.md`). From the ledger and the current text, every key's state is **computed** (P3):

- `incomplete` when it contains `\incomplete`, whatever else is true;
- `accepted` when the latest row's hashes still match;
- `accepted, stale` when something has moved, with each cause named: its own text, a dependency (directly or through another), the preamble, its basis, or the document it was accepted in. `loom status --explain KEY` shows the diff;
- `conflicted` when two live files define it;
- `draft` otherwise.

On top of these, `proved` and `settled` are display states: a statement is proved when it and a proof are freshly accepted, and settled when everything it depends on is settled too. A cited result is a settled leaf by attribution.

Acceptance is personal: each reviewer's latest rows are their own, and a coauthor's acceptance never accepts for you. In the viewer, Review › Your Changes lists every block of the person's documents not freshly accepted, in dependency order, as changed since accepted, taken in from a copy or a pull, or, folded and uncounted, never accepted; **Accept** records an acceptance at once, for one block or a selection, and what loom cannot accept says why before anything is pressed. Overlooking a block never accepts it.

**A look** is the third thing Review keeps, and it says nothing about the mathematics: the text of every open file (one the viewer shows that is text, LaTeX included) as the person last saw it, kept in the history's texts and recorded by their name in `.loom/looked/`. What changed in those files since, whoever made it, since loom cannot tell who, is cut into **changes** word by word, and with the suggested edits waiting to be kept they are what is pending. The document draws them where they are: in Markup removed words are struck and new words underlined in teal, a colour annotations never use, and Final shows the text with every change made. Each change has **Keep** and **Discard**, and the Changes menu keeps or discards them all; Review's Your Changes lists the same changes across the quilt by document, with the same card and a To do that adds the open annotations of others. Keep takes an agent's change into the look, or writes a suggested edit into its file and the look; Discard writes a change's old words back, keeping the text now in the history first (P7), or discards a suggested edit, and discarding a file new since the look removes it. Keep carries every annotation on the changed words onto the new words, marked as written on earlier words, an annotation whose words were all removed stays as a mark at that spot, and keeping a change that answers an annotation resolves it. What is current is what the person has kept, so an annotation written before an agent's change stays on the words it was written on until the change is kept or discarded. Accepting a block in the viewer also keeps the changes touching only the blocks accepted, since the page showed them; keeping accepts nothing, and `loom accept`, which shows no edit, leaves the look alone. A box ticked in the viewer goes into the look as it is written, since the person just made that change. Keep and Discard are the author's (`agents.md`), on the command line `loom changes --keep` and `--discard`, and `loom serve` takes the first look when it finds none, so an agent's first edits are caught.

**Verification** is a different claim: that loom's copy of someone else's result is faithful to their paper. `loom library verify` records it, only the author can make it, and it settles nothing mathematical (below).

**Annotations** are the other kind of record: what anyone, person or agent, says about the text (next section). Annotations never change a state; a key with forty open revisions and a fresh acceptance is accepted.

## Annotations

An annotation is the one record of what anyone, person or agent, says about the text, filed only by `loom annotate`, which the viewer's writes call too (P4), and kept in `.loom/annotations/log.jsonl`. It may be a mark on words, a comment at a place, a mark drawn on a PDF page, or something said about a whole key, document or work. It has an author (a person, or an agent naming itself), a time, a target, and the version of the text it was written on; it belongs to no session.

An annotation is drawn in its own **look**: one of nine colours (grey, brown, red, orange, yellow, green, blue, purple, pink), a style (underline, highlight or strike), a thickness in whole pixels and an opacity. Loom gives a colour no meaning (A4).

A **type** is a preset of the quilt's, kept in `.loom/annotation-types.toml`: a name, a look, whether it stays open until resolved or only informs, whether it is listed in Notes, and instructions that tell an agent when to use it. `loom init` writes the file with the defaults listed, `loom upgrade` adds it where it is missing and never rewrites it, the person edits it in Settings, and an agent may edit it too. The defaults:

| type | look | for |
|---|---|---|
| Revision | red highlight, 65% | something is wrong and must change; how serious is said in the comment |
| Suggestion | orange highlight, 60% | nothing is wrong, but it could be better |
| Question | blue highlight, 60% | something the writer could not decide |
| Note | grey highlight, 60% | only informs, and is listed in Notes |

Types are optional. Having no type is called **Plain**, and the file's `[plain]` sets the plain look an untyped annotation is drawn in unless it sets its own (a yellow highlight by default), so loom, an agent and the viewer draw an untyped annotation alike. An annotation names its type by a fixed id and keeps its look, so renaming a type touches no annotation, and deleting one leaves its annotations untyped and looking as they did; no interface depends on a particular type existing. An agent is given the types by `loom ai orient`, generated from the file, and the MCP server's instructions name each one; a mode names a type by a placeholder that loom fills with its current name.

Only an annotation whose type stays open until resolved is **open**, has Resolve, and is counted by `loom status`; an untyped annotation never is. One that is resolved is hidden until the reader asks for resolved annotations (A6). **Deleting** removes an annotation and its replies from the log. An agent deletes only its own, and deleting by author or by version (`loom ai delete`) is the person's. When the person deletes an agent's annotation, that agent's next `loom since` says so once, from a line under `.loom/since/` that is never committed, and then forgets it.

A **suggested edit** is a record of its own, beside annotations: words on a key replaced with new ones, with a comment if it needs one and the annotation it answers if there is one, written only by `loom suggest` into `.loom/edits/log.jsonl`. It takes exactly the quoted words' place, or goes right before or after them; one with no quote is about the key's body. It is pending beside an agent's changes to open files and drawn with them (above), and `loom changes ID` prints the patch that takes it. Keeping it is the author's act: Keep, in the document or in Review, or `loom changes --keep ID`, writes it into the file, keeping a version of each document it changes first, and records it kept; Discard, or `loom changes --discard ID`, records it discarded and leaves the text alone; an agent withdraws its own with `loom suggest --withdraw ID`. An edit the author made by changing the source instead reads as taken, and keeping it then writes nothing. Several edits on one key are placed together, and one on words another already changes waits. An edit on an agent's copy is not kept: it comes in with the copy. The viewer calls it a suggested edit, never a suggestion, since Suggestion is a type (K7).

A **target** is a key, a labelled equation, a whole document, a cited work as a whole or one of its pages, or a page of a project PDF. An annotation on text is anchored by a quote: the exact words, with a little context before and after, resolved inside the target's own text, so moving text between files never moves an annotation. When the quoted words are gone, the annotation is **detached**: never drawn at a guessed place (A3), listed with its quote. A re-check edits its own earlier finding rather than replying to itself.

How an annotation is drawn is the A set of `principles.md`: its own look, a shape for what it is attached to, and a mark that never splits a formula.

**Open.** Annotations can target only addressable things today. Something said about an untagged statement, or about an open problem that is not yet a node, can only be said about the key or document around it.

## The library

The library is the works a quilt reads and cites, and what loom knows of them. A **work** is one paper, book, set of notes or anything else a person reads, named by a global identifier (a DOI, an arXiv id) where it has one, with whatever loom's store holds for it: its PDF, its LaTeX source, its page text, its digest. A work with no identifier is a work like any other: it opens and reads the same, and nothing asks for one while its document is held. `loom library update` gathers the bibliography, fetches what it may (only when the quilt allows the network, which an agent cannot grant), and maps pages. The viewer starts the same run, for one work from its Info or for every work from Review › Library, and follows it step by step while loom runs it; where the quilt has the network off, it asks the person whether to allow it for that run. A work opens on its Text, the document itself, beside its Info. Info opens on a status line saying whether its text and LaTeX source are filed, how many results its digest holds and how many the person verified, and whether it has an overview. Beneath it stand the overview, the results as cards under the paper's sections, a dozen before the rest fold, and the person's documents that cite the work; its bibliography entry and where its digest came from are folded at the foot. An overview is written lazily: the agent that first reads a work through writes it, and where none exists Info offers to ask for one, which leaves the person's annotation on the whole work for an agent to answer. Review › Library, also reached from the Library shelf under Docs, is where the works are worked on: each row says what the work holds and lacks, how much the person verified and what waits for them, and where they cite it; it names the work's problems with their fixes, from what stands on disk and from the last run on it; its menu runs on the work, uploads the person's PDF, asks for its overview, copies its entry, stops asking for its paper, or deletes it, or one copy of it; and selected rows run together or are deleted together. Deleting takes the work's entry, loom's copy of its document and everything read from it, for good, and says first what goes; a work a document cites or carries stays, since gathering would bring it back. Its proposed results are decided in Review › Proposed Changes. A work is also added by hand: in the viewer a pasted DOI, arXiv id, zbMATH number or BibTeX entry is recognised and looked up, and in the viewer or by `loom library add` a PDF the person provides is copied into the store whatever is known about it. It is filed under the work it plainly shows it is, or under the one the person names, which a work's Info offers beside fetching; any other PDF becomes a new work, its metadata filled in from what the file gives, which the person may correct, and a lookup only adds to that entry where the network is allowed. Filing answers at once and the PDF opens; reading its text follows as a run, which says how far through the pages it is. Either way the work goes into loom's own bibliography marked as added, never into a document's `.bib`. An added work is the library's as much as a cited one, and one nothing cites can be taken out again.

A **digest** holds a work's results as digest nodes, each a statement verbatim with its locator (`Theorem 4.1, p. 12`), so that `\cite[Theorem 4.1]{Man12}` becomes an edge to a result someone can read and check. A digest's results are results whether or not any document declares their environments: each declares its own from its locator, so a quilt of digests alone already has them. A digest is **extracted** mechanically from the work's LaTeX source; nothing is typed from a PDF. For a work with only a PDF, an agent or person **proposes** a result with `loom library propose`, and loom refuses a quotation that is not on the page it names. Proposals wait in a file nothing inputs until the author verifies them, and citing one makes no dependency: the citation is reported, and verifying the proposal makes it one. A result's state is computed: extracted, proposed, verified, or discarded. A proposal whose quotation passed the page check is checked, never verified, and only the author verifies (P15).

A **relation** links two results (same notion, generalises, specialises, depends on, contradicts) with a reason. It is an assertion, never checked and never citable, and it is how connections between works are recorded and found from either end. An annotation on a work (`loom annotate CITEKEY`, with `--page N` and `--quote` for one place on it) says something about what is there.

The details are `docs/specs/digests.md`.

**Open.** The library is organised around what a draft cites: the bibliography is gathered from landmarks, fetching follows a work's own references, and uncited works are demoted. The Learner reads works nobody cites yet, so a work that is read must be as first-class as one that is cited. A work added by hand already is (plan 0.24.2); one only read, in no bibliography, is not yet (see [README](README.md#decided-not-yet-built)).

## Notes

A **note** is an annotation whose type is listed in Notes: the default Note type, or any type the person lists there. Notes is a list loom builds of them beside the document, work or PDF they are on, each linked to its place; nobody edits it (P3). A view of every note in the quilt, grouped by where each was left, is WQ-69 (not built yet). Notes are how exploration and learning leave a trace: an explanation of a definition, an example, an attempt, a dead end and why it failed, a connection between two works. Not built yet (see [README](README.md#decided-not-yet-built)): the claims, promotion and open problems below; the rest of this section is the design as currently decided.

- **Capture costs one gesture** (P14). A note needs only its place; it says something only if its reader wants it to. Loom infers nothing, since it has no model.
- **Quoting is not a record.** Selecting words with no tool on offers Quote, which hands the words and where they came from to an agent, as highlighting part of a reply does in a chat. Until an agent's session can take a quote directly, it is copied with its place.
- **Claims carry their evidence.** A note that claims something says how far it has got (conjectured, tested on examples, sketched, proved here, refuted), and every step past conjectured names its evidence. Who linked the evidence is shown, because a link is itself a claim (P15). Evidence is asked for when a note is promoted, not when it is taken.
- **What is worth keeping is promoted** to a node in a document of the author's (a problem, a lemma, a definition restated in their own words). Promotion is where care is asked for.
- **Open problems are nodes.** A question the Explorer is working on is a `question` or `conjecture` environment in a research document, with an id, edges and a computed status, and the attempts and dead ends about it attached as notes. An agent proposes one as a node in an agent document.

**A mark** (plan 0.28) is an annotation on a page of a PDF, a project's or a cited work's: words drawn in its look, or a pin that holds a comment, ink, words on the page, a box, an oval or an arrow. It is what Preview and Skim give a reader: one press, there later, with a comment if it needs one, moved, changed or deleted at will, with undo. On a PDF page the viewer's toolbar is a document's, with the PDF's own tools beside it: ink, words on the page, a box, an oval and an arrow, and Comment leaves a pin. An agent reads a person's with `loom since`, and may draw its own with `loom annotate FILE --page N --mark TOOL`.

**Loom's log is where a mark lives, and a PDF is what it is exported to and imported from.** A cited work's PDF is the document its anchors were checked against and must never change, a compiled PDF is replaced by the next build, and a mark in the log reaches coauthors and agents where one inside a file would not. So a mark never touches the file it is on. "Save a copy" writes a PDF with the marks in it as real annotations, after the file's own unchanged bytes, and this runs in the viewer, on a static site too. "Take in" makes annotations from a PDF's own: from another copy of the same paper, one marked in Preview say, matched by page, place and words so that taking it in twice adds nothing; or from the PDF being read, whose own annotations are then left off the page while an annotation stands for each. Deleting one of those deletes loom's record only, so the file's own annotation is drawn again and can be taken in again. A comment a PDF holds can be read by clicking it whether or not it is taken in. Nothing syncs with a file, because saving through Apple's PDFKit keeps no identifier on an annotation and rewrites the file's fonts and text layer; and Skim keeps its notes outside the PDF unless it is told to embed them, so they are exported from Skim first.

A mark records the hash of the PDF it was drawn on and the words under and around it, and a drawing its distance from the nearest of them, so a changed file is noticed: the mark stands where those words are found again, on its page or another, a drawing at the same distance from them, and one whose words are not found is detached, listed and not drawn (A3). A changed PDF has no kept copy, so a mark found again says where, and there is no earlier version to open. On a cited work whose LaTeX source loom holds, a mark's words are also found in the source, and an agent reads which file and where. Wherever an agent reads a mark, through `loom since`, `loom ai annotations` or `loom here`, it gets a crop of the page around it, made with `pdftocairo` into the build directory, as an image over MCP; TeX it reads off a crop is its own reading (P8).

A colour taken in from a PDF is drawn as the nearest of the nine, and a strike-out is struck. The exact colour stays on the record, and a saved copy writes it back unless the reader has since changed the mark's colour.

**Open.** Where notes in the author's own words that outgrow an annotation live (as nodes in a notes document, or elsewhere); and how a note cites a script by path and hash, until loom can run code.

## Sessions and transcripts

A **session** is a stretch of work, which a person and agents may share, and its audit trail: `run.log` lists every loom command run in it, and its directory holds what an agent hands the author, such as a script a report cites; the report itself is a message in the session's transcript. An annotation belongs to no session: it carries its author, its time and the version it was written on.

Sessions are not what work is organised around. Work collects around the mathematics: annotations are found from what they are about.

A session's **transcript** is what its participants wrote deliberately with `loom session say`, not a copy of a conversation held in an agent app. An agent writes it so that someone coming back later sees the main points of the discussion, what was decided or found, what is still open, and links to everything durable that came of it. The viewer shows a transcript beside the documents it refers to, its links live, like a long-running annotation.

The viewer's chat composer and agent launching are retired (plan 0.20.1): conversations happen in agent apps, which own the model, the streaming, interruption and permissions.

## The viewer

Arras shows what loom publishes and lets a person read and decide: read documents and works, follow links between them, see annotations and notes where they belong, review and accept, verify library results. It writes nothing itself; every write goes through a control the publisher advertises, and only when the publisher serves it (P11). It works offline, from a static build, on any host.

The principles that govern it are the V and A sets. In short: open on the thing itself, show less, claim only what is known, and never lose the thing you followed a link from.

The frame is a left column and one or two panes. The column has two primary views: **Docs**, which holds the project's tree under **Files**, a shelf open by default and folding as Library's does, each shelf a rounded box holding its head and its rows, so that Files reads as the quilt's directory as it is and Library as what loom keeps of the cited works (its directories and the files the viewer shows, each directory folding as an explorer's does; a document opens as itself with its compiled PDF beneath it, to read and not to mark, saying while it compiles and when its last compile went wrong, and each agent copy beneath it, hung from it by an arrow pointing up into its name, the research state opens as its page where it lives, an included `.tex` file opens the document that reads it at its place, and every other file opens as a file; LaTeX's auxiliary files, such as `.aux`, `.log` and `.synctex.gz`, are left out unless the reader turns that off in Settings, and the agents' config documents, such as `AGENTS.md` and `CLAUDE.md`, when the reader turns that on; ## Coauthors

Coauthors clone the quilt. Sources, the history, annotations and digests are shared; `.loom/.gitignore` names what is not (the build output, runtime state, and the store's copies of other people's documents), personal settings stay in the user config, and identity is never stored in the quilt. Acceptance is per reviewer. Two coauthors who allocate the same node id on separate branches get a conflicted key after the merge, which `loom fork` resolves. A coauthor who works in Overleaf edits a document workspace that `loom sync` exchanges with the quilt through the author's own clone of it, in a directory the author names: fetched changes are reviewed and incorporated by the author, who stamps each document first (P7).

An annotation's id, like a suggested edit's, a session's and a relation's, ends in a token drawn at random rather than a count (`a-2026-11-05-k2m9xq`, `e-2026-11-05-q4hd2r`, `link-k2m9xq`), so coauthors writing on the same day draw different ids. The token says nothing of order, so a listing takes its order from when a record was written. These records live in append-only logs, except that deleting an annotation rewrites the annotation log and a relation's file is rewritten whole, and git calls two clones' additions to one a conflict, which keeping both sides resolves. Should two records still reach a log under one id, by a line such a merge kept twice or a draw that came up the same, `loom lint` reports `loom:repeated-id`, naming the lines and the edit that clears it, and loom changes neither record (P13).

**Open.** A step's number and a message's number are still counted, because each is an order as well as a name, and a random token would lose that. Two clones that each make a step leave a merged ledger reported as `loom:history-corrupt`, which reads without the later step and has no command that mends it. Two clones that each write in one session leave two messages under one number, which nothing reports: `loom:repeated-id` does not read transcripts, and the viewer, which holds a transcript by number, shows only one of them.
