## What was done

### Part A — arras

**Tokens and typography (A1).** `arras/src/lib/theme.css` is chapter 15's vocabulary: `--paper`, `--leaf`, `--sheet`, `--rule`, `--rule-strong`, the three inks, `--link`, `--link-wash`, `--mark`, the five state pairs, the spacing, radius and rail scales. The serif is the site generator's stack and the dark palette is derived from the light one, both settled in DR-90. `state.ts` is the single place a manifest colour class becomes a state tone, so a state the interface adds later renders without a code change; its fallback is tested.

**Preferences (A1).** `prefs.svelte.ts` holds shell, typeface, size, line width and theme in `localStorage` under `arras.prefs`, every access inside try/catch, applied as `data-*` attributes on `<html>`. `app.html` reads them in a blocking script before the first paint, since the viewer renders client-side and would otherwise flash the default theme. `?shell=` overrides the stored shell for one visit.

**The shell (A2).** `NavShell` renders one of `RailSections`, `TopBarTabs` or `IconStrip` from one prop set; `Contents`, `DocumentPicker` and `Settings` are shared. The default is C. Every rail is a scroll container, which is the contents-scrolling fix, and it lives in the shell so no page can regress it. Two registries let a page fill the shell's regions without drawing a rail of its own: `PageRail` for the right rail and `PagePanel` for the left panel, which is how a table page's filters reach the panel that a document's contents otherwise occupy.

**The contents tree (A3).** Built from `manifest.inclusion`, which the viewer read nowhere. Order comes from the tree; depth comes from a new `level` field on section nodes, because the tree nests everything a section contains beneath it and outline depth is not tree depth. The rail stops at level 3, so `\paragraph` units leave it.

**Read view, node page, home, tables (A4).** The read view gives each node the margin column of 15.3.1 and renders the taxon accent as its hairline rule; the right rail appears only when a node the document reaches carries an undiscarded comment. The node page is header, statement, proofs with their own state lines, and the rail in the chapter's order, with "dependents" renamed "used by" and the ancestry list replaced by the "in `<document>`" breadcrumb. Home is the landing route with four metric cards. The review panel explains itself in a sentence and behind a question mark that defines each state and names the command that records it, and a row expands in place into a two-column tinted diff.

**Anchors and links (A5).** The publisher now emits a real `id` on `section`, `div.env` and `details.env-proof` (DR-92); nothing had an anchor target before, so every link into a document dead-ended. The viewer's `anchorId` uses the publisher's slug rule. A reference to a node the same document reaches becomes an in-page jump; one to a node elsewhere goes to its page. Headings carry the Stacks-project affordance. A fragment scrolls to the hash after it mounts, and again when only the hash changes, because the browser cannot scroll to an element that did not exist at navigation time. A key with no page is no longer linked (DR-94).

**The graph (A6).** Force is the default, from `d3-force`; layered keeps ELK; one page, one selection, one filter set, pan, zoom and drag (DR-93). Two old faults die: a section that is an edge endpoint is kept rather than deleted with its edges, and an edge's geometry is read from whatever container ELK placed it in, with that container's offset.

## Design changes

**The manifest gained a field the plan said Part A would not need.** The plan stated that nothing loom publishes changes and that there would be no manifest change and no interface bump. Half of that held: the interface version is unchanged, because the change is additive. But the contents tree cannot be built correctly without knowing a section's own depth. The inclusion tree nests everything a section contains beneath it, so a `\section` following a `\section` is a tree child of the first while being its outline sibling, and a `\paragraph` unit is indistinguishable from a chapter. Section node entries therefore carry `"level"` (DR-91). Without it the ACGS paper's rail fills with paragraph units and indents them all wrongly.

**The publisher had to change for anchors to exist at all.** The plan put anchors in arras. In fact no fragment had a single `id`, so there was nothing for a link to land on and the viewer could not have been fixed alone. `section`, `div.env` and `details.env-proof` now carry an `id`, their key slugged by the rule display equations already used (DR-92). The dialect specification records it. This also means the publisher's own `\ref` hrefs, which were correct all along, now resolve; the fault the plan attributed to them was in the viewer, which overwrote them with a hash built from the bare label.

**The left panel needed a registry, not just the right rail.** Chapter 15.4 gives the left panel different contents per view: a document's contents in read and graph, a table page's filters elsewhere. The plan provided for a right-rail slot only. A second registry was added, symmetric with the first, so a page still draws no navigation.

**One graph fault was not in the plan.** The layout effect read the state it had just written, which made it depend on itself and re-lay the graph hundreds of times per navigation, blocking the page for five seconds. It was found by an end-to-end test timing out, not by eye, which is the argument for the timing assertions.
