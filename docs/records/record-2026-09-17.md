### Design changes during execution

**The author names subjects and categories; loom surveys and infers neither** (DR-126). The plan took default subjects from the depth-1 works' MSC codes and admitted works with no MSC code through a hand-written MSC-to-arXiv table. Every code gave relloc sixteen default families including `00B`; primary codes only, `00` excluded, gave seven but left out `14L`, the second most common family among what the cited works cite. The table was corrected from a measurement on arXiv's records, which improved algebraic geometry and left other fields poor. Asked whether the default should change, the author ruled that a default must not be fixed but computed from a source or specified by the user, starting with configuration, and asked what an analyst or topologist would lose to a table tuned on algebraic geometry. `[crawl] subjects` and `[crawl] categories` are now the author's, with no table and no default; `plan` without subjects surveys the cited works' references so the choice is made from data. The author chose: the survey is `plan` without subjects rather than its own command; a work with no MSC code and no listed category is excluded and listed; a work passes on any of its codes; the survey counts only the cited works' references. The measurement script became `scripts/msc_arxiv_categories.py`, which counts the categories papers in given families file under.

**A work zbMATH does not know under the cited identifier is looked up by title** (DR-126). The first depth-2 plan excluded Fulton's *Intersection Theory*, Kontsevich's torus-actions paper, Fulton–Pandharipande's notes, EGA IV and Laumon–Moret-Bailly for want of any subject: zbMATH indexes them, but not under the chapter and edition DOIs other papers cite. OpenAlex supplies title and authors, zbMATH is searched by them, and zbMATH's `original` title is matched as well as its English one (it files *Champs algébriques* as "Algebraic stacks"). 36 such exclusions fell to 10. What remains is mostly work zbMATH classified before MSC existed: Mumford's GIT (1965), Deligne–Mumford (1969).

**One work is one record under every identifier** (DR-127). The plan filed a work under its first identifier; a work declared by arXiv number was re-keyed by the DOI zbMATH added mid-walk, and two references to one work under different schemes became two records (EGA I twice, five identifiers on two records). Every identifier is now indexed and records a source links are merged, the shallower kept.

**OpenAlex references without an identifier are looked up by title, author and year** (DR-127), not as bare text, which could only ever score possible (Behrend–Fantechi's "The intrinsic normal cone" at 0.75).

**The summary names what was excluded**, by family for works outside the subjects and by category for works with no MSC code, and counts works with neither.

**Fetch counts what is on disk before downloading, and stops when arXiv refuses** (DR-128). The first version counted on-disk works as it reached them, so a failure retried early in the order could be fetched while later downloads were still uncounted, and a second run could exceed the cap; the tests caught it. Three arXiv refusals in a row now end the fetch, and an interruption ends it with what was fetched kept.

**Records are written atomically, services count their failures, and status counts the plan's works.** A fetch killed mid-write could have left a `work.json` that no longer loads, silently dropping the work from later fetches. A plan now names a service that refused requests (with `set LOOM_OPENALEX_KEY` when OpenAlex answers 40x). `status` first counted every record under `refs/`, including three left by earlier plans; loom never deletes them, so status reports them separately.

**Smaller departures from the plan.** The record keeps `depth`, `reached_from`, `reached_by` and `citekeys` as top-level fields rather than the plan's nested `reached` object. The plan's "count the next level's works where their references are already known" was not built. The `\bibitem` tests use short inline bibliographies rather than the two relloc sources, which are other authors' text and would not be in the test directory. An empty `subjects = []` is the same as none: `plan` surveys.

**arXiv throttles a client, not a command.** Harvesting arXiv's OAI-PMH interface for the table while a fetch ran made arXiv answer 406 to every request from loom's HTTP client; curl from the same machine was still answered. The harvest also double-encoded arXiv's resumption token at first. The script now spaces pages ten seconds apart, and loom's `fetch` stops rather than recording a failure against every work.

## Two LaTeX faults in the ACGS quilt (loom)

The author's running requests report "still some latex errors in the ACGS quilt", quoting a proof that showed its own source. Both faults were in loom, and the quoted paragraph — `acgs-002P/proof` — carried one of each.

**Text after an unbraced argument was dropped.** `\'e` takes its argument from the middle of the text that follows the command, and the converter carried on at the next *token*, so the rest of that text went with it: `$q$ in the \'etale topology. Then there exist unique lifts $s_x,s_y$` published as "in the é" followed straight by the next formula. Sixteen words of the paper were missing from the viewer, and nothing reported it. `Converter._resume` now returns what is left of the text the arguments ended inside, and both walkers write it; the same fault applied to `\input file.tex` and to a paragraph opening with an accent.

**A macro inside `\text{…}` cost the whole formula.** `\text{nodes of \ul C}` compiles, since LaTeX's `\underline` opens math itself, but MathJax's text mode has no `\underline` and refuses the formula it is in. No configuration reaches it: text mode takes its macros from its own package, and neither `tex.macros` nor a `textmacros` block overrides them (checked against MathJax 3 in a browser). loom now writes such a macro and its arguments between dollars when publishing math (DR-130); a macro whose body is words, and one already inside math, are left alone.

Verified on a fresh copy of `demos/acgs` served with the current bundle: the paragraph reads "in the étale topology. Then there exist unique lifts …" and the base log structure typesets with its underlined `C`; the page carries no MathJax errors at all, and the quilt's only remaining converter fallbacks are the two `thebibliography` environments in `acgs-003T`. `uv run pytest` 289 passed, 6 skipped, with four new converter tests; ruff and mypy clean.

### Design changes during execution

**A landmark carries loom.sty's macros inline.** The plan said a canon file must compile without `loom.sty` but left how open. `canonize` replaces `\usepackage{loom}` with the package's three `\providecommand`s between `% !LOOM begin loom-macros` and `% !LOOM end loom-macros`, and `draft` swaps the block back. `\uses` and `\incomplete` therefore survive the round trip, and `\providecommand` makes the block harmless where the package is also loaded (DR-139).

**Every writing conversion runs the identity test by default.** The plan gave `--no-check` to `canonize` only. `draft` and `linearize` have it too, on the same rule: a command that writes one new file from another compares them, and a failure removes the file it wrote rather than leaving a copy that does not typeset as its source. `atomize` and `inline`, which the book already specified as reporting and not reverting, are unchanged (6.7).

**A conversion that supersedes the default master moves `[quilt] main`.** Not in the plan. Without it, atomizing the default master leaves the quilt with `main` naming a file that defines nothing, and every later scan says `loom:main-not-found`. `main` is loom's own line — `init`, `import` and `draft` already write it — and the move is recorded in the command's output (4.4.3, 4.8.1).

**`loom:no-live-document`.** The plan had arras name `loom draft` in its empty state. That would have put a loom command in arras's source, which 10.8 forbids and the boundary test enforces. Loom emits the diagnostic instead, with the command as its fix; arras says only what is true of the corpus and points at the problems page. ### Design changes

**The digest contract was struck, not written.** `weft-and-loom.md` §4 asked for a written digest contract both implementations must keep, plus a shared conformance fixture spanning them. Discussed with the author and struck: §3 of the same document says *two digests of one paper may differ, weft's and yours, and that is correct*, which removes the invariant a contract would protect. A digest is a quilt artifact — an abbreviated cited paper under **your** citekey, with your locators, your `\uses` and a place in your ledger — and weft produces no such thing; its extractions are global, unverified and keyed `arxiv:1709.09864v3#thm-4.1`. There is nothing for the two sides to agree on, so a fixture spanning them would test a boundary that does not exist. weft owns its fork's divergence in its own tests. §4 now says so, and §3's ruled-out list was made precise against the "cite this" action two paragraphs above it, which the two lines had been contradicting.

**The crawl was deleted rather than deprecated.** Nothing outside `refs/crawl/` read its storage, `[crawl]` was never in the config template, and git holds the code weft ports — so a deprecation period would have bought nothing and left dead paths in a tool whose selling point is a small promise. The decision record names the commit instead.

**Absence is resolved in the loader, not in the types.** 0.9.5 §5 R2a reads as "every section optional at boot", which suggests making them optional in `types.ts`. That would have pushed a null check into all forty-odd access sites and into every view written afterwards — the same work paid forever. Normalising once at the boundary keeps the types honest *after* the boundary, which is what a publisher/viewer split should mean. The sections therefore stay required in `types.ts` and the *specification* is what changed.

**The vocabulary check asserts less than §11 check 2 says, on purpose.** "No page contains a publisher's name" cannot mean `manifest.publisher.name`: the home page renders it, and rendering a name read from the manifest as attribution is precisely the neutrality the check wants. A name compiled into the source is the violation. The suite therefore checks literal words, and the two that R2b still owes — "not yet compiled" and "loose" — are named in a `PENDING_R2B` list, the pattern `host-neutrality.spec.ts` established, so emptying it is the visible end of that job.

**A config table that is not a table no longer crashes loom** (DR-145). Writing the replacement for the deleted crawl config test surfaced it: `QuiltConfig.from_dict` warned that `[refs]` was not a table and then read it as one, raising `AttributeError` on any `config.toml` containing `refs = "yes"`. Reachable since the warnings were added; nothing covered it. Every table read now goes through one accessor.

**The canon hash is a cache key, not a content hash.** Removing the crawl package changed all three canon hashes in the conformance fixture, because `_canon_hash` mixes in `_code_hash()`, a fingerprint of every `.py` file under `src/loom/`. That is deliberate — in a dev checkout the version string never moves, so a changed converter would otherwise hit the cache — and it is empty for a released version. The consequence worth knowing is that **any** loom code change churns those three lines in the vendored fixture, and the refresh is part of the change rather than a sign that something broke. Not queued: it is correct at release, where it matters.

**The arXiv "refusal" is rate-limiting, not a missing header.** The author suggested the 2026-09-17 hour of failures came from Python's urllib sending no `Accept` header where curl sends `*/*`. Tested directly, including while arXiv was actively refusing: curl with and without `Accept`, and urllib with and without it, all four returned 200 and followed the redirect to `/src/`. loom already sends `Accept: */*` at `digest/fetch.py:51` and `Accept: application/json` at `refs/resolve.py:186`, so there was nothing to fix. What does reproduce is a window-based throttle: two e-print requests back to back drew a 406, and the same URL succeeded seconds later. `_get`'s three attempts at 3s and 6s are sometimes too impatient for that window, which is worth knowing but is not this plan's to change. The useful outcome is that **the fetch path is now verified live** — e-print, PDF and unpack, on both paper fixtures — where DR-144 was going to have to say weft inherits code nobody had exercised.

**A fixture-preparation step nobody had recorded.** Rebuilding the paper fixtures from arXiv, `0805.2065` failed to compile: two `0xD0` bytes, Mac Roman en dashes in bibliography page ranges, which are invalid UTF-8. The earlier session must have fixed them by hand and it was written down nowhere, so the paper tier could not be reproduced from a clean machine. Recorded here; `LOOM_PAPER_FIXTURES` wants a `NOTES.md` beside it the next time someone builds one.

## Plan 0.10: annotations as a log, review mode, reference notes (loom, arras, the book)

Built 2026-09-18 from [the plan](../plans/0.10-annotations-and-review.md), in the five commits it sequenced. loom `3eef05d`, `260e830`, `5b1e9f9`, `506bd7b`, `c87814f`; arras `43be6c7`.

### What was built

**The log.** `annotations/log.jsonl` replaces the tree of `annotations.json` files — one per run, one per author per day, each rewritten whole whenever anything in it changed. Events `created`, `replied`, `edited`, `resolved`, `discarded`; current state by replay. Annotations gain `severity`, `payload` and `placement`, and `citation` joins the kinds. `run` and `author` are separate columns, so "everything from this run" and "everything any agent said about `rl-0002`" are both filters.

**The AI layer's entry points.** `loom ai start` stops launching your agent; `run.toml` becomes `created`, `name`, `discarded`; runs are addressed by name, by a prefix, or by path, with an ambiguous prefix naming its matches and refusing. `loom ai runs`, `loom ai name` and `loom ai findings` are new. `CLAUDE.md` gets one line of loom's and keeps everything else.

**`loom bundle` withdrawn**, its engine kept: `loom source KEY --closure` prints, `loom compile KEY --with FILE` checks a proposal, and `build/bundles/` is still written by the compile that needs it.

**Anchors frozen** against `.loom/last-seen.json`, the only genuinely new machinery in the plan.

**Review mode** (the author's mode 7) and **quick mode** restored; **reference notes** with `loom refs note --accept|--reject`.

### Design changes, and why

**The plan said the last-seen cache would hold hashes. It cannot.** You cannot freeze a text you no longer have: once the author saves, the previous version exists nowhere, because loom reads files and not history. The 0.10 reminder had this right — "a last-seen copy of every key's *text*" — and the plan compressed it wrongly. The cache stores text, one per key, rewritten in place. A key nobody annotated costs one hash comparison, so an unreviewed quilt pays for the cache and nothing more.

**`loom bundle` could not be deleted, and that made the replacement better.** `build_bundle` is the engine behind `loom compile KEY` and `loom check --bundles`, and `render/fragments.py` imports `_macro_block` from the same module. So the *command* went and `tex/bundle.py` survived — which meant the verification path became one option on a command that already bundled and compiled, rather than the temp-copy mechanism the design session proposed. Smaller and more faithful: it compiles the real closure rather than a synthetic stand-in.

**The re-check rule changed shape.** The plan framed the log as enabling `edited`; working through `blocks.md` made the rule sharper than "you may now edit". A reply is dialogue and an edit is restatement, so: resolve what is met, edit what still stands, discard what you should not have raised, and resolve-then-create when it has become a different fault. Replying to yourself is what left one finding wearing a copy per pass.

**A person's annotations still group by day.** With one log the obvious grouping is per author, and that was the first implementation. It makes one enormous thread and loses `comments/<slug>/<date>`, which `specs/manifest.md` documents as a thread id. "What the author said on the 16th" is a session a reader looks for; everything one person has ever written is not.

**`loom comment --run` no longer creates the run directory.** It used to, as a side effect of writing the record file. A run is a directory `loom ai start` makes, and refusing is clearer than silently opening one — but it is a behaviour change, and three tests had to start a run before commenting into it.

### Bugs found and fixed

- **`loom comment --run R --resolve <id-in-R>` silently lost the resolution.** The parent and the writer were two in-memory objects over one file, so the status flip was overwritten a line later. It is the case an agent hits on *every* re-check, and the one test covering resolution happened to take the path that works. An append-only log cannot express it.
- **`Records` was built without `history_dir`** in `build`, `review` and `ai` — only `lint` passed it — so a quilt with a non-default `[quilt] history` read its stale-cause diffs from the wrong directory in every command but one. A test now moves the history and checks the ledger, the frozen texts and the cache all follow.
- **`find_run` never matched a slug prefix**, because a run directory leads with its timestamp. Found by using the command, not by a test.
- **`loom comment --edit ID "body"` put the body in the TARGET slot**, since `--edit` takes no target. Found the same way.
- **`QuiltConfig.from_dict` warned that a table was not a table and then read it as one**, raising on any `config.toml` with `refs = "yes"` (DR-145, found in the previous round and fixed there).
