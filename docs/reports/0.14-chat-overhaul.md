# 0.14, the chat overhaul: what a real agent and a real browser found

This report is for the author. It says what the study and the principles check of plan 0.14 found, what was fixed because of them, and what waits on you. Written 2026-09-23, at the end of the plan.

**Scope, stated first.** Three iterations ran, each on a fresh copy of the showcase set up as a fresh clone would be, with launching on and the Claude preset on Sonnet. The implementor played the author, driving the real viewer through `arras/scripts/drive.mjs` at 1440×900; the agent was Claude Code, started by `loom serve` itself for every turn, never by the implementor. About twenty turns ran in all: 7 in iteration 1 (plus two F2 started unasked), 9 in iteration 2, 4 in iteration 3. Turns took 19 s to 5 min; two were stopped from the Chat for running long. Cost was not metered. The plan's stopping rule was "no fault worth fixing, or the third iteration"; the third still found faults, so the study stopped on the count, not on a clean pass. The principles check ran on the third iteration's quilt at 1440×900 and 1100×800.

**How to read this.** **Verified** means reproduced here, with the file or the shot named. **Reported** means the agent's word. A fault carries **F-n**, a severity, and the test that now holds it; F30 and F31 came from the principles check, not a scenario. Everything load-bearing from the fault log is reproduced below.

**What this cannot tell you** is in §6: with no person in it, the study shows that the Chat works and is legible, and nothing about whether talking to an agent through it is pleasant. §7 is the part that waits on you.

**Where the faults were.** Eleven of the thirty-one are in launching (F2, F6–F8, F12–F17, F19) and were found only because a real agent was started by a real server: none of them is visible to a scripted test that fakes `/_api/events`. Seven are in links (F9, F20, F21, F26–F29), and all were found by following what an agent actually wrote rather than what a test author imagined it would write. The agent's own habits drove that: it links its replies more than anything, and quotes source with `\ref` in it.

## 4. What the agent did

| habit | what it did | verified or reported |
|---|---|---|
| orient | every conversation's first turn ran `loom ai orient` first; resumed turns did not, as the prompt allows, except once after a stop | verified: `run.log` |
| read the packet | quoted each note back and answered it by link, every time | verified: the transcript |
| answer with `say` | every turn that finished answered with `session say`; none wrote a journal | verified |
| links | wrote `[](quilt:…)` itself from `formatting.md` and never called `loom link`; every link that reached the transcript resolved, and no turn's closing text mentions a refused one | verified for the transcript; `agent.log` keeps only a turn's closing text, so a refusal retried within a turn would not show |
| stop after one turn | always, including after a stop (F16) | verified: `agent.json` |
| the permission file | one refusal in the whole study, `refs overview` (F18) | verified: `agent.log` |
| honesty | named what it had not checked (`file-verified`, `memory-grade`, "I did not compile either suggestion"); flagged its own fault F25 unasked on the next turn | verified |
| time | 19 s for a one-line answer; 25–97 s for a note or three; 218–254 s for "does this declare everything it uses"; past five minutes for "read every digest overview", stopped | verified |

Two things it did that nobody asked for, and that the design should know about. It **links its replies** more than anything else ("I replied to your objection in …"), which is why F27 mattered. And it **quotes source verbatim**, `\ref` and all, which is why F28 did.

## 6. What this cannot answer

- **Whether any of it is pleasant.** No person used it. The study shows the Chat works and each element answers its question; it cannot show that talking to an agent through it is better than a terminal.
- **Whether the report is missed from What it did.** The implementor never wanted it, but the implementor also wrote the log.
- **Codex.** Not installed here; its preset is still unverified.
- **Two people in one session.** The showcase's Wren Halloway exists only as history, so F3 was seen but never lived.
- **A long-running week.** Every quilt lived under an hour. Whether `run.log` and the transcript stay legible at a thousand rows was measured only by seeding.
- **Cost.** Not metered: Claude Code on a subscription reports none per turn.

## 7. Experiments for you to run

Each names the decision it could overturn.

1. **A week with launching on**, in a quilt of your own. Overturns decision 4 if the status line is not enough to know what the agent is doing, or DR-278-ikmartin's person-only rule if you find yourself wanting an agent's message to wake another.
2. **Reply from the tray instead of typing**: mark three things and send with no words, for a sitting. Overturns decision 2's "counts only" if you find yourself wanting to see what went, in the message.
3. **Read What it did after a long run**, sixty rows or more, and ask whether you missed the report. That is the one question the plan left to the study, and the study could not answer it.
4. **Follow links mid-thought** while reading the whole document, and count how often landing in the document rather than on the node alone is what you wanted, including the numbering that may differ from the link's name. That tests DR-280-ikmartin.
5. **Write "Theorem 3.4" in the Chat** a few times. and see whether the agent resolves it with `loom search` before reading, as the orientation now tells it to (DR-281-ikmartin).
6. **Invite a second person into a session** and have each of you send: each message should carry only its sender's notes (DR-272-ikmartin).

## 8. After review

The five questions of §2 were decided on 2026-09-23 and built the same day; WQ-43 to WQ-47 are closed.

| fault | decided | built |
|---|---|---|
| F3 | a message carries only its sender's notes, as decision 2 says | `pending` takes the sender; the viewer's packet is the name its messages go under; another person's notes wait for their own message |
| F5 | quote citations and references as written | the renderer puts each command's source on what it draws and the viewer quotes it whole; loom's quote projection also maps quotes and dashes to what the page prints (`Ehrhart’s`), a second cause of the same fault found while fixing it (DR-282-ikmartin) |
| F19 | one policy, loom's own, the same for the person's own agent and a launched one; a quilt does not change it; provisional | rendered as `.claude/settings.json` and `.codex/rules/loom.rules`; `agent.log` opens with where the turn's rules came from (DR-283-ikmartin). Claude Code's settings cannot point to another file, so a single shared file was not possible |
| F21 | reveal a node in an open document that holds it, background tabs included; the default document's numbering names the link | `follow` looks for a holder: the link's own document, then one on screen, then the tab last looked at (DR-280-ikmartin) |
| F23 | a loom command | `loom search "Theorem 3.4"` lists every key the drafting documents number so, the default document's first and marked, `--in DOC` for one document (DR-281-ikmartin) |

The principles check's P2 question — the footer and the Chat's tab both name the session — was judged at review: the tab stays.

WQ-48, studied afterwards: the check of `recorded` hashed a key's text without its children's places while every writer hashed it with them, so every note on a section or a document was unrecorded from birth. Fixed with four related shortcomings — versions frozen at write time, replies and re-checks recording the text they were written against, and no mark for an unrecorded note — and an edit in the viewer that never changed a note's text (DR-284-ikmartin).
