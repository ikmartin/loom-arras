# v0.1 study: register of findings

One row per finding from every investigator's report under `raw/`, keyed by the report's own id. Checkout `v0.1-study` at 71621877. Companion: `register-notes.md` (disagreements, decisions, cuts, weak load-bearing claims, author-only tasks, gaps).

## How to read and extend it

- **Reports registered (15, plus one log):** attach (ATT), core (CORE), cuts (CUT), install (INST), inventory (INV), lean (LEAN), library (LIB), live (LIVE), process (PROC), quant-findings (QF), review (REV), speed (PERF), tests (TEST), viewer (VIEW), walk (WALK), walk-small (SWALK, a second first-time-user walk by a weaker model on twelve of the same tasks), lean-trial (LTRIAL), safety (SAFE); and `small-model.md`, a small model's log on seven requests (SMALL, ids assigned by the registrar). **Pending:** tinytex.
- **walk.md** is the study's only first-hand evidence of what a newcomer can work out: an investigator who had seen no documentation or source attempted eighteen tasks in the running viewer at three widths. Its weights are its own ("stops them", "slows them", "minor"). Task by task, with the code-side ids, in `register-notes.md` g.
- **The author's decision (already made):** v0.1 is built for Claude Code. Codex is not checked during the build; a manual Codex and Gemini check is a gate before shipping. Findings whose weight rests on untested Codex behaviour are tagged **[Author: Claude Code first; Codex part is a pre-ship check]** and listed in `register-notes.md` e; the design stays vendor-neutral where that costs nothing.
- **speed.md measured** what core, viewer and inventory said about slowness from reading the code; its confirmations are tagged **[PERF-n: …]** on the original rows. To fold one in: add its rows under the heading each most affects, in weight order; add any "same thing" lines and proposed work; put its verdicts on earlier claims as a bracketed tag on the original row; update the count table below and `register-notes.md`.
- **Two reports test the others.** `live.md` ran the install and the Claude Code attach for real and gives verdicts on INST and ATT claims; `cuts.md` attacked every proposed hide or remove. Their verdicts are tagged on the original rows as **[LIVE-n: …]** and **[CUT-n: …]**. Three proposals **DO NOT SURVIVE** the cuts review and are tagged so wherever they appear: hiding agent copies and making suggested edits the only route for AI-proposed text (CORE-9, REV-11, review.md §5 and package F; CUT-1), going MCP-only (attach.md C6, ATT-13, ATT-18; CUT-6), and hiding or removing sessions beyond the footer and picker (CORE-12, INV-13, VIEW-4's wider reading; CUT-3).
- **live.md's limit:** the Claude Code CLI on this machine is not signed in, so live.md ran the real CLI against a scripted stand-in for the model. Client start-up, permissions, trust, slash commands and tool execution are real; what an agent chooses to do, the Code tab's own interface, and everything about Codex remain untested (see `register-notes.md` e).
- **Ids the reports did not assign:** QF-n is the quant-findings friction item n (QF-5b its item 5b); QF-B9 its bug 9 (the only bug not also an item); QF-N1 to N4 its "Not tried in the log" checks; QF-W1 to W10 its ten "Works well" entries; LIB-B13 the library report's bug B13; PROC-31 the stale queue count PROC-30 refers to; PROC-census its §1 reading-cost finding; PROC-WQ-nn its §4 work-queue verdicts; LEAN-§7B and LEAN-§7D the lean report's machine requirements and cut line; CUT-14a to CUT-14d the four defects listed under the cuts report's CUT-14; PERF-copy the speed report's "copy hygiene" hazard; WALK-Fn item n of walk.md's "Things that looked broken" where no WALK finding already carries it; SMALL-1 to SMALL-10 the registrar's ids for the small-model log (SMALL-7 and SMALL-8 unverified).
- **walk.md screenshots** are named by file (for example B07-24) and live in that investigator's scratch `study/walk/shots/`; live.md's under `study/live/shots/`.
- **Paths:** without a prefix, under `loom/src/loom/`; `arras/…`, `docs/…`, `loom/tests/…`, `.github/…` from the repository root. `$S` is the investigator's own scratch directory.
- **Columns:** *evidence* as the report gives it; *kind* is reproduced / read in code / measured / from documentation / reasoned (the registrar's judgement of what the evidence is); *weight* is the report's for v0.1 (blocks, hurts, cosmetic, irrelevant, nice-to-have; "not graded" where none; "—" for something fixed; "verdict" for the cuts review's rows); *effort* is the report's guess ("not given" where none); *rec* is the report's; *owns* is what the fix would own where the report says ("—" otherwise). "Registrar:" marks a fact the registrar checked in code.
- Within a heading rows run blocks, hurts, not graded, cosmetic, irrelevant or nice-to-have, verdicts, then fixed; ties keep report order.

## 1. Safe

**safety.md (SAFE) leads this heading.** It ran 487 seeded random sequences of 35 acts (17,045 acts) against copies of the synthetic, showcase and quant quilts, 412 in process through `render.api.handle` and 75 over HTTP against real `loom serve` processes, plus 16 crash runs and 30 real-process race trials. 465 sequences met at least one fault; 225 damaged the person's text, 80 without help from an injected save. Verdict: **the release bar is not met**; eleven distinct faults, six of which damage the person's text; one root, a text test standing in for a record of the write, lies under every sequence that wrote an edit twice.
