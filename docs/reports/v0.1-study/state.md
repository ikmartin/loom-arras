# Where loom stands

A grading of loom on `main` (commit 71621877, 13 November 2026) against the bar for v0.1, the version to be given to two to four pilot mathematicians. It is the second of the study's three documents: the plan is `docs/plans/0.32-v0.1.md` and the evaluation of the code is `codebase.md` beside this file.

## How to read this

The evidence is twenty-seven investigators' reports under `raw/`, written over one day, and a register that merges the findings of nineteen of them (`register.md`, with `register-notes.md` for disagreements, decisions and gaps). A finding is cited by its id, such as SAFE-1 or LIB-2; the register says which report holds it, except for the eight reports it does not cover, such as `security.md` and `spike-door.md`, whose findings are cited with the report's name. Each claim below carries one of four marks:

- **reproduced**: an investigator made it happen and left the steps;
- **measured**: a number taken from a running loom;
- **read**: found by reading the code, not run;
- **checked**: the study's lead confirmed it independently against the code or the files.

Five limits apply throughout. No trial used a real model inside Claude Code's own connection to loom, because the Claude Code command line on this machine was not signed in; a scripted stand-in drove the real client, and a small model reached loom through the shell instead (`live.md`, `small-model.md`). Nothing was tried in the desktop app's Code tab, whose behaviour its documentation mostly does not describe (`claude-code-docs.md`). Nothing was tried in Codex or Gemini, which the author has made a manual check before shipping. Every first-time user, and the researcher of the exploring journey, was an AI model playing a person. And every timing was taken on a machine shared with other sessions, at loads from 3 to 50: counts are exact, seconds are soft.

## The bar, and the grade today

| gate | what it asks | today | the short reason |
|---|---|---|---|
| Safe | Loom does not damage a person's text or records, and each write is undone in one step where it happened | not met | Four faults damage text in an ordinary session and two more in files with Windows line endings or Latin-1 bytes; Keep has no undo where it happens |

## Safe

**Writes to a person's files.** A trial ran 487 random sequences of thirty-five acts (keep, discard, undo, restore, tick, hand edits) against copies of three quilts (synthetic, showcase and the author's quant) and found six faults that damage text: four in an ordinary session and two in files with Windows line endings or Latin-1 bytes (`safety.md`, reproduced). A kept edit can be written twice at 71621877 (SAFE-1, REV-3, reproduced). Where loom itself wrote the text, a comparison of text and not a record decides whether the edit is already in the file; in 14 of the 24 reproduced cases the text was typed in by the person or an agent, and the fault is that the test looks across the whole block instead of at the edit's place (`spike-door.md`). A save from the person's editor made during a Keep is lost with no copy, and two Keeps in two processes, one through the write API and one from the command line, lost a kept edit in one to three of fifteen trials (SAFE-2). An edit filed on a block that was keyed by its position can be written into whichever block now holds that position: on a copy of the author's homework the answer to one problem went into another (SAFE-4). Restoring a version overwrites a file the document no longer includes without keeping it (SAFE-5). Keep turns a file's Windows line endings into Unix ones and its Latin-1 accents into wrong UTF-8, restore writes the same normalised text, and Discard corrupts a file with Windows line endings (SAFE-6, SAFE-7; the restore case read, the others reproduced). The order of writes in `pending.py` is file first and record after (checked), so a crash between the two leaves no trace and nothing repairs it.

**Undo.** Keeping a suggested edit cannot be undone in one step anywhere (REV-2, reproduced; neither AI walker found any way back but restoring the whole file, after about 18 and 25 actions). That restore is the only way back, and in one walk it missed a kept edit, whose "before" version the walker found saved under another document (WALK-F4, reproduced; the cause not checked in code).

**Records.** In the author's own quilt, 34 record lines are signed with a test fixture's name, from a wrong value in the per-user configuration whose origin was not found (`quant-findings.md`); further mentions in a backup, a run log, two stored texts, the split look's own file and a digest bring the lines naming the fixture author to 41 (checked by grep). His record of what he has looked at is split across two files, and nothing can say that two names are one person (checked). A quilt copied while its server runs carries that server's access token in `.loom/serve.json`; loom ignores the file in the copy, since it names another root (PERF-copy; checked in `render/serve.py`).

**Records that follow the text.** When a co-author's edits arrive underneath annotations and suggested edits, records land on the wrong block. Over 4,693 placements on seven papers taken as their authors wrote them (92 % of their pieces keyed by place) under nineteen kinds of edit, today's code put 160 on the wrong block, detached 615 and lost 960; 1,195 of those 1,575 are misses whose words still stand (`check-labels.md`, measured). Imported papers carry ids and fare better. One inserted theorem moves every acceptance keyed by place onto the wrong theorem, where it shows as "accepted, stale" (measured on five).

**An agent's edits in place.** A new quilt lets an agent edit the person's drafts in place and records nothing: `deny` is empty and `track_edits` is off (checked). In three trials nothing recorded such an edit or marked it as an agent's: the page re-rendered the new words, and only an edit to an accepted block showed, as "changed since you accepted" (LIVE-12, with a scripted stand-in for the model in acceptEdits mode; SMALL-4; REV-5). A deny rule is a default and a convention: Claude Code's own tools honour it, a subprocess in bypass mode wrote past it (LIVE-13), and by Codex's documentation its own edits ignore it (ATT-11).

**Security.** With TeX Live's stock configuration, compiling a stranger's TeX cannot run programs: loom passes no `-shell-escape`, TeX Live's restricted shell escape blocks `\write18`, and the routes by which a document could take over the build are closed (`security.md`, reproduced as failing to break in, on TeX Live 2024 only). Five weaknesses need fixing. A file named `loom.py` in a quilt's root runs as the person on every loom MCP tool call (SEC-1, reproduced by running the server's subprocess command by hand, and checked). A hostile web page using DNS rebinding can read the server's token and the quilt's files, though it cannot write (SEC-2, shown with a forged Host header). A TeX document can read any file the person can (SEC-3). An HTML file in the quilt, once the person opens it, can read the quilt with no content policy to stop it sending what it reads elsewhere (SEC-5; the read shown, the sending reasoned). And `.loom/serve.json`, which holds the token, is readable by other users of the Mac (SEC-6b). One limit stays and is to be stated: the boundary between an agent and the author is a convention, and an agent that reads the server's token can perform an author-only act (SEC-4). In a live run with loom's settings applied, a scripted Claude Code session that tried evasions got no author-only act through, though a subprocess it ran in bypass mode wrote into `.loom/annotations/` (LIVE-13).

## Installable

The install line in `loom/README.md` names `ikmartin/loom`, not this repository, `ikmartin/loom-arras` (checked). There is no tagged release. With no TeX on the machine, bringing a paper into a quilt refuses outright, and a paper copied in by hand shows as raw LaTeX, with "PDF did not compile" in the file tree and the reason only in a hover title (LIVE-1, reproduced). `loom serve` serves one quilt and needs a terminal, and every quilt defaults to the same port, so a second one fails until given another; nothing launches the application, lists quilts or makes a new one from the viewer (INST-1, INV-1, LIVE-7). The viewer tells the person to type a loom command in nine places (VIEW-1, read). Today the shortest path from "installed" to "my agent left a comment and I can see it", with TeX already installed, is four typed commands, three questions, two or more approval prompts, and a terminal left open (`live.md`, counted with the command line standing in for the Code tab, whose approval steps are as documented).

A small private TeX, installed by hand beside loom, works. TinyTeX seeded with what loom needs is a 54 MiB download and 328 MB on disk; after three real papers it had fetched 166 MiB and stood at 407 MB. It runs natively on Apple silicon, builds the showcase faster than the author's TeX Live 2024 (19 s against about 30 s cold), and produces the same words except two review fragments that repeat their last line, a latent loom bug (`tinytex.md`, measured). Three things the earlier reasoning missed: starting from a minimal base, real papers needed four, eight and twenty rounds of fetching missing packages (about six for the largest with a seed and a check of the preamble); a missing package can be named from the logs in 34 of 37 cases, not all; and diagrams and PDF figures also need Ghostscript or poppler, which TeX does not bring, so without Homebrew an xy diagram in one test paper lost its arrows and its PDF figure became a broken image.

Windows is far: process control and liveness checks, opening files, about sixty calls with no stated encoding, and the test suite's fake TeX all assume POSIX, though a Windows file lock exists (INST-14, read). There is no macOS job in CI, though every pilot is on a Mac.

## Attachable

The agent side is the strongest part of loom. A small model read the whole forty-kilobyte orientation, summarised the boundary in its own words, left a comment and two suggested edits on the text, declined on the orientation's word to mark a result checked or to add a paper, and wrote up its work, all from seven plain requests (`small-model.md`). In Claude Code's command line, with loom's server and settings passed to it and a scripted stand-in for the model, loom's server starts and its modes appear as commands (LIVE-9, LIVE-14, reproduced). The bridge that tells an agent what page the person has open works; the selection reaches the agent in a document that is one file, is dropped in a document built from included files (LIVE-10, reproduced), and is unverified in Markdown (QF-W3).

What is missing is everything a person sees. Setting up means typing `loom ai init`, and an agent cannot run it for them (ATT-1). Nothing records or shows that an agent is attached; Settings says "Set up" when a file merely exists (ATT-2). Until the person trusts the folder, Claude Code's command line ignores the 55 rules loom wrote to allow its commands and leaves its server pending; whether it applies loom's deny rules then was not tested (LIVE-8). An agent's comments arrive with no notice: the counters and margin markers change and a suggestion appears inline, but nothing says an agent wrote (LIVE-11). Presence can be built, since the client names itself in every request and each conversation has an id, but not in the way first proposed (LIVE-9). No documented way exists for another program to open a folder in the Code tab (`claude-code-docs.md`).

## Legible

Two AI models played first-time users on the showcase: one, which had seen no documentation or source, attempted eighteen tasks in the running viewer, and a weaker model attempted twelve of them without seeing the first walk (`walk.md`, `walk-small.md`). The first achieved ten of eighteen, five partly and three not. Both failed or only partly managed the same six: telling whether an AI can see my comment; telling whether one is connected; undoing a Keep; adding a paper by dropping its PDF; finding all notes in one place; and fixing what Problems reports without a terminal. Commenting on a sentence and not its whole paragraph, and leaving a note attached to nothing, were managed by the stronger walker and not the weaker. The first walker found names pointing the wrong way: "Proposed Changes" holds a cited paper's results, and an AI's edits to the text are under "Your Changes". The showcase's first page is a README written for loom's developers, and a new quilt opens on a README that teaches commands. At 760 pixels wide, a guess at a browser beside an agent app on a laptop, the second pane is off the screen. The weaker walker also had a comment draft discarded by a stray click, found four overlapping ways to mark text, and could fix none of the three Problems it found, because every fix offered is a terminal command.

Reading a proof, opening the compiled PDF and putting a cited work beside the paper worked for both in a few actions.

## Complete

**Proofreading.** The pieces exist: an agent comments and proposes edits without touching the text, and the person keeps or discards. What fails is around them: Review mixes the proposals with much else (below), Keep is not safe to repeat and cannot be undone, and two bugs sit in suggested edits themselves, the worse being that an edit on a section's "body" deletes its heading and label (CUT-14a, reproduced). For anything larger than a local change, the author's real practice is an agent's copy of a document: his paper's working text is a 3,122-line copy, 361 of its 404 annotations are on copies, and the four-day agent session around it carries 97 agent names (CUT-1, measured). A suggested edit cannot carry a change that builds on another, a move, or a new document (reproduced), so copies stay. Taking a copy into the person's document names a terminal command and failed on a paper split into files (EXP-4).

**Learning.** The author's log of eight days' learning from textbooks was checked item by item: nine of forty-one frictions are fixed, twenty-two are still true, and all ten things it says work well still work and need no LaTeX (`quant-findings.md`). What still hurts a learner: a Markdown lesson cannot be annotated or given a suggested edit; a large Markdown edit has no undo unless `track_edits` is on, and it is off by default; status, lint and the agent's orientation speak only of statements and keys, so a quilt of lessons is told that nothing is being worked on; dollar amounts become mathematics; and links in lessons break silently.

**Exploring.** One afternoon on an unproved lemma, with one investigator playing both the researcher in the viewer and the agent, got through all nine steps without the researcher typing a command (`explore.md`). A question as an annotation, an agent's attempt in a copy read beside the paper, library search, a finished proof as suggested edits, and a transcript that reconstructs the week all worked. What hurt: an unproved step prints nothing, so it looks finished; a recorded dead end was missed and re-derived; dead ends, claims and asides are all one type; and no place lists what is open.

**The library.** The wrong match the author hit was reproduced: a work with no author and a title read off a journal's masthead matches every later paper from that journal (LIB-1). Any arXiv id or DOI on a PDF's first two pages is taken as the PDF's own (LIB-2). After a drop there are nine distinct states across two dialogs behind five entry points. Keys come from three generators and include `Of`, `Wor` and one made from a URL. An agent has no channel to propose a work, so it files the reference as a comment on the paper (SMALL).

**Overleaf.** Today's sync treats the quilt as the source and publishes to Overleaf, and pairing is a typed command (INST-9, read); by the work queue's own account it has never been run against Overleaf itself (WQ-16).

**Formalization.** Nothing exists in loom. A trial installed Lean, ran the collaborator's skills on two results of the showcase paper and reached a sealed, checked proof of the easier in twenty minutes of agent time; the install took three and a half minutes and 10.7 GB (`lean-trial.md`, measured on a Mac that already had Homebrew and git, with every decision that belongs to a person simulated and its audits run by subagents of one session). It found that loom's dependency closure misses definitions reached through macros, that `loom status` does not notice the paper's statement changing unless the result was accepted (`loom history` does), and that the skills record the author's approval as a string anyone can write.

## Fast

On the showcase quilt a save reaches the viewer in under a second (0.3-0.9 s). On a copy of relloc, saving a word never written before takes 12 to 21 s to be seen, median 15.75 s (`spike-speed.md`, measured at load 4-14); the audit's 9-15 s (`speed.md`) alternated two words, so TeX came from its cache. Every publication on relloc costs at least five seconds even when nothing changed (PERF-1). Inside a save's build, re-anchoring annotations whose words are gone runs twice, and the second run costs about 2.4 s of 11 s (FAST-2). Two TeX runs sit on the save path, one of them for Review's comparison preview (PERF-2). Each block's cache key hashes its whole file, so a save re-renders every block of the edited file, 63 in relloc's draft (FAST-7); each key also carries every document's page numbers, so one moved page break re-renders all 2,384 blocks with about 50 TeX runs (PERF-3, FAST-7). A cold start on relloc served nothing for about eight minutes, and the typeset draft only after eighteen (PERF-6). A person with no loom author name set pays for 609 calls to git per build, 28-38 s of a build on the loaded machine (PERF-5, FAST-4). Writes from the viewer answer only after a full rebuild, 5.1-6.7 s on relloc (PERF-8); in the exploring journey the first second of typing after marking words was lost, because the mark waits for that write (EXP-3, 1.3-1.5 s on the showcase).

A prototype of the cheap fixes (`spike-speed.md`, `spikes/speed.patch`) brought the median to 11.83 s at two to three times the load, and puts first sight at roughly 5-6.5 s at the audit's load, not the 3-4 s the audit predicted. Re-anchoring once and caching the git name are safe as they are; taking page numbers out of the keys is safe with a preamble check and turned a page shift from 2,384 blocks into one; publishing before TeX delayed the typeset block (median 23.7 s against 15.4 s); answering a write first took 0.03 s but broke 16-17 tests and the viewer's assumption that an answer means the page is current. Under two seconds needs an incremental build.

## Quiet

Of what Review counts on the author's two quilts, 33 % and 72 % is changed mathematics or an AI's proposed edit; of all rows it draws, 17 % and 13 % (`review.md`, measured). No row in either quilt shows a statement an agent changed with the change drawn. Problems shows no problem in the person's own LaTeX on any of three quilts: of 74 diagnostic codes, about ten are LaTeX problems an author would recognise (CORE-15), and a document that fails to compile never reaches the page. Counts disagree between pages. Every new user sees an amber "not writing in a session".

A month of the author's own history was replayed to simulate what a list of "mathematics that changed" would have held at each moment he plausibly looked (`check-changed.md`). With agent copies left out: typically nothing or one row; at worst 102 and 231, each from one bulk arrival he had asked for. Grouped one row per file with a bulk arrival as a single row, the worst would have been 3 and 23. On relloc, though, the mathematics agents rewrote lives in a copy, so such a list shows almost none of it. Who made a change cannot be guessed from timing, and neither quilt has ever recorded an acceptance.

## What works and must not be broken

These are what real use rests on, each confirmed on `main` by an investigator's trial unless marked:

- the bridge that tells an agent what page the person has open, and what is selected in a document that is one file;
- Markdown and HTML files shown in the viewer with no setup, with mathematics, folded answers, figures and boxes that tick;
- PDFs dropped into the quilt, and links that open a book beside a lesson at a page;
- a click on a citation opening the cited result beside the paper;
- reading a work's pages as text, overviews, and notes on a page;
- agent copies of a document, read and annotated beside the paper;
- the research-state page as an agent's index of a problem;
- transcripts as an agent's report, with links to what it wrote;
- annotation types the person defines, which reach the agent's instructions at once;
- the compare view, hover previews on citations, and the status-line hints beside the tools;
- strict type checking in both codebases; and the hermetic TeX environment in tests (read in code).

## What only the author can settle

- In the Code tab: whether picking a folder counts as trusting it; where the approval for loom's server appears; whether loom's modes appear in the `/` menu; whether project hooks run.
- The install on a clean Mac, and the first cold compile there.
- The Overleaf mirror against a real project with git access.
- Codex and Gemini, before shipping.
- A real person's attestation of a formal statement, and a real model in the proofreading journey once the command line is signed in.
