# The build directory loom writes and its viewer reads

This directory specifies what loom publishes into `.loom/build/` and what its viewer, arras, reads there and asks of it: the HTML dialect of fragments, the manifest, the diagnostic codes, the write API, and what loom reads from an author's LaTeX. Loom and its viewer are one tool (P11): the viewer is built from `arras/` and vendored inside loom, so the two change together and nothing between them negotiates a version. The interface files (dialect, manifest, diagnostics, fixture, write API) mark normative statements **[decided]**, a convention kept from the old design book; `source-contract.md` and `digests.md` state their rules plainly. What the specs describe is what the code does: where one disagrees with the code, one of them is wrong.

## Files

- `dialect.md` : the semantic HTML dialect of fragments.
- `manifest.md` : the schema of `manifest.json`.
- `diagnostics.md` : diagnostic codes, reserved and loom's own.
- `source-contract.md` : what loom reads from an author's LaTeX: nodes, ids, proofs, edges, directives.
- `digests.md` : digests of cited works: their files, ids, result states, postnote edges and the library store.
- `fixture.md` : the fixture and how it is used.
- `write-api.md` : the write API, the HTTP form of loom's local commands that the viewer calls.
- `tools/validate-dialect.py` : the fragment validator both codebases vendor; `tools/refresh-fixture.sh` : regenerates `fixture/` and both vendored snapshots.

## Changing what crosses

**[decided]** A change to what loom writes or what the viewer reads changes both sides and these files in one commit, and regenerates the fixture (C3, C5). No version is written into the manifest or checked by the viewer: the viewer reading a build directory is the one vendored in the loom that wrote it, and `scripts/checks/bundle.py` and `loom doctor` say when that vendored viewer is older than `arras/`'s sources.

## Obligations of loom as publisher

1. Write fragments conforming to `dialect.md` and a manifest conforming to `manifest.md`, every section of it.
2. Publish atomically: fragments first, manifest last, by rename.
3. Never depend on the viewer for anything: no callbacks, and no notification beyond a stream that says a new manifest exists and how each document's compile stands (`GET /_api/stream`, specs/write-api.md), which a viewer may ignore; a build directory served as static files is read whole.
4. Carry every diagnostic it knows about into the manifest, using reserved codes where they apply.
5. Regenerate the whole build directory from source on demand; nothing in it is durable.

## Obligations of the viewer

1. Treat the manifest as the only index; never derive structure from fragment contents beyond what the dialect marks up.
2. React to changes only by detecting that `manifest.json` changed; never assume kinds of change.
3. Render unknown diagnostic codes, unknown state labels, and unknown taxa generically, never fail on them.
4. Write only through the write API, which loom serves.

## The fixture

`fixture/` (beside these files) is the build directory of the synthetic quilt, generated by loom with TeX and regenerated when what crosses changes; each codebase vendors a snapshot, so the viewer's suites run without TeX. See `fixture.md`.
