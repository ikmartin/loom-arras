# The loom–arras interface specification

This directory is the contract between publishers (loom, later the author's org site generator) and viewers (arras). A publisher writes a build directory conforming to these files; a viewer renders any conforming build directory. The two share no code.

Status: version 1, implemented by loom and arras (2026-09-16); the fixture in `fixture/` is generated by loom and vendored by both tools, and every additive change since the draft is marked with the decision record or milestone that made it. Every normative statement carries the book's marker, **[decided]**.

## Files

- `dialect.md` : the semantic HTML dialect of fragments.
- `manifest.md` : the schema of `manifest.json`.
- `diagnostics.md` : diagnostic codes, reserved and publisher-namespaced.
- `fixture.md` : the conformance fixture and how it is used.
- `write-api.md` : the write API (deferred).
- `runner.md` : the runner contract (deferred).
- `tools/validate-dialect.py` : the fragment validator both tools vendor; `tools/refresh-fixture.sh` : regenerates `fixture/` and both vendored snapshots.

## Versioning

**[decided]** The interface has an integer version, `interface_version`, written into every manifest. Version 1 is this draft. A change that a conforming viewer of version n could misrender bumps the version; a purely additive change (a new optional field, a new publisher code) does not. Publishers and viewers each declare the versions they produce or accept; a viewer that receives a manifest with a version it does not accept renders the problems page with a single diagnostic saying so and nothing else.

**[decided]** The spec files are versioned together with the workspace repository; the fixture directory records the interface version it conforms to.

## Obligations of a publisher

1. Write fragments conforming to `dialect.md` and a manifest conforming to `manifest.md`.
2. Publish atomically: fragments first, manifest last, by rename.
3. Never depend on the viewer for anything: no callbacks, no notifications (a `POST /_refresh` is the sole deferred exception).
4. Carry every diagnostic it knows about into the manifest, using reserved codes where they apply.
5. Regenerate the whole build directory from source on demand; nothing in it is durable.

## Obligations of a viewer

1. Render any conforming build directory without knowledge of the source language or the publisher.
2. Treat the manifest as the only index; never derive structure from fragment contents beyond what the dialect marks up.
3. React to changes only by detecting that `manifest.json` changed; never assume kinds of change.
4. Render unknown diagnostic codes, unknown state labels, and unknown taxa generically, never fail on them.
5. Write nothing. (The write API, when built, is served by the publisher; the viewer is its client.)

## The fixture

`fixture/` (beside these files, in the workspace repository) is the published build directory of a synthetic quilt, generated by loom and regenerated when the specification changes. Each tool vendors a stamped snapshot for its tests. See `fixture.md`.
