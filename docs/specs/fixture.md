# The conformance fixture

The fixture is the published build directory of a synthetic quilt, generated by loom and kept in the workspace at `specs/fixture/`. It is the executable form of the interface: loom's tests check that loom produces it, arras's tests check that arras renders it. Interface version 1.

## 1. The source quilt

**[decided]** The synthetic quilt lives in loom's repository at `tests/quilts/synthetic/`. Its mathematics is invented ("widgets", "gadgets") so that nothing in it is anyone's paper. Its authored files are `tests/quilts/sources/synthetic/`; the quilt itself is written by `loom/scripts/gen_quilts.py`, which runs loom's own commands on those files under a fixed clock, so every record in it was made by the command that makes one. It exercises, at minimum:

- two masters (`drafting/main.tex`, `drafting/talk.tex`), the second reaching a subset of the nodes, with different taxa declared for one environment (`loom:taxon-conflict`);
- three landmarks under `canon/` (`widgets-v1`, `widgets-v2`, `widgets-v3`) written by `loom canonize` at three moments, each flat and self-contained, one of them edited afterwards so `loom:canon-edited` has something to report;
- a history of five steps — three canonizations and two stamps, one narrowed to the talk — a fork with its ancestry, a revert whose head is again the text of `@1`, and a key removed at the last step, so a retired id exists;
- one id defined by two live files, published as conflicted with `duplicate-id` naming both;
- nodes inline in the master and nodes in `nodes/`;
- a section file included with `\input` and one with `\nest`, so a shifted level appears;
- adjacent proofs, one deferred proof by reference, one theorem with two labelled proofs, one node with two unlabelled proofs (`loom:positional-proof-key`);
- a definition-style node, a remark, an unnumbered `\newtheorem*` environment;
- an equation in a statement referenced from another node, an equation in a proof referenced from another node (`loom:equation-in-proof-referenced`), an equation in prose;
- a file imported with human labels kept as aliases;
- a digest with a `-setup` node, `\uses`, a macro block, and `requires:`, whose headings are section nodes `Kre99-sec-1` and `Kre99-sec-2` (DR-62); one postnote that resolves (`\cite[Theorem 2.1]{Kre99}` in `sy-000A`, an edge `via: postnote`), one that does not (`loom:unmatched-postnote`); one citekey with no digest (`loom:undigested-citekey`);
- an `\incomplete` proof;
- a loose node file and a loose old master with `% !LOOM ignore` (the latter not scanned, so no diagnostic);
- a dangling `\ref` (`dangling-link`), a missing `\input` (`missing-include`), a double inclusion in the talk master (`double-inclusion`);
- an acceptance ledger with six accepted keys, five of them stale — by dependency change (with snapshots and a diff) and by own-text change — and two rows for a key that no longer exists (`loom:retired-ledger-key`);
- two sessions: one an agent and a person both wrote in (with a message in its transcript and `run.log`), holding the agent's findings, one of the person's, replies, resolved and detached annotations; the other discarded; both appear in the manifest as threads of kind `session` with search entries (M6);
- tags on several nodes, a node-level author override;
- one `see` relation between a node the paper reaches and a loose notes-style node, declared node-level and resolved through an alias; one `see` item that names no node (`dangling-link`); one that names the node it is written in (`loom:see-redundant`);
- a tikzcd diagram, an `\includegraphics` of a PDF figure, a block that falls back to SVG (a `\parbox`), a footnote, an itemize, a simple table.

**[decided]** A second, much smaller quilt `tests/quilts/demo/` is the one `loom init --demo` writes: two masters (`drafting/main.tex` and the outline master `drafting/outline.tex`, which reaches one conjecture and one question the paper does not), seven nodes, one digest, one landmark under `canon/` with the step that wrote it, two accepted keys, one stale, its AI layer initialised (`ai/`, `CLAUDE.md`, `AGENTS.md`, `.claude/` with permission settings and skill stubs), one comment from a person, and one finished referee run with a message in its chat, a notes file, and two annotations, so the session, the margin marks and both groups of the document picker have content immediately. It is written by the same generator, and `test_init_demo_matches_fixture` asserts the copy equals what `init --demo` writes.

## 2. Generation

**[decided]** `loom/scripts/gen_quilts.py` writes the quilt; `loom build` on it, with `loom compile` of both masters run first so numbering is present, produces `build/`. The workspace script `specs/tools/refresh-fixture.sh` runs both in an isolated environment (empty HOME and TEXMF trees, `LOOM_FIXED_TIME=2026-09-16T00:00:00Z` so every timestamp is fixed rather than stripped), copies `build/manifest.json`, `build/fragments/`, `build/svg/`, `build/diffs/`, and `build/source/` to `specs/fixture/`, records `interface_version`, the loom version, and the fixed time in `specs/fixture/VERSION`, vendors the result into both tool repositories, and runs `validate-dialect.py` on every fragment (M2). The build exits 1: the quilt carries four intentional errors — two `dangling-link`, one `missing-include`, one `double-inclusion`, one `duplicate-id`.

## 3. Vendoring

**[decided]** Each tool repository vendors a snapshot: `loom/tests/fixture/` and `arras/tests/fixture/`, each with `VERSION`. Loom's CI compares its own build of the synthetic quilt to the vendored snapshot (manifest structurally except for generated, compiler, publisher-version and canon-rendering hashes; fragments textually with SVG bodies normalized) and fails on any other difference (DR-218). A canon-rendering hash includes dvisvgm's machine-specific SVG bytes, so it cannot be compared across TeX Live versions. Arras's CI renders the vendored snapshot in Playwright and checks every page. When the interface changes, the fixture is regenerated in the workspace and both snapshots are refreshed in the same change.

## 4. What the fixture tests

Loom: scanner correctness on every construct above, diagnostics emitted with correct codes and locations, states and causes, marks placement, atomic publish (a test interrupts a publish and checks the manifest is either old or new, never mixed).

Arras: every page kind renders (node, master, digest, thread, review panel, problems, blockers, graph, tags, taxa, search); every diagnostic code appears on the problems page; unknown-code and unknown-state fixtures (added synthetically to a copy of the manifest) render generically; live reload triggers on a manifest change and not on a fragment-only change; the static prerender produces one shell per route with the content loaded client-side (DR-54).

Interface: `specs/tools/validate-dialect.py` passes on every fragment. A JSON schema derived from `manifest.md` would validate the manifest as well; it is not written, and it is not going to be: the vendored fixture compared byte for byte is a stronger check than a schema, and it is what keeps the two implementations in agreement (`docs/work-queue/closed.md`, WQ-14).

## 5. `fixture-minimal`: a second fixture with a different job

**[decided]** `docs/specs/fixture-minimal/` is a hand-written manifest and three fragments belonging to **the specification**, generated by nobody's publisher, vendored into `arras/tests/fixture-minimal/`. Its publisher declares itself `fixture-minimal`, and it omits eleven top-level sections outright — `masters`, `keys`, `regions`, `inclusion`, `annotations`, `threads`, `references`, `diagnostics`, `canon`, `relations` and `generated` — rather than writing them empty, because absence is what §1's floor permits and an empty object would pass without testing it. It carries four things no viewer knows: a state label, a relation kind, a taxon named by a node but absent from `taxa`, and nothing else strange.

**The two fixtures must not be merged.** `specs/fixture/` proves that *one* publisher and *one* viewer agree, construct by construct, byte for byte: it is generated by loom, it is rich, and every assertion against it names real content. `fixture-minimal` proves something the first cannot — that the interface has a floor, and that arras stands on the floor rather than on loom's output. Adding content to it weakens it; asserting rich behaviour against it is a category error. Its suite (`arras/tests/e2e-minimal/`) is deliberately assertion-light: every route renders, nothing throws, and no page speaks a publisher's vocabulary.

It is not touched by `specs/tools/refresh-fixture.sh`, which regenerates the other fixture from loom's synthetic quilt. It is edited by hand, and `specs/tools/validate-dialect.py` runs on its fragments like any other.
