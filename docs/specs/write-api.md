# Write API

The write API is the HTTP form of the publisher's local commands, so that a browser can request record writes and explicit document-workspace steps. It is served by the publisher (loom's `serve`), never by the viewer. Its author-file writes are explicit local incorporation actions: `sync-incorporate` and `adopt-finish`.

**[decided]** The commands it wraps are library functions with the same signatures, and a viewer detects it rather than assuming it.

## 1. Discovery

**[decided]** `GET /_api` returns `{"write_api": 1, "capabilities": [...], "token": "...", "stream": true, "frames": "http://127.0.0.1:PORT"}` or 404, and 403 to a request a browser says came from another page (§3). `frames` is the frames origin an HTML file is shown from (§3), absent where none runs. `stream` says `GET /_api/stream` is served: a `text/event-stream` with an event `manifest`, carrying nothing, each time a new manifest is published; an event `compiles` on opening and each time a compile starts, ends or is asked for, carrying one JSON object keyed by document path, each `{"state": "queued"|"compiling"|"idle", "again": bool, "last": null | {"result": "ok"|"errors"|"failed", "ended", "error", "at"}}`, where `errors` made a PDF though LaTeX reported errors, `failed` made none so the last good one stays, and `at` is the log's `l.N` line where TeX stopped; and a comment every fifteen seconds while idle. The token is what every write must carry (§3). A viewer that receives 404 or a version it does not accept shows no editing affordances. The capability list is what this publisher actually serves, so a viewer must read it rather than assume the table below: an endpoint absent from the list answers 404, and a viewer that hides the affordance is correct.

## 2. Endpoints

**[decided]** All requests and responses are JSON. Errors return `{"error": {"code": "...", "message": "...", "fields"?: {...}}}` with 4xx status, `fields` naming the reason for each field of a form it refused; the codes are the CLI's exit reasons. A request that names something that does not exist answers 404 with `no-such-` and what it named (`no-such-node`, `no-such-annotation`, `no-such-session`, `no-such-quote`, …), the same refusals the CLI exits 2 for; 400 is a malformed request or a write refused on its merits, 403 the CSRF gate (`refused`) or an author's act refused to an agent (`author-only`), 409 a conflict with the quilt's state. An annotation belongs to no session, so no annotation endpoint names one, and a `session` sent with one is ignored.

**[decided]** **A work added by hand** (plan 0.24.2) goes into loom's own bibliography, `.loom/digests/bibliography.bib`, never a document's `.bib`, with `loom-added = {WHEN, WHO}`; the manifest's reference carries it as `added` (specs/manifest.md). `library-lookup`'s `found` is `{state, kind, label, value, entry, key, digest, duplicates, message}`: `state` is `found`, `missing` (the identifier names nothing: a DOI doi.org has no record of, an arXiv id arXiv does not have), `unreachable` (the service could not be asked, `message` saying why), `offline` (it needs the network, which neither `[library] online` nor `online` allows) or `cannot` (an ISBN, a MathSciNet number, or text that is no identifier, which loom does not look up); `entry` is the fields loom would write; `key` the key it would be filed as, unique; `digest` is `source` when an arXiv id lets loom fetch its LaTeX source, else `lookup`; `duplicates` names works already in the library with the same identifier or title and year. A DOI is asked of doi.org by content negotiation, an arXiv id of the arXiv API, a zbMATH number of zbMATH Open; a BibTeX entry is found from its own fields with no network. A request body over 96 MB answers `too-large` (413) before it is read.

**[decided]** **A library run is a job** (plan 0.24.1): a run can take minutes, a compile being allowed ten, so `library-update` answers with `{ok, result, job}` before it starts, and the publisher runs its jobs one at a time on a worker of its own, outside the lock its other writes take, rebuilding when each finishes. A job is `{id, kind: "library-update", works, steps: [{name, state, n, total, item}], state, who, online, redo, submitted, started?, finished?, error?, report?}`: `works` is the citekeys it acts on, empty for every work; each step is `waiting`, `running`, `done`, or `skipped` when it acted on nothing (offline, or nothing in it to do), with how far through the works it is and the one it is on; `state` is `queued`, `running`, `done` or `failed`, a failed run keeping its `error`; `report` is what `loom library update` prints, as its JSON envelope, whose `works` has one line per work saying what failed for it: `lookup_error` (the lookup could not be made), `discarded` (the paper fetched was not this work), `extract_error`, `map_error`. A viewer shows a work's failures from the last run on it while the publisher holds that run; nothing persists them. `online: true` is the person's allowance of the network for that run, as `--online` is, written nowhere; an agent cannot ask for it, since the endpoint refuses an agent. `GET /_api/jobs` answers `{jobs}`, the newest first, to this server's origin with the token, as `GET /_api/here` does. While a run acts on a work, `library-verify` and `library-discard` on that work's results answer `library-busy` (409), since the run writes its digest too. A publisher that runs no jobs answers `library-update` with `no-runner` (409). Jobs are held in memory, and a restarted publisher has none.

**[decided]** `GET /_api/events?session=ID&since=SEQ` answers `{session, from, seq, events}`: the events after `SEQ` in the transcript's page form (specs/manifest.md §10.1) and the last sequence number. It reads by an index of where each event starts, so a poll costs what is new; a `session` that is not an id's shape is refused.

**[decided]** `here` is the reader's place, which `loom here` reports to an agent. A tab posts it after a change of the focused item, the block at the top of its pane, the selection, the PDF page, the session or the block under review has settled, and again when it gains focus, so the tab touched last wins. `item` and `beside` are the focused pane's active item and the other pane's, in the viewer's item shape (`{kind, id, place?}`); `block` is `{src, key}`, the `data-src` and key of the block at the pane's top; `selection` is `{key, text}` in a document, `{file, text}` in a project file, or `{page, text?, rects}` on a PDF page, in points from the page's top left, the box tool's region included; a file item's `place` is its heading, `page=N` or anchor; `page` is the PDF page in view; `annotation` is the id of the annotation whose popup is open, which `loom here` names with a crop of its page when it is on one, as it does a region drawn on a page; `review` is `{key, cause}`, the block under review, the cause in the viewer's words: on `/review` in place of the workspace, and in a document beside Review's panel (`?review=`) alongside its item; on any other page, `route` is `elsewhere` and `path` is the viewer's. A place over 64,000 bytes, or with no `route`, is refused with `bad-field`. `GET /_api/here` answers `{place, when, age}`: the last place, the second it came and how many seconds ago, `place` null before any tab has reported. It requires the token and this server's origin, like a write, since where a person is reading and what they selected are theirs. Nothing writes it to disk, and a server's stop forgets it.


**[decided]** `compare` answers `{ok, left, right, pairs}`. `left` and `right` are `{item, kind, macros}`: the item as asked, `"document"`, `"landmark"` or `"node"`, and the manifest macro set its renderings are typeset with (`canon:<stem>` for a landmark, null for the default). Each pair is `{pair, base, left, right}`: the plain key; which side holds the base — `"left"`, `"right"`, `"both"` when the node changed on both sides since the version an agent document began from, or null when nothing orders them; and per side `{key, hash, fragment?}`, the node's key there, its `data-hash`, and a fragment path under the build directory with the changed words marked as Review marks them. A pair whose hashes agree is no difference and is left out, a display name changed alone included. A pair the quilt no longer has a live node for has no `fragment`, and the viewer keeps its whole-node marks. An item that is none of these is refused with `unknown-item`, 404. It is a read: the publisher does not rebuild after it. The answer is computed when asked, never at build, since the pairs two items can form grow with the square of the landmarks.

**[decided]** `session-purge` is **not** an endpoint and will not become one. Purging erases a session's directory and transcript for good, and the one place that should be reachable from is a terminal where the author typed the word.

**[decided]** `annotate` with `page` records an annotation on a page of a cited work (DR-209) through the same mapping `locate` previews — one function on the publisher, so what the viewer showed is what the log says. `locate` with `span` maps offsets into the page's committed text, which is what a `span=` locator in a URL carries. `locate` with `text` and no `page` maps the quote on the first page whose committed text holds it, which is what a `quote=` locator with no `page=` carries; it is refused with `not-found`, 404, when no page does.

**[decided]** `locate` maps a selection to an anchor **on the publisher**, never in the browser. The client's text layer is a third extraction of a page, after the committed page text and the word boxes; only the publisher holds the other two, and only the publisher can say what the page says. The client sends the selected string and never a decision about what the anchor is. Geometry-only anchors are legal and are never refused.

**[decided]** `undo: true` on `resolve` opens the annotation again (DR-174). It appends another event rather than removing one, so the record still says that it was resolved, when and by whom, and that it was reopened. A viewer offers it in place of the verb that fired, which is what lets those two act on a single click: a wrong one is one click back.

**[decided]** A change is kept or discarded where it is drawn, in its document or in Review, never resolved. Its id is what both endpoints take: `c-` and eight hex digits for an in-place edit, its content's hash, which stands while the change does, and a suggested edit's own id. Every write loom makes on the person's word goes into their look too, so a suggested edit kept is not listed back as an in-place edit of its words; a suggested edit whose key already reads as it taken is kept without writing. An agent withdraws its own open edit with `loom suggest --withdraw ID`; keeping and discarding are the author's.

## 3. Authorship

**[decided]** `author` defaults to the publisher's resolved author name; `as` declares an identity, and an agent names itself including `Agent` or `AI`. The author's verbs refuse a declared agent identity whichever surface it came through, here with 403 `author-only`. A write that names no author is taken for the author's own click in the viewer, which is why no page but the viewer may make one (below).

**[decided]** **Every write carries three checks.** They are CSRF protection and not a login: they keep other *pages* out, not other people.

1. **`X-Loom-Token`** must equal the token in `.loom/serve.json`, which `GET /_api` serves and the viewer reads.
2. **The page it came from** must be this server's: `Origin`, when present, is this server's own, and `Sec-Fetch-Site`, when present, is `same-origin` (or `none`, the person typing the address).
3. **`Content-Type: application/json`** is required.

A browser blocks a cross-origin *response* and never the *request*, so any page the author happens to be reading could otherwise POST into their quilt and create, resolve or delete. A cross-site form post can set neither a custom header nor a JSON content type, which is what closes it. The socket still binds to loopback, which keeps other machines out; it never kept out the page the author was reading. A request failing any of the three answers 403 with `{"error": {"code": "refused", ...}}`.

**[decided]** **No page but the viewer runs in the viewer's origin.** The token keeps other sites out, but `/build/` and `/digests/storage/` are served from the viewer's own origin, an agent writes the build output they serve (`.loom/build/`), and storage holds fetched sources nobody at loom wrote. So everything but the viewer's bundle, which is those files and every JSON answer, is served with `Content-Security-Policy: sandbox` and `X-Content-Type-Options: nosniff`. A page there, HTML or SVG, runs no script and has an opaque origin: it cannot read `/_api`, and a POST it made would carry `Origin: null`, which check 2 refuses. `GET /_api` applies check 2 too and answers 403 `refused` when it fails, so the token goes only to the viewer's own origin. The viewer reads these files with `fetch`, `<img>` and PDF.js, which a response's sandbox does not touch, and a PDF opened in a tab of its own is shown by the browser's viewer as before. A project file the viewer shows is served the same way at `/_files/PATH` (manifest §1, `files`), and nothing hidden is.

**[decided]** **A Markdown file's body is drawn in the viewer's own page**, so a publisher writes the HTML it holds through an allowlist first (specs/dialect.md §1), and nothing from it runs as the viewer: not a script, a handler or a `javascript:` address. A frame in it loads only an `https:` address, which is never this origin, since `loom serve` answers on `http:`. The body is confined under `/build/` as every file there is, which does not touch the viewer's read of it, and the viewer's own page carries no policy that would stop the frame.

**Open.** The allowlist is the publisher's, and a viewer inserts what it reads. An agent may write `.loom/build/`, so a body or a manifest it edits there directly reaches the page unfiltered and can read the token; this was reproduced on 2026-11-04 against a real `loom serve`, and predates HTML in Markdown files. See the [invariant](../design/invariants.md#a-page-the-quilt-holds-never-runs-as-the-viewer).

**[decided]** **An HTML file runs on the frames origin** (plan 0.22.7). `loom serve` answers the project's shown files a second time on a loopback port of their own, which `GET /_api` names as `frames`, so an HTML file the viewer frames runs as a page of its own origin: its scripts run and embedded players (a video) play. That origin serves GET and HEAD for shown files and nothing else — no `/_api`, no bundle, no build output, no store — answers only a request addressed to its own host and port, and sends no CORS headers; check 2 refuses it, so a page there can never read the token or write. **What a page there may rely on:** it reads the project's other shown files by their paths; `GET /.loom/files.json` answers `{"files": [PATH…]}`, every shown file sorted, at an address no shown file can have since `.loom` is never shown; and its `quilt:`, `cited:` and `app:` links go through the bridge below. It has no way to write. Its browser storage lasts only until `loom serve` restarts, since the origin's port is chosen anew each time. Nothing stops it sending what it reads to the network, which embedded players need, so an HTML file in a quilt is trusted as any program the person runs is. Into each HTML page it adds a small script, the bridge, that posts to the viewer's origin alone: a click on a `quilt:`, `cited:` or `app:` link, which the viewer follows as its own; the words selected, which the viewer reports to `here`; and a move to a new anchor. The viewer frames the page with `sandbox` keeping its origin but granting no top navigation, and drops every message not from that frame and that origin. Where no frames origin runs, a viewer shows the page from `/_files/` with no script.

**[decided]** **`open` never runs code.** It opens an application by a plain name (letters, digits, spaces, `.`, `-`, `_`; `open -a` on macOS, `gtk-launch` on Linux) or a shown file whose suffix is a document's — a notebook, a spreadsheet, an office document, an Anki package, audio or video, a book — and refuses a file with an executable bit, a hidden file, and any other suffix (`not-openable`, `no-such-file`, 400 and 404). An agent can write a file and a link to it into the quilt; it cannot make the person's click execute it.

## 4. No model behaviour, and no bridge

**[decided]** A publisher calls no model and starts no agent (plan 0.20.1). A session's inbox is its transcript: agents write it with `loom session say`, and the viewer reads it through `GET /_api/events` and posts nothing into it, since a conversation with an agent happens in the agent's own app. An earlier draft routed a reply through "the bridge": a component that watched threads and invoked the runner. The runner was declined as WQ-15, so the bridge had nothing left to invoke; the viewer's message composer and loom's launching of an agent for a turn (DR-195, DR-203, DR-273-ikmartin, DR-278-ikmartin) were retired in plan 0.20.1. Loom holds no credentials and calls no model.

**[decided]** The direction is the other way round, and it already works: an agent **pulls**. It reads open annotations with `loom status` and `loom ai annotations`, and answers with `loom annotate --reply`. That needs no server, no credentials held by loom, and no tracking of vendor flags that churn. A person writing in the viewer and an agent answering in its own session are the same log seen from two ends, which is what the log was for.

## 5. Selection to quote

**[decided]** The viewer computes the `quote` for an annotation from the user's selection in a fragment: the selected text mapped back through the block's `data-src` to source text. When the selection crosses markup TeX made and the source text cannot be recovered exactly, the viewer sends the rendered text and the publisher attempts the whitespace-normalized match; failure returns the CLI's "quote not found" error and the viewer offers a whole-block annotation instead.

Personal review writes require the displayed `reviewer` to equal the current local identity; missing identity returns `no-reviewer`, changed or missing displayed context returns `reviewer-changed` (409) before mutation. Review decision validation also checks the build's reviewer. The local settings capabilities use the existing localhost and token protections and expose no arbitrary path or configuration write. Unsupported TOML author-table forms refuse rather than risking unrelated keys. Settings changes select a history, never rename it.

**[decided]** `settings-save` changes only the keys the manifest's `config.editable` lists (specs/manifest.md), each checked as the CLI would read it: `quilt.name` non-empty, `quilt.prefix` an id prefix, `quilt.engine` an engine loom runs, `quilt.main` one of the person's documents, `quilt.home` a file the viewer shows, `library.online` a boolean, `lint.disable` codes that can be silenced, `agents.deny` patterns `loom.agents` accepts; an empty `main`, `home` or `contact` removes the line. `quilt.history` and `quilt.research_state` are read-only here, since each names where files already are. A refused change answers `bad-value` (409) with `fields` naming each refused key and why, and nothing is written. The file is edited line by line: a key's value in place with its trailing comment, a commented template line (`# home = …`) made the setting, a new key after its table's last, a new table at the end; the result is parsed and compared with what was asked, so a layout loom cannot edit that way (a dotted key, an inline table) is refused rather than rewritten. A changed deny list leaves Claude Code's permission file stale until `agents-update` or `loom upgrade` rewrites it, which `loom:agent-permissions-stale` and `config.agents.stale` say.

**[decided]** `types-save` writes the types file whole, under the header comment the defaults carry, so the viewer sends every type, and a type it leaves out is deleted: its annotations read as untyped (specs/manifest.md §9). A type with no `id` takes one from its name: lower case, a hyphen for each run of other characters, starting with a letter, with `-2`, `-3` added until it is unique. A type is refused as `bad-field` (400), naming it, when its name is empty or repeats another's (case aside), its id is not lowercase letters, digits and hyphens starting with a letter or repeats another's, a look field is missing or one loom cannot draw (as `annotation_types` documents, specs/manifest.md §1), `open` or `notes` is not a boolean, or `instructions` is not text; nothing is written then. A body with neither a `types` list nor `defaults: true` is `missing-field` (400). An agent edits the file itself, so the endpoint is refused to one (`author-only`, 403).

### Mathematical decisions during incorporation (DR-316-luisa)

| `POST` | `/_api/sync-preview` | `{incoming, base, reviewer}` | prepares the pinned whole pull without applying it and returns a mathematical review preview |

`sync-preview` returns `{ok, result: {token, reviewer, items}}`. `adopt-preview` adds the same object as `result.review` for the selected agent document's changes. Each mathematical item has `{key, name, reason, local, proposed, unavailable}`; local and proposed hold `{path, macros}` for isolated renderings, local may be null for new blocks, and unavailable explains why acceptance is disabled. Items include unchanged dependent proofs and exclude structural sections and prose. Preview preparation changes no acceptance records or author source.

`sync-incorporate` and `adopt-finish` optionally take `review_token` and `accept: string[]` with the effective `reviewer`. Omitting accept accepts nothing. Tokens bind the exact source, proposed patch and reviewer; foreign keys, repeated keys, changed source and stale selections are refused before application. After incorporation the selected blocks' fingerprints are checked again, applicable masters must compile and stale mathematical support must be included in the acceptance batch. The result adds `accepted` and `pending` lists. All unselected preview items remain explicitly pending. If incorporation succeeded but acceptance validation failed, the success result includes `acceptance_error` and pending mathematics; the UI reports both outcomes without suggesting that source application failed. The final server rebuild publishes the resulting review states. Prose has no acceptance action.

## Section drafts and responsive choices (DR-323-luisa)

`adopt-decision` is a metadata-only publication. The body carries the displayed contribution fingerprint and saved choice revision (initially zero); a stale revision returns 409 rather than overwriting another tab. Its returned result has `keys`, `kept`, `document`, `preamble`, `revision` and `fingerprint`. Every successful selection increments the revision; the manifest publishes the same authoritative row without rendering or compiling. The viewer applies that row immediately and ignores older rows for the same reviewer and fingerprint. A manifest poll containing only changed adoption choices preserves the loaded rendering.

`document` selects prose and ordering; `preamble` separately selects macros and packages, and is false by default. Choices whose base/current/proposed inputs still agree survive unrelated source changes; `invalidated` names choices needing inspection again. Preview tokens bind source, proposal, context, reviewer and choices. Selection does not accept mathematics. A copy's review shows accumulated outstanding edits, not just the latest agent message; leaving a change out keeps it available.

Closing and reopening are author actions. Close with outstanding proposals first returns `confirmation_required`, `unapplied` and a message without closing; resend `confirmed: true` to preserve the snapshot and release the scope. Closed source remains on disk but is excluded from the live scan. Reopen refuses a changed retained file, missing source, overlapping scope or occupied identities. The saved rendering and annotations remain readable under the original document path.
