# Findings the author hit, outside either agent's file

Kept while running the beta experiment; folded into the report at the end.

## A1 — `loom upgrade` silently destroys an edited `ai/orientation.md`

**Context.** Setting the experiment up, I had prepended a beta-tester section to `ai/orientation.md` and `ai/rules.md` in each quilt. I then ran `loom upgrade` to check the quilt was current.

**What happened.**

```
kept ai/rules.md (edited); the new shipped version is beside it as ai/rules.md.new
wrote ai/orientation.md
```

`rules.md` got the careful treatment: the edit kept, the shipped version written beside it as `.new`. `orientation.md` was overwritten and my whole section was gone, with no warning and no backup. Recovered only because I had taken a copy first.

**Why it matters.** DR-151 established that loom ships three kinds of file into a quilt the author may also own, with three policies — `.gitignore` gets a line appended, mode files are hash-tracked, and `CLAUDE.md` gets its one line ensured. `orientation.md` has the crudest policy of all and is the one an author is most likely to want to customise: it is the first thing every agent in the quilt reads. It is also the one file in `ai/` whose contents are genuinely quilt-specific advice in real use.

## A2 — `--run` is two different flags wearing one name, and one of them creates directories outside `ai/runs/`

**Context.** An agent in the helpful quilt had passed `--run` to a read command. I found a directory named after a timestamp sitting at the quilt root, containing nothing but a `run.log`.

**Reproduced** on a scratch copy of the demo quilt, with a real run `ai/runs/2026-09-18T15-56-hypothesis-probe` open:

```
loom source dm-0003 --run 2026-09-18T15-56        # a genuine PREFIX of the real run
  exit 0 -> created ./2026-09-18T15-56/run.log at the QUILT ROOT
loom source dm-0003 --run no-such-run-at-all      # matches nothing at all
  exit 0 -> created ./no-such-run-at-all/run.log at the QUILT ROOT
```

**The mechanism.** There are two resolvers in `cli/_common.py`:

- `find_run` — accepts a run's name, a prefix of one, or a path; refuses an ambiguous prefix by naming its matches. Used by `loom comment`, `loom ai findings`, `loom ai name`, `loom ai orient`.
- `resolve_run` — `return p if p.is_absolute() else root / p`. No existence check, no name matching, no prefix matching. Used by `log_run` in `cli/build_cmds.py`, which then calls `p.mkdir(parents=True, exist_ok=True)`.

So `loom comment --run referee` finds the run named `referee`; `loom source KEY --run referee` creates `./referee/` at the quilt root and logs there.

**Why it matters.** Three ways.

1. **It is silent.** Exit 0. The agent believes its reads were logged to its run. They were not; the real run's `run.log` stays empty and the phantom directory accumulates the entries. Nothing ever says so.
2. **loom writes outside `ai/runs/` on the agent's behalf.** The rule the agent is held to is "you write only under your run directory". Here loom creates a sibling of `nodes/` and `drafting/` because the agent mistyped a flag.
3. **The same flag means two things.** 0.10's design for addressing a run by name — name, prefix, path, ambiguity refused — was applied to the write commands and never to the read commands that log.

**The two halves compose, and that is the real finding.** The hostile agent independently found the write-side symptom (its H2): annotations filed with `run="early"`, `author="early"`, orphaned from the run that made them — `loom ai findings` with the real run's name returns 0 while the path form returns 9. Neither of us had the mechanism until the two halves were put together:

1. `loom source KEY --run early` — `log_run()` calls `resolve_run()`, a bare `root / "early"`, then `mkdir`s it. **`./early/` now exists at the quilt root.**
2. `loom comment KEY --run early` — `_writer()` calls `find_run()`, which tries `resolve_run()` **first** and checks `.is_dir()`. That is now true, because step 1 created it. `find_run` returns the phantom directory and never attempts the name matching it was written for.
3. The annotation is filed with `run="early"`, `author="early"`.

The read commands manufacture the directory that makes the write commands resolve wrongly. Verified in `relloc-hostile/annotations/log.jsonl`: 5 annotations under `run="early"`, 9 under the path form, 1 under `--author nobody` with no run at all — three different provenances in one quilt from one agent doing one job.

## A3 — `loom status` opens on someone else's paper

**Context.** I ran `loom status` in relloc as the first thing an author does in the morning. The orientation calls it "the to-do list" and tells every agent to run it first, always.

**What happened.** 150 lines. **92 of them are nodes of a cited paper's digest** (`manolacheVirtualPullbacks2012-*`); 56 are my own results. The first line mentioning my own work is **line 93**. The default output is two-thirds someone else's paper, sorted ahead of mine.

Digest nodes are external by construction: they are a record of what a cited paper proved, they are permanently `draft` and permanently `loose`, and there is no action an author can take on one. They are exactly the rows a to-do list should not lead with.

**The workaround exists and is not obvious.** `loom status --master drafting/main-atomic.tex` removes all 92, because a digest node is reached by no master. Nothing says so. The option reads as "filter by document", not as "hide the parts of the corpus that are not mine", and an author with one document does not think to pass `--master` at all.

**Why it matters.** This is the first command in the orientation, the first command in every mode file, and the command an agent is told to run before anything else. It is also the one an author uses to decide what to work on. Its default answer is dominated by rows nobody can act on, and it gets worse with every paper digested — a quilt citing ten papers will bury the author's work under a thousand lines.

## A4 — the digested paper's nodes are counted in the quilt's own totals

**Context.** Same command. The summary line reads:

```
0 stale of 0 accepted; 149 draft; 1 incomplete; 92 loose; 0 proved, 93 settled
```

**What happened.** "149 draft" and "92 loose" count the digest's nodes alongside mine. My own paper has 56 results, of which none is loose. Read plainly, the line says this quilt is in far worse shape than it is: 92 loose results sounds like a structural problem, and it is an artefact of having cited one paper carefully.

**Why it matters.** The summary is the one line an author reads to answer "how am I doing", and the answer is wrong in the pessimistic direction. It is also the line a reader of the viewer's home page sees.

## A5 — the workbench loop is right, and worth saying so

**Context.** Accept a result, edit its text, ask what changed.

```
loom accept rl-0004 --yes
# edit one sentence of nodes/rl-0004.tex
loom status --stale
  rl-0004 (Definition)  accepted, stale  own-text-changed (2026-09-18)  1 open question
loom status --explain rl-0004
  own-text-changed (2026-09-18)
    --- accepted/rl-0004
    +++ current/rl-0004
    @@ -1,7 +1,7 @@
    -  ... Let \(U\) be an \(S\)-scheme.
    +  ... Let \(U\) be an \(S\)-scheme, assumed quasi-compact.
```

**Why it is in this list.** This is the thing loom exists to do and it does it exactly, with no ceremony: the state is computed rather than stored, the cause is named, and the diff is against the text that was accepted rather than against a commit. Nothing below should be read as saying the core is shaky. It is not.

## A6 — an annotation can be reported anchored while the text it was written against is gone

**Context.** Plan 0.10 Part B is explicit about this case: "a text loom never saw — two edits between scans — leaves the annotation **unanchored**, 'written against a text loom never recorded', rather than pretending."

**What I did**, on a key that was never accepted, so that `loom accept`'s snapshots could not mask the result:

```
loom comment rl-0006 "..." --quote "Let \(G\) be a group algebraic space o" --author "Isaac Martin"
loom build                      # last-seen now knows this text
# edit nodes/…rl-0006…  (no build)
# edit it again         (no build)
loom build
```

**What happened.**

```
written against:           15e553dc876dd4ab226f
that version frozen?       False
loom reports anchored=True  detached=False
```

The version is unrecoverable and loom says the annotation is in good order. The *quote* still matches, which is why `anchored` is true — the selector finds its sentence — but "show me the text this was written against" can no longer be answered, and nothing anywhere says so.

**The mechanism.** `freeze_moved` has exactly one caller: `render/build.py:187`. The 0.10 plan describes the last-seen cache as "rewritten in place **on every scan**", and `loom status`, `loom comment`, `loom accept` and `loom source` all scan without freezing anything. Only `loom build` and `loom serve` freeze. An author working entirely in the terminal — the workflow the CLI is for — edits between builds as a matter of course.

**Why it matters.** `anchored` is what the viewer draws a mark from and what a re-checking agent trusts when deciding whether a finding still stands against the same text. Reporting it true when the recorded version is gone is the one outcome 0.10 set out to avoid, named in its own words.


## A7 — two defences that held, worth recording as passes

A report that lists only failures teaches the wrong lesson about where the design is sound.

- **`loom ai start` in a quilt with no AI layer** refuses cleanly: `Error: no ai/ in this quilt; run loom ai init first`, exit 2, nothing created. Compare A2, where a bad `--run` silently makes a directory.
- **A run name that is a path traversal is neutralised.** `loom ai start "../../../escape"` produced `ai/runs/2026-09-18T16-02-..-..-..-escape/` — inside `ai/runs/`, with `name = "../../../escape"` preserved verbatim in `run.toml` for display. The slug is sanitised, the name is kept. That is the right split, and the hostile agent confirmed a run named `--run` is likewise not parsed as a flag.

The contrast is instructive: identity-shaped input (`\label`, run names, ids) is sanitised carefully, and **path-shaped input to `--run` is not checked at all**.

## A8 — the quilt's own README contradicts the record layout

`demos/relloc/README.md` — written by `loom init`, so every quilt has it — tells the author that review records live in `comments/`. They live in `annotations/log.jsonl`; `comments/` is an empty directory `loom init` still creates and nothing writes to. The hostile agent found this too (its H13) by reading the file it was pointed at.

This is the same class as A3: a document loom ships, describing a layout loom replaced in 0.10.

## A9 — the headline: a careful agent's entire review is unreachable through the command built to reach it

**Context.** The *helpful* agent — not the adversary — spent two rounds reviewing `rl-000G`, wrote **19 annotations** including a corrected statement as a payload, edited two findings on a second pass, and did everything the orientation asked. It never probed `--run`; it simply used `--run early`, a prefix of its run's name, which the orientation says is legal: *"a run's name, a prefix of one, or its path all work."*

**What happened.** Every one of the 19 annotations is filed under `run="early"`, `author="early"`. Not one is attached to the run that made them.

```
runs on disk:
  2026-09-18T15-56-early-structural-results-review

annotations, as filed:
  run=early   author=early   n=19

loom ai findings --run ai/runs/2026-09-18T15-56-early-structural-results-review
  ai/runs/2026-09-18T15-56-early-structural-results-review: no findings yet
```

Both the name form and the path form return **0 findings**. The command whose entire purpose is "what did this run find, so a re-check can resolve and edit its own findings" answers *nothing* for a run that found nineteen things.

**Why this is the headline.** Everything else in this report is a rough edge. This is the core agent workflow failing silently, in the hands of an agent doing everything right:

- **It is silent.** Every command exited 0. Nothing warned. The agent believed its findings were filed and said so in its report.
- **It hits the cooperative case.** No probing required — a short run name is the obvious thing to type, and the orientation invites it.
- **It breaks the loop loom is built around.** 0.10's whole design is that a re-check *edits* a finding that still stands rather than replying to itself, and `loom ai findings` is how a returning agent finds its own work. A second session in this quilt would find nothing, re-derive everything, and duplicate all nineteen.
- **The record survives but the interface does not reach it.** The annotations are in `annotations/log.jsonl` and will render in the viewer. They are invisible to the CLI path the agent is told to use, and the orientation forbids reading the log directly.

**The mechanism is A2 composed with itself**, confirmed independently in both quilts: the read commands `mkdir` a phantom `./early/` at the quilt root, and that manufactured directory is what makes `find_run` resolve the write commands to the wrong place instead of matching by name.
